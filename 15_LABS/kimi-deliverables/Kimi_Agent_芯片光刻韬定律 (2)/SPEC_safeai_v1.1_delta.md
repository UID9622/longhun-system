## 1. 新模块：LawEnforcementGateway（执法审计网关）
```python
class LawEnforcementGateway:
    def register_authority(self, auth: Authority) -> str        # 注册执法主体，返回接入DNA
    def request_access(self, auth_dna: str, query: AuditQuery, warrant: WarrantRef) -> AccessDecision
    def export_evidence_package(self, case_dna: str, auth_dna: str) -> EvidencePackage
```
设计原则（焊死，不许改）：
- **不碰政治**：网关只提供"依法依规的审计通道"，不做内容定性，定性权属于各国法律
- **触发条件**（缺一不放行）：
  T1 涉事判定已是L4熔断或L3限制（系统内确证严重事件）
  T2 执法主体持有有效凭证引用（WarrantRef：本国法律文书编号/国际协作公约编号，格式校验+登记簿核验）
  T3 查询范围与案件DNA绑定（不许全量拖库，只能按案件链条调取）
- **分级接口**（一国一策，P3层适配）：
  - G1 公开层：任何人可查聚合统计（判定总数/分级分布，无个体内容）—— 零门槛
  - G2 主体层：用户查自己的判定与申诉记录 —— 本人DNA验证
  - G3 案件层：本国执法按案件调取完整证据链（判定+打分+上下文+DNA链）—— T1+T2+T3全满足
  - G4 国际层：跨国协作（国际刑警/双边公约渠道），在G3之上加"两国法律双合规校验"开关，由所在国P3配置决定开放与否
- **全程留痕**：每次执法查询本身也是一条审计记录（谁、何时、查了什么、凭据编号），上DNA链，永久可查——**执法也被审计**

## 2. 升级：上游数据DNA编码规则（补小艺缺口1）
- DNATrace 新增 `stamp_upstream(payload_type, content_hash) -> str`
- 所有进入引擎的上游数据（用户请求、输入文档、历史对话批次）先取SHA-256哈希，再盖DNA：`#龍芯⚡️{干支}·{卦名}-上游-{类型}-{序号}`，账本只存**哈希+DNA**，不存原始内容副本（数据主权+最小留存）
- 证据包导出时凭哈希校验内容完整性（内容若被改过，哈希对不上即暴露）
