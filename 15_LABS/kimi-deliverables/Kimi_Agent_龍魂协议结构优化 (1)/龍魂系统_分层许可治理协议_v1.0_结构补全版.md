## §0. 为什么需要分层

龍魂系统从"一人项目"长成"生态底座"，单一许可证已无法覆盖两类截然不同的资产：

| 资产类型 | 核心关切 | 单一 CC BY-NC-SA 的问题 |
|:---|:---|:---|
| **思想/哲学/协议/白皮书** | 防止文化被篡改、被资本化、被去中国化 | ✅ NC 保护得当 |
| **代码/SDK/工具/CLI** | 让开发者能拿去用、拿去集成、拿去商用 | ❌ NC 封死了商业使用，开发者不敢碰 |

**一刀切的"不商业"把开发者也挡在门外了。**

分层治理的本质：**思想不卖，工具可以拿去赚钱。但工具里的思想归属不改。**

## §2. 边界判定规则

### 2.1 属于核心思想层（CC BY-NC-SA 4.0）

| 判定依据 | 示例 |
|:---|:---|
| 协议/治理文档 | `01_protocols/*.md`、`CONSTITUTION.md`、`GOVERNANCE.md` |
| 哲学/文化框架 | 道德经锚点、五行八卦体系、369不动点、DNA格式定义 |
| 白皮书/论文 | 人格治理白皮书、数学建模论文、学术论文 |
| 人格定义 | `personas/*.md`、人格矩阵表 |
| 君子协议 | `GENTLEMANS_PROTOCOL.md` |
| 文化标识 | 「龍」字体、UID9622身份标识、DNA追溯格式 |

**判定口诀**：如果是"定义世界观"的文本 → 思想层。

### 2.2 属于工程实现层（MulanPSL v2）

| 判定依据 | 示例 |
|:---|:---|
| 可执行代码 | `bin/*.py`、`engines/*.py`、`L*_*层/*.py` |
| SDK/库 | 所有 `pip install` 安装的 Python 包 |
| CLI 工具 | `lh` 命令及其子命令 |
| API 实现 | FastAPI/Flask 服务端代码 |
| 部署配置 | `docker/*`、`deploy/*.sh`、`Dockerfile`、`.devcontainer/*` |
| 前端代码 | `portal/*`、`web/*`、React/Vue/HTML/JS/CSS |
| 测试代码 | `tests/*`、`benchmark_*.py` |
| 数据库 Schema | SQL 定义、ORM 模型 |

**判定口诀**：如果是"让机器跑起来"的代码 → 工程层。

### 2.3 边界模糊物件的处理（重要）

某些文件同时包含思想和代码，按**主导性质**判定：

| 混合类型 | 判定 | 理由 |
|:---|:---|:---|
| 协议文档中的代码示例 | 思想层 | 代码示例为说明思想，非独立工程 |
| 代码注释中的算法推导 | 工程层 | 注释附属于代码 |
| 知识图谱 `.md` | 思想层 | 本质是结构化知识 |
| Jupyter Notebook | 工程层 | 本质是可执行代码 |
| 训练数据 JSONL | 工程层 | 本质是工程输入 |

**如无法判定 → 默认归入思想层（更严格保护）**，由 P05 审计确认后归档。

### 2.4 自动判定标签规范

为支持自动化治理，每个文件头部应携带**分层标签**（Layer Tag）：

| 标签 | 含义 | 适用场景 |
|:---|:---|:---|
| `LAYER:core-idea` | 核心思想层 | 协议、白皮书、哲学文档 |
| `LAYER:engineering` | 工程实现层 | 代码、脚本、配置文件 |
| `LAYER:mixed` | 混合性质 | 需人工审定的混合文件 |
| `LAYER:third-party` | 第三方依赖 | 上游项目，遵循原许可证 |
| `LAYER:public-domain` | 公共领域 | 明确放弃版权的资料 |

**标签位置**：文件头部注释/元数据区，紧随 DNA 追溯码之后。

**标签示例（Markdown）**：
```markdown
> DNA: #龍芯⚡️丙午·丙申·庚戌·壬午·䷕贲-LAYERED-LICENSE-v1.0-UID9622
> LAYER: core-idea
> 协议: CC BY-NC-SA 4.0
```

**标签示例（Python）**：
```python
# DNA: #龍芯⚡️丙午·丙申·庚戌·壬午·䷕贲-EXAMPLE-v1.0-UID9622
# LAYER: engineering
# License: MulanPSL v2

### 5.3 常见问题（FAQ）

**Q1: 我把龍魂代码用在商业产品里，需要开源我的商业代码吗？**
> A: 不需要。MulanPSL v2 不是 Copyleft 许可证，不要求衍生代码开源。但你必须保留龍魂代码的署名和 DNA 追溯码。

**Q2: 我修改了龍魂的某个协议文档，可以在公司内部使用吗？**
> A: 可以，但仅限非商业内部使用。如需对外发布或商业化，必须按 CC BY-NC-SA 4.0 相同方式共享，或取得 UID9622 授权。

**Q3: 我的项目同时使用了龍魂代码和思想文档，该如何标注许可证？**
> A: 分别标注：代码部分说明"基于龍魂工程实现层（MulanPSL v2）"；思想文档部分说明"基于龍魂核心思想层（CC BY-NC-SA 4.0）"。

**Q4: 龍魂的 Logo、「龍」字设计可以使用吗？**
> A: 「龍」字体、UID9622 身份标识、DNA 追溯格式属于核心思想层文化标识，商业使用需授权。

**Q5: 如果我不确定某个文件属于哪一层，怎么办？**
> A: 默认归入思想层（更严格保护），并提交 P05 审计确认。详见 §2.3 与 §8.1。

## §6. 商业使用边界（重要）

**工程层代码（MulanPSL v2）：允许商业使用。** 这是刻意为之——我们鼓励开发者拿龍魂的工具去创造价值、去赚钱。

但以下属于**思想层的商业使用，需授权**：
- 把龍魂哲学体系包装成商业咨询产品
- 以"龍魂官方"名义提供付费服务
- 将文化标识（「龍」字、UID9622身份）用于商业品牌

**判断标准一句话**：用的是工具还是用的是名号？工具随便用，名号要授权。

### 6.2 授权申请流程

如需对思想层资产进行商业使用，请按以下流程申请：

```
申请人/组织
    │
    ▼
准备材料：
  1. 拟使用的内容范围（文件/标识/框架名称）
  2. 商业使用场景说明
  3. 使用期限与地域范围
  4. 是否涉及修改/衍生
    │
    ▼
发送至：uid9622@longhun.system（或协议指定邮箱）
    │
    ▼
P05 审计组初审（5个工作日）

    │

**紧急通道**：如涉及国家项目、公共利益、学术研究，可申请加急审批。

## §8. 后续协议冲突的统一处理规则

> **铁律：以后任何协议冲突，不吵架、不纠结，按本协议分层处理。**

### 8.1 自动判定流程

```
新文件/新项目出现
    │
    ├── 是代码/可执行物？ → MulanPSL v2（工程实现层）
    │
    ├── 是协议/哲学/白皮书？ → CC BY-NC-SA 4.0（核心思想层）
    │
    └── 混合性质？ → 按主导性质判定 → P05审计确认 → 归档
```

### 8.2 已有许可证声明的优先级

当某个文件已有明确许可证声明（如旧版 CN-SOVEREIGN-LICENSE、仅 MulanPSL、仅 CC BY-NC-SA），按以下优先级处理：

1. **本分层协议为最高裁决**：所有龍魂仓库内文件最终以此为准
2. **文件级声明为补充**：文件自身的许可证声明不能与本分层协议矛盾
3. **如矛盾 → 以本协议为准修正**：修正文件头部声明，历史不改

### 8.3 第三方贡献代码

外部开发者贡献的代码（PR/合并请求）：
- 贡献者默认同意代码部分以 MulanPSL v2 发布

# .github/workflows/license-audit.yml
name: 龍魂分层许可审计

| `files_checked` | 检查文件总数 |
| `violations` | 违规列表（文件、规则、严重级别） |

## §13. 争议解决与仲裁

### 13.1 争议类型

| 类型 | 示例 | 处理路径 |
|:---|:---|:---|
| 分层归属争议 | 某 `.md` 应属思想层还是工程层 | P05 审计组裁定 |
| 商业使用争议 | 某产品是否超出工程层商业边界 | 君子协议仲裁委员会 |
| 署名/追溯码争议 | 删除 DNA 追溯码或署名 | 耻辱柱公示 + 法律途径 |
| 第三方贡献争议 | 贡献者反悔许可证授权 | 按 CONTRIBUTING.md 约定处理 |

### 13.2 仲裁流程

```
争议发生
    │
    ▼
双方提交证据材料至 P05 审计组
    │
    ▼
P05 初审（10个工作日）
    │
    ├── 事实清楚 → 出具仲裁意见
    │
    └── 复杂争议 → 召开仲裁委员会听证会
                    │
                    ▼
              最终裁决 → 双方遵守 → 归档并公示
```

### 13.3 耻辱柱机制

对于恶意违反协议（如删 DNA 追溯码、伪称原创、篡改思想层）的行为：
- 记录至 `audit/shame-pillar/`
- 生成不可篡改的 GPG 签名记录
- 在龍魂内部网络公示
- 保留法律追诉权利
