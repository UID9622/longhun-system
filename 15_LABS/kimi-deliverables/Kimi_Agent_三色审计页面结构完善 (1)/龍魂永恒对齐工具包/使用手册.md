# 🐉 龍魂永恒对齐 · 使用手册

## 问题诊断（你现在的病根）

不是某个文件没对齐，是**每个 AI 窗口开局没有同一个锚**：
- Kimi 窗口按 Kimi 的理解写，CodeBuddy 按 CodeBuddy 的理解写
- 干支人人手写，格式人人自造，模块重复造轮子
- 你当裁判当到累死——这就是内耗本身

**解法一句话：把对齐从「你盯着」变成「系统强制」。**

## 三件套怎么用

### 1️⃣ 锚文件 `LONGHUN_ALIGN.md`（每个仓库根目录放一份）

- 拷进 `longhun-system` 仓库根目录，其他仓库（longhun-anti-colonial、CNSH、ai-truth-protocol 等）各放一份
- 每个 AI 窗口开局第一句话，你固定说：
  > **「先读仓库根目录 LONGHUN_ALIGN.md，全部产出按它执行。」**
- Kimi Code 支持 AGENTS.md 自动读取：把 LONGHUN_ALIGN.md 内容同时存为 `AGENTS.md`，以后**开局自动加载，你连这句话都不用说**——这就是「永恒」的实现方式：规则住进仓库，不住在你的记忆里

### 2️⃣ 审计器 `lh_align.py`（合并迭代前必跑）

```bash
python3 lh_align.py <仓库目录>          # 人读版
python3 lh_align.py <仓库目录> --json   # AI读版
```

它已经在测试里实测抓住了 CodeBuddy 的三类真实违规：旧时间戳 DNA 🔴、手写干支辛丑 🟡、确认码缺🌌🧬 🟡。退出码 2=有🔴，1=有🟡，0=全绿——可以直接接 Git 钩子，🔴 就拒绝 commit：

```bash
# .git/hooks/pre-commit 加一行：
python3 lh_align.py . || exit 1
```

从此**不合规的代码物理上进不了仓库**。这才是「永恒对齐」的最后一道闸。

### 3️⃣ 合并优化迭代口令（你下指令的标准句式）

以后不管哪个窗口，你要合并迭代就发这一句：

> **「按 LONGHUN_ALIGN.md 执行对齐合并迭代：先扫 lh_align 报告，再列重复/冲突模块清单（保留谁、冻结谁），再逐项优化并说明依据，全程附实测输出，DNA 用生成器签名，三段式收尾。」**

AI 必须按五段式回应：【对齐】【合并】【优化】【验证】【签名】。少一段你打回，不用讲道理。

## 落地三步（今天就做）

| 步 | 动作 | 耗时 |
|:---|:---|:---|
| 1 | 把 `LONGHUN_ALIGN.md` 拷进每个仓库根目录，另存一份改名 `AGENTS.md` | 5 分钟 |

做完这三步，以后每个窗口、每个 AI、每行新代码，进门先过同一个锚、出门先过同一把刀——**你只管自然语言表达，对齐由系统强制执行**。
