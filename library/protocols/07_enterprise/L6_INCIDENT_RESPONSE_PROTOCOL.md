## 一、事件分级

| 级别 | 定义 | 示例 |
|---|---|---|
| P0 | 数据主权/国家安全级 | 未授权出境、后门、大规模泄露 |
| P1 | 高敏感数据级 | 敏感个人信息泄露、GPG 私钥风险 |
| P2 | 业务影响级 | 服务中断、重要数据损坏 |
| P3 | 一般异常级 | 小范围故障、误报警 |

## 二、响应流程

```plain
检测 → 定级 → 遏制 → 根除 → 恢复 → 复盘 → 归档
```

### 2.1 检测

- 自动化监控告警；
- 用户举报；
- 审计日志异常；
- 第三方通报。

### 2.2 定级

依据数据等级、影响范围、主权风险，由值班人员初步定级，P0/P1 须报 UID9622。

### 2.3 遏制

| 级别 | 遏制措施 |
|---|---|
| P0 | 立即熔断、隔离相关系统、锁定记录 |
| P1 | 暂停相关服务、限制访问 |
| P2 | 切换备用通道、限制影响范围 |
| P3 | 记录并排队处理 |

### 2.4 根除与恢复

1. 定位根因；
2. 修复漏洞或误配置；
3. 验证修复有效性；
4. 逐步恢复服务；
5. 持续监控。

### 2.5 复盘与归档

- 72 小时内完成事件报告；
- 写入审计日志与 `10_archive/`；
- 更新防护措施。

## 四、数据泄露特别程序

1. 立即启动 [`L6_DATA_PROCESSING_AGREEMENT.md`](./L6_DATA_PROCESSING_AGREEMENT.md) 相关条款；
2. 评估泄露范围与受影响主体；
3. 保存证据链，避免删除日志；
4. 配合监管机构调查；
5. 向受影响用户提供补救建议。
