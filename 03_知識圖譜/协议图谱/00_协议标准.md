## 一、目的

## 二、与哲学伦理图谱的关系

协议是 `哲学伦理图谱` 的**下游工程层**：

- `哲学伦理图谱` 承载**不可变底线**（principle / belief / doctrine）：数据主权在用户、不得侵犯人权、留痕即主权…
- `协议图谱` 承载**可执行条款**（protocol / clause）：把上述底线落成"怎么操作、谁能动、动了怎么分、违了怎么裁"。

协议节点的 `based_on` 必须指向对应的哲学节点（如 `protocol_knowledge_sovereignty` 基于 `data_sovereignty_in_user`），形成"思想→协议→条款"的引用链。

## 三、层级体系（L0–L3）

| 层级 | 含义 | 节点类型 | 示例 |
|:----:|:-----|:--------|:-----|
| L0 | 顶层契约（焊死，不可修订，引用哲学节点） | principle | 数据主权在用户、不得侵犯人权、留痕即主权 |
| L1 | 核心协议（体系级可执行契约） | protocol | 数据主权与知识贡献协议、言论自由协议 |
| L2 | 子机制/条款（协议下的具体规则） | clause | 零征用、自愿贡献、主权撤回、知识定价、骂权分级、权重评估、自骂优先、DNA追溯、争议处理 |
| L3 | 执行/自动化（触发、归档、审计） | clause | 自动审计、自动归档、红蓝对抗触发 |

> L0 节点已在 `哲学伦理图谱/` 中，本协议图谱通过 `related` 与 `layer` 字段与其连通，不重复定义。

## 四、节点字段规范

```
id          唯一ID（英文slug，如 protocol_knowledge_sovereignty）
type        protocol | clause（L1/L3 用 protocol，L2 用 clause）
title       中文标题
layer       L1 | L2 | L3
dna         DNA追溯码（#龍芯⚡️... 或 #CONFIRM🌌9622-ONLY-ONCE🧬LK9X-772Z）
owner       归属（恒为 UID9622 · 诸葛鑫）
claim       一句话主张（这条协议/条款是什么）
based_on    [基于的 L0 哲学节点 id / 源文件]
reasoning   推导/逻辑（为何这样定）
conclusion  结论/动作（执行表现）
why         为什么不可妥协
source_link 溯源链接（指向 master 协议文档相对路径 + 锚点）
related     [关联节点 id]
immutable   true/false（L1 核心协议大多焊死，L2/L3 可随版本迭代）
created     农历干支日期（禁公历）
```
