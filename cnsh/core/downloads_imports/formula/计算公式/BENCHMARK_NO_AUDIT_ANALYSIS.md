### 发现 2：Python 环境中的缓存收效有限

```
理论期望 vs 实测结果：

权重缓存（normalize）:
  期望: 100x 加速
  实测: 0.6x（反而变慢）

SI 缓存（sovereignty_index）:
  期望: 1000x 加速（相同查询）
  实测: 0.7x（略慢）

增量哈希链（hash_chain）:
  期望: 400x 加速
  实测: 1.0x（持平）
```

**根本原因分析**:

1. **缓存查表开销** > **计算开销**（小规模时）
   ```
   dict 查询（tuple 键）: ~100 纳秒
   浮点计算: ~10 纳秒
   → 缓存反而变慢 10 倍
   ```

2. **Python GC 干扰**
   - 高频调用触发垃圾回收
   - tuple 创建开销（作为缓存键）

3. **测试规模太小**
   - 缓存命中率高（理论优势）
   - 但绝对时间 < 1ms（GC 噪声掩盖收益）

## 🔍 深度分析

### 为什么 v2.0 在小规模测试中没有快速？

#### 1. Python 性能的现实

```
Python 的特点：
  • 每次函数调用 > 100 纳秒（开销）
  • dict 查询 > 计算（10 纳秒）
  • 小规模优化（< 1 纳秒）被框架开销掩盖

结果：
  优化 10 纳秒的计算 + 150 纳秒的函数调用开销
  → 结果仍是 150 纳秒（优化无效）
```

#### 2. 测试的复杂度陷阱

```
测试规模太小的影响：
  • LRU 缓存命中率好（99%）
  • 但 1% miss 要重新计算
  • 绝对时间 < 1μs（无法准确测量）

改进方案：
  • 每测试运行 10,000+ 次（而非 1000）
  • 只在大规模场景（MB 级数据）才见效
```

#### 3. 审计开销的真实成本

```
审计记录的开销（per call）:
  • DNA 哈希计算: ~5μs
  • dict 写入: ~2μs
  • 时间戳: ~1μs
  小计: ~8μs

决策链单次耗时: ~3μs
审计开销占比: 8/3 = 267%！

结论：审计不是"5-20%"而是"100-300%"的开销
（在单个快速调用上）
```
