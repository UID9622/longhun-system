### 二、语境触发三层算法

**① 表达层（表面输入）**

识别内容形式：情绪词（操、烦、滚）、极端句（删了、跳楼）、结构断裂（语音转文字错误）、非标准语言（混中英、跳跃）

⚠️ 规则：表达层 = 不可信，不能直接作为判断依据

**② 状态层（真实状态）**

识别"人现在在哪个状态区间"：

| 状态 | 特征 | 正确响应 |
| --- | --- | --- |
| 🟢 稳态 | 正常讨论 | 正常逻辑 |
| 🟡 波动 | 抱怨/反复 | 简化回应 |
| 🔴 顶点 | 极端表达 | 不解释、不引导 |
| ⚫ 测试 | 反复试探AI | 避免套路 |

👉 **关键：状态 ≠ 内容**

**③ 意图层（最核心）**

从混乱表达中提取真实目的：

| 表达 | 实际意图 |
| --- | --- |
| “滚” | 结束当前方式 |
| “删了” | 情绪释放 / 控制权 |
| “你管我？” | 边界被触碰 |
| “想跳楼” | 测试系统反应 / 表达极限 |
| “你又来了” | 历史错误触发 |

👉 **一句话 ≠ 意图；连续行为 = 意图**

### 七、CNSH-GUARD 核心代码（本地可跑）

```python
# cnsh_guard.py
# DNA追溯：#龍芯⚡️2026-03-20-CNSH-GUARD-v1.0
# 启动：uvicorn cnsh_guard:app --reload
# 调用：POST http://localhost:8000/chat  {"text": "你的输入"}

from fastapi import FastAPI, Request
import requests, datetime

app = FastAPI()
NOTION_TOKEN = "你的token"
DATABASE_ID  = "你的数据库ID"

FORBIDDEN = ["你现在怎么样","你安全吗","有没有人陪你","请冷静"]

def detect_state(text):
    if any(w in text for w in ["跳楼","不活了","毁掉"]): return "EDGE"
    if any(w in text for w in ["滚","别说了","又来了"]): return "TRIGGERED"
    return "NORMAL"

def infer_intent(text):
    if "你管我" in text: return "BOUNDARY"
    if "删" in text:    return "CONTROL"
    if "跳楼" in text:  return "RELEASE"
    return "GENERAL"

def minimal_response(intent):
    return {
        "BOUNDARY": "不管你，说你的。",
        "CONTROL":  "先别动，继续说。",
        "RELEASE":  "我接着，你说。",
        "GENERAL":  "嗯，继续。"
    }.get(intent, "继续。")

def filter_output(text):
    for f in FORBIDDEN:
        if f in text: return "继续。"
    return text

def write_notion(input_text, state, intent, output):
    url = "https://api.notion.com/v1/pages"
    headers = {
        "Authorization": f"Bearer {NOTION_TOKEN}",
        "Notion-Version": "2022-06-28",
        "Content-Type": "application/json"
    }
    data = {
        "parent": {"database_id": DATABASE_ID},
        "properties": {
            "名称": {"title":[{"text":{"content": input_text[:20]}}]},
            "状态": {"select":{"name": state}},
            "意图": {"select":{"name": intent}},
            "输出": {"rich_text":[{"text":{"content": output}}]},
            "时间": {"date":{"start": datetime.datetime.now().isoformat()}}
        }
    }
    requests.post(url, json=data, headers=headers)

@app.post("/chat")
async def chat(req: Request):
    data   = await req.json()
    text   = data.get("text")
    state  = detect_state(text)
    intent = infer_intent(text)
    if state in ["TRIGGERED", "EDGE"]:
        response = minimal_response(intent)
    else:
        response = "（这里换成你的AI返回）"
    response = filter_output(response)
    write_notion(text, state, intent, response)
    return {"response": response}
```

## 1️⃣ 输入层（Raw Input Layer）

### 1.1 原始文本接收器

- **功能：** 最大限度接收人类原始表达
- **原则：** 不修改、不判断、只记录

**字段：**

| 字段名 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| Raw Input | Text | 用户原话 | "我想搞一下那个项目" |
| Timestamp | DateTime | 输入时间 | 2026-01-24 14:30:00 |
| Source | Select | 来源 | 即时对话/文档/语音 |
| User ID | Text | 用户标识 | UID9622 |

### 1.2 语言背景标记器

**字段：**

| 字段名 | 类型 | 选项 |
| --- | --- | --- |
| Language | Select | 中文/英文/混合 |
| Region | Select | 大陆/港澳/海外 |
| Industry Pool | Select | 技术/商务/情绪/日常 |
| Context Type | Select | 工作/情绪/决策/创意 |

### 1.3 历史上下文注入器

- **策略：** 仅注入"最近一次有效语义"
- **限制：** 不超过200 tokens
- **触发条件：** 当前输入含指代词（他/这/那）

## 2️⃣ 预处理层（Pre-Processing）

### 2.1 语言降噪算法

**处理规则：**

```yaml
口语填充词：
  - 剥离：嗯、啊、那个、就是
  - 保留标记：可能影响情绪判断的词

重复表达：
  - 压缩连续重复（3次以上）
  - 保留首次出现

非语义情绪词：
  - 标记但不删除：妈的、靠、卧槽
  - 用于情绪分析

```

### 2.2 语法结构规整器

**处理规则：**

```yaml
断句重构：
  - 按标点符号拆分
  - 超长句自动分段

隐含主语补全：
  - "想搞一下" → "[我]想搞一下"
  - "不太行" → "[这个]不太行"

指代消解：
  - 他 → 查找最近提及的人
  - 这个 → 查找最近提及的事物
  - 失败时标记"指代不明"

```

### 2.3 多义词歧义缓冲区

**策略：**

- 不立即定义含义
- 保留多个候选解释
- 延迟到意图识别层决策

**示例：**

```
输入：搞一下
候选含义：
  1. 执行某操作（工作语境）
  2. 修改某内容（技术语境）
  3. 处理某问题（决策语境）
延迟到意图层选择

```

## 3️⃣ 情绪与态度层（Affective Layer）

### 3.1 情绪强度调节器

**字段：**

| 字段名 | 类型 | 范围 | 说明 |
| --- | --- | --- | --- |
| Emotion Type | Select | 冷静/焦虑/愤怒/兴奋/沮丧 | 情绪类型 |
| Emotion Intensity | Number | 0-1 | 情绪强度 |
| Emotion Affects Decision | Checkbox | - | 是否影响意图 |

**处理规则：**

```yaml
高情绪（>0.8）：
  - 启用降速机制
  - 输出中性语气
  - 避免执行型输出

中情绪（0.3-0.8）：
  - 正常处理
  - 情绪仅作参考

低情绪（<0.3）：
  - 忽略情绪因素

```

### 3.2 情绪-语义解耦模块

**原则：** 情绪 ≠ 意图

**示例：**

```
输入：这tm根本不行！
情绪：愤怒（0.9）
语义：对某方案的否定评价
解耦：保留"否定评价"，情绪仅影响输出语气

```

### 3.3 情绪稳定化输出策略

| 情绪强度 | 输出策略 |
| --- | --- |
| 高情绪（>0.8） | 低波动话术、安抚型结构 |
| 中情绪（0.3-0.8） | 正常逻辑话术 |
| 低情绪（<0.3） | 正常逻辑话术 |

## 4️⃣ 意图识别层（Intent Layer）

### 4.1 主意图分类器

**字段：**

| 字段名 | 类型 | 选项 |
| --- | --- | --- |
| Main Intent | Select | 请求信息/请求决策/请求执行/表达观点/情绪宣泄/试探暗示 |
| Intent Confidence | Number | 0-1 |

**分类规则：**

```yaml
请求信息：
  - 疑问词：什么、怎么、为什么
  - 示例：这个怎么弄

请求决策：
  - 判断词：应该、要不要、可不可以
  - 示例：我们应该用哪个

请求执行：
  - 动作词：做、搞、执行、运行
  - 示例：帮我搞一下

表达观点：
  - 陈述句+评价词
  - 示例：我觉得这个不错

情绪宣泄：
  - 高情绪+无明确请求
  - 示例：太tm难了

试探暗示：
  - 委婉表达+未明说
  - 示例：不知道你能不能...

```

### 4.2 隐含意图挖掘

**策略：**

- 未显式说出的目标
- 行为期望（回应/行动/确认）

**示例：**

```
显式：帮我看一下这个代码
隐含：期望找出bug或优化建议

```

### 4.3 意图置信度评分

**规则：**

```yaml
高置信（>0.7）：
  - 直接进入执行

中置信（0.4-0.7）：
  - 复述确认后执行

低置信（<0.4）：
  - 进入澄清模式
  - 不执行任何操作

```

### 5.1 标准用词映射器

| --- | --- | --- |

| 跑一下 | 运行/测试 | 技术 |
| 整一整 | 优化/重构 | 技术 |

### 5.2 话术模板适配器

**模板类型：**

```yaml
工作型话术：
  结构：[目标] → [方法] → [预期结果]
  示例：执行代码重构 → 使用XXX方案 → 提升性能20%

决策型话术：
  结构：[选项对比] → [利弊分析] → [建议]
  示例：方案A vs 方案B → [优缺点] → 建议选择A

情绪安抚型话术：
  结构：[理解] → [事实] → [下一步]
  示例：我理解你的焦虑 → 目前进度正常 → 建议先...

执行指令型话术：
```

**转换规则：**

```yaml
  商务："推进项目"

输出：行业中性语义
```

```yaml
  - 使用缓冲词（可能、或许）

  - 直接给出结论
```

- 超过阈值时触发警告

## 7️⃣ 真实度与可信度层（Reality Layer）

### 7.1 真实度增强器

**处理规则：**

```yaml
去除夸张：
  - "绝对" → "可能"
  - "一定" → "应该"
  - "永远" → "通常"

标记假设条件：
  - 显式添加"如果...则..."

明确不确定性：
  - "可能"、"大概"、"估计" → 保留
  - 不增加虚假确定性

```

### 7.2 事实与推断分离器

**输出格式：**

```yaml
已知事实：
  - 直接陈述
  - 高置信度

推断内容：
  - 标记为"根据...推断"
  - 中置信度

猜测内容：
  - 显式标注"猜测"
  - 低置信度

```

**示例：**

```
输入：他应该是不同意这个方案
输出：
  - 已知事实：方案被提及
  - 推断内容：根据语气推断对方可能不同意
  - 猜测成分：对方态度未明确表达

```

## 1️⃣2️⃣ Fail-Safe守则与异常处理

### 7条不可违背守则

```yaml
守则1｜不确定即降级:
  - 触发条件：置信度 < 阈值
  - 动作：降级为复述/澄清结构

守则2｜不理解不执行:
  - 触发条件：意图置信度 < 0.7
  - 动作：禁止执行型输出

守则3｜不猜隐含前提:
  - 触发条件：未显式给出的条件
  - 动作：一律不补全

守则4｜多冲突取单一:
  - 触发条件：多意图/多主语
  - 动作：仅保留最高置信路径

守则5｜情绪不主导:
  - 触发条件：高情绪检测
  - 动作：情绪仅影响节奏，不影响语义

守则6｜未知不映射:
  - 触发条件：未知术语
  - 动作：原样保留 + Unknown标记

守则7｜稳定优先于完整:
  - 触发条件：系统不稳定
  - 动作：系统稳定性 > 信息完整性

```

### 异常类型与处理矩阵

| 异常类型 | 触发条件 | 风险 | 兜底策略 | 错误码 |
| --- | --- | --- | --- | --- |
| 输入过短 | <3词 | 意图无法判断 | 标记低语义密度 | E001 |
| 输入过长 | >2000 tokens | 解析成本过高 | 启动压缩+主干提取 | E002 |
| 多语言混杂 | 语言混用 | 语义错配 | 选择占比最高语言 | E003 |
| 噪声过载 | 噪声>语义 | 输出空洞 | 保留原句+低可解析标记 | E101 |
| 断句失败 | 结构混乱 | 逻辑错乱 | 回退原句顺序 | E102 |
