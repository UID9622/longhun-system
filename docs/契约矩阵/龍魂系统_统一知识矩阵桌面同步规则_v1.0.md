## 摘要

本文檔規範龍魂系統所有對外文檔（協議、規則、論文、技術文檔、技能說明、執行報告）如何映射到桌面統一知識矩陣，確保分類對齊、索引完整、無孤立文件，並通過 `sync_index.json` 實現自適應鎖與增量同步。

## 關鍵詞

知識矩陣、桌面同步、自適應鎖、文件分類、無孤立文件、DNA 追溯

---

## 一、目標

讓所有協議、規則、哲學論文、技術文檔、技能說明、執行報告不再「孤懸」於各個子目錄，而是：

1. **統一出口**：全部映射到桌面一個文件夾。
2. **分類對齊**：按《知識矩陣總綱 v2.0》的模塊架構擺放。
3. **自適應鎖**：來源文件變更時，桌面鏡像可增量更新；索引與校驗和即為「鎖」。
4. **無孤立文件**：任何進入桌面的文件都必須在 `sync_index.json` 與 `README.md` 中有登記。

## 三、同步規則（自適應鎖）

### 3.1 鎖的定義

- **鎖 = `sync_index.json`**。
- 每個文件記錄：來源路徑、桌面相對路徑、MD5 校驗和、大小。
- 當來源文件 MD5 變化時，鎖判定為「需要更新」。
- 當來源文件消失時，鎖判定為「需要移除」（目前腳本採取全量重建，未來可改為增量）。

### 3.2 增量同步流程

1. 掃描所有配置的來源目錄。
2. 對每個文件計算分類（按檔名與路徑關鍵字）。
3. 複製到桌面的對應分類文件夾。
4. 生成新的 `sync_index.json` 與 `README.md`。
5. 同步腳本本身也被複製到 `99_索引與自適應鎖/`，確保「鎖自帶鑰匙」。

### 3.3 無孤立文件原則

- 任何進入桌面的文件必須同時出現在：
  - `sync_index.json`
  - `README.md` 文件索引
- 如果發現某文件只存在於桌面而不在索引中，視為「孤島」，下次同步會被清理或重新歸類。

## 四、如何重新同步

```bash
# 方式一：直接運行同步腳本
python3 ~/Desktop/龍魂系統·統一知識矩陣/99_索引與自適應鎖/sync_longhun_knowledge_desktop.py

# 方式二：從項目源頭運行
python3 ~/longhun-system/bin/sync_longhun_knowledge_desktop.py
```

每次運行會：
- 清空舊桌面鏡像（避免殘留孤島文件）。
- 按最新來源重新複製與分類。
- 重新生成索引與鎖。

---

## 五、分類規則擴展方法

若某文件被分錯類，請按以下步驟修正：

1. 打開 `~/longhun-system/bin/sync_longhun_knowledge_desktop.py`。
2. 修改 `CATEGORIES` 列表中的關鍵字規則（順序越靠前優先級越高）。
3. 重新運行同步腳本。
4. 檢查桌面 `README.md` 中的分類結果。

1. 分類規則基於檔名與路徑關鍵字啟發式匹配，可能存在誤分類，需要人工複核。
2. 同步腳本目前採取全量重建策略，未來可升級為真正的增量同步。
3. 用戶級技能目錄（`~/.kimi-code/skills/`）若發生變動，腳本規則需同步更新。
4. 本規則不保證覆蓋所有文件類型，特殊二進位或媒體文件需另行處理。
