【核心原则】
═══════════════════════════════════════════════════════════════════════════════
原则一: 一票否决权
─────────────────
· 所有🔴阻断判定，必须由大本营（华为手机）执行，加工厂（Mac）无阻断权
· 加工厂检测到异常，只能向大本营提交"阻断申请"，由大本营最终判定
· 大本营离线时，加工厂进入"只读缓存模式"，不执行任何写入/发布操作
原则二: 科技自主权
─────────────────
· 主密钥（GPG/加密/身份）物理存储于华为手机安全元件（SE），不可导出
· 加工厂持有的是"会话子密钥"，有效期≤24h，由大本营动态签发
· 子密钥泄露时，大本营一键撤销，加工厂立即失效
· 仓库发布用的GPG签名，必须由大本营硬件签名，加工厂不可代签
原则三: 硬件锚定
─────────────────
· 大本营DNA签名绑定华为手机硬件指纹（IMEI+SE_ID+芯片序列号）
· 加工厂DNA签名绑定Mac序列号（KVQQ7KLF76），但前缀标记为[FACTORY]
· 任何未绑定已知硬件指纹的操作，自动🔴阻断
· 硬件更换时，必须在大本营执行"设备注册仪式"，生成新的硬件锚定
原则四: 单向数据流
─────────────────
· 大本营 → 加工厂: 指令/密钥/待加工数据（加密通道）
· 加工厂 → 大本营: 加工结果/申请/日志（加密通道，需审批）
· 加工厂 → 仓库: 禁止直接推送
· 大本营 → 仓库: 唯一写入通道，每次携带硬件签名

【大本营模块】MOD-CAMP-01 · 主密钥库
┌─────────────────────────────────────────────────────────────────────────────┐
│ 模块ID: MOD-CAMP-01-v1.0                                                    │
│ 位置: 华为手机安全元件(SE) + 可信执行环境(TEE)                               │
│ 功能: 持有并保护所有主密钥，执行硬件级签名                                   │
│ 输入口:                                                                     │
│   IN-1  key_operation  enum   GENERATE / SIGN / VERIFY / ROTATE / REVOKE     │
│   IN-2  key_type       enum   GPG / AES / RSA / ECDH / HARDWARE             │
│   IN-3  auth_biometric bytes  生物特征认证（指纹/面容）                      │
│   IN-4  auth_pin       str    6位PIN码（备用认证）                            │
│ 输出口:                                                                     │
│   OUT-1 key_status     enum   ACTIVE / EXPIRED / REVOKED / LOCKED           │
│   OUT-2 signature      bytes  硬件签名结果（仅SIGN操作）                       │
│   OUT-3 sub_key        dict   会话子密钥（含有效期+权限范围）                  │
│   OUT-4 audit_log      list   密钥操作审计记录                                │
│ 校验规则:                                                                   │
│   RULE-1  生物特征认证失败>3次 → 锁定PIN认证，通知大本营持有者                  │
│   RULE-2  PIN错误>5次 → 主密钥库锁定24h，需硬件重置恢复                        │
│   RULE-3  子密钥有效期≤24h，过期自动失效，不可续期（必须重新申请）              │
│   RULE-4  密钥轮换周期: GPG主密钥≥2年，AES密钥≤90天，子密钥≤24h               │
│   RULE-5  所有密钥操作必须记录审计日志，保留≥180天                            │
│ 失败策略:                                                                   │
│   FAIL-1  RULE-1/2 触发 → 🔴锁定，返回 ERR-CAMP01-KEY-LOCKED                    │
│   FAIL-2  RULE-3 触发（子密钥过期）→ 🔴拒绝，返回 ERR-CAMP01-SUBKEY-EXPIRED     │
│   FAIL-3  硬件异常（SE故障）→ 🔴阻断，触发大本营应急模式（备用密钥卡）          │
│ 接口契约:                                                                   │
│   · 向 MOD-CAMP-02 输出 signature（用于一票否决判定）                         │
│   · 向 MOD-CAMP-03 输出 sub_key（用于加工厂授权）                             │
│   · 向 MOD-SEC-03 输出 audit_log（用于安全审计）                              │
│ DNA签名: #UID9622⚡️2026-06-12-CAMP01-KEY-VAULT-v1.0                            │
