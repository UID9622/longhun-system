```markdown
CONFIRM: #CONFIRM🌌9622-ONLY-ONCE🧬LK9X-772Z
```

### 1.1 版本號規則

- `v1.0.0`：首次正式對外發布。
- `v1.1.0`：內容擴展、新增章節。
- `v1.0.1`：錯字修正、數據勘誤、引用補全。
- 任何宣稱「重大發現」「證明」「等價」的變動必須升級 `Y`（如 `v2.0.0`），並經過三色審計。

### 1.2 DNA 編碼規則

```
#龍芯⚡️<日期>-<主題簡稱>-v<版本>
```

- 日期：ISO 8601（`YYYY-MM-DD`）。
- 主題簡稱：英文或拼音縮寫，禁止空格，例如 `RIEMANN-OBSERVATION`、`KNOWLEDGE-MATRIX`。
- 版本：與文檔版本號一致。

## 二、正文結構

### 2.1 摘要（Abstract）

- 不超過 256 字。
- 必須說明文檔的**性質**（觀察/規範/協議/記錄）和**局限**。
- 禁止在摘要中出現「證明」「定理」「等價」等未經同行評審的詞語，除非確有數學證明並附證明過程。

### 2.2 關鍵詞

- 5–10 個。
- 中英文對照優先。
- 禁止堆砌無關熱詞。

### 2.3 目錄（可選但推薦）

長文檔必須提供錨點目錄。

### 2.4 章節內容

- 每節必須有明確標題。
- 使用分層標題：`#` 文檔標題、`##` 一級節、`###` 二級節。
- 代碼、公式、數據必須標註來源與可復現條件。

### 2.5 引用與溯源（References & Provenance）

- 所有外部事實、數據、定理、代碼片段必須列出引用。
- 引用格式：
  ```
  [1] 作者. 標題. 來源, 年份. URL（如有）
  ```
- 內部文檔引用格式：
  ```
  參見《文檔名》(#DNA-簽名)
  ```
- 若為原創推論，必須標註「原創推論，未經同行評審」。

### 2.6 數據與實驗

- 必須說明復現環境：操作系統、語言版本、庫版本、運行日期。
- 必須提供原始數據或生成數據的代碼。
- 必須說明近似方法、參數選擇、樣本範圍。

### 2.7 誠實局限（Honest Limitations）

- 必須獨立成章。
- 至少列出 3 條本分析的局限或不確定性。
- 對於觀察性框架，必須明確聲明：「本文檔不構成數學證明或法律意見。」

## 四、語言與格式規範

1. **術語一致性**：同一概念全篇使用同一術語，首次出現附英文對照。
2. **避免絕對化用詞**：不用「絕對」「必然」「已經證明」等，除非有嚴格論證。
3. **數據精度**：數值結果保留有效數字，並標註單位或相對誤差。
4. **可讀性**：段落不宜過長，善用列表、表格、代碼塊。
5. **無孤立文件**：每份文檔必須在 `academic_papers_registry.json` 或相應 registry 中登記。
