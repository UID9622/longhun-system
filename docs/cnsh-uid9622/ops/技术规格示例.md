# 问题陈述

你想解决什么问题？如果有 PRD，这可以是来自 PRD 的同步区块。链接到与背景相关的任何其他文档。

## 目标

这个项目实施后，应该是什么情况？

## 非目标

哪些内容明确不在范围内，为什么？

# 建议的解决方案

要解决此问题并实现项目目标，需要进行哪些更改？

**有哪些高层架构变化？**

图表在这里可能非常有用。

**高级数据模型有哪些变化？**

这些应包括任何数据库架构更改，或对结构化字段的任何更改，例如现有的 JSON 列。

**UI 的主要变化是什么？**

## 风险

这组变化可能会带来哪些风险？考虑运行[预先检验](https://www.notion.com/templates/pre-mortem-template)以增加风险。请务必在实施和推广计划中记录降低这些风险的措施。

**是否有任何向后不兼容的更改？**

**该项目是否对安全和数据隐私有特殊影响？**

**这种变化是否会显著增加我们任何后端系统的负载？**

**此项目是否有任何依赖项？**

# 替代解决方案

你考虑了哪些替代方案？描述你如何选择建议解决方案的评估标准。

# 实施和推广计划

根据与该项目的规模和范围相关的内容填写此部分。此部分也可以在项目启动时作为待定，但随着项目的进展，你应该逐步填写此部分。

**此项目是否需要迁移？**

如果需要进行大量迁移，请为其编写单独的技术规格，并在此处链接。描述在迁移不成功时如何回滚。

**此项目是否在实验或特性中被标记？**

描述如何在需要时支持增量发布。

## 成功标准

**你将如何验证该解决方案是否正常工作？**

描述你将执行哪些自动和/或手动测试。此项目是否需要负载或压力测试？这也可以是与 QA 共享并在此处链接的单独测试计划文档。

**你将采取哪些监测和警报措施来确保该项目不会降低性能和可靠性？**

例如，请求、延迟和错误率增加。
