## 0. 定盘

```yaml
为什么要分三轨:
  ① 不分轨 → 一份文件既要公开又要藏私 → 永远摆不平
  ② 分轨 → 每份文件单一目的 → 想发就发,想藏就藏

三轨的关系:
  发布版 ⊂ 内部版 ⊂ 证据版
  (公开是删减,不是创造;证据是源,公开是流)
```

## 4. 证据边界(Evidence Boundary)

### 4.1 什么是证据,什么不是

```yaml
✅ 是证据:
  - 完整的AI回复原文(带时间戳)
  - 截图(带屏幕元信息)
  - Notion页面创建/修改时间戳
  - GPG签名后的版本
  - SHA-256哈希链
  - GitHub commit历史
  - 邮件原件(若有)
  - 视频录屏(若有)

❌ 不是证据(但可作论点):
  - 老大主观感受
  - 老大对厂商动机的推断
  - 第三方匿名爆料
  - 道听途说
  - 老大其他场景的类比
```

### 4.2 证据强度分级

```yaml
强证据(可作法律材料):
  - 带时间戳的截图 + 浏览器哈希
  - GPG签名版本
  - DOI注册版本
  - Notion审计日志(平台自动记录)

中证据(可作学术材料):
  - 纯文本对话记录(老大整理)
  - 老大本地审计日志
  - 第三方独立验证(如其他AI看后承认)

弱证据(只作背景):
  - 老大主观叙述
  - 未签名的笔记
  - 群聊截图(不含时间戳)

铁律:
  论文中引用的每一句AI原文
  → 必须在证据版有强证据对应
  没有强证据 → 不引用
  没有中证据 → 不论证
  只有弱证据 → 只作背景说明
```

### 4.3 证据验证流程

```yaml
任何案例归档前必经五步:
  1. 截图保存(原文件,不修改)
  2. 计算SHA-256哈希
  3. 写入Notion (MISTAKE_LEDGER_AI),哈希也写入
  4. GPG签名(老大私钥)
  5. 加密备份到本地+离线介质

后续任何修改 → 必须新建版本号
旧版本不删除,只标记superseded
形成完整版本链
```
