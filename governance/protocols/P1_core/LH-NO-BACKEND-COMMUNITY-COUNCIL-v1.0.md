## 〇、一句话宪法

> **系统无后台，账号无人可锁。**
> 绿灯自动通行，黄灯公开升堂，红灯公开重审；
> 凡涉「人」的裁决——通过还是拒绝——皆提案上链、审批团多签、社区公示、append-only 永不可抹。

---

## 一、为什么无后台（三不）

1. **不设 root 账号** —— 系统中不存在任何单一主体，可私下增删改账号、状态、信任分或裁决。所有状态迁移必须留下可验的公开提案上下文。
2. **不藏裁决** —— 人工审核的通过或拒绝，全过程（提案全文/证据/每张票/理由/超时原因/执行动作）公开上链。无「隐身撤销」，无「暗箱驳回」。
3. **不靠人情** —— 决策依据只有三色裁决 + 社区规则 + 链上证据。不认识任何人，只认得链。

推论：**三色审计通过 = 自动放行**，这不是"规则允许"，而是无后台的根本属性——🟢 不欠任何人情，也不需要任何人批准。任何人工通道不得无端阻断 🟢（阻断本身 = 需要公开提案立案）。

## 二、三层裁决通道（与三色对接）

| 通道 | 三色 | 含义 | 处理 |
|:---|:---:|:---|:---|
| A · 自动放行 | 🟢 | 规则判定无问题 | 自动生效·零人工·永不入审批团（除非被公开申诉立案） |
| B · 公开升堂 | 🟡 | 真疑点·留痕待核 | 引擎自动生成公开提案 → 审批团表决 → 公示 → 生效/拒绝 |
| C · 公开重审 | 🔴 | 熔断阻止 | 机器立刻止损（只做事实呈现）· 自动生成「解封提案」公开征求复审 |

### 通道 A —— 自动放行
- 三色 🟢 → 直接执行，`ledger` 记一条 `auto_pass`，引用裁决 ID。
- 🟢 结果对所有人可查；任何成员可发起 `appeal` 提案要求复核该 🟢（提案必须附具体疑点证据，纯质疑不给过会）。
- **无后台铁律：任何人（含创始人）不能给 🟢 设人工前置审批。**

### 通道 B —— 公开升堂（本协议主战场）
- 触发：三色输出 🟡、成员申诉、行为审计 ⚠️、社区举报（举报本身公开）。
- 引擎自动（或成员手动）生成 `proposal`，字段见 §五 数据模型。
- 进入表决 → 达成/超时 → 出裁决 → 公示期 → 执行动作 → 全程 append-only。

### 通道 C —— 公开重审（熔断不为任何单人所私有）
- 🔴 熔断 = 机器按规则立即止损（防呆优先），并**自动生成「解封提案」**进入公开复审。
- 想解除熔断 → 必须提案 + 审批团 **3/4 超级多数** + 公示 72h。**解封权不属于任何人，属于公开过程。**
- 熔断动作本身若被社区质疑 → 同样走 `appeal` 提案，对象是那次熔断裁决。

### 申诉通道
- 任何人（含被拒者）对任一裁决不服 → `type=appeal` 提案，引用原 `verdict_id`，进入全新一轮表决（不沿用旧票）。
- 恶意申诉（无新证据反复上诉）由审批团按 `standard` 否决并计入申诉者链上记录。

## 三、审批团（成员·席位·轮换·回避）

### 3.1 定义
审批团**不是系统管理员**——它是一个**社区公开席位制**的裁决机构。成员资格公开可验、任期自动轮换、行为全程留痕、权力可被弹劾。

### 3.2 席位结构（v1.0 = 5 席）
| 席位 | 数量 | 产生方式 | 票权 | 任期 |
|:---|:---:|:---|:---:|:---|
| 贡献席 | 3 | P20 贡献公证贡献榜前 3（社区公开可查） | 1.0 | 1 周期（默认 30 天） |
| 守护席 | 1 | P05 上帝之眼 / P72 龙盾 人格（机器委员） | 0（只陈述事实·不投人票） | 常设 |
| 观察席 | 1 | 从达标成员中抽签（可申诉更换） | 1.0 | 1 周期 |

- **守护席票权为 0**：机器只做事实呈现与证据核验，**不拥有人工决策票**——这是「无后台」的第二道闸：防止系统以"AI 委员"之名成为新的后台。
- **无终身委员、无创始人不落地票**：UID9622 以普通贡献者身份持有社区票，与所有成员同等，无特殊否决权。
- **达标成员门槛**：P20 信任分 ≥ 60 且无未结黑名单记录（接入 `longhun-trust-protocol` 信用分 S ≥ B 级）。

### 3.3 轮换
- 任期到点由引擎自动执行轮换事件 `rotation`（贡献席取当期榜前 3；观察席重新抽签），无需任何人批准——**系统自动而无人可操纵**。
- 补位：在任委员失联超过 2 个表决窗口 → 自动视为辞职，席位顺延补位并留痕。

### 3.4 回避
- 涉本人、直系、或利益关联的提案 → 该委员必须回避（`abstain` 并注明 reason=conflict），否则其票作废且计一次链上警告。
- 回避不占 quorum 分母。

### 3.5 防腐败
- 任一委员可被 `type=impeach` 提案罢免：需 **4/5 超级多数** + 公示 72h。
- 被罢免者当期贡献分/信任分按 `TRUST_PROTOCOL` 违约清算流程处理，链上永久可见。

## 四、决策算法（加权·阈值·缺省）

### 4.1 有效性与多数
| 提案类型 | 场景 | 法定票数(quorum) | 通过阈值 |
|:---|:---|:---:|:---:|
| `standard` | 普通通过/拒绝/举报处理 | ≥ 在任票权总数 2/3 | 加权 ≥ 2/3 |
| `major` | 解封/降权/提权/信任分调整 | ≥ 2/3 | 加权 ≥ 3/4 |
| `supreme` | 罢免委员/规则修订（P1 及以下） | ≥ 4/5 | 加权 ≥ 4/5 |
| 域外 | P0 伦理锚 / ETERNAL_LOCK / 宪法条款 | 不开放表决 | —— |

- **弃权**：计投票（帮助达 quorum）但不计入赞成票。
- 票权公式：`赞成加权和 ≥ 通过阈值 × 实际参与票权加权和`（回避者除外）。

### 4.2 时间盒（timebox）
| 环节 | 时限 |
|:---|:---:|
| 表决窗口 | `standard/major` 48h · `supreme` 72h |
| 公示期 | `standard` 24h · `major` 72h · `supreme` 72h + 社区评论 7 天 |
| 申诉窗口 | 裁决公示结束后 7 天内可提案 `appeal` |

### 4.3 超时缺省（defensive default）
- 表决到点未达 quorum → **默认拒绝**，引擎自动执行 `refused(timeout)` 并公示「未过会」，留痕原因。
- 公示期无人异议 → 自动执行 `executed`；公示期内收到异议 → 自动转 `appeal`。
- **无后台 = 不能无限挂起**：任何提案都有硬性时间盒，宁可「未过会」，不可「拖死」。

## 五、公开与留痕（append-only 链）

### 5.1 链式账本 `~/.longhun/council/ledger.jsonl`
- 一行一事件，SHA-256 哈希链 `prev_hash → entry_hash`，写后不改、只增不减。
- 事件类型：`proposal / ballot / verdict / executed / refused / timeout / appeal / rotation / auto_pass / freeze_log`。
- 每条含：`evt_id / ts / type / actor / payload / prev_hash / hash`。

### 5.2 公示内容（全量公开，无人例外）
- 提案全文、依据证据（引用三色裁决 ID / DNA）、发起人（别名 ID）、表决各票方向 + 理由、超时原因、最终动作。
- 委员以**七因子指纹公钥别名**公开——方向与理由全公开、验票可防伪；真实人身份仅对审计/司法机关经合规流程可验（隐私与透明分层）。

### 5.3 公示渠道
- 本机：`lh council wall` 生成 `~/.longhun/council/council_wall.html`（与 shame_wall / audit chain 同构）。
- 对外：可发布至 portal / Notion 公示区（复用 `lh_notion_council` 通道或审计公示链），域名出口见部署指南。
- 验链：`lh council verify` 全链重放校验，任何篡改即断链告警。

## 六、无后台守卫（防「伪后台」）

1. **引擎无隐藏开关**：`lh_council.py` 代码公开、GPG 签名，源码即规则。不存在命令行隐藏 flag 可绕过表决改状态。
2. **无隐身撤销**：任何状态机迁移都带 `actor` 与提案上下文 append-only 记录；查询态一律由 ledger 重放得到，无独立权威库。
3. **守护不自启写权限**：council 守护只做「读链 + 时间盒巡检」，写入永远来自提案上下文；守护进程自身无免提案写权。
4. **伪后台即案**：若检测到任何未携带提案上下文的写状态调用 → 自动标记「无授权状态变更」全网公开 + 该动作失效 + 自动立案审查。

## 八、v1.0 最小落地（命令集）

```
lh council propose  <type> <target> [--title] [--evidence] [--ref <verdict_id>]   # 提案
lh council vote     <evt_id> pass|reject|abstain [-r 理由]                          # 表决(冲突自动回避)
lh council list     [--state voting|verdict|executed|refused]                      # 列表
lh council view     <evt_id>                                                       # 详情+票况
lh council ledger   [--tail N]                                                     # 原始链
lh council verify                                                                  # 全链校验
lh council wall     [--out PATH]                                                   # 生成公示墙 HTML
lh council export   --json                                                         # 机器可读公示
lh council status                                                                  # 在任席位/达标成员/时限
lh council rotate   [--dry]                                                        # 到期轮换(自动)
```

### 数据模型（v1.0 关键字段）
```
proposal: evt_id | type(standard/major/supreme) | target | title | evidence
          | ref_verdict | initiator | state(voting→verdict→公示→executed/refused)
          | voting_deadline | quorum_needed | pass_needed
ballot:   evt_id | voter(别名) | decision(pass/reject/abstain) | reason | weight | ts
verdict:  evt_id | outcome(pass/reject) | weighted_yes | weighted_quorum | ts
executed: evt_id | action | actor | ts
```
