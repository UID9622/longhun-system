## §1. 概述

龍魂提示词工程框架定义了从意图解析到最终输出的全链路提示词体系。
核心原则：**提示词不是"写一段话"，是结构化知识注入+约束编码**。

### 设计哲学
1. **结构化优先** — 提示词是JSON，不是自然语言段落
2. **约束显式化** — 允许什么、禁止什么，不靠"委婉暗示"
3. **DNA绑定** — 每条提示词挂追溯码，可审计可回滚
4. **分层注入** — 系统层→人格层→任务层→安全层，逐层叠加

## §4. 提示词注入协议

### 4.1 注入时序

```
会话开始
  → L0系统层注入（一次·不可变）
  → 意图解析→人格选择
  → L1人格层注入（动态·按需切换）
  → 用户输入到达
  → L2任务层注入（动态构造·含上下文）
  → 模型推理
  → L3安全层检查（输出前）
  → 输出
```

### 4.2 ANSI 标记规范

提示词内部使用标记系统进行层级控制：
```
<!-- LH:SYS -- L0 系统层 · 不可覆盖 -->
<!-- LH:PER -- L1 人格层 · 人格切换时替换 -->
<!-- LH:TSK -- L2 任务层 · 每轮替换 -->
<!-- LH:GRD -- L3 安全层 · 输出前注入 -->
```

## §8. 最佳实践

1. **约束前置**: 禁止项写在允许项前面，模型更容易遵守
2. **具体化**: 不说"安全地处理"，说"PII字段替换为***MELTDOWN***"
3. **正向引导**: 说"必须包含DNA头部"比"不要忘记DNA头部"有效
4. **层级分明**: 系统层→人格层→任务层·每层职责清晰不交叉
5. **示例驱动**: 复杂输出格式附带完整示例，比规则描述更有效
6. **审计留痕**: 每次提示词变更记录DNA+原因·可追溯可回滚
