第3节 注释怎么写（双通道互兜底，不是排版好看）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3.1 一句话原理：双语注释 = 通心译运行时形态——
    中文注释 ↔ CNSH:: 视角（归属/签章/三色）
    英文注释 ↔ M:: 视角（验收/真假/落库）
    一条注释落两份语义指纹，任一通道兜底另一通道：
    防偷换概念、防失忆、防本地宝宝读取变味。

3.2 注释三规格（焊死）
| 规格 | 位置 | 写法 | 用途 |
|------|------|------|------|
| 文件头注 | 文件首 | 第2节2.2标准头 | 归属与授权 |
| 函数头双注 | 每个函数上 | 中文一行+英文一行 | 语义双指纹 |
| 关键行尾注 | 关键逻辑行尾 | # 中 # EN | 防读岔 |

3.3 标准写法（照抄即可）
```
# 【中】计算数字根：反复相加至个位，∈{3,9} 触发🔴熔断（归属：龍.审计）
# [EN] Digital root: iterate to single digit; {3,9} triggers REJECT fuse (M:: verify)
函数 数字根(整数 n):
    当 n >= 10:                # 中：压到个位 # EN: collapse to single digit
        n = 各位和(n)
    返回 n
```

3.4 注释四不准
  ❌ 只写英文——斩断CNSH::通道，归属语义丢失
  ❌ 只写中文——M::机器验收通道断，跨系统对接抓瞎
  ❌ 中英不同义——双指纹打架，视同篡改嫌疑🟡
  ❌ DNA行翻译——DNA/CONFIRM/SEAL三行原样保留，永不翻译

3.5 验收：附录B注释配对校验器——提取所有【中】/[EN]对，
    配对率必须=100%，孤注（只有单边）报🔴。

第6节 C语言怎么融入（CNSH→C是编译目标，不是外援）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
6.1 融入原理：C是五段管线的目标语言之一（第5节⑤），
    CNSH语义经IR翻译成C源码——所以融入分双向：
| 方向 | 机制 | 场景 |
|------|------|------|
| CNSH→C | 目标代码生成器输出.c，gcc/clang编译 | 性能核心（数字根/审计/加密盾） |
| C→CNSH | FFI外部函数接口，C编译为.so/.dylib被调用 | 复用已有C库（硬件驱动/算法库） |

6.2 ABI对接约定（焊死）
  ① 整型用 int64_t（跨平台无歧义）② 字符串一律UTF-8 char*
  ③ 返回值三色语义：0=🟢 1=🟡 -1=🔴 ④ 函数名英文映射（龍.审计.数字根→lh_audit_digital_root）
  ⑤ 头文件必须带DNA注释行（原样不译）

6.3 示例：CNSH数字根 → 生成的C代码（附录B实测gcc编译运行）
  CNSH源：龍.审计.数字根(n)，∈{3,9}→🔴
  生成C：
```c
/* DNA: #龍芯⚡️2026-07-21-LEARN-INTEGRATE-MANUAL-V1.0-P0 */
/* 中:数字根审计∈{3,9}熔断 | EN:digital root audit, {3,9}=REJECT */
#include <stdint.h>
```
