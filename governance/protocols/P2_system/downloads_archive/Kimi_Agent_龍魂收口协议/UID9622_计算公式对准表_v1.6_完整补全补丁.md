### Y5｜触发器优先级与互斥规则

```
触发器优先级（高→低）：

P0 一票否决触发器（最高，无条件拦截）
    ↓
P1 主权触发器（SI < 0.34 直接熔断）
    ↓
P2 安全触发器（密钥/token/私钥/删除）
    ↓
P3 审计触发器（Risk ≥ 41 🔴）
    ↓
P4 守恒触发器（S < 7 强制新窗口）
    ↓
P5 标准计算链触发器（dr → W → Risk → S → D → Action）
    ↓
P6 可选增强触发器（贡献值/相似度/时间衰减）
    ↓
P7 监控触发器（最低，仅记录不拦截）
```

**互斥规则：**

| **规则** | **说明** |
|---|---|
| 互斥-1 | P0触发时，P1-P7全部失效，直接BLOCKED |
| 互斥-2 | P1触发时，P2-P7可并行计算但结果不输出，等SI恢复 |
| 互斥-3 | P2触发时，P3-P7可计算但Action强制为"sealed" |
| 互斥-4 | P3与P4同时触发，优先执行P4（强制新窗口覆盖🔴） |
| 互斥-5 | P5链中任意节点截链，后续节点不触发 |
| 互斥-6 | P6可选触发器不截链，只增强信息 |
| 互斥-7 | 同一公式在同一轮计算中只触发一次，禁止重复触发 |

### W3｜裁决引擎伪代码

```
函数 冲突裁决(冲突事件):
    输入: 冲突事件 = {高层规则, 低层规则, 冲突类型, 上下文}
    输出: 裁决结果 = {胜方, 败方, 动作, 原因}
    
    步骤1: 提取优先级
        P_高 = 冲突事件.高层规则.优先级  // P0-P7
        P_低 = 冲突事件.低层规则.优先级  // P0-P7
    
    步骤2: 检查一票否决
        如果 冲突事件.高层规则 ∈ 一票否决列表:
            返回 {胜方: 高层, 败方: 低层, 动作: "BLOCKED", 原因: "一票否决"}
        
    步骤3: 检查主权熔断
        如果 P_高 == "P0" 或 P_高 == "P1":
            返回 {胜方: 高层, 败方: 低层, 动作: "SI_FUSE", 原因: "主权熔断不可覆盖"}
    
    步骤4: 标准优先级比较
        如果 P_高 < P_低:  // 数字越小优先级越高
            返回 {胜方: 高层, 败方: 低层, 动作: "HIGH_WINS", 原因: "优先级高"}
    
    步骤5: 同级冲突处理
        如果 P_高 == P_低:
            // 使用最近使用优先(LRU)策略
            如果 冲突事件.高层规则.最近使用时间 > 冲突事件.低层规则.最近使用时间:
                返回 {胜方: 高层, 败方: 低层, 动作: "LRU_WINS", 原因: "最近使用"}
            否则:
                返回 {胜方: 低层, 败方: 高层, 动作: "LRU_WINS", 原因: "最近使用"}
    
    步骤6: 异常兜底
    返回 {胜方: 高层, 败方: 低层, 动作: "DEFAULT", 原因: "默认裁决"}
```
