## 摘要

龍魂记忆编辑器 v3.1 是一款面向个人知识主权的本地优先（local-first）记忆管理工具。该系统以**天干地支四柱**为时间戳生成唯一 DNA 追溯码，将每条记忆与不可伪造的时间-身份锚点绑定；同时采用分类标签、数字根、关键词提取和 Notion 双向同步，实现从快速捕获到长期归档的完整工作流。本文介绍其设计目标、核心算法、工程实现与局限，并对文中声明进行强度审计。

**关键词**：本地优先；记忆管理；天干地支；DNA 追溯；中文语义；Notion 同步

## 1. 引言

### 1.1 问题背景

当前主流笔记与记忆工具面临三个核心问题：

1. **平台锁定**：用户记忆数据存储于第三方云端，迁移成本高。
2. **追溯困难**：缺乏轻量、可读的本地唯一标识，导致记忆难以引用、审计与去重。
3. **语境丢失**：对话、灵感、决策过程等场景记忆常被简化为纯文本，丢失时间、身份与分类语境。

### 1.2 设计目标

龍魂记忆编辑器试图在以下约束下解决上述问题：

- **本地优先**：原始记忆默认存储于用户本地文件系统与浏览器 IndexedDB。
- **可读追溯**：每条记忆拥有包含天干地支四柱的 DNA 码，便于人眼识别与跨系统引用。
- **分类治理**：将记忆划分为原子事实、场景记忆、全局概览、原始会话四类。
- **可扩展同步**：通过 Notion API 实现可选云端同步，并基于 DNA 自动去重。

### 1.3 贡献

- 提出并工程化了一套以天干地支四柱为核心的时间-身份追溯码生成方案。
- 实现了一个零依赖（标准库）的 CLI 保存/搜索/列表工具，以及一个单文件 Web 界面。
- 提供了本地索引 + Markdown 文件 + Notion 数据库的混合存储架构。
- 对系统声明进行首次结构化强度审计，明确事实、工程实现与理论推断的边界。

## 2. 核心概念

### 2.1 天干地支 DNA

DNA 格式示例：

```
#龍芯⚡️丙午丁酉己酉丙寅-MEMORY-699E-UID9622
```

其中 `丙午丁酉己酉丙寅` 依次为年、月、日、时四柱，由当前 UTC 时间计算得到。该 DNA 同时承载：

- **时间锚点**：精确到小时的时间刻面。
- **身份锚点**：UID9622 标识创作者/系统实例。
- **随机盐**：4 位十六进制随机数，降低同一小时内重复冲突概率。

### 2.2 记忆分类

| 分类 | 图标 | 用途 |
|:---|:---:|:---|
| 原子事实 | 🔬 | 可验证的知识碎片、参数、Bug 记录、公式 |
| 场景记忆 | 🎬 | 上下文、决策过程、经验教训、环境信息 |
| 全局概览 | 🌍 | 系统架构、路线图、优先级、战略认知 |
| 原始会话 | 💬 | 未加工的对话原文、灵感速记、草稿 |

### 2.3 数字根与关键词

- **数字根**：对记忆内容 Unicode 码点求和，反复归约至个位数，作为内容指纹的轻量摘要。
- **关键词**：基于停用词过滤与词频统计的启发式提取，用于本地搜索与 Notion 标签补充。

## 3. 算法与实现

### 3.1 天干地支四柱计算

#### 年柱

```
天干索引 = (年份 − 4) mod 10
地支索引 = (年份 − 4) mod 12
```

以 1984 年甲子年为基准。

#### 月柱

采用公历月份近似映射（非二十四节气严格换月）：

```
月支索引 = (月份 + 1) mod 12      # 1月≈寅，2月≈卯，…，12月≈丑
月干索引 = (五虎遁基数 + 月份 − 1) mod 10
```

#### 日柱

以 1984-02-02 为甲子日基准：

```
日干支索引 = (当日 − 基准日) mod 60
```

#### 时柱

```
时支索引 = ((小时 + 1) // 2) mod 12
时干索引 = (五鼠遁基数 + 时支索引) mod 10
```

### 3.2 系统架构

```
┌─────────────────────────────────────────────┐
│  用户界面层                                  │
│  ├── Web: memory-editor.html (IndexedDB)    │
│  └── CLI: save_memory.py (本地文件 + JSON)   │
├─────────────────────────────────────────────┤
│  存储层                                      │
│  ├── ~/Desktop/龍魂系统·本地知识库/記憶/    │
│  │   ├── 記憶_YYYYMMDD_HHMMSS_*.cnsh.md    │
│  │   └── index.json                         │
│  └── Notion Database (可选云端同步)          │
├─────────────────────────────────────────────┤
│  同步层                                      │
│  └── sync_to_notion.py (DNA 去重 + 限速)    │
└─────────────────────────────────────────────┘
```

### 3.3 同步协议

1. 读取本地 `index.json`。
2. 按日期过滤，按 limit 截断。
3. 对每条记忆：
   - 以 DNA 为键查询 Notion 数据库。
   - 若已存在则跳过。
   - 否则创建页面，设置图标、标题、分类、标签、数字根、日期与正文块。
4. 请求间隔 0.35 秒，以符合 Notion API 限速。

## 4. 实验与验证

### 4.1 功能测试

在 macOS + Python 3.12 环境下完成：

- `save_memory.py` 可正常保存、列表、搜索、JSON 输出。
- `sync_to_notion.py` dry-run 模式可正确枚举待同步条目。
- `install.sh` 在临时 HOME 下成功创建目录结构并复制文件。

### 4.2 边界情况

- 空内容：CLI 拒绝保存。
- 缺少 DNA：Notion 同步跳过该条目。
- 数字根非数值：同步脚本归一化为 0。
- Notion 未配置：脚本给出明确提示并退出。

## 5. 讨论

### 5.1 优势

- **零外部依赖**：CLI 工具仅使用 Python 标准库，降低部署与维护成本。
- **人眼可读**：天干地支 DNA 比纯 UUID 更具文化与时间意义。
- **去重能力**：DNA + Notion 查询实现跨会话去重。

### 5.2 局限与风险

1. **月柱近似**：公历月份映射简化了传统干支月柱，与严格二十四节气存在偏差。
2. **冲突概率**：同一小时内随机盐为 16 位（4  hex），冲突概率约为 1/65536，可接受但非密码学安全。
3. **本地存储风险**：无内置备份与版本控制，依赖用户自行管理。
4. **Notion 字段耦合**：数据库字段名与类型固定，缺少自动迁移能力。
5. **关键词提取简单**：基于停用词过滤与词频，未引入分词模型，对长文本效果有限。

### 5.3 未来工作

- 引入节气表，支持严格月柱计算。
- 增加本地备份、版本回退与 GPG 签名链。
- 将 Web IndexedDB 与 CLI 文件索引统一为同一数据源。
- 引入更鲁棒的中文分词与向量化检索。
