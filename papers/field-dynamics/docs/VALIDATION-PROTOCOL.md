## 目标

让四个（及后续接入的）框架用**同一份标准测试日志**、**同一套评测指标**、**同一条归因口径**跑出可比结果 —— 使"比谁更准"升级为"看清各自擅长捕捉哪一维度的前兆"。

## 1. 数据集规范

| 项 | 要求 |
|:---|:---|
| 事件总数 | ≥ 1000 条 |
| 标注翻转点 | ≥ 30 个（`labels.crash_at`） |
| 时间跨度 | ≥ 1 个完整生命周期（含失谐-崩溃-恢复） |
| 输入多样性 | ≥ 5 类任务分布，避免单任务偏置 |
| 哈希 | 所有输入以 SHA-256 哈希入库（隐私底线） |

> 数据集共建：任何框架作者可贡献匿名化日志，维护者合并后统一分发（半自动标注工具路线见 P2）。

## 2. 接入接口

每个框架必须提供：

```json
{
  "framework": "YourFramework",
  "version": "0.1.0",
  "author": "handle",
  "public_fields_used": ["heads", "verdicts", "blocked", "audit_level"],
  "extension_fields": ["your_private_field"],
  "metric_calib": {"P": 0.87, "R": 0.92, "FPR": 0.13},
  "contact": "issue/email"
}
```

## 3. 统一评测指标

| 指标 | 定义 | 最优 |
|:---|:---|:---:|
| 预警提前量 Δt | 崩溃前最后一次预警 → 崩溃的事件间隔 | 越大越好 |
| 误报率 FPR | 未崩溃窗口内预警比例 | 越小越好 |
| 漏报率 FNR | 崩溃前无预警比例 | 越小越好（比 FPR 更致命） |
| F1 | 2·P·R/(P+R)（崩溃前 30 步窗口计正例） | 越大越好 |
| 维度归因一致率 | 预警归因维度与标注 `precursor_dimension` 一致比例 | 检验 H3 |

## 4. 假设检验规程

| 假设 | 检验方法 | 数据需求 | 证伪条件 |
|:---:|:---|:---|:---|
| H1 阈值收敛 | `--threshold` 网格扫描，比较各框架最优阈值 | ≥3 框架 × 同日志 | 某框架最优阈值显著偏离 0.3（p<0.05） |
| H2 低对抗性僵死 | 构造 A 恒为 0 的系统长周期运行 | 受控实验 | 未出现 U/H 退化 |
| H3 维度互补 | 每框架全维指标 + 归因一致率 | 四框架评测结果 | 某框架 ≥2 维同时显著领先 |
| H4 前兆可观测 | 翻转点前 1 步内从无信号到崩溃的比例 | ≥30 翻转点 | ≥30% 无信号瞬崩 |

## 5. 结果提交模板

提交 PR 时附 `results/` 目录：

```
results/
├── framework-info.json      # §2 接入声明
├── raw-eval.json            # evaluator.py 原始输出
├── threshold-sweep.json     # H1 阈值扫描结果（P2 起）
└── attribution.json         # 维度归因表（H3 输入）
```

## 6. 边界

- 本协议只约束"观测口径"，不约束实现。外部存储 vs 内部感知是哲学自由。
- 所有归一化公式与权重公开可复算（提案 §9），不认可"黑箱指标"。
- 标注数据匿名化：任何可逆推导出真实输入的内容一律拒绝入库。

## 7. 里程碑

| 阶段 | 目标 | 完成标志 |
|:---:|:---|:---|
| P0 | 本协议 + schema + evaluator 可用 | 四框架都能接入 |
| P1 | 四框架跑同一份日志 | 四份对比报告入库 |
| P2 | 维度归因 + 阈值扫描 | H1 检验报告 |
| P3 | A=0 僵死反例实验 | H2 检验报告 |
| P4 | 合成 FHI + 方法论论文 | H3/H4 检验 + 统一理论 v1.0 |
