## 报告漏洞

请**不要**在公开 Issue 中披露漏洞细节。优先选择：

1. **GitHub Private Security Advisories**（推荐）：在仓库 `Security → Report a vulnerability` 提交
2. **邮件**：通过本仓库任何维护者公开渠道（GitHub 主页）联系

请在报告中包含：

- 影响的版本 / commit
- 复现步骤（最小可复现样本优先）
- 预期行为 vs 实际行为
- 影响评估（如：是否可能被远程利用）

## 披露流程

1. 收到报告后 **7 天内**回复确认
2. 确认有效后优先修复，修复完成前不公开细节（协调披露）
3. 修复发布后公开致谢（如报告者愿意署名）

## 已知边界（本项目特意保持透明）

- **评测脚本不接受不可信输入**：`evaluator.py` 只读 JSONL 文件，不做网络请求、不执行日志内容。若你在 CI 里跑第三方日志，建议先做格式校验（schema 校验）
- **示例日志为合成数据**：`sample-log.jsonl` 只用于演示管线，不代表任何真实系统的观测值
- **不存储敏感数据**：日志格式要求 `input_hash` 为 SHA-256 哈希，不鼓励存原文；任何贡献者不得在仓库提交含真实个人数据的日志
