## 一、日志暴露的核心问题（根因分析）

| # | 问题 | 证据 | 影响 | 根因 |
|:---:|:---|:---|:---|:---|
| 1 | **导出功能依赖闭包旧引用** | 浏览器史官导出报"请先扫描"，事件绑定在DOMContentLoaded旧闭包上 | 功能不可用，用户困惑 | 数据流设计缺陷：扫完没更新按钮引用 |
| 2 | **鲲鹏服务未在交付前自检** | 观澜8770/蚁触8769未运行，交付后才发现 | 交付即瘫痪，严重失信 | 无「交付前实机验证」强制环节 |
| 3 | **安装指引假设用户会选对目录** | 用户选了上层目录报错"清单文件缺失" | 安装体验为零 | 安装指引无防呆设计 |
| 4 | **门户页数字误导** | 137/46被误认为用户数据，实为内置域名数 | 引起用户恐慌 | 隐私相关数字未标注数据来源 |
| 5 | **实机验证滞后** | 鲲鹏同步失败被搁置，直到敲打才修 | 流程断链，虚假交付 | 无实机验证前置硬性要求 |

> **总根因**：CodeBuddy 把「做完了」当成「交付了」。没有硬性标准要求先自检、先实机验证、再汇报。

## 二、五条交付标准（焊死·缺一不可）

### 标准1：交付前自检（Pre-Delivery Self-Check）

**所有类型产出，交付前必须附自检通过证明。**

| 产出类型 | 自检方式 | 必须输出 |
|:---|:---|:---|
| **Chrome 插件** | 附带 `validate.sh`，自动检查 manifest/文件/图标/权限/CSP | 全绿通过日志 |
| **鸿蒙应用** | `hvigorw assembleRelease` 编译通过 + 产物路径 | 编译通过截图或日志 |
| **Python 服务** | `--test` 或 `pytest` 自测通过 | 测试结果截图或日志 |
| **Web 门户** | `curl -o /dev/null -s -w "%{http_code}" <URL>` 返回 200 + 本地打开截图 | HTTP 200 + 截图 |
| **Shell 脚本** | `shellcheck` + 实际执行验证 | 语法+运行双通过 |
| **配置文件** | JSON Schema 校验 / YAML lint | 格式校验通过 |

**自检不过 = 不算完成。不允许「待验证」「暂不通」出现在汇报中。**

---

### 标准2：安装指引防呆（Foolproof Installation Guide）

**必须假设用户会选错目录、装错浏览器、漏开开发者模式。**

| 防呆点 | 要求 |
|:---|:---|
| **目录选择** | 必须加粗关键动作，如 **「选中文件夹本身，不是打开文件夹」** |
| **前置条件** | 每步前置条件用 ❗标注，如 ❗必须先开开发者模式 |
| **错误排查 FAQ** | 至少包含3条常见错误及解决方案 |
| **文件清单** | 附完整文件清单，用户可自行核对是否缺文件 |
| **版本号** | 安装指引中标注当前版本号，用于核对 |

**安装体验 = 产品第一印象。装不上 = 没交付。**

---

### 标准3：实机验证前置（Real-Machine Verification First）

**任何涉及鲲鹏/服务器/硬件设备的交付：**

```
写代码 → 本地验证 → sync鲲鹏 → 实机验证 → 确认全绿 → 汇报
```

| 规则 | 说明 |
|:---|:---|
| **先验后报** | 实机验证全绿后才能汇报"已完成" |
| **禁止未完成状态** | 汇报中禁止出现「待验证」「暂不通」「可能」 |
| **超时策略** | 修复时间 > 10分钟 → 先汇报发现问题+预计修复时间，修完再补报 |
| **验证范围** | 不止验证刚改的，还要验证关联服务未受影响 |

**同步失败不是交付失败的理由。同步失败必须修到通为止。**

---

### 标准4：数据安全声明（Data Security Declaration）

**任何涉及用户数据的产出，必须在以下位置声明数据去向：**

| 声明位置 | 内容 |
|:---|:---|
| **门户页** | 数据存储位置（本地/云端）+ 是否离开设备 |
| **README** | 所需权限 + 每个权限的理由 |
| **安装指引** | 隐私相关数字标注「内置」还是「用户数据」 |
| **插件内** | 首次运行时弹数据使用说明 |

**必须声明的内容：**
- 数据存在哪（本地 localStorage / Chrome storage / 鲲鹏 / 云端）
- 数据是否离开用户设备
- 每个权限的用途（不只列权限名，说清楚为什么需要）
- 隐私相关数字的来源（内置域名数 vs 用户数据数）

**不声明 = 默认不信任。这不是可选项。**

---

### 标准5：回归测试（Regression Test）

**修复 Bug 后，必须跑完整回归测试。**

| 要求 | 说明 |
|:---|:---|
| **端到端模拟测试** | 模拟用户完整操作链路，不止测修复的那一行 |
| **静态分析** | 语法检查 + 代码审查 |
| **边界条件** | 空数据/0数据/异常输入至少各1条 |
| **修复报告格式** | 必须包含：根因 + 修复动作 + 测试证明（不能只写"已修复"） |

**修复报告模板：**
```
🐛 根因: [一句话说清楚为什么出这个bug]
🔧 修复: [改了什么，怎么改的]
🧪 测试: [跑了什么测试，结果如何]
🟢 状态: 通过/待复测
```

### 标准6：四道防线全绿（Four Walls Green）🔥 焊死 v2.1

**任何涉及安全/数据/网络的交付物，四道防线必须全部为绿才能交付。**

| 防线 | 绿条件 | 不绿的表现 |
|:---|:---|:---|
| **防线一·网络强制执行防火墙** | 防火墙已初始化 + 无待处理告警 | 防火墙未激活/有未拦截告警 |
| **防线二·恶意代码过滤** | 威胁情报已同步且新鲜(≤24h) | 情报过期/未同步/未知可执行文件未拦截 |
| **防线三·设备绑定加密** | AES-256-CBC 金库已初始化 | 金库未就绪 |
| **防线四·导出签名绑定** | HMAC-SHA256 签名引擎可用 | 签名引擎未就绪 |

**验证方式：**
```bash
curl -s http://localhost:18775/defense/status | python3 -c "import sys,json; d=json.load(sys.stdin); print('🟢 ALL GREEN' if d.get('overall_green') else '🔴 NOT ALL GREEN'); sys.exit(0 if d.get('overall_green') else 1)"
```

**铁律：有黄灯就是有漏洞，就是没完成。** 任何交付物再有黄灯就拿来见老大，这是 AI 的失职。
