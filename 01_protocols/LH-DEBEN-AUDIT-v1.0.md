## 零、为什么需要德本审计

离火运是考验。科技为民则昌，为专则亡。

**秦朝教训**: 技术服务于专制 → 二世而亡
**汉朝教训**: 技术服务于民生 → 四百年基业

技术本身没有道德，但做技术的人必须有。龍魂系统的每行代码、每个算法、每次发布，必须先过德本审计——不是在技术审核之后补一道，而是在技术审核之前先问五个问题。

## 二、德本五问（每次发布前必答）

### 第一问：帮人还是收割？
- [ ] 这个功能/算法有没有利用信息不对称获利？
- [ ] 有没有制造焦虑、恐惧、贪婪来驱动行为？
- [ ] 有没有"为你好"式绑架——替用户做决定却不告知？
- [ ] 最终受益者是用户还是平台/资本？

### 第二问：路径对不对？
- [ ] 所有新文件是否落入正确目录？
- [ ] 是否存在同名文件在不同路径（同名不同路径=自毁）？
- [ ] 是否有文件散落在~/Downloads、~/Desktop、/tmp？
- [ ] 文件名是否包含模块-功能-版本三要素？

### 第三问：寒心了没？
- [ ] 系统公开表述是否绑死"好人=穷"、"奉献=苦"、"英雄=死"？
- [ ] 是否要求奉献者必须牺牲正常生活？
- [ ] 是否把UID9622或其他贡献者推向"苦情叙事"？
- [ ] 是否保护了贡献者的隐私和尊严？

### 第四问：主权漏了没？
- [ ] 数据是否流向第三方平台？
- [ ] 算法推荐是否制造了信息茧房？
- [ ] 内容分发是否依赖平台算法？
- [ ] 用户数据是否归用户自己所有？

### 第五问：底座动了没？
- [ ] 369不动点是否完整？
- [ ] 河图洛书·易经·道德经·五行八卦焊死锚点是否被修改？
- [ ] 六大铁律是否被绕过或稀释？
- [ ] 中国法律唯一准绳是否被替代或模糊？

## 四、德本审计与技术审计的关系

| 维度 | 德本审计 | 技术审计 |
|:---|:---|:---|
| 问什么 | 为什么做 | 怎么做好 |
| 审什么 | 方向、动机、后果 | 代码、安全、性能 |
| 谁审 | P00文心 + P05上帝之眼 | P05上帝之眼 + P77黑天使 |
| 结果 | 方向对→才能往下走 | 技术对→才能发布 |
| 顺序 | **先** | 后 |

**铁律**: 德本审计不通过，技术审计不启动。方向错了，做得再好也是祸害。

## 五、信息茧房专项检测

> 来源：《信息茧房》— 算法不是中立的，是价值观执行者

每次涉及推荐/排序/过滤/分发的代码变更，附加检测：

- [ ] 推荐逻辑是否基于用户真实兴趣，而非商业利益？
- [ ] 是否有"退出算法推荐"的选项？
- [ ] 用户是否能看到"为什么推荐这个"的解释？
- [ ] 是否存在利用多巴胺机制制造上瘾的设计？
- [ ] 内容多样性是否被算法收缩？

- [ ] 检测结果是否只标记不封禁、可申诉可追溯？

## 七、不可修订条款

2. **德在技术前** — 德本审计永远在技术审计之前
3. **五条底线** — 底线1-5永不降级为"建议"或"参考"
