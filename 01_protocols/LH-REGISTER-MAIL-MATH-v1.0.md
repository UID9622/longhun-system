## §1. 邮箱权重格 (Email Weight Lattice)

### 1.1 偏序定义

邮箱域集合 D，定义权重映射 W: D → [0, 1]：

```
W(d) = { 1.0  d ∈ CORE_WHITELIST
       { 0.8  d ∈ OBSERVATION_LAYER
       { 0.6  d ∈ OVERSEAS (默认)
       { 0.0  d ∈ DISPOSABLE_BLACKLIST
```

### 1.2 半格结构

(D, ⊑) 构成有界分配格，其中：
- ⊥ = 0.0（一次性邮箱·与门硬闸）
- ⊤ = 1.0（运营商级·天然实名）
- 全序: 0.0 ⊏ 0.6 ⊏ 0.8 ⊏ 1.0

### 1.3 形近仿冒检测

给定品牌名池 B = {b₁, ..., bₙ}，域名前缀 p = prefix(d)：

```
typosquat(d) ⟺ ∃b ∈ B: len(b) ≥ 5 ∧ d_L(p, b) ≤ 2
```

其中 d_L 为 Levenshtein 编辑距，性质：
- d_L(a, b) = 0 ⟺ a = b
- d_L(a, b) = d_L(b, a)（对称）
- d_L(a, c) ≤ d_L(a, b) + d_L(b, c)（三角不等式）
→ (Σ^*, d_L) 构成度量空间

**阈值 θ=2 的理由**：长效品牌名(len≥5)的编辑距误报率极低——两个随机5字母串编辑距≤2的概率 ≈ 0.3%。短品牌名(139/wo等3字符以下)编辑距2误杀概率 > 50%，不参与检测。

**判定顺序**（协议 §5.4 工程化）：
1. 格式校验
2. 一次性邮箱黑名单（与门·独立）
3. 核心白名单（优先于形近检测——自己不是自己的仿冒者）
4. 观察层
5. 形近检测（仅对非白名单域）
6. 默认海外轨

### 1.4 与门约束

```math
W(d) = 0 ⟹ T_reg = 0  （不计算后续因子）
```

这是协议 §5.3 的数学化：一次性邮箱不问总分直接拒绝。

## §2. 注册信任分合成 (Registration Trust Score)

### 2.1 线性加权模型

```
T_reg = α₁·W_e + α₂·D_dev + α₃·I_ip + α₄·B_beh
```

权重向量 α = [0.40, 0.30, 0.20, 0.10]，Σαᵢ = 1.0。

| 因子 | 权重 | 含义 | 归一化范围 |
|:---|:---:|------|:---|
| W_e | 0.40 | 邮箱域权重 | {0, 0.6, 0.8, 1.0} |
| D_dev | 0.30 | 设备指纹可信分 | [0, 1] |
| I_ip | 0.20 | IP风险分 | [0, 1] |
| B_beh | 0.10 | 行为时序分 | [0, 1] |

### 2.2 判定函数

```
                  ⎧ 🟢 直接放行       if T ≥ 0.75
J(T_reg) =       ⎨ 🟡 人工/二次核验   if 0.50 ≤ T < 0.75
                  ⎩ 🔴 拒绝           if T < 0.50
```

阈值推导：
- 核心白名单+满分设备: T = 0.40×1.0 + 0.30×1.0 + 0.20×1.0 + 0.10×1.0 = 1.0 → 🟢
- 核心白名单+中等设备(0.5/0.5/0.5): T = 0.40×1.0 + 0.15 + 0.10 + 0.05 = 0.70 → 🟡
- 海外轨+满分设备: T = 0.40×0.6 + 0.30 + 0.20 + 0.10 = 0.84 → 🟢
- 海外轨+中等设备(0.5/0.5/0.5): T = 0.40×0.6 + 0.15 + 0.10 + 0.05 = 0.54 → 🟡
- 海外轨+差设备(0.3/0.3/0.3): T = 0.40×0.6 + 0.09 + 0.06 + 0.03 = 0.42 → 🔴

### 2.3 模型性质

**单调性**：若各因子单调不减，T_reg 单调不减（线性正系数保证）。

**敏感性**：∂T/∂W_e = 0.40 > ∂T/∂D_dev = 0.30 > ∂T/∂I_ip = 0.20 > ∂T/∂B_beh = 0.10。
邮箱权重是最大影响因子——准入的设计核心。

## §3. 验证码熵安全 (Verification Code Entropy)

### 3.1 安全参数（焊死）

| 参数 | 值 | 数学记号 |
|:---|:---|:---|
| 码空间 | 10⁶ | N = 6位数字 |
| 有效期 | 300s | Δt = 5分钟 |
| 最大错误 | 3次 | M = 3 |
| 锁定时间 | 900s | τ_lock = 15分钟 |
| 申请限流 | 5次/小时 | r_email |

### 3.2 穷举上界

单码单窗口内：

```
P_brute = M/N = 3/10⁶ = 3 × 10⁻⁶
```

预期穷举次数（几何分布）：

```
E[X] = (N+1)/(M+1) ≈ 250,000
```

由于每小时限流5次申请，实际不可行。

### 3.3 HMAC存储安全性

```
store: HMAC-SHA256(code, salt)
code: 仅存内存·发送瞬间存在
log: CODE_ATTEMPT: <hmac_hash>  （无明文）
```

攻击面：即使数据库被拖，攻击者只能看到 HMAC 哈希值。由于 code 是 6位数字（10⁶ 空间），离线穷举10⁶次可行——但 salt 每次随机（8字节 = 2⁶⁴ 空间），每次穷举需重新建彩虹表。综合安全边界：salted HMAC 使离线穷举成本高 2⁶⁴ 倍。

### 3.4 状态机

```
IDLE → [正确] → USED（一次性·不可复用）
     → [错误×3] → LOCKED(900s)
     → [过期·300s] → EXPIRED
     → [已用] → USED
```

## §4. 激活码链 (Activation Code Chain)

### 4.1 结构

```
ACT-{YYYYMMDD}-{random_16hex}-{sig_8hex}
```

- random_16hex: CSPRNG 64位随机数（碰撞概率 ≈ n²/2⁶⁵）
- sig_8hex: HMAC-SHA256(secret, email_hash || device_fp || timestamp)[:8]

### 4.2 时间戳对齐

生成时 `now = floor(time.time() / 5) × 5`（对齐5秒网格），验证时以步长5搜索当天全量时间戳（86400/5 = 17,280 个候选点）。HMAC 计算 ≈ 1μs/次 → 总搜索耗时 ≈ 17ms。

### 4.3 三验判定

```
valid ⟺ format_valid(code) 
         ∧ sig_match(code, email_hash, device_fp) 
         ∧ not_expired(code, τ=72h)
```

缺一即🔴。

### 4.4 绑定注入

激活码绑定四元组 {email_hash, device_fp, timestamp, used_flag}。
激活完成 → 设置 used_flag = True → 铸入用户DNA链环。

## §5. 多级令牌桶 (Multi-Level Token Bucket)

### 5.1 数学模型

单桶 (b, r)：容量 b，填充速率 r (令牌/秒)。

```math
T(t) = min(b, T(t_last) + r·(t - t_last))
```

消费：`T(t) ≥ 1 → T(t) -= 1 ∧ allow`，否则 `→ deny`。

### 5.2 三维配置

| 维度 | 容量 b | 填充速率 r |
|:---|:---:|:---|
| 邮箱 | 5 | 5/3600 (≈ 1.39×10⁻³) |
| IP | 20 | 20/3600 (≈ 5.56×10⁻³) |
| 设备 | 10 | 10/3600 (≈ 2.78×10⁻³) |

联合判定：

```math
allow ⟺ (T_email(t) ≥ 1) ∧ (T_ip(t) ≥ 1) ∧ (T_device(t) ≥ 1)
```

### 5.3 热保护策略

任一桶空 → 统一返回"频率限制·稍后重试"，不透露哪个维度超限。

数学理由：透露维度 = 给攻击者探测信号。攻击者可以换IP/换设备逐一试探，直到找到唯一瓶颈。不透露 = 攻击者无法定位薄弱点。

## §6. 通道路由决策树 (Channel Router)

### 6.1 决策函数

```
route(msg_class, device, alive_map) → primary_channel
```

决策树：

```
if msg_class = "凭证类":
    return "smtp"           # 高保障·不可降级
    
if msg_class = "安全类":
    primary = pick_push(device, alive)
    return {primary, "smtp"}  # 双发
    
if msg_class = "实时类":
    return pick_push(device, alive)  # + smtp 兜底

if msg_class = "营销类":
    return None             # 不存在
```

### 6.2 推送通道选择函数

```
pick_push(device, alive):
    if device = "华为" ∧ alive["pushkit"]:  return "pushkit"
    if alive["wxpusher"]:                    return "wxpusher"
    if alive["pushdeer"]:                    return "pushdeer"
    return "smtp"                            # 主权兜底
```

### 6.3 通道熔断

连续失败3次 → 熔断该通道24h。心跳5分钟探测一次。

数学模型：指数退避简化版。在免费通道额度受限的条件下，连续失败=额度已满或服务已挂，24h 冷却给予服务恢复窗口。
