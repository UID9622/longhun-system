## 二、使用规则（怎么引用）

1. **套骨架**：产出开头标注 `范式: LH-OUTPUT-PARADIGM-v1.0 九段式`，按九段组织内容。
2. **可裁剪**：小产出（≤150 token 汇报）只留段1焊点+段9签名；文档/功能/协议默认全段。
3. **不颠倒**：焊点永远第一（为什么），签名永远最后（谁来负责）。
4. **在骨架上优化**：v1.0 先完整跑通；v2.0 起只做增量优化——补充验证、加自动化、扩科目、接新端。**禁止推翻骨架重来。**
5. **引用既有资产**：动手前先盘点系统已有实现（如账法 v2.1 引擎已在 `08_BIN/ledger_audit/`），只在缺口上建设。

## 三、九段细则（每一段的最低标准）

### 段1 · 焊点
- 记录老大原话 verbatim（若为AI提议则标注"AI提议·待老大确认"）。
- 焊点=防漂移锚点，可修复但需走修订流程（见焊死修复律）。

### 段2 · 铁律
- 表格化：编号 | 铁律 | 说明。违反即错误。
- 铁律必须可执行可校验（如"每笔必有DNA"→正则校验）。

### 段3 · 恒等式/原理
- 一条公式或一张结构图讲透核心（mermaid 优先）。
- 必须可代入真实数据验证。

### 段4 · 可运行代码
- 仅标准库（hashlib/datetime/json…），零三方依赖。
- 交付前必须真实运行一次，输出结果附在文档中。
- 注释写"为什么"，不写"是什么"。

### 段5 · 验证机制
- 至少一层防篡改（哈希/SHA/校验和）。
- 三色标记：🟢通过 / 🟡待核 / 🔴红线。
- 提供反例演示（篡改后应被拦截）。

### 段6 · 落地链路
- 多端留档：主存档+镜像+公开展示（如 GitHub+Notion+本地）。
- 自动化：cron/CI/回调，一条命令全跑。

### 段7 · QA排查
- Top 高频问题表：现象 | 原因 | 解决步骤。
- 每项三步内可操作，不写空话。

### 段8 · 演进路线
- 明确 v1.0→v2.0 的里程碑与完成时间。
- 每版只列**增量**（新增了什么），不重复旧版内容。

### 段9 · 签名盖章
- DNA（干支卦·模块·动作）+ 归属名（诸葛鑫 | UID9622 · 龍芯北辰）+ GPG + 三色。
- 对外发布必须 GPG 分离签名（`bin/lh_gpg_sign.py sign`）。

## 五、地基继承铁律（v1.1 新增·代码版"不重复造轮子"）

> **老大焊点（2026-08-31·verbatim·永不删）：**
> 「以后每次新功能，第一行永远是这个：`from longhun_base import LonghunTransaction`。
> 继承，只写新加的方法。绝对不允许把 `longhun_tx_hash` / `WITNESS` 字典复制出来重写一遍。」

### 三条铁律

| # | 铁律 | 落地动作 | 反例（❌绝对禁止） |
|:---:|:---|:---|:---|
| B1 | **地基只 import，永不复制修改** | 新文件第一行 `from longhun_base import LonghunTransaction` | 复制 base 文件改参数 / 重写 `longhun_tx_hash` |
| B2 | **每版只加新能力，旧接口向下兼容，从不删** | 新方法只写增量；重写方法第一行 `super().xxx()` 取父类结果再拼接 | 删父类方法 / 改 WITNESS 字典原值 |
| B3 | **四个细节永远从唯一真源取，不手填** | DNA格式、哈希公式、见证匹配、`✓平` 标记 → 全部来自 `longhun_base.py` | 手写格式串 / 硬编码见证名 / 漏 `✓平` |

### 唯一真源映射表

| 细节 | 唯一真源位置 | 说明 |
|:---|:---|:---|
| 地基代码 | `scripts/longhun_base.py`（GitHub `UID9622/longhun-ledger`·本地 `08_BIN/ledger_audit/longhun_base.py`） | 永不动·原样落地 |
| DNA格式 | `LonghunTransaction._gen_dna()` | `#龍帳⚡️YYYY-MM-DD-DR-CR-AMT-SEQ-UID9622` |
| 哈希公式 | `longhun_tx_hash()` | `SHA256(dna\|dr\|cr\|amount\|timestamp)[:8].upper()` |
| 见证来源 | `WITNESS` 字典 | 扩展用 `get_witness()` 重写，不改字典 |
| 账簿行标记 | `ledger_line()` | 末尾必带 `✓平` |

### 继承三步（每次加功能都这四步走）

```python
# 1. 第一行 import 地基（不复制）
from longhun_base import LonghunTransaction

# 2. 继承，只写新加的方法
class MyFeature(LonghunTransaction):
    def ledger_line(self):
        base = super().ledger_line()          # 先取父类完整行
        return f"{base} | {self.new_part()}"  # 只加新内容

# 3. 实测验证：同一笔交易哈希必须与父类一致（继承不动地基的铁证）
# 4. push 前：不动旧文件，只加新文件
```

> **验证样板（已实测 🟢）**：`08_BIN/ledger_audit/example_extension.py` 中 v1.1/v1.2 继承链，
> T1 哈希 `5F9C5755` 与地基冒烟输出完全一致 → 证明继承零改动。
