## 一、模板设计原则

### 1.1 为什么需要统一模板

龍魂系统的技术白皮书不是一次性的。随着系统迭代（模型升级、架构演进、引擎新增），白皮书会持续产出。如果没有统一格式，每份白皮书结构不同、读者阅读成本高、版本间对比困难。

统一模板解决三个问题：
1. **可对比**：同一模板下，v1.9和v2.0的差异一眼可见
2. **可追溯**：固定章节编号，引用时可精确到章节
3. **可信度**：规范格式本身就是专业性的体现

### 1.2 白皮书不是政府专利

「白皮书」本质上是一种**公开、权威、规范的报告文体**。只要做到「公开透明、逻辑严密、数据详实」，技术文档完全可以使用白皮书框架。

龍魂白皮书属于**民间技术白皮书**，与政府白皮书的区别：
- 不代表官方立场，只陈述系统自身的技术事实
- 不涉及政策建议，只描述系统设计思路
- 坦诚说明局限性和已知问题

### 1.3 三个铁律

| # | 铁律 | 说明 |
|:---:|------|------|
| 1 | **公开透明** | 技术细节、设计思路、局限性全部公开，不藏不掖 |
| 2 | **描述多于定义** | 让读者理解系统能力，但不暴露底层实现细节 |
| 3 | **定性多于定量** | 核心算法思路可描述，具体参数、密钥算法不公开 |

## 二、标准章节结构

> 以下为强制结构。所有龍魂技术白皮书必须包含这9个一级章节。二级标题可根据具体主题灵活调整。

### 必选章节（9章）

| 章节 | 标题 | 内容要求 | 页数建议 |
|:---:|------|------|:---:|
| 零 | **为什么要有这份白皮书** | 一句话说清动机：这份白皮书要回答什么问题、写给谁看 | 0.5页 |
| 一 | **背景与定位** | 行业痛点、技术趋势、研发初衷、本次版本在整体演进中的位置 | 1-2页 |
| 二 | **核心架构与原理** | 系统架构、技术原理、关键突破、设计哲学 | 2-5页 |
| 三 | **版本对比与演进** | 与前一版本的系统性对比，含数据对比表 | 1-3页 |
| 四 | **数据与评估** | 测试方法、评估指标、实测数据、对比基准 | 2-4页 |
| 五 | **已知局限与诚实声明** | 坦诚说明当前版本的局限性、已知问题、边界条件 | 1-2页 |
| 六 | **未来展望** | 下一版本规划、技术路线、待解决问题 | 1-2页 |
| 七 | **部署与运维** | 部署步骤、环境要求、回退策略、监控方案 | 1-2页 |
| 八 | **附录** | 术语表、文件清单、版本演进总表、引用协议索引 | 2-4页 |

### 可选附录

| 附录 | 适用场景 |
|:---|------|
| A. 术语表 | 所有白皮书必备 |
| B. 文件清单 | 涉及代码/配置的白皮书 |


### 3.2 表格规范

- 所有对比类信息优先使用表格，禁止用纯文字罗列
- 表格必须包含表头分隔行
- 数值类列右对齐或居中对齐

### 3.3 ASCII图示规范

- 架构图、流程图使用ASCII art
- 使用 `┌─┐│└┘├┤┬┴┼` 等box-drawing字符
- 禁止使用emoji作为结构性元素（可在强调文字中使用）

### 3.4 签章规范

- 每份白皮书必须包含 GPG 分离签名（.asc 文件）
- 签章命令：`gpg --local-user <KEY> --detach-sign --armor --output <FILE>.asc <FILE>`
- DNA追溯码必须唯一，格式：`#龍芯⚡️<干支四柱>-<模块>-WHITEPAPER-v<版本>`

### 3.5 命名规范

- 文件名：`LH-[主题]-WHITEPAPER-v[版本].md`
- 示例：`LH-MODEL-WHITEPAPER-v2.0.md`
- 签章文件：同名 + `.asc`

## 四、质量检查清单

> 每份白皮书发布前必须通过以下检查。

### 结构检查（5项）

- [ ] 包含全部9个必选章节（第零章到第八章）
- [ ] 文档头部信息完整（性质/地位/原则/DNA/确认/GPG）
- [ ] 章节编号一致（零、一、二...八，禁止混用阿拉伯数字和中文数字）
- [ ] 附录A（术语表）存在且至少包含10个术语
- [ ] 文档末尾有签名区

### 内容检查（5项）

- [ ] 第五章（已知局限）非空，至少列出3个已知问题
- [ ] 第四章（数据与评估）含可验证的实测数据
- [ ] 第三章（版本对比）含与前一版本的对比表
- [ ] 没有泄露核心机密（密钥算法、具体参数阈值、内部IP等）
- [ ] 所有引用的协议/文档标注了DNA或文件路径

### 签章检查（3项）

- [ ] GPG分离签名文件（.asc）已生成
- [ ] DNA追溯码唯一且格式正确
- [ ] 日期使用干支历+公历双标注

## 五、模板使用指南

### 5.1 适用场景

| 白皮书类型 | 示例 | 适用本模板 |
|:---|:---|:---:|
| 模型升级 | LH-MODEL-WHITEPAPER-v2.0 | ✅ |
| 架构演进 | LH-ARCH-WHITEPAPER-v1.0 | ✅ |
| 协议发布 | LH-PROTOCOL-WHITEPAPER-v1.0 | ✅ |
| 安全审计 | LH-SECURITY-WHITEPAPER-v1.0 | ✅ |
| 人格治理 | LH-PERSONA-GOVERNANCE-WHITEPAPER-v1.4 | ✅ (已有，可逐步迁移) |

### 5.2 版本号规则

- 白皮书版本号独立于系统版本号
- 首次发布：v1.0
- 小修订（纠错、补充）：v1.1, v1.2...
- 大改版（结构调整、章节重写）：v2.0

### 5.3 与旧版白皮书的关系

- 现有白皮书（如人格治理v1.4、隐私v1.0）不强制迁移，新版白皮书必须遵循此模板
- 旧版白皮书在下次大版本更新时逐步对齐
