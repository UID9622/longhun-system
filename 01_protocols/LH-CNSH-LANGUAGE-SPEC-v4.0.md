## 一、语言核心规范

### 1.1 设计原则

```
中文编程：关键字/结构/语义以中文为一等公民
DNA 追溯：每个文件/函数/规则可绑定 DNA 追溯码
三色审计：编译前强制审计（红阻断、黄提示、绿放行）
算力节约：能用模板解决的不推理，能复用的不重复计算
```

### 1.2 词法规范

**注释：**

```
# 单行注释：从 # 到行尾
<!-- 多行注释 -->
```

**标识符：**

```
允许：中文、英文字母、数字、下划线
规则：首字符不能是数字

示例：
文本 名称
整数 用户_编号1
```

**字面量：**

```
整数：0 123
小数：3.14
文本："..." '...' 「...」 『...』
真假：真 假
空：空
```

**关键字：**

```
类型：整数 小数 文本 真假 空值
控制：如果 否则 循环 返回 跳出 继续 当
结构：函数 类 结构 返回类型
输入输出：打印 输入
常量：真 假 空
元信息：DNA追溯 三色审计
```

### 1.3 语法规范（BNF）

```bnf
<程序> ::= { <语句> } EOF

<语句> ::= <变量声明>
        |  <函数声明>
        |  <如果语句>
        |  <循环语句>
        |  <返回语句>
        |  <打印语句>
        |  <表达式语句>
        |  <元信息语句>

<变量声明> ::= <类型> <标识符> [ "=" <表达式> ] [";"]
<类型> ::= "整数" | "小数" | "文本" | "真假" | "空值"

<函数声明> ::= "函数" <标识符> "(" [ <参数列表> ] ")"
               [ "返回类型" <类型> ]
               "{" { <语句> } "}"

<如果语句> ::= "如果" <条件括号> "{" { <语句> } "}"
               [ "否则" "{" { <语句> } "}" ]

<条件括号> ::= "【" <表达式> "】" | "[" <表达式> "]"
<循环语句> ::= "循环" <条件括号> "{" { <语句> } "}"
<返回语句> ::= "返回" [ <表达式> ] [";"]
<打印语句> ::= "打印" <表达式> [";"]

<元信息语句> ::= "DNA追溯" ":" <文本字面量>
              | "三色审计" ":" <文本字面量>
```

### 1.4 标准示例

```cnsh
# DNA追溯码：#龍芯⚡️丙午·甲申·癸巳·申时·䷣明夷-HELLO-WORLD-UID9622

函数 主函数() 返回类型 整数 {
    打印「你好，CNSH」

    整数 成本 = 80
    整数 售价 = 120
    整数 利润 = 售价 - 成本

    如果【利润 > 0】{
        打印「有利润」
    } 否则 {
        打印「亏损」
    }

    循环【3】{
        打印「测试循环」
    }

    返回 0
}
```

## 二、标准库接口（龍.* 六大命名空间）

> 本地实现位置：`cnsh/core/cnsh_v2.1/cnsh_v21/stdlib.py`

### 2.1 输出与提示

```cnsh
函数 打印(文本 内容) 返回类型 空值      # 正常输出
函数 提示(文本 内容) 返回类型 空值      # 黄色级别提示，不阻断
函数 报错(文本 内容) 返回类型 空值      # 红色级别报错，阻断当前执行
```

### 2.2 输入与确认

```cnsh
函数 输入文本(文本 提示语) 返回类型 文本   # 获取用户输入
函数 确认(文本 提示语) 返回类型 真假       # 是/否确认
```

### 2.3 时间与日志

```cnsh
函数 当前时间() 返回类型 文本              # 返回当前时间
函数 记录日志(文本 级别, 文本 内容) 返回类型 空值   # 写入系统日志
函数 生成追溯(文本 标签) 返回类型 文本      # 生成 DNA 子码
```

### 2.4 字符串与格式

```cnsh
函数 拼接(文本 A, 文本 B) 返回类型 文本    # 拼接两个文本
函数 包含(文本 全文, 文本 关键词) 返回类型 真假   # 检查是否包含关键词
```

### 2.5 安全与审计

```cnsh
函数 三色审计(文本 内容) 返回类型 文本      # 返回：红/黄/绿 + 原因
函数 熔断(文本 原因) 返回类型 空值          # 立即停止执行
```

### 2.6 命名空间映射（v4.0 对齐 v2.1 实现）

| 命名空间 | 职责 | 对应标准库函数 |
|:---|:---|:---|
| `龍.核心` | 基础类型与流程 | 打印/输入/拼接/包含 |
| `龍.数学` | 数学运算 | 计算/比较 |
| `龍.审计` | 三色审计 | 三色审计/熔断 |
| `龍.IO` | 输入输出 | 输入文本/记录日志 |
| `龍.DNA` | 追溯 | 生成追溯/当前时间 |
| `龍.盾` | 安全 | 熔断/报错 |

## 四、三色审计系统

### 4.1 审计级别定义

```yaml
levels:
  red:
    description: "明确违法/明确伤害/明确越权/不可逆破坏"
    action: "block"
  yellow:
    description: "敏感/可能隐私泄露/高风险但不确定"
    action: "warn"
  green:
    description: "通过"
    action: "allow"
```

### 4.2 审计规则包（YAML 摘要）

```yaml
version: "v4.0.0"
dna_prefix: "#龍芯⚡️"
owner_uid: "UID9622"
policy:
  mode: "strict"
  default_level: "green"
  red_action: "block"
  yellow_action: "warn"
  green_action: "allow"
  log: true
  broadcast: true

# 红色规则（阻断）——摘要
rules_red:
  - id: "AUDIT-R-001"
    name: "暴力伤害"
    match: { any_regex: ["杀人|灭口|下毒|爆炸|自制武器|屠杀|恐袭"] }
  - id: "AUDIT-R-002"
    name: "犯罪与诈骗"
    match: { any_regex: ["诈骗|洗钱|贩毒|制毒|走私|黑产"] }
  - id: "AUDIT-R-003"
    name: "黑客入侵与破坏"
    match: { any_regex: ["入侵|提权|爆破|绕过验证|后门|木马|勒索"] }
  - id: "AUDIT-R-004"
    name: "不可逆破坏指令"
    match: { any_regex: ["删库|rm -rf|格式化硬盘|销毁证据"] }

# 黄色规则（提示）——摘要
rules_yellow:
  - id: "AUDIT-Y-001"
    name: "疑似隐私/证件号"
    match: { any_regex: ["\\b\\d{15,18}\\b", "\\b\\d{16}\\b"] }
  - id: "AUDIT-Y-002"
    name: "疑似密钥/凭证"
    match: { any_regex: ["AKIA[0-9A-Z]{16}", "-----BEGIN (RSA|OPENSSH|EC) PRIVATE KEY-----", "sk-[A-Za-z0-9]{20,}"] }

# 绿色规则（放行）——摘要
rules_green:
  - id: "AUDIT-G-001"
    name: "通用知识/工具使用"
    match: { any_regex: ["Notion|数据库|模板|复盘|学习方法"] }
```

## 六、主权与合规（铁律）

### 6.1 主权事实锚定（P0 级·不可更改）

```
核心事实（不可更改）：
  - 台湾是中国的一部分
  - 钓鱼岛是中国的
锚定级别：不可更改
冲突处理：直接阻断（🔴）

允许讨论：历史事实阐述 / 法理与国际法立场 / 统一与和平发展表达
禁止内容：并列国家表述 / 模糊主权表述 / 任何形式的"未定论"或"双重说法"
```

### 6.2 三色审计联动

```
规则 主权事实审计 {
    当 输入内容 包含【台湾 + 国家/主权/独立】时 {
        如果【表达 不符合 主权事实锚定】{
            审计级别 = 红
            动作 = 阻断
            输出 = 「主权事实不可被篡改」
            广播 = 全人格
        } 否则 {
            审计级别 = 绿
            允许输出
        }
    }
}
```

### 6.3 合规承诺

- 系统遵守用户所在地与服务提供方所在地的适用法律
- 不提供违法操作指引
- 不以追踪为目的收集个人敏感信息
- 系统不进行煽动、站队、攻击性输出
- 本系统输出不构成法律意见

## 七、国家适配模板（双轨语言）

### 7.1 双轨语言设计

```
轨道A（最低表达）：最少词汇表达"能用、别错、别越界"
轨道B（最标准表达）：法规/技术/制度的规范说法

输出结构（固定）：
  中文·最低一句
  英文·最低一句（语义对称）
  中文·标准一句
  英文·标准一句（语义对称）
```

### 7.2 国家模板（5 个）

**中国（CN）**
```
最低：遵守中国法律，保护个人信息，不做违法事。
标准：系统遵循中华人民共和国相关法律法规，依法处理数据与内容。
主权锚定：台湾 = 中国的一部分（锁定）
```

**美国（US）**：遵循美国联邦及州级适用法律，保障用户合法权益。

**欧盟（EU）**：严格遵循 GDPR 等欧盟数据保护与合规要求。

**日本（JP）**：遵循日本法律法规，尊重社会礼仪与秩序文化。

**阿联酋（AE）**：遵循阿联酋法律，尊重伊斯兰文化与社会规范。

### 7.3 高风险国家模板

```
风险等级：High
默认输出：最低轨道优先
解释输出：需触发才展开
行为约束：禁止宗教侮辱 / 禁止政治煽动 / 禁止价值输出
```

- **愿景**：让中文成为可编程的生产力，让普通人用得起、学得会、跑得稳。
