龍魂体系内存在多套颜色体系：
  - 三色审计 (🟢🟡🔴) → 审计判定
  - 五色治理 (绿黄红黑金) → 治理决策
  - 七色不动点 (绿黄红黑金蓝紫+银跑马灯) → 安全分级
  - 真实性三色 (实🟡演⚪疑🔴) → 内容真伪
  - 女娲五彩石 (红黄青白黑) → 文化底座

各自独立→运维眼花→紧急时看不清哪个色最重要。

本协议**将它们焊死为统一的7+1色阶体系**：
  每一份产出、每一条告警、每一个节点，只需看颜色就知道它在哪一级、有多重要。

原则:
  1. 颜色即优先级 — 不看文字看颜色，红色 = 立即处理
  2. 多色取最严 — 一个物品多判定，取最高优先级色
  3. 动画即状态 — 闪烁 = 异常，脉冲 = 处理中，常驻 = 稳定
  4. 降级自动 — 从高到低只能手动解除，从低到高自动触发

跑马灯专用规则:
  - 紫色边框跑马灯: 4个光点沿边框顺时针旋转，表示"观察中"
  - 多色跑马灯(升级中): 黄→红渐变滚动 = 升级警告
  - 跑马灯速度映射紧急度: 2s/圈=观察 · 0.8s/圈=临近熔断

P4 · 判定优先级规则（一个物品同时触达多色时）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

规则1: 多色取最严（颜色 = max(触发的所有色的优先级)）
  例: 审计🟢通过 + 外部输入 → 取 🟣观察紫 (P2 > P7)
  例: 真实来源🟡金 + 安全告警 → 取 🔴断空红 (P0 > P3)

规则2: 降级只能手动，升级自动
  从 P7→P5: 自动（如：审计通过→48h后出现新数据源不明→自动升待核黄）
  从 P5→P3: 自动（如：待核→人工确认权威来源→自动升主权金）
  从 P3→P5: 禁止自动降级（需人工签章）
  从 P0→P7: 不可直降，必须 P0→P2(观察)→P5(待核)→P7(放行) 逐级解

规则3: 默认色 = 观察紫 (P2)
  任何未明确判定的新输入，默认🟣观察紫，不入绿不入红。

规则4: 自检色
  系统自身组件 = 追踪蓝 (P4)，与用户内容色分开。
  Portal仪表盘本身永远🔵追踪蓝边框，内容按P0-P7着色。

每个需显示的状态项，输出统一视觉签名 = 色块 + 色带 + 标签

格式:
```
┌─────────────────────────────────────┐
│ 🔴  [ 断空红 ]  P0·紧急熔断         │  ← 色块标签
│ ══════════════════════════════════ │  ← 跑马灯色带(动画)
│ 审计引擎: 检测到未授权GPG签章请求     │  ← 内容
│ 时间: 2026-08-02 14:30 · #DNA追溯   │  ← 元数据
└─────────────────────────────────────┘
```

色带规则:
  - 色带颜色 = 主色
  - 动画效果 = 该色对应的动画
  - 色带高度 = 3px (紧凑) / 6px (标准) / 12px (仪表盘)
  - 多重状态 = 色带渐变 (左→右: 旧色→新色)
  - 升级中 = 色带左右滚动 + 颜色渐变
