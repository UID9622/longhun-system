## 一、问题陈述

当前龍魂体系内存在多条互不统属的记忆处理路线：

| 路线 | 职责 | 冗余点 |
|---|---|---|
| 外脑压缩引擎 | SimHash 去重、摘要、时间衰减、关联图谱 | 全量扫描，无差别压缩 |
| 记忆永存引擎 | 三格式快照、跨平台同步 | 未达稳定的记忆也归档 |
| 不动点桥接层 | 七色不动点 ↔ 信息素映射 | 只映射，不落地归档 |
| 文件压缩引擎 | zlib/gzip/zstd + 龍魂字典 | 纯字节压缩，无不动点语义 |
| 排序不动点协议 | 人民/护弱排序判定 | 用于决策，未接入记忆流 |

**核心问题**：
1. 同一文本被多次哈希、多次判定、多次压缩。
2. 大量尚未稳定的草稿/中间态记忆进入长期归档，浪费存储与算力。
3. 不动点理论只停留在映射层，没有成为归档的闸门。

## 二、统一原则

本协议将上述五条路线合并为 **一条「不动点记忆归档」流水线**，遵循以下原则：

### 2.1 一次计算，多处复用

- **SHA-256**：用于唯一 ID、DNA 锚链、GPG 签名输入。
- **SimHash**：用于近似去重、相似检索。
- **不动点判定**：用于颜色状态、路由决策、是否归档。

### 2.2 不到不动点，不归档

| 状态 | 含义 | 动作 |
|---|---|---|
| 🟡 YELLOW | 待确认 | 进缓冲池，72h 后重判或丢弃 |
| 🔴 RED | 法律红线 | 阻断，不上链，按 KFPP 熔断处理 |
| ⚫ BLACK | 隐私敏感 | 本地隔离，不进入共享归档 |
| 🟢 GREEN | 稳定可放行 | 轻量压缩后归档 |
| 🟡 GOLD | 主控确认 | 最高优先级归档，多重签名 |

### 2.3 轻量压缩

- 不使用 LLM 摘要（省算力）。
- 采用 **龍魂字典替换 + zlib level=6**，只在不动点触发。
- 压缩率目标：文本类 ≥ 30%，代码/协议类 ≥ 50%。

### 2.4 可追溯，可恢复

每条归档记录包含：
- `id`：SHA-256 前 16 位
- `hash`：完整 SHA-256
- `simhash`：64-bit 相似指纹
- `dna`：龍魂 DNA 签章
- `source`：来源（Kimi / CodeBuddy / 本地脚本）
- `timestamp`：UTC 时间锚
- `state`：不动点状态
- `archive_path`：压缩文件路径

## 三、流水线

```
记忆输入
   │
   ▼
┌─────────────────┐
│ 1. 哈希计算     │  ← SHA-256 + SimHash 一次完成
│   (sha256/simhash)│
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 2. 近似去重     │  ← SimHash 汉明距离 ≤ 3
│   (dedup)       │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 3. 不动点判定   │  ← 三闸同判
│   (judge)       │
└────────┬────────┘
         │
    ┌────┴────┐
    ▼         ▼
 非不动点    不动点
    │         │
    ▼         ▼
 缓冲池    字典+zlib压缩
 (pending)    │
              ▼
           归档索引
        (fixed_point_index.jsonl)
```

## 四、不动点判定规则（轻量版）

### 4.1 正向锚词（+0.35，只触发一次）

`确认码`、`确认`、`焊死`、`归档`、`落地`、`完成`、`通过`、`决定`、`DNA`、`签章`、`GPG`、`冻结`、`永不`、`只此一次`、`DONE`

### 4.2 摇摆信号（-0.45，只触发一次）

`待定`、`待确认`、`TODO`、`考虑一下`、`maybe`、`也许`、`或者`、`回头再说`、`暂定`、`草案`、`初稿`

### 4.3 排序锚点（+0.20）

文本中出现 `人民`、`老百姓`、`弱者`、`护童`、`公益` 等护弱/人民优先词。

### 4.4 高稳定性标记（+0.35）

文本中含 `#CONFIRM`、`DNA:`、`#龍芯` 等强标记。

### 4.5 状态映射

| 综合得分 | 状态 | 动作 |
|---|---|---|
| ≥ 0.7 | GOLD | 主控确认，归档 |
| ≥ 0.3 | GREEN | 稳定，归档 |
| < -0.2 | RED/BLACK | 阻断/隔离 |
| 其他 | YELLOW | 缓冲池 |

## 五、文件格式

### 5.1 归档压缩文件 `.fpz`

- 内容：`zlib.compress(龍魂字典替换后的文本)`
- 命名：`{sha256前16位}.fpz`
- 存放：`state/fp_memory_archive/`

### 5.2 索引文件 `fixed_point_index.jsonl`

每行一个 JSON，包含第 2.4 节全部字段。

### 5.3 缓冲池 `pending_buffer.jsonl`

临时存放未达不动点的记忆，由定时任务重判或清理。

## 八、算力与存储约束

- **禁止 LLM 参与归档**：不动点判定必须纯规则，不调用模型。
- **禁止全量扫描**：只处理新输入，不周期性重扫全部历史。
- **缓冲池上限**：默认保留 7 天，过期未达不动点自动清理。
- **归档文件上限**：单条压缩后不超过 10MB，超过则切片。
