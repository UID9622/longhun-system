## 四、漏洞挖掘实战流程

### 4.1 标准流程（PDCA）

```
Plan（计划）
  ├── 选平台 → 注册 → 实名
  ├── 读规则 → 明确测试范围
  └── 选目标 → 边缘资产优先

Do（执行）
  ├── 信息收集 → 子域名/IP/技术栈
  ├── 漏洞探测 → 自动化扫描+手工验证
  └── 证明危害 → 截图/录屏，不破坏

Check（检查）
  ├── 写报告 → 清晰+完整+可复现
  ├── 提交 → 等待审核
  └── 修复验证 → 确认漏洞已修

Act（改进）
  ├── 复盘 → 总结思路
  ├── 沉淀 → 写技术文章
  └── 进阶 → 冲击更高难度
```

### 4.2 信息收集技巧

```bash
# 1. 子域名枚举
subfinder -d example.com -o subs.txt

# 2. 技术栈识别
whatweb example.com

# 3. 端口扫描
nmap -sV -p- example.com

# 4. 目录扫描
dirsearch -u "https://example.com" -e php,html,js

# 5. 敏感文件寻找
# 备份文件：.bak, .zip, .tar.gz
# 配置文件：.git, .env, config.php
# 测试页面：test.php, admin.php, phpinfo.php
```

### 4.3 高频漏洞类型（新手首选）

| 漏洞 | 检测方法 | 危害 |
|------|----------|------|
| **SQL注入** | 输入单引号/双引号，看是否报错 | 数据泄露 |
| **XSS** | 输入<script>alert(1)</script> | 会话劫持 |
| **文件上传** | 上传.php后缀，修改Content-Type | 远程代码执行 |
| **命令注入** | 输入;ls /或|whoami | 服务器控制 |
| **越权访问** | 修改orderId/userId参数 | 查看他人数据 |
| **逻辑漏洞** | 修改金额/数量/状态 | 财产损失 |

## 五、合规红线（必守）

### 5.1 绝对禁止

```
❌ 未经授权测试任何系统
❌ DDoS攻击
❌ 暴力破解（无授权）
❌ 植入后门
❌ 篡改业务数据
❌ 删除系统文件
❌ 下载/留存/传播敏感数据
❌ 利用漏洞越权操作（超出证明危害）
❌ 使用勒索病毒/挖矿程序
❌ 出售漏洞给黑产
```

### 5.2 必须遵守

```
✅ 只测试平台/企业授权的资产
✅ 遵循"最小影响原则"
✅ 仅截图证明漏洞存在，不下载数据
✅ 提交清晰、完整、可复现的报告
✅ 等待厂商修复后再公开
✅ 配合完成漏洞验证
```

## 六、龍魂视角：为什么合规挖洞

```
你不是在帮企业，你是在帮所有人。

每个漏洞被修复 = 少一个被黑产利用的入口
每个漏洞被修复 = 少一个用户数据泄露
每个漏洞被修复 = 少一个财产损失

龍魂系统的安全基线：
  ├─ 可吸收研究病毒/武器数据用于防御
  ├─ 绝不输出/制作/传播攻击手段
  ├─ 所有科研成果强制公开透明
  └─ 红线：不危害人类、社会、地球、环境

漏洞挖掘同理：
  ├─ 可以研究漏洞原理
  ├─ 可以提交给企业修复
  ├─ 绝不利用漏洞搞破坏
  └─ 绝不把漏洞卖给黑产
```
