## 一、规范总览：为什么需要术语白话化

龍魂系统是一个**面向人民**的系统。如果老百姓看不懂你在说什么，那你的系统再牛也是**精英的玩具**。

| 问题 | 后果 | 白话化解法 |
|:---|:---|:---|
| 满屏英文术语 | 普通人直接放弃 | 每个术语配大白话 |
| 缩写满天飞 | 新手开发者一头雾水 | 缩写必须展开 |
| 端口、目录、命令无解释 | 用户不知道点哪里 | 悬浮提示+对照表 |
| 版本号看不懂 | 不知道能不能用 | 状态标签（稳定/测试/废弃） |
| 技术文档像天书 | 只有专家能维护 | 初中文化能看懂才算合格 |

**核心原则：**
> **技术不应是精英的壁垒，而应是人民的工具。认知主权，从能看懂开始。**

这不是"降低标准"，是**"扩宽入口"**。高手看代码，普通人看白话，各取所需，互不干扰。

## 二、背景：痛点与核心判断

### 痛点

| 现象 | 问题 |
|:---|:---|
| 满屏英文目录名（`portal/`, `service/`, `_work/repos/`） | 普通开发者看不懂，不知道这是干什么的 |
| 端口号（`8765`, `9622`, `8501`） | 不知道哪个端口对应哪个服务 |
| 命令（`lh deploy`, `lh status`） | 不知道命令到底在做什么 |
| 版本号（`v1.0`, `v2.0-beta`） | 不知道版本代表什么状态 |
| 缩写在日志/文档里随处可见 | 新手开发者一头雾水 |

### 核心判断

> **技术不应是精英的壁垒，而应是人民的工具。**
>
> 龍魂系统的所有产出——代码、文档、界面、日志——必须让一个普通老百姓（或初中文化的开发者）也能看懂。这不是"降低标准"，是"扩宽入口"。
>
> **认知主权，从能看懂开始。**

| `localhost:9622` | **本地通讯端口9622** | 专门留给 `lh` 命令用的，用来执行龍魂系统里的各种指令 |

| 术语 | 大白话解释 | 实际作用 |

## 四、反面教材：不好的术语解释长什么样

知道"好"的标准之前，先看"坏"的例子。

### 4.1 反面示例：端口解释

```
❌ 不好的解释：
"localhost:8765 是龍魂系统的核心服务端口。"
→ 问题：没解释"端口"是什么，没解释"核心服务"是干嘛的。

✅ 好的解释：
"本地通讯端口8765 —— 你家书房的电脑地址，用来跑龍魂系统核心服务。"
→ 优点：用"你家书房"类比"本地"，用"跑"代替"部署"，普通人秒懂。
```

### 4.2 反面示例：目录解释

```
❌ 不好的解释：
"portal/ 存放前端入口文件。"
→ 问题："前端"是什么？"入口文件"是什么？

✅ 好的解释：
"门户目录 —— 存放系统首页和入口页面的地方，相当于龍魂的'大门'。"
→ 优点：用"大门"类比"门户"，用"首页"代替"前端入口"。
```

### 4.3 反面示例：命令解释

```
❌ 不好的解释：
"lh deploy 执行部署操作。"
→ 问题："部署"是技术黑话，普通人听不懂。

✅ 好的解释：
"执行部署 —— 把当前龍魂系统的修改推送到鲲鹏服务器上。"
→ 优点：说清楚"推送到哪里"、"修改了什么"，动作具体。
```

### 4.4 白话化三原则

| 原则 | 说明 | 检验标准 |
|:---|:---|:---|
| **先中文后英文** | 术语先给中文大白话，括号里给英文 | 普通人第一眼看到中文 |
| **用类比不用定义** | 用生活场景类比，不用技术定义 | 初中文化能秒懂 |
| **说人话不说黑话** | "推送"代替"部署"，"大门"代替"入口" | 不说"前端""后端""全栈" |

## 五、落地执行方案

### 5.1 网页端：术语悬浮提示

在网页上，**鼠标悬停在任何技术术语上时，自动弹出一个浮窗，用大白话解释这个术语是什么。**

### 5.2 侧边栏/底部：术语表

在每一个页面的侧边栏或底部，都放一个"术语表"，列出当前页面上出现的所有技术术语。

### 5.3 命令行：`lh term` 查询工具

```bash
lh term localhost:8765
# 输出: 📖 本地通讯端口8765 → 你家书房的电脑地址，用来跑龍魂系统核心服务

lh term --list
# 输出: 所有术语对照表

lh term --scan docs/README.md
# 输出: 文件中出现的术语及解释
```

### 5.4 文档：大白话注释块

在Markdown文档里统一添加"大白话注释"块——在每个标题或术语下方加一个折叠块。

### 6.2 扩展标准

一个新术语要进入龍魂术语库，必须通过**三关**：

```
第一关：必要性 —— 这个术语在系统中出现频率 > 3次？
第二关：清晰度 —— 白话解释能让初中文化的人秒懂？
第三关：一致性 —— 解释风格与现有术语库一致？
```

### 6.3 审核流程

```
提交PR → 自动校验（格式检查）→ 社区投票（3人赞同）→ 合并入库 → DNA归档
```

## 十、FAQ

### Q1：为什么不能用纯英文术语？
**A：** 龍魂系统是给中国人用的。英文术语是技术界的"行话"，但不是"普通话"。行话会让很多人被挡在门外。

### Q2：会不会让文档变得冗长？
**A：** 不会。大白话解释是"可选的"——默认隐藏，点击展开。想看的看，不想看的不影响阅读。

### Q3：谁来维护术语表？
**A：** 社区共同维护。任何人都可以提 PR 添加新术语，审核通过后合并。

### Q4：术语的"大白话解释"有标准吗？
**A：** 有。必须让一个初中文化、不懂技术的普通人能看懂。如果看不懂，说明解释还不够"白"。

### Q5：和"通心译"是什么关系？
**A：** "通心译"是把英文翻译成中文，解决"语言不通"的问题。"术语白话化"是把中文术语翻译成大白话，解决"懂中文但不懂技术"的问题。两者一起，让龍魂系统真正做到"人民可理解"。
