## 一、三通道定义（P0 决策 · 2026-08-24 老大拍板）

AI 助手对外服务只走三条通道，任何新增通道必须先过 P05 审计 + P72 熔断审 + P15 签章：

| 通道 | 载体 | 定位 | 数据落库 | 状态 |
|:---|:---|:---|:---|:---|
| **P0** | 自有网站 AI 对话（uid9622.cn） | 主权主通道·不落库 | ❌ 不落库（隐私零存储） | 🟢 运营 |
| **P1** | 微信公众号 AI 助手 | 触达大众·轻量问答 | 按隐私规则逐项授权 | 🟡 待 AppID/Secret |
| **P2** | GitHub 开源机器人（longhun-bot） | 开发者生态·开源协作 | 仓库公开数据·无隐私 | 🟢 运营（沙箱隔离） |

**铁律**：
1. 三通道共用同一把**统一熔断闸门**（见 §2），任一通道异常 → 熔断该通道，其余通道照常。
2. 三通道任何请求不得绕过 `lh_channel_gate.py` 检查直接放行。
3. 飞书永久搁置（2026-08-24 数据主权红线裁决），不得恢复为助手通道。

## 二、统一熔断闸门规范（P72 · 三通道共用）

### 2.1 状态机（每通道独立）

```
CLOSED ──(连续失败 ≥ 阈值)──▶ OPEN ──(冷却窗口到期)──▶ HALF_OPEN ──(探测成功 1 次)──▶ CLOSED
   ▲                                                                                   │
   └──────────────────────────(探测失败 → 回 OPEN)──────────────────────────────────────┘
```

### 2.2 参数（引擎默认值，可按通道覆写）

| 参数 | 默认 | 说明 |
|:---|:---|:---|
| 失败阈值 | 3 次 | 连续失败计数达到 → OPEN |
| 冷却窗口 | 300 秒 | OPEN 后多久进入 HALF_OPEN |
| 半开探测 | 1 次成功即恢复 | 探测失败回 OPEN |
| 熔断记录 | JSON 持久化 | `_work/channel_gate_state.json`（append 审计） |

### 2.3 熔断动作

1. OPEN 期间该通道请求**直接拒绝**（返回 `channel_meltdown`），禁止静默放行。
2. 熔断原因写审计日志（谁/何时/通道/原因/DNA）。
3. 恢复后自动放行，无需人工（L3 行为级自动恢复）。

## 三、P2 开源机器人沙箱隔离规范（P72）

P2 通道（GitHub 外接口）强制沙箱，由 `bin/lh_bot_sandbox.py` 统一拦截：

### 3.1 方法白名单（只读优先）

| 方法 | 允许 | 说明 |
|:---|:---|:---|
| GET / HEAD | ✅ | 只读·全放行 |
| POST | 🟡 审核 | issues/comments/PR 评论等非破坏动作 |
| PATCH / PUT | 🟡 审核 | 需在沙箱白名单路径内 |
| DELETE | 🔴 禁止 | 默认拒绝，须显式 `--allow-delete` + 审计 |

### 3.2 路径规则

- 默认仅允许 `UID9622/*` 仓库（配置 `ALLOWED_OWNERS` 可扩）。
- 禁止路径：`/repos/*/forks`(递归)、`/orgs/*`、`/user` 级写操作、`/admin`。
- 危险动作关键词（force push/transfer/delete 等）命中 → 🔴 拦截。

### 3.3 审计

每次沙箱放行/拦截都写审计 JSONL（`_work/bot_sandbox_audit.jsonl`），append-only。

## 四、数据主权铁律（三通道通用）

1. 通道内对话**不训练**：用户消息仅用于当次回答，不回流训练集（P0 第 2 条）。
2. 涉及手机号/身份证/健康/位置等 D2+ 数据 → 通道端侧加密后才可出设备，云上只存密文。
3. 所有通道对外输出挂**原创声明块** + GPG 签名（原创声明协议 v1.0）。
