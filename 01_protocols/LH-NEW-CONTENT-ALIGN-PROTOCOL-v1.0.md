## 一、协议目标（老大原话焊点·verbatim）

> 「以后新增任何内容，如果有不符合我们系统深度集成联动的，你可以都修复一下嘛。是不是都按照标准来？不要每一次做都是重新的，每一次做都是有关联的，好吧」

翻译成系统语言：

| 老大意图 | 系统机制 |
|:---|:---|
| 新增内容要符合标准 | 新增/修改任何内容，必须先过**对齐检查清单**（§二） |
| 不符合就修复一下 | 对齐器自动补齐缺项（§三），不再"发现→报告→等老大" |
| 不要每次重来 | 对齐是**幂等**的：缺啥补啥、已合规跳过、重复跑不破坏 |
| 每一次都有关联 | 新内容自动登记（COMMAND_INDEX/协议INDEX/功能清单）+ 自动补 DNA/归属名/许可/签名/反向链接 |

**核心转变**：从「git 提交时拦截 🔴 阻塞」→「新增时自动对齐 🟢 放行」。pre-commit 是最后一道闸，本协议是入场标准。

## 二、新增内容对齐检查清单（8 项 · 全类型适用）

> 执行器: `python3 08_BIN/lh_standard_align.py <文件或目录> [--fix]`
> 缺任一 🔴 项 → --fix 自动补；🟡 项提示待人工确认。

| # | 检查项 | 标准 | 不达标影响 |
|:---:|:---|:---|:---:|
| 1 | **归属名** | 含「诸葛鑫」/「归属名」/「ZHUGEXIN」 | 🔴 |
| 2 | **DNA 追溯码** | 含 `#龍芯⚡️` 或 `DNA:`（格式 `#龍芯⚡️YYYY-MM-DD-模块-动作-v1.0-UID9622`） | 🔴 |
| 3 | **确认码** | 含 `CONFIRM` / `#CONFIRM🌌9622-ONLY-ONCE🧬LK9X-772Z` | 🔴 核心文件 |
| 4 | **分层许可** | 思想层(.md 协议/哲学/白皮书)=`CC BY-NC-SA 4.0` · 工程层(.py/.js/.sh/.yml)=`MulanPSL v2` | 🔴 协议类 |
| 5 | **P0 声明** | 协议/铁律/宪法类文件须含「P0」或「焊死」 | 🔴 协议类 |
| 6 | **GPG 签名** | 同目录 `.asc` 分离签名（`bin/lh_gpg_sign.py sign`） | 🔴 |
| 7 | **反向链接** | 核心产出须链回公开首页/协议 INDEX（`01_protocols/INDEX.md`） | 🟡 |
| 8 | **登记入库** | 新引擎/命令→`COMMAND_INDEX.md` · 新协议→`01_protocols/INDEX.md` · 新功能→`功能清单.md` | 🟡 |

**豁免清单**（天然无 DNA/归属名，不检查）：`.asc/.sig`（机器签名）· `.json/.jsonl`（数据·DNA 在 MANIFEST）· 二进制（.png/.mp4/.zip 等）· `.sha256` · 三方库/`node_modules`/`.venv`/`weights/`/`models/`/`dist/`。

## 三、自动修复规则（幂等 · 只增不改）

| 缺项 | 自动补法 |
|:---|:---|
| 缺归属名 | 复用 `lh_fix_attribution.py` 逻辑：确认码行后 / 文件头（跳 shebang）插入 `归属名: 诸葛鑫 | UID9622 · 龍芯北辰` |
| 缺 DNA | 按文件名+当天日期生成 `#龍芯⚡️YYYY-MM-DD-<模块>-<动作>-v1.0-UID9622` 插入文件头 |
| 缺确认码 | 插入 `# CONFIRM: #CONFIRM🌌9622-ONLY-ONCE🧬LK9X-772Z`（代码）/ `> CONFIRM: ...`（md） |
| 缺许可 | md 协议类插 `> 协议: CC BY-NC-SA 4.0（核心思想层）`；代码插 `# License: MulanPSL v2 (https://license.coscl.org.cn/MulanPSL2)` |
| 缺 P0 声明 | 协议类插 `> 【文档性质】P0-ETERNAL（永恒定锚级）` |
| 缺 GPG 签名 | 调 `python3 bin/lh_gpg_sign.py sign --force <文件>` |

**安全性（P0：不把能用的改坏）**：
- 只插入标准头，**不改正文**
- 幂等：已有项跳过，重复跑不叠加
- 二进制/数据/签名文件零触碰
- 修改前冻结原版到 `archive/frozen/`

## 四、执行时机（自动触发 · 查表硬触发）

| 场景 | 动作 |
|:---|:---|
| 任何 AI 新增/修改文件（协议/代码/脚本/配置） | 交付前跑 `lh_standard_align.py <文件> --fix` |
| 批量交付（本次会话多文件） | `lh_standard_align.py <目录> --fix` |
| git 提交前 | pre-commit 五阶段兜底（已有）· 本协议为前置补齐 |
| 每月巡检 | `lh_standard_align.py scan`（只报不修·看存量欠账） |

**与节能协议对齐**：只处理**本次变更文件**，不做全库扫描；`scan` 巡检 ≤1 次/月。
