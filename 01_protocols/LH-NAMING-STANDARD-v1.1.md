## 一、龍魂生态唯一命名规范（焊死版）

### 1.1 生态根目录命名（只能二选一）

```
/龍魂系统/           # 中文生态根（推荐）
或
/longhun-system/      # 英文生态根（兼容）
```

**规则：** 整个生态只有一个根，选了就焊死，不许改。
**归档要求：** 选定后须在 `P0_根目录注册表.md` 中登记，登记后冻结。
**本生态裁决：** 当前登记为 `/longhun-system/`（详见 `01_protocols/P0_根目录注册表.md`）。

### 1.2 协议/宪法/核心文件命名（带 DNA）

```
格式：[序号]_[中文主体]_☯UID9622·[DNA].cnsh

示例：
01_龍魂宪法_☯UID9622·#龍芯⚡️丙午·丙申·辛酉·丙申·䷉履_CONSTITUTION.cnsh
02_三色审计协议_☯UID9622·[DNA]_AUDIT.cnsh
03_人格矩阵协议_☯UID9622·[DNA]_MATRIX.cnsh
```

**扩展名说明：**
| 扩展名 | 含义 | 备用标准映射 |
|:---|:---|:---|
| `.cnsh` | 龍魂 Constitution Shell（专用）| 对外分发映射 `.md` |
| `.py` | Python 代码 | 标准 |
| `.json` | 配置/数据 | 标准 |
| `.yaml` | 部署配置 | 标准 |

**规则：** `.cnsh` 为龍魂生态内部专用扩展名，跨系统交互时自动映射为 `.md`（落地引擎 `lh naming convert`）。
**🔴 焊死：** 序号必须零填充两位，不许 `1_`，必须 `01_`。

### 1.3 代码文件/脚本命名（四层结构）

```
格式：[层级]_[功能]_[DNA后缀].py

层级定义（焊死）：
L0_协议层/     # 不可变协议 · 仅创始人可写入
L1_引擎层/     # 核心引擎 · 需 16 人格签章
L2_工具层/     # 工具脚本 · 社区可贡献
L3_应用层/     # 应用模块 · 用户自定义
L4_数据层/     # 数据/配置 · 只读/审计

示例：
L0_协议_P0宪法冻结器_[DNA].py
L1_引擎_DNA生成器_v3.0_[DNA].py
L2_工具_认知索引构建器_[DNA].py
L3_应用_浏览器自动化控制器_[DNA].py
```

**规则：** 所有代码文件一眼看出层级，不用猜。
**冲突裁决：** 层级判断争议以 `P0_根目录注册表.md` 的 `层级映射表` 为准（落地引擎内置同表）。

## 八、别名映射环境（v1.2 新增 · 老文件物理不动 · 环境变量识别）

### 8.1 原则

> **存量老命名不改 · 映射即识别 · 新规范约束新增。**

已有索引/引用链焊死的老文件（`LH-*.md`、老工具脚本等）**物理文件不动**，
通过"别名注册表"登记 老名→规范名 映射，系统自动识别为合规，不误报、不改名、不破坏引用。

### 8.2 注册表 & 环境变量

| 项 | 值 |
|:---|:---|
| 默认注册表 | `config/naming_alias_registry.json` |
| 环境变量 | `LH_NAMING_ALIAS_FILE`（自定义别名文件路径，优先于默认） |
| 别名DNA | `#龍芯⚡️丙午·丙申·辛酉·丙申·䷉履-NAMING-ALIAS-1c857e60`（数字根6·369锚点命中） |

```json
{
  "aliases": {
    "LH-CODE-NAMING-STANDARD-v1.0.md": {
      "canonical": "01_代码命名规范_☯UID9622·丙午·丙申·辛酉·丙申·䷉履_CODE-NAMING-v1.0.md",
      "layer": "L0",
      "status": "legacy",
      "note": "存量老命名规范·已被引用链焊死·别名识别"
    }
  }
}
```

### 8.3 命令速查（`lh naming alias`）

```
lh naming alias                    → 别名看板（映射总数·环境变量通道）
lh naming alias register --old <老名> --canonical <规范名> [--layer Lx] [--note ...]
lh naming alias unregister --old <老名> [--yes]
lh naming alias resolve --name <名字> [--dir .]      # 老名↔规范名 双向解析·递归找物理路径
lh naming alias scan --dir . [--dry-run]             # 扫描未注册老文件·生成建议映射
lh naming alias scan --dir . --import --yes          # 批量导入建议映射
lh naming alias import --file x.json [--yes]         # 批量导入 JSON 映射文件
```

### 8.4 联动规则（引擎内置）

- `lh naming check`：命中别名 = 合规（输出 `🟢 别名识别: N 个老文件已注册`），不再误报
- `lh naming dashboard`：显示 `别名映射: N 个老文件已注册`
- `resolve` 双向解析：老名→规范名 / 规范名→老名，递归定位物理路径
- 环境变量 `LH_NAMING_ALIAS_FILE` 指向的文件缺失 → 自动回退默认注册表

### 8.5 实测记录（mock 全流程）

1. register 注册老协议 → check 不再误报，`别名识别: 1` 🟢
2. resolve 双向解析（老名↔规范名）+ 递归找到物理路径 🟢
3. scan 生成建议映射 → `--import --yes` 批量导入 🟢
4. `LH_NAMING_ALIAS_FILE` 指向自定义文件 → 看板切换成功 🟢
5. unregister 注销 → 注册表干净（不污染真实注册表）🟢
