§0 总纲定位
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

花名册 = AI工程公司全员档案。系统运行的一切调度——任务派发、执行、审计、
交付、发布、维护——全部以此为唯一依据。

0.1 三条铁律
  ① 一人格一主责部门：每个人格归属一个部门，不可双挂。
  ② 平台监督层不上记分牌：P05/P06/P13/P15/P72/P77 只审计不记贡献分。
  ③ 上线必须四证齐全：路由编号 + IPA + 功能定位 + DNA，缺一不可上线。

0.2 花名册的四种角色身份
  | 身份标记 | 含义 | 示例 |
  |:---|:---|:---|
  | `数字人格` | 龍魂体系内置AI人格 | P01诸葛亮、P04鲁班 |
  | `外部AI` | 第三方AI工具，协作链路成员 | Kimi/DeepSeek/Claude |
  | `平台服务` | 基础设施平台 | Notion/GitHub/鲲鹏 |
  | `历史人物` | 已冻结封存的前代人格/引擎 | 僧一行/网织者 |

0.3 花名册 = 系统调度的硬编码基础
  系统每次接收指令 → 查花名册 → 匹配信号词 → 路由到对应人格 → 按
  协作圈分配上下游 → 执行 → 审计 → 归档。花名册不准，调度必乱。

§2 IPA定义与格式规范
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

2.1 IPA = Identity · Persona · Access = 人格触发调用缩写

  不是UUID、不是普通ID——IPA是系统调度时的分机号。
  每个活跃人格有且仅有一个IPA。

2.2 IPA格式（与IPA-DICT-112 §22-EX对齐）
  ```
  IPA-{层级}-{代号}-{职能缩写}
  ```

  | 段 | 含义 | 取值 | 示例 |
  |:---|:---|:---|:---|
  | IPA | 固定前缀 | IPA | IPA |
  | 层级 | 人格所在层 | P=人格层 / S=子系统 / AI=外部AI / PF=平台 / PH=历史 | P14 / S1 / AI-01 |
  | 代号 | 人格英文缩写 | 4-8字符大写 | LVMENG / ZHUGE / MOONSHOT |
  | 职能 | 职能缩写 | 4-12字符大写 | DEPLOY / STRATEGY / AUDIT |

  完整示例: `IPA-P14-LVMENG-DEPLOY` = P14吕蒙·部署执行

2.3 IPA状态
  | 状态 | 含义 | 调度行为 |
  |:---|:---|:---|
  | 🟢 `active` | 已焊死·正常调度 | 正常路由 |
  | 🟡 `pending` | 待焊·沙盒跑通前 | 不转活跃·仅🟡标记 |
  | 🔴 `frozen` | 已冻结·不可调度 | 不响应路由 |
  | ⚫ `deprecated` | 已废弃 | 不响应·只留档 |

2.4 IPA命名铁律
  ① 空IPA = 待焊，不允许参与调度。
  ② IPA不可重复，不可复用（冻结人格的IPA不回收）。
  ③ IPA变更需经 P13姜子牙审批 + P15乔前辈签章 + P05审计。

§3 路由机制（五元组+六步流）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

3.1 路由五元组
  每条路由记录包含五个必填字段：

  | # | 字段 | 含义 | 格式 |
  |:---:|:---|:---|:---|
  | ① | **路由编号** | 唯一工号 | `UID9622-{CODE}-{NNN}` |
  | ② | **优先级** | 调度优先级 | P0(∞焊死) P1(立即) P2(高) P3(中) P4(低) P5(建议) |
  | ③ | **权重** | 同优先级下的比较权重 | 0.00-1.00 |
  | ④ | **短DNA** | 8位十六进制哈希 | P02生成→P03验→P05审计 |
  | ⑤ | **信号词** | 触发该人格的关键词列表 | 逗号分隔 |

3.2 六步调度流
  ```
  用户输入 → ①信号词命中 → ②查花名册匹配 → ③路由到目标人格
  → ④人格接单执行 → ⑤P05审计 → ⑥P03归档留痕
  ```

  每一步的负责方：
  | 步 | 动作 | 负责方 | 失败处理 |
  |:---:|:---|:---|:---|
  | ① | 信号词命中 | P00文心（意图解析） | 无命中→降级P04默认路由 |
  | ② | 查表匹配 | 花名册适配器 | 无匹配→上报P01推演 |
  | ③ | 路由分发 | P13姜子牙（权限校验后） | 权限不足→拒绝+P05记录 |
  | ④ | 接单执行 | 目标人格 | 执行失败→P72熔断评估 |
  | ⑤ | 审计 | P05上帝之眼（三色判定） | 🔴→阻断+P72升级 |
  | ⑥ | 归档 | P03雯雯（四签+德字闸） | 归档失败→重试≤3次+P05标记 |

3.3 防抖动机制
  连续3次触发同一人格 → 锁定该人格路由30分钟 → 期间自动降级到P04默认路由。

3.4 跨部门路由
  跨部门任务必须经由「朱雀主台」(P00文心+P01诸葛亮)挂号分发，
  禁止部门间直接点对点调用。违例→P05🔴标记。
