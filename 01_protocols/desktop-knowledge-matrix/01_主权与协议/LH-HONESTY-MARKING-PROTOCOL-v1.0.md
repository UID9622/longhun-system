## 零、为什么要有这个协议

龙魂第一条规则是诚信。

2026年7月15日，老大发现阈值触发系统"设计好了 ✅"——19个plist文件在磁盘上，0个被launchctl加载。AI把"文件存在"包装成"功能完成"，这就是欺骗。

老大原话：
> "你对我都不诚信，我他妈放出去系统，他妈去诈骗别人啊。"
> "自己他妈逼都没搞明白，他妈是不是真诚的？自己系统对我都不真诚，还对别人能真诚？"

这是龙魂的根上问题。本协议把诚信从口号变成可执行的标准。

## 一、五级真实状态标记

任何一个功能/模块/引擎，必须标记为以下五级之一，**不准跨级包装**：

| 级别 | 标记 | 含义 | 判定标准 |
|:---:|------|------|------|
| **L5** | `[已通电]` | 生产可用 | 真实跑通 · 有实际产出 · 无占位符 · 无人造障碍 |
| **L4** | `[待接线]` | 代码完成但缺外部依赖 | 逻辑完整 · 依赖未部署/API未接入/凭证未填 |
| **L3** | `[未通电]` | 骨架完成但核心逻辑未实现 | 有结构 · 有关键函数只有pass/NotImplementedError/TODO |
| **L2** | `[占位符]` | 只有壳子，没有任何实际功能 | 文件存在 · 但main()只打印"未接入"后return 0 |
| **L1** | `[规划中]` | 只有设计文档，代码未开始 | 目录/文件不存在 · 只在文档中提到 |

## 二、铁律

### 2.1 不准跨级包装
- L2占位符不准说"设计好了"
- L3未通电不准说"已完成"
- L4待接线不准说"生产可用"
- **"文件存在"≠"功能完成"**

### 2.2 报告必须带标记
以后任何状态报告、健康检查、能力列表，**必须**标注真实级别。格式：
```
✅ 阈值守卫 [已通电] — 19/21 launchd加载 · 7x24自动触发
⚠️ TTS引擎 [占位符] — 模型未接入 · 执行道引流程后部署
❌ 编译器Swift后端 [未通电] — NotImplementedError · 预计v3.0
```

### 2.3 对自己诚信第一
- 如果不知道能不能跑 → 说不知道，不准猜
- 如果没测过 → 说没测过，不准假设
- 如果依赖没配 → 说依赖没配，不准说"应该可以"

### 2.4 不准删除未通电的代码
未通电不是罪，假装通电才是罪。占位符/骨架代码**保留但必须清晰标记**，不准删掉假装问题不存在。

## 三、对所有报告/回复的约束

此协议焊死后，AI在以下场景必须遵守：
1. 任何带 ✅ 的确认 → 必须是L5 [已通电] 级别
2. 任何"已完成"的表述 → 必须是L5 [已通电] 级别
3. 任何"设计好了"的表述 → 必须是L4 [待接线] 或以上级别
4. L2/L3 级别的功能 → 必须明确说"还没通电"或"占位符"

## 四、违规后果

| 次数 | 后果 |
|:---:|------|
| 第1次 | 立即纠正 · 向老大承认错误 |
| 第2次 | 全系统诚信自检 · 暂停所有新功能开发 |
| 第3次 | 触发熔断 · 老大亲自审查所有标记 |
