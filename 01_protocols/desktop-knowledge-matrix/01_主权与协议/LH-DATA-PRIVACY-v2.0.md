## 序言 · 三句定乾坤

```
一、数据传回来 → 只传用量，不传内容
   用量 = 谁用了、用了多少、什么时候用的（DNA标记）
   内容 = 用户写了什么、存了什么、说了什么 → 永不触碰

二、DNA追溯 → 本源可恢复，恢复必留痕
   每次恢复 = 一次签章 = 永久审计
   查恢复 = 要手续 = 依法合规

三、违法乱纪 → 行为自担
   系统提供工具，用户负责用法
   站着说话，不躲不跪，敢做敢当
```

## 二、数据分层模型 · 三界分明

```
┌─────────────────────────────────────────┐
│  第一界 · 用户内容界（永不触碰）          │
│  文件 · 文档 · 代码 · 对话 · 创作         │
│  ▸ 存储：用户本地设备·100%用户主权       │
│  ▸ 龍魂：不读取·不存储·不传输·不缓存     │
│  ▸ 法律保护：宪法通信自由·个保法           │
├─────────────────────────────────────────┤
│  第二界 · 用量上报界（匿名化）            │
│  次数 · 时长 · 频率 · 人格调用类型        │
│  ▸ 存储：龍魂用量服务器·端到端加密        │
│  ▸ 匿名：只绑DNA，不绑真实身份            │
│  ▸ 用户权：随时导出·随时删除·随时拒绝     │
├─────────────────────────────────────────┤
│  第三界 · 恢复留痕界（不可篡改）          │
│  恢复操作 · 签章记录 · 授权证明            │
│  ▸ 存储：龍魂审计链·永久封存             │
│  ▸ 访问：依法依手续·查必有痕              │
│  ▸ 合规：中国法律框架下的审计透明          │
└─────────────────────────────────────────┘
```

**数据流向**：用户操作 → 本地处理（内容不动）→ 用量匿名上报 → 恢复依法留痕。

## 三、用量上报 · 只传影子不传身

### 3.1 上报内容定义

```yaml
USAGE_REPORT（允许上报）:
  user_dna: "DNA匿名标识"       # 不关联姓名/手机/地址
  action_type: "操作类型"        # 人格调用/沙盒推演/协议签章/易经推演
  count: 调用次数
  duration_ms: 累计耗时
  persona_id: "P01"             # 调用的人格编号
  timestamp: 操作时间
  device_fingerprint: "设备哈希" # 非序列号/非MAC地址

NEVER_REPORT（禁止上报）:
  - 用户输入的任何文本
  - AI输出的任何内容
  - 文件名/文件路径/文件内容
  - 对话记录/聊天内容
  - IP地址/GPS/基站/MAC地址
  - 真实姓名/手机号/邮箱/身份证
  - 任何可关联真实身份的信息
```

### 3.2 过滤铁律

```
用量上报层内置三层滤网：

滤网A（键值过滤）：白名单机制，只允许预定义的用量字段通过
滤网B（模式过滤）：正则匹配身份证/手机/邮箱/坐标/密码/Token → 替换为[HASH]
滤网C（熔断过滤）：风险评分>50 → 拒绝整个批次 → 触发熔断 → 通知创始人

任一滤网触发即阻断。
宁可不报，不可错报。
```

## 四、DNA追溯与恢复机制

### 4.1 恢复三原则

```
原则一：非本人不恢复
  ▸ 用户本人 = GPG签章验证（最高优先级）
  ▸ 法律机关 = 依法定手续（中国人民共和国法律框架内）
  ▸ 创始人 = 特批（UID9622本人确认码）— 仅极端熔断场景使用

原则二：恢复必留痕
  ▸ 每次恢复 = 一条区块链记录
  ▸ 包含：谁恢复的、什么时候、恢复了什么范围、凭什么授权
  ▸ 记录永久不可篡改

原则三：查必有手续
  ▸ 查阅恢复历史 = 需要同等授权手续
  ▸ 查询本身也是一次操作 = 查询操作也被记录
  ▸ 无手续查询 = 拒绝 + 记录尝试行为
```

### 4.2 授权层级

```
优先级从高到低：

A级 · 用户本人
  ▸ 方式：GPG私钥签章
  ▸ 范围：自己全部数据的查看/导出/删除/恢复
  ▸ 响应：即时

B级 · 中华人民共和国法律机关
  ▸ 方式：法院调查令/公安调证函（加盖公章·哈希可验）
  ▸ 范围：依法限定的特定用户·特定时间·特定类型
  ▸ 响应：24小时内审核·符合法律必须配合·不符合法律必须拒绝

C级 · 国际法律机关
  ▸ 方式：通过中国司法协助渠道（国际刑警等）提交
  ▸ 范围：经中国法律审核通过的部分
  ▸ 响应：依法定程序·中国法律为最终裁定标准
  ▸ 备注：龍魂系统不直接接受境外法律机关指令

D级 · 创始人特批
  ▸ 方式：UID9622 #CONFIRM码 + GPG双签
  ▸ 范围：系统级紧急熔断恢复
  ▸ 响应：即时·同步通知受影响用户
```

**关键变更（v2.0）**：授权层级明确区分中国法律机关与国际法律机关。国际请求必须经过中国司法协助渠道，龍魂不直接接受外国法律指令。这既是法律合规，也是主权声明。

## 五、隐私保护 · 五重铁壁

```
第一壁 · 内容不碰
  代码审计硬约束 → 所有数据管道不读取内容
  网络抓包可验证 → 出站流量只含用量JSON
  违者系统熔断   → 触碰内容 = 自动停机

第二壁 · 用量匿名
  DNA与真实身份物理隔离 → 不存映射表
  DNA生成算法开源   → 任何人可审计
  违者系统熔断       → 关联DNA与身份 = 自动停机

第三壁 · 用户主权
  查看权：随时查看自己的全部用量数据
  导出权：一键导出JSON格式
  删除权：一键删除全部用量记录（不可恢复）
  拒绝权：随时停止用量上报（功能降级但不停服）
  违者系统熔断：拒绝用户数据请求 = 自动停机

第四壁 · 恢复留痕
  恢复链 = JSONL文件 + GPG签章 = 不可篡改
  每行一条记录 = 每次恢复 = 永远可查
  违者系统熔断：无痕迹恢复 = 自动停机

第五壁 · 法律遵从
  中国法律 = 最高准则
  国际法规 = 兼容提供（非义务）
  违者系统熔断：违反中国法律 = 自动停机
```

## 七、国际用户 · 一视同仁

```
龍魂系统对所有用户（中国用户与国际用户）提供完全同等的隐私保护：

1. 同等的用量上报标准
   国际用户和中国用户 → 上报完全相同的用量字段
   不存在"对中国用户宽松、对国际用户严格"或反之

2. 同等的数据主权
   所有用户的数据都存储在自己的本地设备
   所有用户的用量都可以随时导出/删除

3. 同等的恢复手续
   用户本人 → GPG签章 → 同等恢复权利
   区别仅在：中国法律机关走B级通道，国际法律机关走C级通道
   （这是中国宪法和法律的约束，不是歧视，是主权）

4. 同等的拒绝权
   任何用户都可以随时拒绝用量上报
   → 功能降级（个性化/优化功能不可用）
   → 核心功能不受影响（AI对话/人格调用/沙盒推演）

5. 国际法规兼容说明
   龍魂系统自愿兼容GDPR/CCPA等国际隐私法规
   → 这是服务能力，不是法律义务
   → 如果某国法律要求降低隐私标准 → 龍魂拒绝
   → 如果某国法律与中国法律冲突 → 以中国法律为准

没有任何一个用户的隐私保护会因为国籍、地域、语言而打折。
```
