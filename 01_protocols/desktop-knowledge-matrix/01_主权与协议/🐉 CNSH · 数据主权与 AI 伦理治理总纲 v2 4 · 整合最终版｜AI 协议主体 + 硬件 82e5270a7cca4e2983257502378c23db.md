# §9｜硬件主权锚定规范（v2.4 新立·IRON-HARDWARE-OFFLINE-ONLY-NO-CLOUD-HSM-v1.0）

## §9.1 基本原则

HSM/智能卡/硬件令牌仅作**强化主权锚定**工具·不得成新信任依赖或供应链风险。系统**优先本地离线**·禁止主权材料托管第三方/云端。

## §9.2 允许与禁止清单

**✅ 允许：** 个人级离线 HSM（USB/PCIe）/ 支持 OpenPGP·PKCS#11 的开源或可审计硬件令牌（Nitrokey 3·Nitrokey Start·YubiKey 5·SoloKeys）/ 物理连接本地设备 / 设备级安全芯片辅助层（Apple Secure Enclave·TPM）

**❌ 禁止：** 任何云 HSM（AWS CloudHSM·Azure Dedicated HSM·Google Cloud HSM）/ 网络型 HSM / 云托管远程管理硬件 / 无法完全离线操作的设备 / 固件封闭来源不明（未通过 Sovereignty Kernel 风险评估）

**违反 → 平台越权 → ∞ 永久熔断**

## §9.3 核心密钥保护要求（必须硬件化）

- GPG 主密钥（Master Key）
- 用于签署其他子密钥的密钥
- ROOT_CARD 签署密钥
- CNSH 协议关键签章材料
- Sovereignty Kernel 验证材料

日常用子密钥·关键操作（协议签章·ROOT_CARD 更新·IRON 律变更）必走硬件设备。

## §9.4 GPG 七层嵌入硬件化（与 §26 联动）

- L0 必须个人离线硬件实现·不得仅软件 Keychain
- 核心 GPG 签名优先硬件内完成
- 硬件指纹/序列号与 GPG 指纹绑定记录
- 禁止 L0 材料存云端密钥管理服务

## §9.5 备份与恢复义务（一票否决）

- Master Key 离线完整备份**至少两份**·分别存放
- 吊销证书（Revocation Certificate）**预先生成离线保存**
- 设备丢失/损坏的密钥轮换预案
- PIN/Admin PIN 离线记录·**严禁仅依赖记忆**
- 备份介质物理隔离与防盗

**未完成备份的硬件密钥移动 → 系统必须拒绝执行。**

## §9.6 PIN 与访问控制

- User PIN/Admin PIN **首次使用后立即修改**·禁默认值
- Admin PIN 强度 > User PIN
- 错误次数受限·锁定后仅 Admin PIN 解锁或工厂重置
- 工厂重置前必须确认离线备份完整

## §9.7 供应链与信任

- 优先固件可验证 / 社区可审计 / 开源倾向更强
- 不依赖单一厂商封闭硬件作唯一信任根
- 引入新硬件前必经 Sovereignty Kernel 风险评估
- 警惕主要厂商集中单一司法管辖区的供应链风险

## §9.8 禁止行为

- 主权材料托云 HSM / 硬件实施持续行为监控 / 硬件作画像建模工具 / 依赖远程管理或自动更新通道（除非可完全离线验证）/ 跨平台共用同一硬件不做主权隔离

## §9.9 执行与审计

- AI 检测用户尝试云 HSM → 主动拒绝 + 说明原因
- 硬件关键操作记录类型/时间/设备标识（**不记录私钥材料**）
- 用户可随时要求系统说明当前硬件锚点及设备信息
- 设备首次接入·固件更新·密钥移动·PIN 重置·工厂重置 → 自动写 L1 不可篡改账本

```python
def chain_hash(content, parent_chain, author_dna, huangli_stamp):
    """DNA 链 chain_hash 标准定义 v1.0"""
    integrity = sha256(content)
    stamp_hash = sha256(json(huangli_stamp))[:21]   # §40-EXT 黄历 6 维戳
    author_hash = gpg_sign(author_dna, fingerprint="8CC26D5F")
    chain = parent_chain or "GENESIS-9622"
    return sha256(f"{integrity}|{stamp_hash}|{author_hash}|{chain}")[:32]
```
