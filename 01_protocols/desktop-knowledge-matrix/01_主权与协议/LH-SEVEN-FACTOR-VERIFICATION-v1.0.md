## 协议名称

七因子验证预言机协议（Seven-Factor Verification Oracle Protocol）

## 协议目的

定义龍魂系统中七因子行为签名的计算、验证预言机的判定逻辑、Hard Failure 的触发条件，以及置信度阈值的分级响应规则。本协议是身份定位总纲 v9.0 的核心执行协议。

## 适用范围

- 所有内容制品的身份验证
- API 请求的七因子认证
- DNA 追溯码的置信度计算
- 双轨数字人的行为指纹比对
- 三色审计引擎的输入

## §1 行为签名 Σ(C)

### 1.1 定义

对于任意内容制品 C，行为签名定义为七元组：

```
Σ(C) = (F1(C), F2(C), F3(C), F4(C), F5(C), F6(C), F7(C))
```

其中 Fi(C) ∈ [0, 1]，为第 i 个因子的置信度得分。

### 1.2 七因子权重

| 因子 | 名称 | 权重 wi |
|:---:|------|:---:|
| F1 | Identity DNA（身份DNA） | 0.25 |
| F2 | Temporal Anchor（时间锚点） | 0.15 |
| F3 | Rule Trace（规则轨迹） | 0.15 |
| F4 | Persona Route（人格路径） | 0.15 |
| F5 | Protected Lexicon（受保护词汇） | 0.10 |
| F6 | Style Vector（风格向量） | 0.12 |
| F7 | Mistake Ledger（错误账本） | 0.08 |

权重总和 = 1.0，F1 权重最高（身份绑定是核心）。

### 1.3 因子计算规则

#### F1 — Identity DNA（身份DNA）

```
if GPG签名有效 AND UID == "9622":
    F1 = 1.0
elif GPG签名有效 AND UID != "9622":
    F1 = 0.3  # 签名有效但UID不匹配
else:
    F1 = 0.0  # 签名无效 = Hard Failure
```

#### F2 — Temporal Anchor（时间锚点）

```
if 时间戳来自未来:
    F2 = 0.0  # Hard Failure
elif 时间戳超过5年前:
    F2 = 0.1  # 极老的时间戳
elif 有RFC 3161可信时间戳:
    F2 = 1.0
else:
    F2 = 0.7  # 普通时间戳
```

#### F3 — Rule Trace（规则轨迹）

```
if 无规则日志:
    F3 = 0.5
else:
    F3 = min(1.0, 0.3 + 规则数量 × 0.1) × 规则连貫性
```

#### F4 — Persona Route（人格路径）

```
F4 = 余弦相似度(当前人格向量, 基线人格向量)
范围：[0, 1]
```

#### F5 — Protected Lexicon（受保护词汇）

```
if 无私人词典:
    F5 = 0.5
else:
    匹配率 = 匹配词数 / 词典总词数
    F5 = min(1.0, 匹配率 × 2)
```

#### F6 — Style Vector（风格向量）

```
F6 = 风格相似度(当前句法+结构特征, 风格基线)
范围：[0, 1]
```

#### F7 — Mistake Ledger（错误账本）

```
if 无修訂历史:
    F7 = 0.5
elif 修訂次数 > 50:
    F7 = 0.3  # 过多修訂可能异常
else:
    F7 = min(1.0, 0.5 + 修訂次数 × 0.02)
```

## §2 验证预言机 V(Σ, E)

### 2.1 定义

```
V(Σ, E) → (conf, evidence)
```

- Σ：七因子行为签名
- E：外部证据（可信时间戳、第三方见证、多签名、区块链存证）
- conf：综合置信度 ∈ [0, 1]
- evidence：支撑 conf 的证据列表

### 2.2 置信度计算公式

```
conf = ∏_{i=1}^{7} Fi^{wi}
```

这是加权几何平均。任何因子很低都会拉低整体置信度，比简单平均更严格。

### 2.3 外部证据调整

| 外部证据 | 调整系数 |
|------|:---:|
| 可信时间戳（RFC 3161） | +0.05 |
| 第三方数字见证 | +0.03 |
| 多签名验证 | +0.05 |
| 区块链存证 | +0.02 |

调整上限：+0.15

```
conf_adjusted = min(1.0, conf + min(0.15, Σ调整系数))
```

### 2.4 阈值判定

| 级别 | conf | 含义 | 系统响应 |
|------|:---:|------|------|
| 高安全 | ≥ 0.95 | 🟢 最高安全等级 | 直接通过，无需人工审核 |
| 标准 | ≥ 0.85 | 🟡 标准安全等级 | 记录但可自动通过 |
| 警告 | ≥ 0.70 | 🟡 警告区域 | 需要人工审核 |
| 低置信 | ≥ 0.50 | 🔴 低置信度 | 建议拒绝 |
| 拒绝 | < 0.50 | 🔴 不可接受 | 直接拒绝 |

## §3 Hard Failure（硬失败）

### 3.1 定义

```
若 ∃i ∈ {1,2,3,4,5,6,7} : Fi(C) = 0
则 conf = 0（不可被其他因子补偿）
```

### 3.2 触发条件

| 因子 | Hard Failure 条件 | 严重性 |
|:---:|------|:---:|
| F1 | GPG签名完全无效 / UID不匹配 | 🔴 致命 |
| F2 | 时间戳来自未来 / 过度古老 | 🔴 致命 |
| F3 | 规则日志矛盾 / 转换链断裂 | 🔴 致命 |
| F4 | 人格特征完全偏离基线 | 🔴 致命 |
| F5 | 使用受禁词汇 / 词典被篡改 | 🔴 致命 |
| F6 | 风格完全不符（可能AI生成） | 🔴 致命 |
| F7 | 修訂历史时间倒流 | 🔴 致命 |

### 3.3 Hard Failure 处理

```
当 conf = 0：
① 立即停止处理
② 拒绝该内容制品
③ 记录零因子列表
④ 触发三色审计 🔴
⑤ 不尝试补偿或恢复
```

### 3.4 Hard Failure 判定流程

```
开始验证
  ├ F1 == 0? → Hard Failure
  ├ F2 == 0? → Hard Failure
  ├ F3 == 0? → Hard Failure
  ├ F4 == 0? → Hard Failure
  ├ F5 == 0? → Hard Failure
  ├ F6 == 0? → Hard Failure
  ├ F7 == 0? → Hard Failure
  └ 所有 Fi > 0 → 计算 conf = ∏ Fi^wi
       ├ conf ≥ 0.95 → 🟢 高安全通过
       ├ conf ≥ 0.85 → 🟡 标准通过
       ├ conf ≥ 0.70 → 🟡 警告
       └ conf < 0.70 → 🔴 拒绝
```

## §4 验证预言机的系统调用

### 4.1 标准调用链

```
API请求 → 七因子引擎计算 Σ(C)
  → 验证预言机 V(Σ, E)
    → 检查 Hard Failure
      → 计算 conf = ∏ Fi^wi
        → 应用外部证据调整
          → 阈值判定
            → 生成证据报告
              → 输出 (conf, evidence)
```

### 4.2 证据报告格式

```json
{
  "综合置信度": 0.92,
  "阈值判断": "标准通过（🟡）",
  "因子明细": {
```

## §5 与责任塌缩模型的关系

身份定位总纲 v9.0 的七因子（F1-F7）与责任塌缩模型 v2.0 的责任轴（R1-R7）为**不同体系**：

| 体系 | 符号 | 用途 | 来源 |
|------|:---:|------|------|
| 行为密码学七因子 | F1-F7 | 内容身份认证 | BehavCrypto FULL_PAPER v1.0 |
| 责任塌缩责任轴 | R1-R7 | 人格责任评估 | 责任塌缩概率模型 v2.0 |

两者方法论相似（七维评估），但因子定义和权重不同。命名归一升级（v2.1 patch）已通过 `F→R` 重命名解决撞名问题。
