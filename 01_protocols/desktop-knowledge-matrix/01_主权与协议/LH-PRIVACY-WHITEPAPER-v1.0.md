## 一、隐私不是黑箱

**传统隐私 = 藏起来，不让看。**

**龍魂隐私 = 可追溯，需授权，审计留痕。**

| 对比 | 传统黑箱 | 龍魂设计 |
|------|----------|----------|
| 数据存储 | 平台云端，用户看不见 | 本地优先，用户可控 |
| 访问权限 | 平台任意查看 | 相关部门持手续审计 |
| 追溯能力 | 无，删了就是删了 | DNA标识，行为留痕 |
| 责任归属 | 平台说了算 | 个人担责，做事留痕 |
| 透明度 | 不透明 = 隐私 | 可审计 = 真隐私 |

**核心原则：做事留痕，自担责任，不偷偷摸摸。**

## 二、DNA追溯替代内容暴露

### 2.1 传统模式的问题

```
用户语音 → 上传云端 → 平台分析内容 → 推荐/监控/泄露
                ↑
        用户不知道平台看了什么、怎么用
```

**问题：**
- 内容暴露 = 隐私泄露
- 平台黑箱 = 用户无知情权
- 删除难 = 数据永久留存
- 追责难 = 谁看了、怎么用，查不到

### 2.2 龍魂模式：DNA追溯

```
用户行为 → 本地生成DNA标识 → 上传DNA（无内容）
                ↓
        需要审计时：相关部门持手续
                ↓
        本地提取DNA对应内容 → 验证 → 追责/澄清
```

**优势：**
- **不暴露内容**：上传的是DNA标识，不是语音/文字内容
- **可追溯**：DNA对应本地内容，需要时可验证
- **需授权**：不是谁都能看，相关部门持手续
- **可审计**：行为留痕，责任清晰

## 四、审计流程：不是谁都能看

### 4.1 审计申请

```
申请方：相关部门（非任意机构）
申请材料：
  - 法律依据（哪条法规要求审计）
  - 审计范围（哪些DNA标识）
  - 审计目的（查什么、为什么查）
  - 时限要求（审计有效期）
```

### 4.2 审计执行

```
Step 1: 接收加密文件（含DNA追溯码）
Step 2: 读取DNA追溯码（无需解密内容）
Step 3: SM2签名验证 → "DNA来源是否真实？"
Step 4: SM3哈希验证 → "数据是否被篡改？"
Step 5: 阈值比对 → "是否在合规范围内？"
Step 6: 输出三色结果：🟢通过 / 🟡待审 / 🔴超标
```

### 4.3 审计结果

| 结果 | 含义 | 后续 |
|------|------|------|
| 🟢 通过 | DNA真实、数据完整、合规 | 归档，无进一步行动 |
| 🟡 待审 | 部分警告，需复核 | 限期补充材料或整改 |
| 🔴 超标 | DNA伪造、数据篡改、违规 | 依法追责，用户可申诉 |

## 五、用户权利

### 5.1 知情权

- 知道哪些数据在本地、哪些在云端
- 知道DNA标识对应什么行为
- 知道谁申请审计、审计结果

### 5.2 控制权

- 决定本地数据保留多久
- 决定哪些行为生成DNA、哪些不生成
- 决定云端功能是否启用

### 5.3 删除权

- 彻底删除本地数据，DNA同步失效
- 删除后，审计无法追溯（法律另有规定除外）
- 删除记录本身也留痕（防止恶意删除）

### 5.4 申诉权

- 对审计结果有异议，可申诉
- 申诉过程公开透明，有期限
- 申诉结果可验证，不可篡改
