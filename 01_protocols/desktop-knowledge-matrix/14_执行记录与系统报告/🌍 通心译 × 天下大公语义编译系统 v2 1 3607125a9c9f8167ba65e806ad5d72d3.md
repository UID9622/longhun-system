# §1｜CNSH 解析器架构（完整管线）

## 1.1 四阶段编译管线

```
用户自然语言输入
  ↓
[Stage 1: 通心译层] Lexer + 情绪识别 + 语义净化
  ↓
[Stage 2: 语义解析器] Parser → 意图提取 → SAST 生成
  ↓
[Stage 3: 审计层] Watchdog 三色 + 文化适配 + 套壳检测
  ↓
[Stage 4: 代码生成器] SAST → Python / JS / Rust / CNSH 中文
  ↓
可执行输出 + DNA 留痒
```

## 1.2 与传统编译器的对比

| 维度 | 传统编译器（GCC/LLVM） | CNSH 解析器 |
| --- | --- | --- |
| 输入 | 严格语法的代码 | 自然语言（含情绪/比喻/潜台词） |
| 前端 | Lexer → AST | 通心译 → SAST（语义抽象树） |
| 中间表示 | AST / IR | SAST（语义抽象语法树） |
| 后端 | 机器码生成 | 多语言代码生成 |
| 审计 | 无 | 三色审计 + DNA 追溯 |
| 文化 | 无 | 文化适配层 |

# §2｜通心译六层模型（技术实现）

## 2.1 六层完整定义

| 层 | 名称 | 输入 | 输出 | 接驳 |
| --- | --- | --- | --- | --- |
| L0 | 原话保留层 | 用户原始输入 | 不修改的原文存档 | 记忆系统 v1.1 |
| L1 | 情绪净化层 | 原话 | 情绪标签 + 净化后语义 | F09 余弦相似度 |
| L2 | 意图骨架层 | 净化语义 | 主体/状态/动作/优先级 | SAST 生成 |
| L3 | SAST 生成层 | 意图骨架 | 语义抽象语法树 | 代码生成器 |
| L4 | 审计层 | SAST | 三色标记 + 风险评估 | Watchdog v1.2 |
| L5 | 文化适配层 | 审计后 SAST | 目标文化的表达风格 | 国家配置引擎 |

## 2.2 情绪识别体系（补全）

### 情绪分类与强度量化

| 情绪类型 | 示例词汇 | 强度范围 | 处理方式 |
| --- | --- | --- | --- |
| 中性 | “帮我查一下” | 0-2 | 直接解析指令 |
| 轻微不满 | “有点烦”“麻了” | 3-4 | 情绪标记 + 解析 |
| 明显情绪 | “气死我了”“烦死了” | 5-6 | 先响应情绪 + 解析 |
| 强烈情绪 | “草”“卧槽”“我去” | 7-8 | 情绪与指令分离 |
| 极度情绪 | 粗口/极端表述 | 9-10 | 只响应情绪，不执行 |

### 情绪-指令分离算法

```python
def tongxinyi_parse(raw_input: str) -> ParseResult:
    # L0: 原话保留
    archive_raw(raw_input)
    
    # L1: 情绪净化
    emotion = detect_emotion(raw_input)  # 返回 {类型, 强度, 方向}
    cleaned = remove_emotion_noise(raw_input, emotion)
    
    # L2: 意图骨架
    intent = extract_intent(cleaned)  # 返回 {主体, 状态, 动作, 优先级}
    
    # L3: SAST 生成
    sast = generate_sast(intent)
    
    # L4: 审计
    tricolor = watchdog_audit(sast)  # 返回 AUTO_OK / NEED_CONFIRM / BLOCKED
    
    # L5: 文化适配
    adapted = culture_adapt(sast, target_culture)
    
    return ParseResult(emotion, intent, sast, tricolor, adapted)
```

# §3｜SAST 语义抽象语法树（技术补全）

## 3.1 SAST 节点类型完整定义

| 节点类型 | 说明 | 示例 |
| --- | --- | --- |
| IF_NODE | 条件判断 | “如果库存不足，就提醒采购” |
| LOOP_NODE | 循环迭代 | “把每个订单都检查一遍” |
| ACTION_NODE | 执行动作 | “重启服务器” |
| QUERY_NODE | 查询检索 | “查一下昨天的订单” |
| ASSIGN_NODE | 赋值设置 | “把价格设为 99 元” |
| NOTIFY_NODE | 通知提醒 | “提醒采购部门” |
| AUDIT_NODE | 审计检查 | “审计这个页面” |
| COMPOUND_NODE | 复合节点 | “先检查再处理” |
| EMOTION_NODE | 情绪标记 | “草，卡死了”中的“草” |

## 3.2 SAST 生成示例

# §5｜套壳检测系统（技术补全）

## 5.1 三维检测算法

| 检测维度 | 方法 | 接驳公式 | 阈值 |
| --- | --- | --- | --- |
| **结构相似度** | 函数调用链 + 模块关系图比对 | F09 余弦相似度 | 相似度 > 0.85 = 警告 |
| **语义相似度** | 真实业务逻辑 + 参数流向比对 | F09 + 语义向量距离 | 相似度 > 0.80 = 警告 |
| **数字根一致性** | 提取逻辑根 + 结构根 + 数字根 | F06 数字根 dr | dr 相同 + 结构 > 0.85 = 高概率同源 |

## 5.2 套壳检测流程

```
输入两段代码 / 两个系统
  ↓
[结构提取] 函数调用链 + 模块依赖图
  ↓
[语义提取] 业务逻辑向量化
  ↓
[数字根提取] 逻辑根 + 结构根 + 数字根
  ↓
[三维对比] F09 余弦相似度 + F06 数字根一致性
  ↓
[三色输出]
  🟢 原创度高
  🟡 有实质改动但结构相似
  🔴 仅换壳（换变量名 + 换UI + 隐藏来源）
```

## 5.3 套壳检测的商业价值

这是整个 CNSH 体系中**最接近可直接卖钱的模块**：

- 开源生态的合规审计
- 企业代码的知识产权保护
- AI 输出的原创性验证
