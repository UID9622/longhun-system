## 摘要

本文档规范龍魂系统所有对外文档（协议、规则、论文、技术文档、技能说明、执行报告）如何映射到桌面统一知识矩阵，确保分类对齐、索引完整、无孤立文件，并通过 `sync_index.json` 实现自适应锁与增量同步。

## 关键词

知识矩阵、桌面同步、自适应锁、文件分类、无孤立文件、DNA 追溯

## 一、目标

让所有协议、规则、哲学论文、技术文档、技能说明、执行报告不再“孤悬”于各个子目录，而是：

1. **统一出口**：全部映射到桌面一个文件夹。
2. **分类对齐**：按《知识矩阵总纲 v2.0》的模块架构摆放。
3. **自适应锁**：来源文件变更时，桌面镜像可增量更新；索引与校验和即为“锁”。
4. **无孤立文件**：任何进入桌面的文件都必须在 `sync_index.json` 与 `README.md` 中有登记。

## 三、同步规则（自适应锁）

### 3.1 锁的定义

- **锁 = `sync_index.json`**。
- 每个文件记录：来源路径、桌面相对路径、MD5 校验和、大小。
- 当来源文件 MD5 变化时，锁判定为“需要更新”。
- 当来源文件消失时，锁判定为“需要移除”（目前脚本采取全量重建，未来可改为增量）。

### 3.2 增量同步流程

1. 扫描所有配置的来源目录。
2. 对每个文件计算分类（按档名与路径关键字）。
3. 复制到桌面的对应分类文件夹。
4. 生成新的 `sync_index.json` 与 `README.md`。
5. 同步脚本本身也被复制到 `99_索引与自适应锁/`，确保“锁自带钥匙”。

### 3.3 无孤立文件原则

- 任何进入桌面的文件必须同时出现在：
  - `sync_index.json`
  - `README.md` 文件索引
- 如果发现某文件只存在于桌面而不在索引中，视为“孤岛”，下次同步会被清理或重新归类。

## 四、如何重新同步

```bash
# 方式一：直接运行同步脚本
python3 ~/Desktop/龍魂系统·统一知识矩阵/99_索引与自适应锁/sync_longhun_knowledge_desktop.py

# 方式二：从项目源头运行
python3 ~/longhun-system/bin/sync_longhun_knowledge_desktop.py
```

每次运行会：
- 清空旧桌面镜像（避免残留孤岛文件）。
- 按最新来源重新复制与分类。
- 重新生成索引与锁。

---

## 五、分类规则扩展方法

若某文件被分错类，请按以下步骤修正：

1. 打开 `~/longhun-system/bin/sync_longhun_knowledge_desktop.py`。
2. 修改 `CATEGORIES` 列表中的关键字规则（顺序越靠前优先级越高）。
3. 重新运行同步脚本。
4. 检查桌面 `README.md` 中的分类结果。
