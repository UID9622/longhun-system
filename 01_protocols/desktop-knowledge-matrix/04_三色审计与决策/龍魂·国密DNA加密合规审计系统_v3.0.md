## 一、国密加密引擎

**源码**: `longhun_crypto_engine.py`（1,818行）
**文档**: `guomi_crypto_engine.md`（624行）
**DNA追溯码**: `#龍芯⚡️2026-07-04-GUOMI-CRYPTO-v3.0`

### 1.1 国密算法层（纯Python实现，零外部依赖）

| 算法 | 用途 | 实现 |
|------|------|------|
| **SM3** | 256位哈希摘要 | 数据完整性验证 |
| **SM4** | 128位对称加密 | 文件内容加密（CBC模式+PKCS7填充） |
| **SM2** | 椭圆曲线非对称签名 | DNA追溯码签名/验证 |

### 1.2 文件加密器（4种数据类型）

| 加密器 | 数据类型 | 加密方式 | DNA嵌入 |
|--------|----------|----------|---------|
| **图片加密器** | JPG/PNG | SM4-CBC | EXIF元数据 + LSB水印 |
| **文本加密器** | 文本文件 | SM4-CBC | DNA头尾标记 |
| **个人信息加密器** | 银行卡/电话/身份证 | SM2公钥加密 | SM2签名 + 哈希链 |
| **配方加密器** | 配方/参数 | SM4-CBC | 成分阈值 + 合规DNA |

### 1.3 加密流程

```
原始文件 → SM4加密 → 生成DNA追溯码 → SM2签名DNA → 嵌入DNA → 加密文件
                                                              ↑
检测部门: 读取DNA → SM2验证签名 → SM3哈希对比 → 三色审计结果
         （无需解密内容）
```

| **DNA验证** | 签名+哈希 | 全部通过 | 部分警告 | 验证失败 |

### 2.2 五大检测器

## 四、检测部门验证流程

### 4.1 完整验证流程

```
企业提交: 加密文件（含DNA追溯码）
    ↓
检测部门:
  Step 1: 读取DNA追溯码（无需解密）
  Step 2: SM2签名验证 → "DNA来源是否真实？"
  Step 3: SM3哈希验证 → "数据是否被篡改？"
  Step 4: 阈值比对 → "是否在合规范围内？"
  Step 5: 三色审计输出
    ↓
结果: 🟢合规通过 / 🟡待审查 / 🔴不合规
```

### 4.2 关键特性

| 特性 | 说明 |
|------|------|
| **无需解密** | 检测部门不需要企业密钥，只需核对DNA |
| **DNA可见** | 加密后DNA追溯码仍然可读 |
| **动态阈值** | 不同行业不同标准，可配置 |
| **防篡改** | SM3哈希+SM2签名双重保障 |
| **防伪造** | 非对称签名，无法伪造 |
| **防重放** | 时间戳+唯一DNA标识 |

## 五、应用场景

### 5.1 配方保护

```
食品企业: 配方加密 → DNA嵌入（成分阈值）→ 提交检测
检测部门: 核对DNA → 验证阈值 → 🟢合规/🔴防腐剂超标
结果: 配方不泄露，合规性可验证
```

### 5.2 AI文本检测

```
AI生成文本 → DNA嵌入（幻觉率基准）→ 提交审计
审计系统: 检测幻觉率 → 事实一致性 → 🟢可信/🔴幻觉严重
结果: AI输出可追溯，质量可量化
```

### 5.3 个人信息保护

```
个人信息 → SM2加密 → DNA嵌入（隐私级别）→ 存储/传输
检测: 验证加密强度 → 🟢SM4+SM2/🔴弱加密
结果: 信息不泄露，保护强度可审计
```

### 5.4 企业参数合规

```
企业申报参数 → 加密 → DNA嵌入（申报值）→ 提交监管
监管: 实际值vs申报值 → 🟢一致/🔴偏差20%+
结果: 参数不公开，合规性可验证
```
