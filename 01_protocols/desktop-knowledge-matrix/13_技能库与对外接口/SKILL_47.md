## 一、功能概述（TL;DR）

龍魂系統守護進程（longhun-daemon）是龍魂體系的核心基礎設施管理器，提供：

- **守護進程管理**：安裝/啟動/停止/重啟所有龍魂服務
- **一鍵啟動器**：按依賴拓撲順序分四階段啟動全部服務
- **健康檢查器**：定時心跳探測，三色狀態判定（綠/黃/紅）
- **自恢復機制**：服務崩潰時自動重啟（指數退避策略）
- **日誌輪轉**：自動清理和壓縮歷史日誌
- **啟動檢查**：驗證所有配置、依賴和前置條件

## 二、使用示例

### 2.1 快速啟動

```bash
# 進入技能目錄
cd /mnt/agents/output/longhun-v5-skills/local/longhun-daemon

# 一鍵啟動全部服務
python3 scripts/一鍵啟動器.py

# 查看狀態看板
python3 scripts/守護進程管理器.py --status

# 健康檢查
python3 scripts/健康檢查器.py --dashboard
```

### 2.2 守護進程模式

```bash
# 安裝為系統服務（systemd / launchd 自動適配）
python3 scripts/守護進程管理器.py --install

# 進入守護模式（帶自恢復）
python3 scripts/守護進程管理器.py --daemon

# 定時健康檢查
python3 scripts/健康檢查器.py --daemon --interval 30
```

### 2.3 服務管理

```bash
# 啟動/停止/重啟單個服務
python3 scripts/守護進程管理器.py --start 龍魂操作台
python3 scripts/守護進程管理器.py --stop MCP服務
python3 scripts/守護進程管理器.py --restart Kimi集成

# 停止全部服務
python3 scripts/守護進程管理器.py --stop-all

# 卸載系統服務
python3 scripts/守護進程管理器.py --uninstall
```

### 2.4 日誌管理

```bash
# 執行日誌輪轉
python3 scripts/健康檢查器.py --rotate
```

## 三、參數規格

### 3.1 守護進程管理器

| 參數 | 類型 | 默認值 | 說明 |
|------|------|--------|------|
| `--start` | string | - | 啟動指定服務 |
| `--stop` | string | - | 停止指定服務 |
| `--restart` | string | - | 重啟指定服務 |
| `--start-all` | flag | false | 啟動全部服務 |
| `--stop-all` | flag | false | 停止全部服務 |
| `--status` | flag | false | 查看狀態看板 |
| `--install` | flag | false | 安裝系統服務 |
| `--uninstall` | flag | false | 卸載系統服務 |
| `--daemon` | flag | false | 守護進程模式 |

### 3.2 一鍵啟動器

| 參數 | 類型 | 默認值 | 說明 |
|------|------|--------|------|
| `--daemon` | flag | false | 守護進程模式 |
| `--stop` | flag | false | 停止全部服務 |
| `--status` | flag | false | 查看狀態 |
| `--check` | flag | false | 僅檢查前置條件 |
| `--phase` | string | - | 僅啟動指定階段 |

### 3.3 健康檢查器

| 參數 | 類型 | 默認值 | 說明 |
|------|------|--------|------|
| `--daemon` | flag | false | 定時檢查模式 |
| `--dashboard` | flag | false | 顯示狀態看板 |
| `--rotate` | flag | false | 日誌輪轉 |
| `--check` | string | - | 檢查指定服務 |
| `--interval` | int | 30 | 檢查間隔秒數 |

### 3.4 健康閾值配置

```python
健康閾值 = {
    "心跳間隔秒": 30,        # 健康檢查間隔
    "心跳超時秒": 10,        # 單次檢查超時
    "連續失敗閾值": 3,       # 觸發告警的連續失敗次數
    "重啟冷卻秒": 60,        # 兩次重啟間的最小間隔
    "最大重啟次數": 5,       # 單服務最大重啟次數
    "內存告警MB": 512,       # 內存告警閾值
    "內存致命MB": 1024,      # 內存致命閾值
    "CPU告警百分比": 80,     # CPU告警閾值
    "CPU致命百分比": 95,     # CPU致命閾值
    "磁盤告警百分比": 85,    # 磁盤告警閾值
    "磁盤致命百分比": 95,    # 磁盤致命閾值
}
```

## 六、運行機制

### 6.1 啟動流程

```
[啟動序列開始]
    │
    ▼
[前置條件檢查] ──→ Python版本 / 網絡 / 端口 / 磁盤
    │
    ▼
[第一階段：基礎設施] ──→ 龍魂操作台 (port 8443)
    │
    ▼
[第二階段：中間件] ──→ MCP服務 (port 8443/mcp)
    │
    ▼
[第三階段：集成服務] ──→ Kimi集成 + Notion同步
    │
    ▼
[第四階段：智能引擎] ──→ 自動化評估 + 復盤引擎
    │
    ▼
[生成啟動報告]
```

### 6.2 健康檢查循環

```
[定時觸發] 每 N 秒
    │
    ▼
[檢查進程存活] ──→ os.kill(pid, 0)
    │
    ▼
[檢查端口可達] ──→ socket.connect()
    │
    ▼
[獲取資源使用] ──→ ps rss,pcpu
    │
    ▼
[狀態判定]
    ├── 健康 (綠) ──→ 無告警
    ├── 警告 (黃) ──→ 記錄追蹤
    └── 危險 (紅) ──→ 觸發自恢復
    │
    ▼
[自恢復策略]
    ├── 連續失敗 < 閾值 ──→ 繼續監控
    ├── 重啟次數 < 上限 ──→ 自動重啟
    └── 重啟次數 >= 上限 ──→ 告警並停止嘗試
```

### 6.3 自恢復機制

| 條件 | 動作 |
|------|------|
| 進程不存在但應運行 | 自動重啟 |
| 端口不可達 | 重啟並記錄 |
| 連續失敗 >= 3 次 | 觸發告警 + 重啟 |
| 重啟次數 >= 5 次 | 停止自動恢復 |
| 兩次重啟間隔 < 60秒 | 冷卻等待 |

## 八、注意事項

### 8.1 安全須知

- 守護進程需要適當的權限來管理系統進程
- `--install` 需要 root / sudo 權限（systemd）
- 生產環境建議使用專用用戶運行

### 8.2 已知限制

- Windows 平台僅支持基本進程管理（無 systemd/launchd）
- 定時任務（cron）需要配合系統 cron 或自帶調度器
- 端口 8443 衝突時會嘗試接管，但可能失敗

### 8.3 君子協議

> 未經龍魂體系授權，不得修改核心進程參數、健康閾值和啟動順序。
> 所有操作均通過三色審計日誌留痕，違規操作可追溯。

## 九、故障排除

### 9.1 常見問題

| 問題 | 原因 | 解決方案 |
|------|------|----------|
| 端口 8443 被佔用 | 其他服務佔用 | `lsof -ti :8443` 查找並終止 |
| 服務啟動後立即退出 | 依賴缺失 | 檢查 Python 模塊是否安裝 |
| 自恢復無限重啟 | 配置錯誤 | 檢查服務啟動指令和環境變量 |
| 磁盤空間不足 | 日誌過大 | 執行 `--rotate` 進行日誌輪轉 |

### 9.2 調試方法

```bash
# 查看審計日誌
tail -f logs/daemon_audit_$(date +%Y-%m-%d).log

# 查看錯誤日誌
tail -f logs/launchd.err.log

# 手動檢查單個服務
python3 scripts/健康檢查器.py --check 龍魂操作台

# 僅檢查前置條件
python3 scripts/一鍵啟動器.py --check
```
