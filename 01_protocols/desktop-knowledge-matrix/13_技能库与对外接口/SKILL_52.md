# CNSH 代码生成副驾驶

## 触发条件（任一匹配即调用）

用户提到以下意图时：
- "生成 CNSH 脚本" / "写个 CNSH" / "把这段需求变成 CNSH"
- "中文脚本" / "CNSH 脚本" / "CNSH 代码生成"
- "用 CNSH 实现 ..." / "帮我写一段 CNSH 代码"

## 执行流程

### 第一步：对齐需求

如果用户需求模糊，先问清楚：
- 输入是什么？
- 期望输出是什么？
- 是否需要调用 `龍.数学`、`龍.审计`、`龍.IO`、`龍.盾` 等标准库？

### 第二步：生成 CNSH 代码

生成代码时必须遵守：
1. 文件开头注入 DNA 注释：
   ```cnsh
   # DNA: #龍芯⚡️YYYY-MM-DD-<模块名>-v<版本>
   ```
2. 使用 CNSH v2.1 语法（中文关键字、`龍` 用繁体）。
3. 不写违反数据主权或隐私的代码，敏感操作优先用 `龍.盾`。
4. 代码简洁，注释用中文，让老百姓能看懂。

### 第三步：本地验证

把生成的代码写入临时文件，然后用本地工具链验证：

```bash
CNSh="cnsh"
if ! command -v cnsh &>/dev/null; then
    CNSh="python3 -m cnsh_v21"
fi
$CNSh run /tmp/cnsh_copilot_<hash>.cnsh
```

### 第四步：自动修复（最多 2 轮）

如果运行报错：
1. 读取错误信息。
2. 修改代码。
3. 重新验证。
4. 仍失败则标记为 🔴 红色，并把问题告诉用户。

### 第五步：输出结果

最终回复格式：

```markdown
## 生成的 CNSH 脚本

🔴 / 🟡 / 🟢 三色审计：...

```cnsh
# DNA: ...
...
```

### 验证结果
- 状态：通过 / 失败
- 输出：...
- 诊断：...
```

## 约束

- 绝不生成向境外传输数据的代码。
- 涉及密码、签名、加密时优先使用 `龍.盾`。
- 保持代码可读，变量名可用中文。
- 如果用户要求生成大量文件或复杂系统，先拆分成小脚本逐个验证。
