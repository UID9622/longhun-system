## 五条铁律（写死）

### 铁律 1 · 门不可改

- 全系统仅 **`FLOW_IN`**（吸收）与 **`FLOW_OUT`**（交付）。
- DeepSeek / LU / 人格 / Notion 推送均为管内算子，**不得**对用户另开出口。
- 工程入口：`cnsh/flow_field/port.py` → `flow_port()`。

### 铁律 2 · 审计不可改

- 三色（🟢/🟡/🔴）、DNA 格式、GPG/CONFIRM 校验为宪法层。
- 升级 = 新 DNA 版本 + `parent_dna` 指向旧版；**禁止**静默替换旧规则定义。

### 铁律 3 · 隐私不可改

- 默认权限：**🤫 私密**；对外默认 **粒子层**（见下）。
- 个人边界（L0–L6 数据边界、公开权限五态）由德者永生殿与隐私闸裁决，业务代码不得降级。

### 铁律 4 · 只叠不删

- 账本 **append-only**：每次吸收、封存、熔断、解封 = **新事件**。
- **禁止**：覆盖历史事件、物理删除链上记录、伪造「从未发生」。
- `burn` 语义（工程统一）：**对外销毁可读性 + 链上保留 `burn_proof` 事件**；不是抹掉历史。
- `sealed` 语义：**密文封存 + `seal_proof` + 外显仅粒子**；解封须授权且再叠一条 `unseal_observed` 事件。

### 铁律 5 · 可溯源 · 可恢复

- **辨真假**：DNA + SHA256 + 父链 + GPG/CONFIRM + 三色；伪造需整条链，成本高。
- **恢复原文**：仅合法场景（本人、书面授权、T0/T1 规定的双签/审计）→ 解封一次 → **必须留痕**（谁、何时、为何）。
- 恢复本身不可无痕；**监督的是权力，不是窥探路人**。
