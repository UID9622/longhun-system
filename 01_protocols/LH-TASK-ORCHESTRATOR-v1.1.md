## 🧬 二、龍魂任务编排引擎 · 核心设计

### 2.1 核心概念

```yaml
任务编排引擎:
  定义: 将用户需求自动拆解为可执行任务链，追踪每一步的执行状态
  特点:
    - 自动拆解: AI自动分析需求，生成任务步骤
    - 可视化: Web面板展示所有任务状态
    - 可追溯: 每个任务带DNA，可回溯执行过程
    - 可干预: 用户可暂停、继续、终止任务
    - 无黑箱: 执行日志完全透明
```

### 2.2 数据模型

| 表 | 用途 |
|---|---|
| `tasks` | 任务主表（ID/标题/状态/优先级/DNA/耗时...） |
| `task_steps` | 步骤表（步骤ID/命令/输出/耗时...） |
| `execution_logs` | 执行日志表（审计级日志/JSON数据...） |

### 2.3 核心公式

```
受益权 = Σ(行为贡献值 × 时间衰减因子 × 社区验证权重)
数学根 dr = digital_root(int(SHA-256(task_id), 16))
审计判定 = dr∈{3,9}→🔴 | 高危命令→🔴 | priority≥9无复核→🟡 | 其余→🟢
```

## 🚀 三、使用演示

```bash
# 创建任务

# 执行任务（自动过三色审计闸门）
```

## 🚦 四、任务状态机

```
pending ──execute(🟢审计通过)──▶ running ──全部步骤完成──▶ completed(终态)
   │                               │  ▲
   │ cancel                        │  │ resume(唤醒原线程)
   ▼                               ▼  │
cancelled(终态)   ◀──cancel──   paused    failed ──retry──▶ pending
```

**合法转换表**：6 状态 / 9 条合法迁移 / 2 终态(completed/cancelled) / 非法转换拒绝并留痕
