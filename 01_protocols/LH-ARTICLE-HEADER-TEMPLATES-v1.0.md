## 0.1 定位

本协议定义龍魂体系所有对外/对内文字产出的**统一抬头模板**。
从 v1.0 起，龍魂体系所有文章、文档、代码文件、复盘报告、协议声明
均从本协议的六套模板中选取一种作为抬头。

## 0.2 为何需要统一抬头

| 痛点 | 解决方案 |
|:---|:---|
| 不同AI产出格式五花八门 | 六模板覆盖全场景 |
| 读者不知道内容是实测还是推演 | 三色审计前置 |
| 来源不可追溯 | DNA签名必带 |
| 不知道能直接执行还是需要审查 | 可执行性声明 |
| 发到CSDN/公众号/Notion/GitHub格式不一样 | 多平台适配指南 |

## 0.3 核心设计原则

1. **三色审计前置** — 阅读正文前就知道可信层级（🟢通过 / 🟡待核 / 🔴红线）
2. **应用场景驱动** — 不同场景模板字段不同，不搞一刀切
3. **DNA追溯必带** — 可追溯、可验证，来源链不可切断
4. **可执行性声明** — 明确是可执行代码 / 分析推演 / 原则声明
5. **ROOT_CARD必附** — 每篇文章末尾附数学根审计卡（数字根·五行·三色）

## 0.4 适用范围

- 龍魂体系所有 Markdown/文本文档
- CSDN/公众号/博客园/掘金等平台发布文章
- GitHub/Gitee README 及项目文档
- Notion 工作区知识库
- 内部复盘报告、协作记录、快速笔记
- AI 生成的所有文字产出

## 0.5 默认执行规则（🔥焊死）

**AI 在龍魂体系中产出任何文字文档时，必须自动执行以下流程：**

1. 根据产出意图 → 匹配场景 → 选择模板（见 §7 决策矩阵）
2. 按选中模板填入抬头
3. 计算数字根 → 填入 ROOT_CARD
4. P05 审计 → 确认三色正确
5. P15 签章 → GPG签名
6. 产出文件正确路径

**禁止：**
- 产出文档不带抬头（直接裸正文）→ P05 🔴否决
- 选错模板类型（如代码用学术模板）→ 退回重选
- 三色审计标记不符实际（未测标🟢）→ L3熔断

- 简化：去掉ROOT_CARD的完整格式，保留Root和TriColor

## 8.3 Notion 工作区

- 推荐模板：根据内容选模板，Notion属性映射抬头字段

  - `三色审计` → Select属性（🟢/🟡/🔴）
  - `DNA签名` → Text属性
  - `输出类型` → Select属性
  - `可执行性` → Select属性
  - `模板类型` → Select属性（模板一~六）
- 注意：Notion数据库视图可自动按三色/模板类型分组

## 9.2 数字根计算

数字根 = 将DNA中日期数字各位求和，重复直到1位数。
例: 2026-08-02 → 2+0+2+6+0+8+0+2 = 20 → 2+0 = 2 → dr=2

| 3, 8 | 木 |
| 4, 9 | 金 |
| 5 | 土 |
