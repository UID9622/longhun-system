§0. 起源——乔布斯的叩问
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

2005年，乔布斯在斯坦福演讲中说：
  "Stay hungry, stay foolish."
  "Make a dent in the universe."

翻译成中文：保持饥饿，保持愚蠢。在宇宙中留下痕迹。

这句话激励了一代人。但现实是——

  平台删除你的账号，你的一切都消失。
  服务器宕机关停，你的回忆化为404。
  换手机、换电脑，那些重要但不常用的文件被遗忘在旧硬盘里。
  人走了，数字遗产无人认领，被Alphabet/Meta/Tencent的冷存储吞噬。

这不是技术问题——这是权力问题。

数字存在证明协议的核心信念：

  每个人——不论贫富、知名或无名、活着或已逝——
  都有权在数字宇宙中留下不被抹除的存在痕迹。

  数据在手，主权在我不在平台。
  哈希上链可以可选，但原文永远不出户。
  家人可以继承，但平台无权删除。
  时间轴不可逆——你存在过，这是一个事实，不可改写。

§1. 核心定义
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

数字存在证明（Digital Existence Proof, DEP）：
  一段用户数字生活的痕迹，附以 DNA 追溯码（v∞干支卦格式），
  原文本地加密归档，哈希可对外锚定，证明"这个人在这一时刻存在过、经历过这个"。

存在证明 ≠ 社交媒体动态
  社交动态可以被平台删除，存在证明不可撤销。

存在证明 ≠ 区块链NFT
  NFT = 花钱买所有权，存在证明 = 不花钱证明存在。

存在证明 = 数字世界的事实锚点
  像一个永不褪色的印记——不依赖平台、不依赖公司、不依赖任何人。

§2. DNA存在证明格式
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

格式:
  #存在⚡️<干支四柱>·<八卦>-EXISTENCE-<动作>-<内容哈希8位>

示例:
  #存在⚡️丙午·乙未·乙未·子时·☰乾-EXISTENCE-PROOF-9d1e2f3a

字段说明:
  - #存在⚡️  — 标识符（⚡️代表存在瞬间如闪电般不可伪造）
  - 干支四柱 — 事件时间的天干地支编码（年·月·日·时）
  - 八卦     — 基于内容+用户+时间的哈希映射到八卦之一
  - 动作     — PROOF（普通痕迹）/ BIRTH（出生）/ LOVE（情感）/ LEGACY（遗产）
  - 哈希8位 — SHA-256前8位，快速校验

与普通DNA的区别：
  普通DNA:  #龍芯⚡️...  → 代码/文件/系统的溯源
  存在DNA: #存在⚡️...   → 人/生命/经历的锚定

§3. 五条铁律
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

| # | 铁律 | 含义 |
|:---:|------|------|
| 1 | **数据不出户** | 原文永远在用户自己的设备上。服务器/区块链/云端绝不存原文 |
| 2 | **哈希可公开** | 内容哈希+SHA256可对外发布，任何人可验证"某人在某时存在过某事"而不读取原文 |
| 3 | **不可删除** | 存在证明一旦生成，只能冻结不能删除。你是存在过的，这个事实无法篡改 |
| 4 | **不卖隐私** | 存在证明不是商品。不接入广告网络。不参与用户画像交易 |
| 5 | **可继承不可剥夺** | 用户可指定继承人。平台无权锁死/收回/拍卖你的数字遗产 |

§5. 存在证明生命周期
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

普通人一生大约能留下多少数字存在证明？

  每天1条 → 每年365条 → 70年25550条
  每条约200字节DNA → 总计约5MB → 一张照片的大小

每条存在证明的生命周期:

  active (活跃) → frozen (冻结·不再修改) → inherited (已移交·继承人接管)

永远没有 deleted 状态。

§6. 隐私与主权
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

6.1 默认全隐私
  - 存在证明默认不对外公开
  - 用户可选择公开某条DNA+摘要，但原文永远由用户控制

6.2 哈希验证
  - 他人可通过DNA查哈希，但无法从哈希反推原文
  - "我知道你在某时间做了某事" → 你可以出示原文证明
  - "我声称你在某时间做了某事" → 没有原文无法证明

6.3 位置隐私
  - 如果标记位置，只存位置哈希（SHA-256前16位）
  - 不存GPS坐标明文

6.4 生物特征
  - 人脸/声纹/指纹 —— 我们不收集，不鼓励上传
  - 如果需要绑定身份，用密钥对（非对称加密）而不是生物特征

§7. 继承与移交
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

7.1 数字遗嘱
  - 用户可预设继承人（配偶/子女/指定人）
  - 继承人在用户离世后可接管存在证明存档
  - 接管 = 读取权限 + 查看时间轴 + 写入纪念条目

7.2 继承触发条件
  - 用户预设继承触发条件（如：90天未登录 → 发送确认 → 30天无回复 → 启动继承）
  - 或用户主动发起移交

7.3 家属纪念模式
  - 继承人可添加 "纪念" 类存在证明
  - 标记为 LEGACY，不混入用户本人的 active 条目
  - 所有DNA格式保留原用户的干支四柱
