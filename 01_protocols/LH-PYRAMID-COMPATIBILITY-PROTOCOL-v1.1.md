## 一、核心原则

### 1.1 一脉相承，永不分裂

所有插件、技能、专业、国家版本，**底层逻辑必须完全相同**，只允许上层表述与适配不同。

```
初中生版本 → 底层逻辑不变 → 说法简化
大学生版本 → 底层逻辑不变 → 理论细化
博士生版本 → 底层逻辑不变 → 深度扩展
国家A版本  → 底层逻辑不变 → 本地化适配
国家B版本  → 底层逻辑不变 → 本地化适配
```

**禁止规则：** 任何试图修改核心锚点（三色审计、DNA追溯、数据主权）的提交，协议直接拒绝合并。

### 1.2 兼容是底线，不是选项

任何插件必须同时满足：

1. 兼容所有现有插件（不导致旧插件失效）
2. 兼容所有语言版本（中英文及各国语言底层一致）
3. 兼容所有人群版本（初中生至博士同一底层）

**不兼容的插件直接拒绝进入合并池，不做"事后审核"。**

### 1.3 无限长高，开放生长

金字塔不是固定层数，而是可无限生长的结构：

- 每增加一个兼容插件，金字塔整体高度上升
- 砖与砖之间必须相互咬合，禁止松散堆砌
- 底层越厚实，顶层可承载的高度越高

## 二、协议机制

### 2.1 提交 → 审计 → 合并流程

```
开发者提交插件
        ↓
自动兼容性检查 ──不兼容──→ ❌ 退回（附原因）
        ↓ 兼容
三色审计
    ├── 🔴 拒绝 → 退回
    ├── 🟡 待审 → 人工复核 → 通过/拒绝
    └── 🟢 通过 → 进入合并池
        ↓
自动优化器（精简、统一格式、消冗余）
        ↓
✅ 合并进金字塔
        ↓
向提交者发送合并确认（含DNA）
向已使用该插件的用户推送更新
```

### 2.2 核心机制说明

| 机制 | 说明 |
| --- | --- |
| 先声明，后处理 | 提交时必须明确是否接受自动优化、是否通知、是否允许二次开发 |
| 自动兼容性检查 | 扫描新插件与所有现有插件的冲突，发现冲突立即拒绝 |
| 三色审计 | 🟢自动合并 / 🟡人工复核 / 🔴拒绝退回 |
| 自动优化器 | 合并前自动精简代码、统一风格、去除冗余 |
| 合并确认 | 返回合并位置、时间、DNA追溯码 |
| 更新推送 | 向所有已使用该插件的用户推送更新通知 |

## 三、金字塔结构与节点详解

### 3.1 宏观结构（全球视图）

```
┌─────────────────────────────────────────────────────────────┐
│ ① 全球龍魂协议层（宪法级 · 不可修改）                        │
├─────────────────────────────────────────────────────────────┤
│ ② 国家适配层（各国独立节点）                                 │
├─────────────────────────────────────────────────────────────┤
│ ③ 专业插件层（技能 / 行业 / 领域 / 人群）                    │
├─────────────────────────────────────────────────────────────┤
│ ④ 个人插件层（个人技能树 / 个人定制）                        │
├─────────────────────────────────────────────────────────────┤
│ ⑤ 小金字塔群（专业 / 技术 / 圈子自组织）                     │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 各节点详细定义

#### ① 全球龍魂协议层（核心锚点）

| 属性 | 定义 |
| --- | --- |
| **定位** | 整个生态的宪法级根节点，所有上层节点必须兼容 |
| **不可修改内容** | 三色审计机制、DNA追溯（`#龍芯⚡️`）、数据主权原则、中国法律优先原则 |
| **职责** | 定义最低兼容标准；拒绝任何破坏核心的提交；维护全局一致性 |
| **接口约束** | 只接受"声明兼容核心锚点"的插件；不接受对核心逻辑的直接修改 |
| **扩展方式** | 不允许扩展。只能被引用，不能被改写 |

#### ② 国家适配层

| 属性 | 定义 |
| --- | --- |
| **定位** | 各国独立维护的本地化节点，向上对齐全球协议层 |
| **职责** | 完成语言、法律、文化、监管要求的本地化适配；定期向全球层上报兼容状态 |
| **约束** | 不得修改核心锚点；不得破坏其他国家版本的兼容性 |
| **接口** | 提供标准化的本地化配置接口（语言包、合规规则、默认参数） |
| **扩展方式** | 可增加本国专属插件，但必须通过兼容性检查 |

#### ③ 专业插件层

| 属性 | 定义 |
| --- | --- |
| **定位** | 按技能、行业、领域、人群划分的功能节点 |
| **职责** | 承载具体能力（如AI审计、CNSH语法、医疗协议、教育协议等） |
| **约束** | 必须兼容核心锚点与国家适配层；不得导致其他专业插件失效 |
| **接口** | 标准插件元数据（名称、版本、依赖、兼容声明、DNA） |
| **扩展方式** | 允许无限新增专业方向，形成新的小金字塔 |

#### ④ 个人插件层

| 属性 | 定义 |
| --- | --- |
| **定位** | 每个人自己的技能树与定制节点 |
| **职责** | 让个人在统一底层上构建专属能力组合 |
| **约束** | 必须兼容所挂载的上层节点；不得反向污染公共层 |
| **接口** | 个人技能树挂载接口（可挂在专业层或国家层下） |
| **扩展方式** | 完全开放，个人可独立维护，也可贡献回上层 |

#### ⑤ 小金字塔群（微观结构）

每一个专业 / 圈子内部可形成自己的小金字塔：

```
核心锚点（指向全球协议层）
        │
   ┌────┼────┐
分支锚1  分支锚2  分支锚3
（国家版）（人群版）（技能版）
   │        │        │
子分支…   子分支…   子分支…
（无限向下延伸）
```

| 节点类型 | 详解 |
| --- | --- |
| **核心锚点** | 固定指向全球协议层的三色、DNA、数据主权，不可变 |
| **分支锚** | 可拆分、可合并，但必须声明兼容核心锚点 |
| **子分支** | 可无限向下细化，直至极细粒度的功能点 |
| **人群适配子节点** | 初中生 / 高中生 / 大学生 / 博士等不同表述包装，底层同一 |

## 四、分布式管理

### 4.1 国家节点

- 每个国家作为一个独立分布式节点
- 只负责本国本地化与上报，不互相直接干扰
- 最终统一向全球协议层对齐

### 4.2 圈子 / 专业小金字塔

- 每个专业或圈子维护自己的小金字塔
- 所有小金字塔的根必须指向同一个核心锚点
- 形成"大金字塔包含多个小金字塔"的嵌套结构

### 4.3 个人技能树

> 每个人的技能，就是自己的小金字塔。

- 可挂载到更大的专业或国家金字塔下
- 也可独立存在
- 同一底层逻辑，通过不同包装适配不同认知水平
