## 一、协议概述

### 1.1 目标与哲学

**核心哲学：**「上下文在，认知在；上下文乱，系统瘫。」

本协议定义龍魂体系管理对话上下文的全生命周期流程。从用户通过**龍魂万年历**发起对话开始，到对话结束、上下文归档为止，每一个状态的变迁、每一次压缩操作、每一次与知识图谱的联动，都必须经过本协议的标准化处理。

**存在理由：**
- 未经管理的上下文是认知混乱的第一根源
- 自动切换话题会导致记忆丢失、决策失误
- 没有压缩的上下文会线性增长，最终耗尽资源
- 没有知识图谱联动的对话是孤立的，无法利用体系智慧

## 四、窗口状态机（四态模型）

### 4.1 状态定义

```
┌─────────────────────────────────────────────────────────────────────┐
│                                                                     │
│    ┌──────────┐                                                     │
│    │  ACTIVE  │ ← 上下文全加载，对话进行中                          │
│    │  (活跃)  │   · 完整上下文在内存                                │
│    └────┬─────┘   · 知识图谱关联节点已加载                        │
│         │         · 52技能按需触发                                  │
│    ┌────┴─────┐                                                     │
│    │ STANDBY  │ ← 上下文未回收，标记时间，等待用户                  │
│    │ (待机)   │   · 上下文保留在内存，但标记为 standby               │
│    └────┬─────┘   · 30秒计时器启动（仅用于提醒，不自动切换）       │
│         │         · 知识图谱节点降温开始                            │
│    ┌────┴─────┐                                                     │
│    │ SWITCHED │ ← 旧上下文归档，新上下文加载中                      │
│    │ (已切换) │   · 旧上下文经过L1/L2压缩后归档                     │
│    └────┬─────┘   · 新上下文初始化，加载默认知识图谱节点            │
│         │         · 52技能重新评估触发条件                          │
│    ┌────┴─────┐                                                     │
│    │  CLOSED  │ ← 完整归档，DNA记录，对话结束                       │
│    │ (已关闭) │   · 上下文经过L3压缩后长期归档                      │
│    └──────────┘   · 生成完整DNA证据链                               │
│                   · 通知万年历更新状态                              │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 4.2 状态转换规则

| 当前状态 | 触发条件 | 下一状态 | 操作 | 需用户确认？ |
|---------|---------|---------|------|------------|
| ACTIVE | 用户离开/30秒无操作 | STANDBY | 标记时间，启动降温计时器 | 否（自动） |
| STANDBY | 用户返回/继续对话 | ACTIVE | 恢复活跃状态，停止降温 | 否 |
| STANDBY | **用户明确切换话题** | SWITCHED | 执行L1压缩→归档旧上下文，加载新上下文 | **是（必须）** |
| STANDBY | 用户明确结束对话 | CLOSED | 执行L2/L3压缩→完整归档 | 是（建议） |
| SWITCHED | 新上下文加载完成 | ACTIVE | 新上下文进入活跃状态 | 否 |
| SWITCHED | 用户请求返回旧话题 | ACTIVE | **从归档恢复旧上下文** | 否 |
| ACTIVE | 用户明确结束对话 | CLOSED | 执行L2/L3压缩→完整归档 | 是（建议） |
| CLOSED | （终端状态，无出口） | — | DNA记录已完成 | — |

**关键原则：**
- **STANDBY → SWITCHED 必须用户确认**：原始方案的30秒空闲自动切换已被废除。系统检测到切换意图后，必须向用户确认：「检测到话题切换意图（从「旧话题」到「新话题」），是否确认切换？已完成的讨论将归档，可随时恢复。」
- **用户明确指令优先**：用户说出「换话题」「下一个」「聊别的」等明确指令时，无需再次确认，直接执行切换
- **STANDBY 状态超时不自动关闭**：原始方案的超时关闭机制已被废除，必须用户明确结束

### 4.3 状态转换详细流程

#### 4.3.1 ACTIVE → STANDBY

```
触发：用户30秒无输入

操作序列：
1. [DNA记录] 生成状态转换记录，精确到毫秒
2. [降温启动] 知识图谱关联节点开始降温（活跃度×0.9/秒）
3. [计时器启动] 启动待机计时器（仅用于统计，不触发自动操作）
4. [通知万年历] 更新万年历状态显示为「待机」
5. [审计标记] 🟢 绿色通过
```

#### 4.3.2 STANDBY → SWITCHED（核心流程）

```
触发：用户确认切换话题 或 用户明确切换指令

操作序列：
1. [意图确认] 用户明确说出「换话题」等指令 → 跳过确认
             系统检测到语义切换 → 向用户确认，等待回应

2. [L1压缩] 对旧上下文执行L1摘要压缩：
   · 生成话题摘要（≤200字）
   · 提取关键结论（bullet points）
   · 记录未完成项（待办列表）
   · 保留时间戳和DNA签名

3. [归档写入] 将L1压缩结果写入 ~/.龍魂/workspace/archive/
   文件名格式：ctx_{话题ID}_{YYYYMMDD}_{HHMMSS}_{压缩级别}.json

4. [知识图谱降温] 旧话题关联节点降温至基线水平

5. [新上下文加载] 初始化新上下文：
   · 加载默认知识图谱节点（根节点 + 当前人格关联节点）
   · 根据新话题关键词匹配图谱节点
   · 沿关系加载关联节点（最多2层）
   · 52技能重新评估触发条件

6. [DNA记录] 生成完整的状态转换DNA链
7. [通知万年历] 更新万年历显示新话题、新状态
8. [审计标记] 🟢 绿色通过（如果用户确认）/ 🟡 黄色（如果自动推断）
```

#### 4.3.3 SWITCHED → ACTIVE（恢复流程）

```
触发：用户请求返回旧话题

操作序列：
1. [查询归档] 从 ~/.龍魂/workspace/archive/ 查询旧话题归档
2. [L1解压] 恢复L1压缩的摘要 + 关键结论 + 未完成项
3. [上下文重建] 重建旧上下文的核心认知框架
4. [知识图谱升温] 重新加载旧话题关联节点，恢复活跃度
5. [DNA记录] 记录恢复操作
6. [通知万年历] 更新状态为「活跃（已恢复）」
7. [审计标记] 🟢 绿色通过
```

#### 4.3.4 任意状态 → CLOSED

```
触发：用户明确结束对话

操作序列：
1. [L2压缩] 提取核心实体 + 关系图谱节点链接
2. [L3压缩] 固化关键决策 + 用户偏好 + 技能触发记录
3. [完整归档] 写入 ~/.龍魂/workspace/archive/closed/
   文件名格式：session_{会话ID}_{YYYYMMDD}_{HHMMSS}_closed.json
4. [DNA证据链生成] 生成完整的会话级DNA证据链
5. [Notion同步] 异步同步到Notion（如果配置）
6. [知识图谱更新] 将新实体和关系写入知识图谱（待审核）
7. [通知万年历] 更新状态为「已关闭」，释放资源
8. [审计标记] 🟢 绿色通过
```

### 6.2 联动规则

#### 规则1：话题关键词匹配

```
输入：当前上下文中的关键词列表（从语义锚点提取）
处理：
  1. 对每个关键词，在知识图谱节点名称和描述中搜索
  2. 匹配算法：包含匹配 + 编辑距离 ≤ 2
  3. 返回匹配的节点列表，按相关度排序
输出：匹配节点列表（node_id, match_score）
```

#### 规则2：关联节点加载（最多2层）

```
输入：直接匹配的节点列表
处理：
  1. 对每个匹配节点，沿边加载1层关联节点
     · 关系类型优先级：DEPENDS_ON > TRIGGERS > ENABLES > CONTAINS > 其他
  2. 对1层关联节点，继续加载2层关联节点（仅高权重边）
  3. 限制：最多加载20个关联节点，避免过载
输出：扩展节点列表（node_id, layer_distance, relation_path）
```

#### 规则3：节点活跃度管理

```
活跃度计算公式：
  active_score = base_score × temperature × recency_factor

  base_score: 节点固有权重（0-100，来自知识图谱）
  temperature: 温度系数（1.0 = 活跃，0.1 = 冷冻）
  recency_factor: 时间衰减因子（e^(-λ×Δt)，λ=0.001）

温度管理：
  · 当前话题关联节点 → temperature = 1.0（升温）
  · 旧话题关联节点 → temperature 按 0.9/秒 衰减（降温）
  · temperature < 0.1 的节点 → 从活跃上下文移除
```

#### 规则4：不相关节点自动降温

```
触发：话题切换 或 30秒无操作
处理：
  1. 识别当前上下文不再关联的节点
  2. 这些节点的 temperature 按 0.9/秒 衰减
  3. 当 temperature < 0.1 时，标记为「休眠」
  4. 休眠节点不加载到活跃上下文，但保留在知识图谱中
输出：休眠节点列表
```

### 7.2 阶段一：感知层 — 上下文监测与变化检测

**目标：** 实时监测对话上下文的变化，检测切换意图。

#### 7.2.1 语义相似度计算（替代原始关键词检测）

```python
# 语义相似度计算伪代码
def calculate_similarity(current_topic, new_input):
    """
    计算新输入与当前话题的语义相似度
    返回：0-100的相似度分数
    """
    # 1. 提取语义锚点（复用输入过滤协议的输出）
    current_anchors = extract_anchors(current_topic)
    new_anchors = extract_anchors(new_input)

    # 2. 计算Jaccard相似度（关键词集合重叠度）
    jaccard = jaccard_similarity(current_anchors, new_anchors)

    # 3. 计算话题模型相似度（主题分布匹配）
    topic_sim = topic_model_similarity(current_topic, new_input)

    # 4. 综合分数
    similarity = jaccard * 0.4 + topic_sim * 0.6
    return similarity
```

**阈值定义：**

| 相似度区间 | 判定 | 操作 |
|-----------|------|------|
| ≥ 70 | 同话题延续 | 继续当前上下文 |
| 40 - 69 | 话题漂移 | 🟡 黄色标记，提示用户确认 |
| < 40 | 话题切换 | 🟡 黄色标记，请求用户确认切换 |

#### 7.2.2 用户明确指令检测

```
无需确认直接执行的指令（白名单）：
  · "换话题" / "换一个话题" / "聊别的"
  · "下一个" / "下一个话题"
  · "结束" / "结束对话" / "拜拜" / "再见"
  · "回到{话题名}" / "恢复{话题名}"

检测优先级：明确指令 > 语义相似度计算
```

#### 7.2.3 上下文健康监测

```
监测指标：
  · 上下文大小（token数）→ 超过阈值时🟡提示压缩
  · 知识图谱加载节点数 → 超过20个时🟡提示降温
  · 对话轮数 → 超过50轮时🟡建议归档

阈值：
  · 上下文大小警告：4000 tokens
  · 上下文大小阻断：8000 tokens（必须压缩）
  · 知识图谱节点上限：20个活跃节点
  · 对话轮数建议归档：50轮
```

### 7.3 阶段二：认知层 — 压缩执行与知识图谱联动

**目标：** 执行压缩策略，管理知识图谱联动。

#### 7.3.1 压缩执行流程

```
输入：压缩级别（L1/L2/L3）+ 目标上下文
处理：
  1. 根据压缩级别选择压缩模板
  2. 提取保留字段，丢弃非保留字段
  3. 生成压缩摘要（L1使用摘要算法，L2/L3使用实体提取）
  4. 计算压缩比
  5. 附加DNA签名和时间戳
输出：压缩后的上下文数据 + 压缩报告
```

#### 7.3.2 知识图谱联动执行

```
输入：当前上下文 + 新用户输入
处理：
  1. 从输入中提取关键词
  2. 调用 kg_match(keywords) 匹配图谱节点
  3. 调用 kg_expand() 加载关联节点（最多2层）
  4. 更新节点活跃度（升温新节点，降温旧节点）
  5. 将关联节点信息注入上下文
输出：更新后的上下文 + 关联节点列表
```

### 7.4 阶段三：决策层 — 状态转换确认与执行

**目标：** 确保状态转换经过用户确认，所有操作可追溯。

  3. 用户明确结束对话
     → 提示：「确认结束对话？讨论内容将完整归档。」
     → 选项：[确认结束] [继续对话]

无需确认的场景：
  1. 用户说出明确切换指令（白名单）
