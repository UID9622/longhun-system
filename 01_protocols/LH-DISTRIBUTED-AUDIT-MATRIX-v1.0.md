## 一、设计理念（太极原理·369不动点）

> **不是60项全过，是该触发的才触发。**
> **不是一刀切，是因人而异。**
> **人是最大变量，审计随人变。**
> **369不动点，权重分层，分布式管理。**

### 369不动点原理

```
        3（天）
       /  \
      6    9
     /      \
    人（变量）

3 = 天层（战略/决策）→ 审计：价值观、方向、DNA
6 = 人层（用户/身份）→ 审计：身份、权限、偏好
9 = 地层（执行/落地）→ 审计：代码、功能、性能

不动点 = 无论怎么变，核心锚点不变
         → P0协议、DNA追溯、为人民服务（永远不变）
```

## 二、审计触发公式（焊死）

```
人 = 身份 + 场景 + 权重 + 偏好 + 认证 + 历史
审计项 = f(人, 文件类型, 文件结构, 文件权限)
```

| 维度 | 变量 | 触发哪些审计 |
|:---|:---|:---|
| **身份** | 老百姓/专业人士/学生/老人/技术人员 | 人群对齐项不同 |
| **认证** | 已认证/未认证/专家认证 | 专业人士过认证审计，普通人不过 |
| **场景** | 开店/维权/医疗/合同/日常 | 场景专项审计不同 |
| **权重** | P0/P1/P2/P3/P4 | P0全审，P4简审 |
| **偏好** | 语音/文字/极简/详细 | 交互审计项不同 |
| **历史** | 新手(<5次)/熟手(5-50次)/专家(>50次) | 引导审计项不同 |

## 七、联动触发机制

```
当一个节点被审计时：
    ↓
[1] 判断节点类型 → 触发对应审计协议
    ↓
[2] 判断用户身份 → 调整审计严格度
    ↓
[3] 判断专业度 → 调整审计深度
    ↓
[4] 判断个人偏好 → 调整输出格式
    ↓
[5] 检查联动节点 → 是否需要联动审计？
    ↓
    ├── 是 → 触发关联节点审计（递归）
    └── 否 → 输出审计报告
    ↓
[6] 汇总结果 → 生成综合审计报告
    ↓
[7] 记录DNA → 归档到审计日志
```

### 联动示例

```
节点：数字人民币接口
    → 属于"支付金融" → 触发金融审计协议
    → 联动检查：
      ├── 安全防护体系 → 触发安全审计协议
      ├── P0协议 → 触发协议审计协议
      └── 数据同步 → 触发同步审计协议
    → 汇总生成综合审计报告
```
