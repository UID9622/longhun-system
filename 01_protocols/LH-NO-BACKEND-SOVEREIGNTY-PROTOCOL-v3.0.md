## 零、协议定位

本协议是龍魂系统无后台架构的最高治理文件。

**它解决一个根本矛盾**：既要全部开源接受全球审查，又要保护核心不可被滥用。

表面是矛盾的——之前焊死的是"保护核心"，现在要求"全部公开"。
但这两者不是冲突，而是一套组合拳，是龍魂体系最精妙的一刀。

**本协议定义了"焊死-公开"双层架构**，使开源与保护不再对立，而是互为因果。

## 一、焊死-公开双层架构总则

```
┌─────────────────────────────────────────────────────┐

```

### 1.1 公开层——这把剑，给你用

- 所有引擎、算法、架构代码，**全量开源**，接受全球审查。
- 任何人可以阅读、学习、审计、修改、部署。
- 开发者可以替换公开层的任何部分。
- 公开层代码通过标准接口调用焊死层能力。

## 二、为什么兼容——四层拆解

### 第一，保护的不是"代码"，而是"魂"

之前焊死协议保护的，不是核心代码的算法细节。
保护的是**设计哲学、宪法精神、数据主权规则**。

这些东西，代码全公开别人也抄不走。
魂不在代码里，魂焊死在每一条协议、每一次骂人、每一篇檄文里。
代码可以复制，但一个退伍老兵为人民服务的初心，复制不了。

### 第二，公开的是"锁"，保密的是"钥匙"

把核心引擎代码全公开，等于告诉全世界：
这就是我的锁——结构、原理、漏洞，全给你们看。

但钥匙是什么？钥匙是用户自己手里的设备指纹、生物特征、本地加密密钥。
服务器上从来不存，碰都碰不到。

所以公开的是"怎么造的锁"，但永远不碰"谁来开的门"。
这就是之前焊死的保护逻辑——**壳可以公开，核必须自持**。

### 第三，公开本身就是最狠的"保护"

核心代码全公开，最怕的不是用户。用户不懂代码，他们只看初心。
最怕的是竞争对手——他们一看，发现这套东西从底层设计上就杜绝了收割的可能。
想抄，就得把自己的整个商业模型推翻。

这等于拿着自己的源代码，给全世界上一场公开课：
**这才叫站着挣钱。**

保护的不是技术壁垒，而是道德壁垒。

### 第四，兼容的落点——双层架构

两套协议（焊死保护 + 全量公开）的兼容，落在"公开层-焊死层"双层架构上：
- 公开层确保透明、可审计、可复现——这是开源的力量
- 焊死层确保核心不可被篡改、不可被滥用——这是主权的基础

两层不是对立，是互为因果。越透明，越安全。越开源，越不能被收购。

### 第五，最深的防线——所有权不可让渡

以上四层解释的是"技术层面"的兼容。但还有一层更根本的：

**龍魂系统不属于资本市场，不属于任何公司，不属于任何外部势力。**

## 四、数据自持三原则

### 原则一：数据不出设备

- 用户行为数据、生物特征、设备指纹一律本地处理
- 上云数据视为"已失主权"

### 原则二：加密由用户自持

- 密钥在用户设备上生成，服务器不碰私钥
- 加密算法（公开层）任何人可审计
- 派生算法（焊死层）不可见

### 原则三：注销 = 真删除

- 用户可以随时导出全部数据
- 用户可以随时彻底删除
- 删除后不留任何衍生数据
