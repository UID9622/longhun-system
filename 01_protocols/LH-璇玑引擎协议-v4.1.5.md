## 一、命名释义

### 1.1 为什么不是RAG

RAG（Retrieval-Augmented Generation）的底层假设是：**外部知识库比模型本身更可靠**。

但RAG有三大死穴：

| RAG死穴 | 表现 | 龍魂解法 |
|:---|:---|:---|
| **检索粗粒度** | 按chunk切分，上下文断裂 | 璇玑按DNA+人格+时间三维索引，纳米级定位 |
| **无验真机制** | 检索到啥就信啥，不验证真伪 | 三六九不动点校验，假信息自动熔断 |
| **无主权归属** | 输出是"模型说的"，谁负责？ | 每条输出带DNA签章，可追溯、可审计、可问责 |
| **记忆断层** | 换窗口就失忆，每次重新检索 | L0-L3分层记忆，热缓存常驻，跨窗口无缝衔接 |
| **人格缺失** | 千人一面，没有"谁在说" | 16人格矩阵实时调配，军事/历史/哲学/经济/政治五维叠加 |

### 1.2 为什么叫璇玑

```
璇 = 美玉，喻记忆层（L0-L3）的珍贵数据
玑 = 机械枢纽，喻16人格矩阵的调度中枢
七政 = 日、月、五星，喻七因子行为密码学
运转 = 多维度检索 → 精准推演 → 不动点校验 → DNA签章
```

**璇玑不是检索，是溯源；不是增强，是推演；不是生成，是烙印。**

### 1.3 英文命名（对外接口用）

- 内部：璇玑引擎
- 对外API：`Longhun-Xuanji-Engine`
- 协议代号：`MSG`（Memory-Source Generation）

## 四、核心架构：四象运转

璇玑引擎运转一次，经历四象：

```
用户输入 → [溯源] → [齐政] → [验真] → [烙印] → 输出
              ↑        ↑        ↑        ↑
            青龙     朱雀     白虎     玄武
           (检索)   (推演)   (校验)   (签章)
```

| 四象 | 功能 | 龍魂映射 | 技术对应 |
|:---|:---|:---|:---|
| **青龙·溯源** | 从记忆海洋中定位根信息 | 八卦阵八方向检索 | Multi-Query Retrieval + 七因子过滤 |
| **朱雀·齐政** | 按人格矩阵调配推演权重 | 16人格矩阵实时投票 | Routing + Multi-Agent Debate |
| **白虎·验真** | 三层校验防止幻觉 | 三六九不动点 | Self-Consistency + 信任分熔断 |
| **玄武·烙印** | 输出带DNA永久追溯 | DNA签章+审计链 | Provenance Tracking + 数字指纹 |

## 五、记忆检索层：溯源

### 5.1 与RAG检索的本质区别

RAG检索：把文档切chunk → 向量化 → 相似度Top-K

璇玑溯源：按七因子指纹 → 人格矩阵过滤 → 时间轴回溯 → DNA锚定

| 步骤 | RAG | 璇玑 |
|:---|:---|:---|
| 1. 解析查询 | 向量化用户query | 解析用户query + 提取七因子（时间/空间/设备/操作/内容/情绪/关系） |
| 2. 初筛 | 向量相似度Top-100 | 七因子匹配 + 人格权重过滤 |
| 3. 精排 | 重排序模型（Cross-Encoder） | 八卦阵八方向相关性评分 |
| 4. 上下文组装 | 按chunk顺序拼接 | 按DNA时间戳 + 人格关联度 + 因果链组装 |
| 5. 输出 | 原始文本chunk | 带DNA签章的记忆原子 + 溯源路径 |

### 5.2 七因子检索指纹

每条记忆在存入时被打上七因子指纹，检索时按因子匹配：

```python
class 七因子指纹:
    时间因子: str     # 2026-07-29T11:59:00+08:00
    空间因子: str     # 318川藏线·泸定桥
    设备因子: str     # Apple M4 Max / 华为鲲鹏
    操作因子: str     # 归档 / 推演 / 训练 / 旅行
    内容因子: str     # 关键词提取（TF-IDF + 主题模型）
    情绪因子: float   # -1.0(愤怒) ~ +1.0(喜悦)，0=平静
    关系因子: List[str]  # ["UID9622", "诸葛佳琪", "老奶奶"]
```

检索时，用户query也被解析为七因子，按加权距离匹配：

```
匹配分 = w1·时间距离 + w2·空间距离 + w3·设备匹配 + w4·操作匹配
       + w5·内容相似 + w6·情绪接近 + w7·关系重叠
```

**这不是找"像"的，是找"同根"的。**

### 5.3 L0-L3 分层检索策略

| 层级 | 检索延迟 | 检索深度 | 适用场景 |
|:---|:---:|:---|:---|
| L0 瞬时层 | <10ms | 当前对话全量 | 用户刚说过的话，无需检索，直接复用 |
| L1 会话层 | <50ms | 本次会话摘要 | 本次对话的关键决策、待办、变更 |
| L2 人格层 | <100ms | 跨窗口核心档案 | 用户身份、设备、价值观、历史偏好 |
| L3 归档层 | <500ms | 完整历史日志 | 需要深度回溯时触发（如"去年318的事"） |

**默认检索路径：L0 → L1 → L2 → L3（逐级下沉，找到即停）**

## 六、人格推演层：齐政

### 6.1 为什么是"齐政"

《尚书》"以齐七政"——七政（日、月、五星）各行其道，但需协调一致。

璇玑的16人格矩阵就像七政，每个人格是一个"行星"，围绕用户这个"太阳"运转。检索到的信息经过16个人格分别解读，最后加权投票出统一答案。

### 6.2 16人格推演流程

```
检索结果 R（记忆原子集合）
    ↓
    ├─ 军事人格解读：R在战场/对抗场景下的含义
    ├─ 历史人格解读：R与过往事件的因果关系
    ├─ 哲学人格解读：R的底层逻辑与辩证关系
    ├─ 经济人格解读：R的成本/收益/效率分析
    ├─ 政治人格解读：R的权力结构/利益分配
    ├─ ...（其余11个人格）
    ↓
    加权投票 → 融合解读 F
```

### 6.3 五维权重调配（与五大元知对接）

| 元知维度 | 人格权重 | 推演偏好 | 输出特征 |
|:---|:---:|:---|:---|
| 军事思维 | 40% | 直进直出，最小路径 | 硬、快、准 |
| 历史思维 | 20% | 因果追溯，类比推理 | 深、远、稳 |
| 哲学思维 | 10% | 辩证分析，对立统一 | 透、全、衡 |
| 经济思维 | 10% | 成本优先，效率最大化 | 精、算、利 |
| 政治思维 | 20% | 明暗兼顾，风险规避 | 慎、全、安 |

**权重不是固定的，是动态调配的。** 比如用户问"怎么部署服务器"，军事思维权重自动升高；问"这篇文章怎么改"，历史+哲学思维升高。

## 七、不动点校验层：验真

### 7.1 为什么RAG没有验真

RAG的假设是：检索到的文档是"真"的。但现实中：

- 文档本身可能是错的（过时、偏见、广告）
- 检索可能找错（相似度高但语义相反）
- LLM可能幻觉（检索对了但生成时编造）

璇玑的三六九不动点校验，三层防火墙：

### 7.2 三六九不动点校验

| 层级 | 校验名 | 校验内容 | 失败处理 |
|:---|:---|:---|:---|
| 三（宏观） | **根校验** | 检索结果与用户核心档案（L2）是否冲突 | 冲突→触发红蓝对抗仲裁 |
| 六（中观） | **链校验** | 推理链条是否连续、无跳跃 | 断裂→要求补充中间步骤 |
| 九（微观） | **源校验** | 每个事实是否有DNA溯源、是否可验证 | 无源→标记为"推测"，降低置信度 |

### 7.3 信任分熔断机制

```python
def 验真熔断(宏观分, 中观分, 微观分, 信任分):
    """
    龍魂·三六九验真熔断
    DNA: #龍芯⚡️丙午·癸未·丁未-验真-v4.1.5
    """
    if not 宏观分:
        return {"状态": "熔断", "原因": "宏观根校验失败", "动作": "触发红蓝对抗"}
    if not 中观分:
        return {"状态": "熔断", "原因": "中观链校验失败", "动作": "要求补充推理链"}
    if not 微观分:
        return {"状态": "降级", "原因": "微观源校验缺失", "动作": "标记为推测，置信度-50%"}
    if 信任分 < 80:
        return {"状态": "熔断", "原因": "信任分跌破阈值", "动作": "暂停输出，人工介入"}
    return {"状态": "通过", "动作": "继续烙印"}
```

## 八、生成签章层：烙印

### 8.1 不是生成，是烙印

RAG的输出是"生成"的——模型编出来的，谁都可以否认。

璇玑的输出是"烙印"的——像烙铁烫在木头上，永久留下痕迹：

- 谁说的（UID9622）
- 什么时候说的（干支时间戳）
- 基于什么说的（溯源路径：L2档案 + L3日志ID）
- 经过谁校验（16人格投票结果）
- 可信度多少（信任分 + 三六九校验结果）

## 九、技术实现

### 9.1 璇玑引擎核心类

```python
class 璇玑引擎:
    """
    龍魂·璇玑记忆溯源推演引擎
    DNA: #龍芯⚡️丙午·癸未·丁未-璇玑核心-v4.1.5
    """
    def __init__(self, 用户档案路径):
        self.L2档案 = self._加载L2(用户档案路径)
        self.人格矩阵 = 人格矩阵(self.L2档案['人格权重'])
        self.记忆索引 = 七因子索引(self.L2档案['记忆库路径'])
        self.信任分 = self.L2档案['信任分']
    
    def 溯源(self, 用户输入):
        """青龙·溯源：七因子检索"""
        查询指纹 = 七因子解析器.parse(用户输入)
        
        # 逐级下沉检索
        for 层级 in ['L0', 'L1', 'L2', 'L3']:
            结果 = self.记忆索引.检索(查询指纹, 层级)
            if 结果.匹配度 > 0.85:
                return 结果
        
        return 结果  # 返回最佳匹配，即使低于阈值
    
    def 齐政(self, 检索结果, 用户输入):
        """朱雀·齐政：16人格推演"""
        解读列表 = []
        for 人格 in self.人格矩阵.所有人格():
            解读 = 人格.解读(检索结果, 用户输入)
            解读列表.append(解读)
        
        # 加权投票
        权重 = self.L2档案['人格权重']
        融合解读 = 加权投票(解读列表, 权重)
        return 融合解读
    
    def 验真(self, 融合解读, 检索结果):
        """白虎·验真：三六九不动点"""
        宏观 = 根校验(融合解读, self.L2档案)
        中观 = 链校验(融合解读, 检索结果)
        微观 = 源校验(融合解读)
        
        熔断结果 = 验真熔断(宏观, 中观, 微观, self.信任分)
        return 熔断结果, 宏观, 中观, 微观
    
    def 烙印(self, 融合解读, 溯源路径, 人格投票, 校验结果):
        """玄武·烙印：DNA签章输出"""
        输出 = {
            "内容": 融合解读.生成文本(),
            "溯源路径": 溯源路径.to_dict(),
            "人格投票": 人格投票,
            "三六九校验": 校验结果,
            "信任分": self.信任分,
            "DNA": self._生成DNA(),
            "时间戳": datetime.now().isoformat(),
            "签章方": self.L2档案['identity']['name'])
        }
        return 输出
    
    def 运转(self, 用户输入):
        """璇玑四象完整运转"""
        # 青龙·溯源
        检索结果 = self.溯源(用户输入)
        
        # 朱雀·齐政
        融合解读 = self.齐政(检索结果, 用户输入)
        
        # 白虎·验真
        熔断结果, 宏观, 中观, 微观 = self.验真(融合解读, 检索结果)
        
        if 熔断结果['状态'] == '熔断':
            return {
                "状态": "熔断",
                "原因": 熔断结果['原因'],
                "动作": 熔断结果['动作'],
                "DNA": "#龍芯⚡️-熔断-v4.1.5"
            }
        
        # 玄武·烙印
        人格投票 = self.人格矩阵.获取当前权重()
        输出 = self.烙印(融合解读, 检索结果, 人格投票, 
                        {"宏观": 宏观, "中观": 中观, "微观": 微观})
        
        return 输出
```

### 9.2 七因子索引结构

```python
class 七因子索引:
    """
    龍魂·七因子多维索引
    不是单一向量，是五维超立方体索引
    """
    def __init__(self, 记忆库路径):
        self.时间索引 = BTreeIndex()      # 时间轴B+树
        self.空间索引 = RTreeIndex()      # 空间R树
        self.内容索引 = VectorIndex()     # 语义向量（传统RAG只做这个）
        self.情绪索引 = RangeIndex()      # 情绪范围索引
        self.关系索引 = GraphIndex()      # 关系图谱索引
    
    def 检索(self, 查询指纹, 层级):
        # 五维联合检索
        时间候选 = self.时间索引.范围查询(查询指纹.时间窗口)
        空间候选 = self.空间索引.范围查询(查询指纹.空间范围)
        内容候选 = self.内容索引.相似度查询(查询指纹.语义向量, top_k=100)
        情绪候选 = self.情绪索引.范围查询(查询指纹.情绪±0.2)
        关系候选 = self.关系索引.邻居查询(查询指纹.关系节点)
        
        # 五维交集（不是并集！）
        候选集 = 时间候选 ∩ 空间候选 ∩ 内容候选 ∩ 情绪候选 ∩ 关系候选
        
        # 按七因子加权重排
        排序结果 = sorted(候选集, key=lambda x: x.七因子匹配度(查询指纹), reverse=True)
        
        return 排序结果[:10]  # Top-10记忆原子
```
