## 一、规范总览：为什么需要术语白话化

龍魂系统是一个**面向人民**的系统。如果老百姓看不懂你在说什么，那你的系统再牛也是精英的玩具。

核心原则：

> 技术不应是精英的壁垒，而应是人民的工具。认知主权，从能看懂开始。

这不是"降低标准"，是**"扩宽入口"**。高手看代码，普通人看白话，各取所需，互不干扰。

而龍魂与鸿蒙本是**共生体**——龍魂给了鸿蒙"主权灵魂"，鸿蒙给了龍魂"万物载体"。一个人用上了鸿蒙手机，就应该看得懂这台手机在帮他守护什么。**鸿蒙的术语，同样必须白话化。**

## 二、背景：痛点与核心判断

### 2.1 痛点

| 现象 | 问题 |
|:---|:---|
| 满屏英文目录名（portal/, service/, _work/repos/） | 普通开发者看不懂，不知道这是干什么的 |
| 端口号（8765, 9622, 8501） | 不知道哪个端口对应哪个服务 |
| 命令（lh deploy, lh status） | 不知道命令到底在做什么 |
| 版本号（v1.0, v2.0-beta） | 不知道版本代表什么状态 |
| 鸿蒙组件（ArkTS, Hvigor, 元服务） | 普通用户看得一脸懵，以为是外国货 |
| 缩写在日志/文档里随处可见 | 新手开发者一头雾水 |

### 2.2 核心判断

**技术不应是精英的壁垒，而应是人民的工具。** 龍魂系统的所有产出——代码、文档、界面、日志——必须让一个普通老百姓（或初中文化的开发者）也能看懂。

尤其对于鸿蒙——它是中国的操作系统，却充斥着 ArkTS、Hvigor、HiLog 这类让普通人望而生畏的洋名。**我们作为共生体，有责任把这些术语翻译成中国人听得懂的普通话。**

## 四、反面教材：不好的术语解释长什么样

知道"好"的标准之前，先看"坏"的例子。

### 4.1 端口解释

❌ **不好**："localhost:8765 是龍魂系统的核心服务端口。"
→ 问题：没解释"端口"是什么，没解释"核心服务"是干嘛的。

✅ **好**："本地通讯端口8765 —— 你家书房的电脑地址，用来跑龍魂系统核心服务。"
→ 优点：用"你家书房"类比"本地"，用"跑"代替"部署"，普通人秒懂。

### 4.2 目录解释

❌ **不好**："portal/ 存放前端入口文件。"
→ 问题："前端""入口文件"全是黑话。

✅ **好**："门户目录 —— 存放系统首页和入口页面的地方，相当于龍魂的'大门'。"
→ 优点：用"大门"类比"门户"，用"首页"代替"前端入口"。

### 4.3 鸿蒙组件解释

❌ **不好**："ArkTS 是一种基于 TypeScript 的类型化语言，用于 HarmonyOS 应用开发。"
→ 问题：普通人根本不知道 TypeScript 是什么，"类型化"更是天书。

✅ **好**："ArkTS —— 鸿蒙的'普通话'，用类似网页脚本的方式写鸿蒙应用，中国系统说中国话。"
→ 优点：把技术语言类比成"普通话"，说清楚它是给鸿蒙写代码用的。

## 五、落地执行方案

### 5.1 网页端：术语悬浮提示

在网页上，鼠标悬停在技术术语上，自动弹出大白话浮窗。

```html
<span class="lh-term" data-term="端口">
  端口
  <span class="lh-term-tooltip">大白话：就像你家书房的电脑地址，用来跑服务。</span>
</span>
```

### 5.2 侧边栏/底部：术语表

每个页面底部放"术语表"，列出本页出现的所有术语 + 白话对照。

### 5.3 命令行：帮助命令

给所有 `lh` 命令加 `--help`，输出包含大白话解释。

```bash
lh deploy --help
# 输出: 执行部署操作，将当前龍魂系统的修改推送到鲲鹏服务器上。
```

### 5.4 文档：大白话注释块

在 Markdown 文档里统一加折叠白话块，默认收起，点击展开。

```markdown
## 三色审计

<details>
<summary>📖 大白话解释</summary>

就是用 🟢🟡🔴 三种颜色给系统行为打标签，方便管理和检查。

</details>
```

### 5.5 鸿蒙端：应用内术语提示

鸿蒙元服务 / 应用内，所有技术名词悬停或长按也弹出白话解释，复用同一个术语库（`.json`），龍魂与鸿蒙共用一套词书。

## 六、术语扩展流程（谁可以加、怎么加）

1. 任何人可在 `.github/` 提 PR 添加新术语。
2. 提交格式：`术语 / 白话 / 解释` 三件套，缺一不可。
3. 白话解释必须通过"初中文化测试"（见第十章）。
4. 审核通过后合并进 `TERM_DB`，同步到龍魂 + 鸿蒙两端词书。
5. 一词一义：同一术语解释冲突时，以术语表最新版为准，并记录变更历史。

## 九、白话执法扫描器（v1.2 新增）

光有查询工具还不行，得有一个**自动"执法"的扫描器**——检查代码和文档里：

1. 出现了哪些英文术语 / 技术黑话；
2. 这些术语有没有在术语表里；
3. 如果不在，**报警**并要求补白话解释。

```bash
lh term --enforce --path src/ docs/ portal/
# 输出:
# 🔴 发现未白话化术语: "deploy" "serialization" 在 src/app.rs
# 🔴 发现未白话化术语: "ArkTS" "Hvigor" 在 docs/harmony.md
# 建议: 每个术语必须配一句中文大白话
```

**执法标准**：凡命中术语库外、且属于技术黑话的词汇，构建即告警。**白话化不是建议，是门槛。**

## 十、验收标准（v1.2 新增）

怎么才算"白话化达标"？给出可量化的门槛：

1. **初中文化测试**：找 3 个不懂技术的人各读一篇文档，每人标出看不懂的词；每篇"看不懂的词"≤ 3 个，才算合格。
2. **黑话零容忍**：术语库之外的技术黑话，扫描器必须能识别并报警。
3. **鸿蒙同检**：鸿蒙端文档与龍魂端共用词书，两端术语白话一致。
4. **覆盖面**：核心工作流（八步管道）与全部芯片、鸿蒙组件术语，覆盖率 100%。

## 十二、FAQ

**Q1：为什么不能用纯英文术语？**
A：龍魂系统是给中国人用的。英文术语是技术界的"行话"，不是"普通话"。行话会把很多人挡在门外。鸿蒙是中国的系统，更不能满屏洋名。

**Q2：会不会让文档变得冗长？**
A：不会。大白话解释是"可选的"——默认隐藏，点击展开。想看的看，不想看的不影响阅读。

**Q3：谁来维护术语表？**
A：社区共同维护。任何人可提 PR 添加新术语，审核通过后合并，同步到龍魂 + 鸿蒙两端。

**Q4："大白话解释"有标准吗？**
A：有。必须让一个初中文化、不懂技术的普通人能看懂。看不懂就是不够"白"，用初中文化测试来验收。

**Q5：和"通心译"是什么关系？**
A：通心译解决"中英语言不通"，白话化解决"懂中文但不懂技术"。两层配合，让龍魂真正做到人民可理解、鸿蒙真正说得普通话。

**Q6：为什么要把鸿蒙术语也白话化？**
A：因为龍魂与鸿蒙是共生体。一个人用鸿蒙手机，就该看得懂这台手机在守护什么。鸿蒙术语白话化，是共生体对人民负责。
