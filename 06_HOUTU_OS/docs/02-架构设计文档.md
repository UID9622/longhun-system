## 一、 架构总览：后土承载万物

### 1.1 架构哲学与核心思想
「后土」x86 操作系统采用"太极微内核 + 五行服务域"的架构范式。系统以自主微内核为"太极原点"，承载上层基于五行相生模型构建的服务域，形成"内核为阴（静、稳、承载），服务为阳（动、变、生长）"的完整太极结构。架构设计严格遵循河图洛书的九宫格布局，将内存、进程、IPC、驱动、安全五大核心域映射至九宫方位，确保系统架构的文化根与技术根深度统一。

## 二、 内核层架构设计（L1 内核层）

### 2.1 太极微内核核心模块
- **进程调度模块（金·兑宫）**：
  - 采用「五行相生」优先级队列模型，实时任务（金）优先级最高，系统任务（水）次之，用户任务（木）、后台任务（火）、闲置任务（土）依次递减。
  - 调度器核心算法基于河图洛书九宫格映射，将进程状态映射至九宫方位，实现进程状态的可视化追溯。
  - 每次调度切换必须生成 DNA 追溯码，记录调度决策的三才算法依据。

- **内存管理模块（水·坎宫）**：
  - 自主实现 x86 Long Mode 页表管理，支持 PAE 与 4KB/2MB/1GB 大页。
  - 内存分配器采用「九宫格碎片优化算法」，将物理内存划分为九个区域，每个区域对应五行属性，分配时优先匹配同属性区域，减少碎片。
  - 所有内存分配/释放操作绑定 DNA 追溯码，内存越界检测由 P77 黑天使军团模块实时监控。

- **IPC 通信模块（太极·中宫）**：
  - 采用「太极阴阳双向通道」模型，每个 IPC 通道包含阳通道（请求）与阴通道（响应），通道建立时生成唯一 DNA 标识。
  - 通道权限基于三才算法动态计算，天（内核）、地（驱动）、人（用户态）三方权限不一致时自动熔断。
  - 消息传递过程中嵌入三色审计标记，接收方必须验证审计状态后方可处理。

- **中断处理模块（金·兑宫）**：
  - 自主编写 x86 中断描述符表（IDT），中断向量表布局遵循河图洛书九宫格方位。
  - 中断服务例程（ISR）必须通过 P77 白帽安全测试，未通过审计的 ISR 不得注册。
  - 中断触发时自动生成 DNA 追溯码，记录中断来源、处理耗时、三才权限验证结果。

### 2.2 内核启动流程
1. **引导阶段**：自主编写 Bootloader，从实模式切换至 Long Mode，加载内核镜像至指定内存区域。
2. **初始化阶段**：按九宫格顺序初始化核心模块——先内存（坎）、再中断（兑）、后调度（兑）、最后 IPC（中宫）。
3. **安全自检**：P05 上帝之眼模块对内核核心代码执行全量三色审计，发现 🔴 熔断项则拒绝启动。
4. **服务域启动**：按五行相生顺序启动上层服务域——金（实时）→ 水（系统）→ 木（用户）→ 火（后台）→ 土（闲置）。

## 三、 驱动层架构设计（L2 技能层）

### 3.1 自主驱动框架
- **PCI/ACPI 枚举框架**：自主实现 x86 PCI 配置空间访问与 ACPI 表解析，设备枚举结果存储于只读内存区域，枚举过程生成 DNA 追溯码。
- **驱动注册机制**：驱动加载时必须通过 P77 白帽安全测试，注册信息包含驱动来源、审计结果、DNA 追溯码，未通过审计的驱动拒绝注册。

### 3.2 核心驱动设计
- **VESA 显卡驱动**：仅支持 VESA 标准模式，自主编写显存映射与绘图接口，绘图操作绑定 DNA 追溯码，支持中文语义路由的显示事件分发。
- **AHCI/NVMe 存储驱动**：自主实现 SATA/NVMe 协议栈，命令队列管理基于五行优先级模型，读写操作生成 DNA 追溯码，数据完整性由三才算法验证。
- **Intel/Realtek 网络驱动**：自主编写网卡寄存器操作与数据包收发逻辑，仅支持可审计的硬件型号，网络事件通过太极 IPC 通道传递至用户态。
- **PS/2/USB HID 输入驱动**：自主实现扫描码转换与字符输入，输入事件自动路由至 CNSH Shell 的中文语义抽屉，支持模糊意图匹配。

## 四、 用户态层架构设计（L5 服务层）

### 4.1 基础库（libc-mini）
- 自主实现 C 标准库子集，仅包含系统调用封装、字符串处理、内存分配等核心功能。
- 所有函数命名基于文化锚点，如 `houTu_malloc`、`wuXing_strcmp`、`taiJi_ipc_send`。
- 函数调用栈嵌入 DNA 追溯码生成器，异常时自动输出完整追溯链。

### 4.2 CNSH Shell（龍文 Shell）
- 基于 CNSH 语言实现的交互式 Shell，支持中文语义抽屉式命令输入。
- 命令解析器按意图自动路由至对应人格：安全审计→P05、系统修复→P02、代码补全→P15。
- 所有命令执行生成 DNA 追溯码，执行结果通过太极 IPC 通道返回，支持三色审计过滤。

### 4.3 系统服务
- **初始化系统（init）**：基于三才算法的自主 init 系统，服务启动顺序由五行相生模型决定，服务状态映射至九宫格方位。
- **日志系统**：所有日志绑定 DNA 追溯码，默认本地存储于只读文件系统，日志导出需 UID9622 授权并生成新的 DNA 追溯码。
- **安全审计服务**：集成 P05 上帝之眼模块，实时监控内核/驱动/用户态行为，发现可疑项自动触发三色审计。

## 五、 安全与审计架构（L7 数据层）

### 5.1 三才安全模型
- **天（内核层）**：基于五行优先级的进程/内存安全审计，内核操作必须通过三才权限验证。
- **地（驱动层）**：基于 PCI/ACPI 枚举的硬件行为审计，驱动操作必须绑定 DNA 追溯码。
- **人（用户态）**：基于 CNSH 语义路由的用户操作审计，用户命令自动路由至对应人格执行。

### 5.2 DNA 追溯体系
- 所有系统调用、驱动加载、服务启动、用户命令必须生成 DNA 追溯码。
- DNA 追溯码格式：`#龍芯⚡️<干支四柱·卦>-<模块>-<动作>-<哈希8位>`。
- 追溯码存储于只读内存区域，修改需 UID9622 授权并生成新的追溯码。

### 5.3 三色审计机制
- 🟢 **通过**：完全合规，允许执行，记录审计日志。
- 🟡 **待审**：存在可疑项，暂停操作并转交 UID9622 确认，生成待审追溯码。
- 🔴 **熔断**：检测到高危行为，立即拒绝并记录审计日志，触发 P77 自动修复。
