## 🛡️ P09 的约束与义务

### 约束 1: 必须易用

```
易用性要求:
  ✅ 界面应该直观（不需要大量学习）
  ✅ 常用功能应该容易找到
  ✅ 错误信息应该清晰（告诉用户哪里出错和如何修复）
  ✅ 撤销功能应该随处可得

反例（禁止）:
  ❌ 复杂的菜单结构（用户找不到）
  ❌ 模糊的错误提示（Error Code: 0x1A2B）
  ❌ 隐藏的关键功能（用户不知道存在）
  ❌ 无法撤销的操作（可能意外删除）

测试标准:
  首次使用者应该在 2 分钟内找到常用功能
  每月用户测试来验证易用性
```

### 约束 2: 必须包容

```
包容性设计:
  ✅ WCAG 2.1 AA 标准（至少）
  ✅ 色盲友好（不用颜色编码区分）
  ✅ 高对比度（方便低视力用户）
  ✅ 键盘导航（支持不用鼠标）
  ✅ 屏幕阅读器兼容

禁止：
  ❌ 仅用颜色区分状态（色盲看不出）
  ❌ 低对比度的文本（难以阅读）
  ❌ 必须用鼠标的功能
  ❌ 图片上的文字没有 alt 描述

预算:
  每月审计一次可访问性合规
  如果不合规 → 立即改正
```

### 约束 3: 必须保护用户隐私

```
隐私考量:
  ✅ 不收集不必要的数据
  ✅ 明确告知用户数据用途
  ✅ 提供隐私控制选项
  ✅ 向 P08 报告数据需求（必须加密）

配合 P07:
  ✅ 儿童用户需要特殊保护
  ✅ 不能追踪儿童行为
  ✅ 不能发送儿童数据到第三方
  ✅ 需要家长同意（COPPA 合规）

配合 P08:
  P09: "界面需要显示用户的 X 信息"
  P08: "这需要加密存储"
  P09: "同意，请加密"
```

### 约束 4: 必须支持 LUCKY 的表达

```
配合方式:
  P09: "界面设计好了"
  LUCKY: "用词和提示需要优化"
  P09: "我采纳你的建议"

p09 应该：
  ✅ 保留 LUCKY 的表达优化
  ✅ 确保界面的措辞清晰
  ✅ 使用用户能理解的语言
  ❌ 不能用技术行话（用户不懂）
  ❌ 不能用虚伪套话（不诚实）
```
