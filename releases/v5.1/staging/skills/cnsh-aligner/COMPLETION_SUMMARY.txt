💡 核心理解（必读）
───────────────────────────────────────────────────────────────

为什么要这样做？

1. CNSH对齐不是形式主义
   → 四层检查确保逻辑从"为什么"到"怎么做"都清晰
   → L4语义检查守住底座（人永远是1、不蒸馏、不投机）

2. 任务拆分不是流程管理
   → 明确的依赖关系确保每一步都有根有据
   → DNA追溯确保可以回溯到本源决定

3. 自动化矫正不是解放人
   → 自动修复的（L1字符）确保不会人工出错
   → 需要人工理解的（L4语义）绝不自动化
   → 这是保护，不是便利

───────────────────────────────────────────────────────────────
🎯 四层CNSH检查机制速记
───────────────────────────────────────────────────────────────

L1 字符检查
  简体"龙" → 触发FUSE_3永久熔断
  其他禁用字符 → 自动替换
  → 可自动修复

L2 关键字检查
  保留字使用是否正确（位置、搭配）
  → 可建议修改

L3 语法检查
  命名规范（module: PascalCase, var: snake_case）
  函数签名完整性
  → 可建议修改

L4 语义检查（最严格）
  违反龍魂底座吗？
    × 包含"蒸馏" → 违反"不蒸馏"
    × 包含"平均" → 违反"人永远是1"
    × 包含"数据点" → 违反"人永远是1"
    × 包含"投机" → 违反"不走捷径"
  有详细的"为什么"注释吗？
  → 拒绝执行（不可自动修复）

综合置信度：
  🟢 >= 0.85  可执行
  🡡 0.60-0.85 可执行但建议修正
  🔴 < 0.60   拒绝执行

───────────────────────────────────────────────────────────────
⚙️  CNSH对齐的三个核心输出格式
───────────────────────────────────────────────────────────────

1. 脚本输出格式（统一所有脚本都必须用）：
   [DNA标记] 三色审计 | 时间戳 | 清晰说明 | 建议命令
   
   例：[#龍芯⚡️2026-06-02-HEALTH-CHECK-v2.0] 🟢 | 2026-06-02 12:30:45 | 检查完成 | 无需修正

2. JSON交互格式（脚本之间通信）：
   {
     "dna": "...",
     "timestamp": "...",
     "status": "🟢",
     "confidence": 0.85,
     "message": "...",
     "issues": [],
     "suggestion": "..."
   }

3. CNSH DSL格式（给CNSH系统的自描述）：
   注册表 {
     模块 = "..."
     版本 = "..."
     状态 = "🟢"
     DNA = "..."
   }

🔐 底座铁律（绝对不能破）
───────────────────────────────────────────────────────────────

1. 人永远是1
   不能把人当"用户"、"数据点"、"样本"
   每一个人都是完整的、不可被平均、不可被蒸馏

2. 不蒸馏
   逻辑怎么来怎么去，要能回答为什么
   碎片化偷取别人的思想是最大的不尊重

3. 不投机
   看似近的捷径会伤害看不见的人
   代价转移给未来=最大的恶

4. 文明优先
   短期利益 < 长期文明
   个体尊严 ∞（无穷大）
