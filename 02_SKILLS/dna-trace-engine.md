# /dna-trace-engine · DNA追溯引擎

## 摘要

DNA追溯引擎是龍魂系统的内容溯源核心。为每个内容制品生成不可篡改的DNA追溯码（格式：`#龍芯⚡️{日期}-{类型}-{项目}-{版本}`），支持四级DNA格式（基础/完整/审计/违规），实现SM3哈希链+SM2数字签名的双签保护机制。L2登记层遵循「只存哈希、不存正文」原则，确保即使登记层被入侵也无法还原原始身份数据。DNA校验遵循严格五步流程：格式检查→SM3哈希验证→SM2签名验证→七因子阈值检查→审计日志记录。

## 一句话定义

> DNA追溯码 = 数字内容的「基因标签」——创建时间+类型+项目+版本，SM3指纹保护，SM2身份签名，贯穿内容全生命周期。

## 关键词

DNA追溯 DNA Traceability, SM3哈希 SM3 Hash, SM2签名 SM2 Signature, 哈希链 Hash Chain, L2登记层 L2 Registration Layer, 双签 Double Signature, 内容溯源 Content Provenance, DNA校验 DNA Verification

## 四级DNA格式

### 基础DNA（Base DNA）

```
#龍芯⚡️{日期}-{类型}-{项目}-{版本}
```

示例：`#龍芯⚡️乙巳·壬午·甲戌·庚午·䷕贲-JPG-企业A-v1.0`

### 完整DNA（Full DNA）

```
#龍芯⚡️...|SM3:{哈希}|THRESH:{置信度}|SIG:{签名}
```

示例：`#龍芯⚡️乙巳·壬午·甲戌·庚午·䷕贲-JPG-企业A-v1.0|SM3:a1b2c3d4e5f6g7h8|THRESH:0.92|SIG:sm2sig12345678`

### 审计DNA（Audit DNA）

```
#AUDIT🟢|DNA验证通过|SM3匹配|SM2签名有效
#AUDIT🟡|DNA验证警告|建议人工复核
#AUDIT🔴|DNA验证失败|{失败原因}
```

### 违规DNA（Violation DNA）

```
#AUDIT🔴|DNA验证失败|SM3不匹配|成分超標
```

## 核心功能

### 1. 生成基础DNA

```python
当前日期 = datetime.now().strftime('%Y-%m-%d')
dna码 = f"#龍芯⚡️{当前日期}-{内容类型}-{项目名称}-v{版本}"
```

### 2. 生成完整DNA（含SM3+SM2）

```
完整DNA = 基础DNA | SM3哈希 | 阈值 | SM2签名片段

步骤：
① SM3引擎计算基础DNA的哈希
② SM2引擎对基础DNA签名（取前16位）
③ 组装：基础DNA|SM3:哈希|THRESH:置信度|SIG:签名
```

### 3. 解析DNA

提取字段：原始码、类型、日期、内容类型、项目名称、版本、SM3哈希、阈值、签名

### 4. 验证DNA

- 格式检查：必须以 `#龍芯⚡️` 开头
- SM3哈希比对（如提供预期哈希）
- SM2签名验证（如有SM2引擎）

## DNA双签机制

| 层次 | 算法 | 作用 | 验证内容 |
|:---:|------|------|------|
| 第一签 | SM3 | 完整性保护 | 内容是否被篡改 |
| 第二签 | SM2 | 身份认证 | 签名者是否为UID9622 |
| 组合验证 | SM3+SM2 | 双重确认 | 内容完整且身份真实 |

## L2登记层

**核心原则**：只存哈希，不存正文。

```
登记七因子时：
  不存 Fi 的原始得分
  只存 SHA-256(Fi:得分:DNA追溯码) 的前16位
```

**验证时**：
- 重新计算因子摘要 → 与登记记录比对
- 任一因子不匹配 → 对应该因子 Fi=0 → conf=0（Hard Failure）
- 所有因子匹配 → 验证通过

```python
class L2登记层:
    登记库 = {}  # 内容ID → 登记记录
    
    def 登记七因子摘要(内容ID, 七因子向量, DNA追溯码):
        因子摘要 = {
            F1: SHA256("F1:0.95:DNA码")[:16],
            F2: SHA256("F2:0.88:DNA码")[:16],
            ...
        }
        整体摘要 = SHA256(json(因子摘要))
        登记库[内容ID] = {DNA追溯码, 因子摘要, 整体摘要, 登记时间}
    
    def 验证登记(内容ID, 七因子向量, DNA追溯码):
        重新计算摘要 → 逐因子比对
        任一不匹配 → 熔断：Fi=0 → conf=0
```

## DNA校验五步流程

```
① 格式检查
  └ 验证DNA是否以 #龍芯⚡️ 开头

② SM3哈希验证
  └ 确认内容完整性未被破坏

③ SM2签名验证
  └ 确认签名者身份为UID9622

④ 七因子阈值检查
  ├ conf < 0.85 → 🔴 触发熔断（conf=0）
  ├ 0.85 ≤ conf < 0.95 → 🟡 标准通过
  └ conf ≥ 0.95 → 🟢 高安全通过

⑤ 审计日志记录
  └ 所有结果（通过/失败）均记入DNA日志
```

## DNA与七因子对接

```
内容制品 → 七因子引擎计算 Σ(C)
  → L2登记层登记七因子摘要（只存哈希）
    → DNA追溯引擎生成完整DNA（含SM3+SM2）
      → 三色审计引擎验证
        → 输出审计DNA标签
```

## 诚实局限

1. DNA验证依赖原始输入完整性，无法检测「输入已变但声称未变」的中间人攻击。
2. L2登记层的 SHA-256 前16位截断在极端碰撞场景下存在理论风险（概率约 2^-64）。
3. 哈希链的完整性依赖首节点正确初始化，首节点被篡改则整链失效。
4. DNA追溯索引当前为手动维护，未实现自动全量扫描。
