## 1. 产品定位

### 1.1 这是什么

创新溯源推演器是龍魂系统 **P05 上帝之眼**人格下的一个专用子引擎，用于对争议性技术/创新的来源归属进行**基于公开证据的推演分析**。

### 1.2 解决什么问题

| 场景 | 说明 |
|------|------|
| 🏭 **技术争议** | "这个操作系统到底是自研的还是基于XX改的？" |
| 🔬 **创新归属** | "MoE架构到底是谁先提出的？" |
| 📜 **专利溯源** | "这个芯片架构最早是谁公开的？" |
| 🌐 **开源溯源** | "这个项目是fork了谁的？许可证链是什么？" |

### 1.3 不是什么

| ❌ 不是 | ✅ 实际上是 |
|:---|------|
| **不是**事实认定工具 | 是**推演辅助**工具 |
| **不是**法律证据 | 是**研究参考** |
| **不是**审判官 | 是**时间线整理者** |
| **不替**你下结论 | **综合加权后排序**，你自己看 |
| **不替**你担责 | 报告底部有**8条法律免责声明** |

### 1.4 核心原则

> **只推演 · 不审判 · 不站队 · 可验证 · 可校正**

## 4. 五维推演算法

### 4.1 算法公式

```
综合推演分 P = Σ(W_i × S_i)，其中：

  i ∈ {时间优先, 技术深度, 证据链, 独立度, 社区认可}

  W_i 为各维度权重：
    W_时间优先 = 0.30
    W_技术深度 = 0.25
    W_证据链   = 0.20
    W_独立度   = 0.15
    W_社区认可 = 0.10

  S_i 为各维度得分，范围 [0, 1]
```

### 4.2 各维度评分细则

#### ⏰ 时间优先度（权重 30%）

| 条件 | 得分 |
|:---|:---:|
| 唯一最早公开记录 | 1.0 |
| 并列最早公开 | 0.85 |
| 比最早晚 ≤30天 | 0.75 |
| 比最早晚 ≤180天 | 0.60 |
| 比最早晚 ≤365天 | 0.40 |
| 比最早晚 >365天 | 0.20 |
| 日期未知 | 0.0 |

#### 🔬 技术深度（权重 25%）

| 指标 | 加分 |
|:---|:---:|
| 摘要内容 > 200字 | +0.4 |
| 有关键主张列表 | +0.15/条（最多+0.3） |
| 来源为论文/专利/代码仓库 | +0.3 |
| 合计封顶 | 1.0 |

#### 🔗 证据链完整度（权重 20%）

| 条件 | 得分 |
|:---|:---:|
| 证据中包含引用/致谢/fork/致敬等关键词 | 0.7 |
| 无引用链信息 | 0.3 |

#### 🎯 独立度（权重 15%）

| 条件 | 得分 |
|:---|:---:|
| 可能独立并行发现 | 1.0 |
| 可能存在借鉴 | 0.6 |
| 可能高度依赖 | 0.2 |
| 未知（默认） | 0.5 |

#### 🌐 社区认可度（权重 10%）

基于证据来源的平均可信度（9类来源的可信度值取平均）。

### 4.3 置信度计算

整体推演置信度基于证据量：

| 证据数量 | 参与方数 | 置信度 |
|:---|:---|:---:|
| ≥20条 | ≥3方 | 0.7 |
| ≥10条 | ≥2方 | 0.5 |
| ≥5条 | 任意 | 0.3 |
| <5条 | 任意 | 0.1 |

| 4 | "相似性"不构成抄袭/侵权的判定，仅提示可进一步研究 |
| 5 | 本报告**不作为任何商业决策、法律诉讼、舆论攻击的依据** |
| 6 | 报告中的置信度仅反映搜索证据的充分性，非事实确定性 |
| 7 | 如有信息不准确，欢迎提供补充证据进行校正推演 |
| 8 | 本工具所有者不为任何基于本报告的后续行为承担责任 |

### 7.2 为什么需要法律护盾

- 推演≠判定：我们只是基于公开信息做了加权排序
- 时间线≠事实：公开时间不等于研发时间
- 任何人有异议 → 提供补充证据 → 重新推演 → 结论可校正

### 7.3 配合防篡改扫描

推演结果入库前必须过 `lh_anti_tamper.py --self`（自研内容通道）：
- 红色警报词（如"判定/认定/抄袭/侵权"等）会触发熔断 → 报告不过关
- 黄色警报词仅记录不判定
- 通过后才归档到 `L7_数据层/`

## 9. 自动归档系统（v1.1 新增）

### 9.1 归档触发机制

推演完成后**自动触发归档**，无需手动操作。每次 `search`/`analyze`/`pipe` 命令执行完毕后，引擎自动将推演结果写入四层存储。

```
推演完成 → archive_trace() 自动调用
  ├─ JSONL 链（append-only，不可覆不可删）
  ├─ JSON 索引（快速查询）
  ├─ SQLite 数据库（结构化查询）
  └─ Markdown 报告文件（人类可读）
```

可通过 `--no-archive` 标志跳过归档。

### 9.2 四层存储架构

| 层 | 路径 | 格式 | 用途 |
|:---|------|------|------|
| **JSONL 链** | `L7_数据层/innovation_trace_chain.jsonl` | append-only JSONL | 事件流，不可篡改的完整记录 |
| **JSON 索引** | `L7_数据层/innovation_trace_index.json` | JSON | 快速查询，含统计信息 |
| **SQLite 数据库** | `L7_数据层/data/longhun_unified.db` → `innovation_traces` 表 | SQLite | 结构化查询，按置信度/时间/关键词筛选 |
| **MD 报告** | `L7_数据层/strategy_reports/innovation_traces/` | Markdown | 人类可读的完整报告 |

### 9.3 查询历史推演

```bash
# 列出最近的推演记录
python3 bin/lh_innovation_tracer.py list
python3 bin/lh_innovation_tracer.py list -n 50          # 显示最近50条
python3 bin/lh_innovation_tracer.py list -v             # 显示详细信息（含内容哈希）

# 获取特定推演的完整报告
python3 bin/lh_innovation_tracer.py get <DNA后缀8位>
python3 bin/lh_innovation_tracer.py get <DNA后缀8位> -v   # 完整报告
python3 bin/lh_innovation_tracer.py get <DNA后缀8位> --json  # 结构化JSON输出
```

### 9.4 数据库表结构

```sql
CREATE TABLE innovation_traces (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    dna TEXT UNIQUE,           -- DNA追溯码
    topic TEXT,                -- 推演主题
    timestamp TEXT,            -- 推演时间
    confidence REAL,           -- 置信度 (0.0-1.0)
    parties_count INTEGER,     -- 参与方数量
    evidence_count INTEGER,    -- 证据数量
    parties_json TEXT,         -- 参与方画像JSON
    timeline_json TEXT,        -- 时间线JSON
    summary TEXT,              -- 推演摘要
    report_text TEXT,          -- 完整报告
    content_hash TEXT,         -- 内容哈希（防篡改校验）
    tags TEXT,                 -- 关键词标签
    uid TEXT DEFAULT 'UID9622' -- 用户标识
);
```

### 9.5 归档特性

- **append-only**: JSONL 链不可覆不可删，永久留痕
- **DNA 绑定**: 每条记录都有唯一 DNA 追溯码
- **防篡改**: `content_hash` 基于推演内容计算，可用于校验完整性
- **DNA 注册表集成**: 自动向 `dna_registry_index.json` 登记
- **重复检测**: JSON 索引自动跳过已存在的 DNA 记录
- **优雅降级**: 任一层存储失败不影响其他层和主流程
