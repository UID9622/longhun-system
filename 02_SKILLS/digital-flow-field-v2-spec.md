## 1. 概念设计：从"统计"到"流场"

| 维度 | 旧版（v1.0 静态分析器） | 新版（v2.0 数字流场） |
|:---|:---|:---|
| 输出形式 | 表格 + 图表 | 动态粒子流场 + 实时图谱 |
| 字符映射 | 数字根 → 频次 | 数字根 → 粒子运动轨迹 |
| 交互方式 | 点击按钮 → 看报告 | 输入即流动、参数实时反馈 |
| 可解释性 | 数字根分布 | 每个字符的"流场签名"可见 |
| 后端引擎 | 无（CLI 直算） | ParticleSystem + 物理模拟 |
| 应用场景 | 统计分析 | AI 决策可视化、文本指纹识别、流场联动 |

**核心逻辑链**：
```
文本 → 逐字符 Unicode 码点 → 数字根(1-9) → 颜色/速度/方向/大小映射 → 粒子流场运动 → 数字指纹图谱
```

## 5. 核心算法 · 字符→粒子映射

### 5.1 数字根计算

```python
def char_digital_root(char: str) -> int:
    """Unicode 码点各位数字反复求和，直到 1-9"""
    code = ord(char)
    while code >= 10:
        code = sum(int(d) for d in str(code))
    return code
```

**约束**：
- 空字符 → 0（无效粒子，不渲染）
- 数字根范围严格 [1, 9]
- 与 `bin/lh_time_engine.py` 中的数字根定义一致（P06 校验通过）

### 5.2 字符→粒子映射规则

| 属性 | 映射公式 | 说明 |
|:---|:---|:---|
| **颜色** | `COLOR_SCHEMES[scheme][root]` | 三套方案可选（九色/五行/灰度） |
| **速度** | `0.3 + (root/9) × 0.7` | 数字根越大速度越快 |
| **初始角度** | `(idx/total) × 2π` | 按文本位置均匀分布 |
| **初始半径** | `0.3 + 0.3 × (idx/total)` | 螺旋展开 |
| **粒子大小** | `3 + 6 × (1 - |root-5|/4)` | 5 最大，向两端递减 |
| **轨迹上限** | `trail_length` 参数控制 | 默认 20 帧 |

### 5.3 χ² 随机性检验

- **原假设**：数字根呈均匀分布（1~9 各占 1/9）
- **自由度**：df = 8
- **临界值**：α=0.05 → χ² < 15.51 判定为"符合随机分布"
- **判定输出**：✅ 符合 / ⚠️ 偏离

### 5.4 文本数字指纹

```
每个字符的数字根 → 形成指纹序列
示例: "道可道" → [8, 7, 8]（Unicode 36947→3+6+9+4+7=29→2+9=11→1+1→2...等）
展示上限: 前 500 字符
格式: 纯数字字符串（如 878354921...）
```

## 21. 常见问题 FAQ 🆕

### Q1: 为什么数字根要用 Unicode 码点而不是字符本身？
**A**: Unicode 码点是字符的客观数字表示，不受字体、编码方式影响，且天然可跨语言。中英文混排文本用同一套算法公平对待。

### Q2: χ² 检验显示"偏离随机分布"，意味着什么？
**A**: 意味着该文本的数字根分布与均匀分布有统计显著差异。可能原因：①文本有结构性（如诗歌格律）②特定字符集偏好（如数字集中的文本）③AI 生成文本可能存在模式。这不一定是"问题"，但是一个值得注意的信号。

### Q3: 流场中粒子聚在一起正常吗？
**A**: 如果文本数字根分布偏向某些值，对应颜色的粒子会聚集。这是文本结构的真实反映。想要均匀分散的流场，可以增大中心引力参数。

### Q4: 为什么不支持 PDF/Word 直接导入？
**A**: PDF/Word 是富文本格式，结构复杂。建议先用其他工具（如 `python3 -m markitdown`）转为纯文本再导入。v2.2 计划集成格式转换。

### Q5: 能在手机上看吗？
**A**: Streamlit 界面在移动端浏览器体验不佳，推荐在桌面端使用。v3.0 计划提供移动端适配。

### Q6: 我的文本有隐私数据，安全吗？
**A**: 安全。所有处理纯本地完成，不联网、不上传、不记录。URL 抓取功能会向目标服务器发请求，这是唯一的网络调用。

### Q7: 如何集成到龍魂系统的其他模块？
**A**: 直接 `from flow_engine.core import analyze_text, generate_text_fingerprint` 即可。返回值是标准 Python dict，可被任何模块消费。
