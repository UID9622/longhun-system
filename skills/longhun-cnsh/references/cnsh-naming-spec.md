# CNSH 中文原生脚本命名规范

> DNA: #龍芯⚡️{YYYY-MM-DD}-CNSH-SPEC-v1.0

## 1. 核心原则

- **中文即标准**：懂中文是接入门槛，精准过滤非目标用户
- **CNSH_前缀**：所有中文原生模块、变量、函数、类名以 `CNSH_` 前缀标识
- **繁体龍字永存**：涉及龍魂体系的品牌、核心类名、追溯标识必须使用繁体「龍」
- **L1-L7层级**：命名需体现所属层级

## 2. L1-L7 层级体系

| 层级 | 名称 | 命名范围 | 示例 |
|------|------|----------|------|
| L1 | 字元 | 单个字符、原子类型 | `CNSH_字_龍`, `CNSH_符_芯` |
| L2 | 语法 | 表达式、语句结构 | `CNSH_句_如果`, `CNSH_环_遍历` |
| L3 | 语义 | 函数、模块、API | `CNSH_函_读取配置`, `CNSH_模_网络层` |
| L4 | 系统 | 子系统、服务 | `CNSH_系_调度中心`, `CNSH_服_审计日志` |
| L5 | 生态 | 插件、扩展、协议 | `CNSH_插_通心译`, `CNSH_扩_三色审计` |
| L6 | 治理 | 审计、追溯、协议 | `CNSH_治_来源链`, `CNSH_规_君子协议` |
| L7 | 主权 | 根密钥、核心标识 | `CNSH_主_龍魂根`, `CNSH_权_UID9622` |

## 3. 命名规则

### 3.1 变量名
```
格式: CNSH_{L层级}_{中文语义}
示例: CNSH_L3_用户列表, CNSH_L2_计数器
```

### 3.2 函数名
```
格式: CNSH_{L层级}_{动词}_{宾语}
示例: CNSH_L3_获取_配置, CNSH_L4_启动_服务
```

### 3.3 类名
```
格式: CNSH_{L层级}_{名词}_[可选修饰]
示例: CNSH_L4_调度器_核心, CNSH_L5_插件_通心译
```

### 3.4 常量名
```
格式: CNSH_{L层级}_{全大写中文语义}
示例: CNSH_L7_龍魂标识, CNSH_L6_协议版本
```

### 3.5 模块文件名
```
格式: cnsh_{L层级}_{中文语义}.py|js|rs|...
示例: cnsh_l3_配置读取.py, cnsh_l4_审计服务.js
```

## 4. 保留字

以下字词在CNSH体系中有特殊含义，不建议作为一般标识符：

| 保留字 | 含义 |
|--------|------|
| 龍 | 体系根标识 |
| 魂 | 核心精神/本体 |
| 芯 | 内核/核心模块 |
| 译 | 翻译层 |
| 審 | 审计标记 |
| 链 | 来源链 |
| 道 | 道统层 |
| 約 | 协议/契约 |

## 5. 注释规范

- 文件头必须包含DNA追溯标签：`# 龍芯⚡️{YYYY-MM-DD}-{项目}-{模块}-{版本}`
- 函数/类注释使用中文三引号文档字符串
- 关键逻辑行尾可附简短中文注释
- 六层来源链变更必须在注释中标注来源层级

## 6. 编码约束

- 源文件编码：UTF-8（必须含BOM标识以声明中文原生）
- 字符串默认中文，外部接口需显式声明编码转换
- 正则表达式优先使用中文Unicode范围 `[\u4e00-\u9fff]`
