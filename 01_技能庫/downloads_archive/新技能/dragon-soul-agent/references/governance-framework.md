# 龍魂治理框架

> DNA: #龍芯⚡️{YYYY-MM-DD}-GOVERNANCE-FW-v1.0

## 1. 三色审计体系

所有代码变更必须通过三色审计标记：

### 🟢 安全（Green / 通）
- 纯文本修改、注释更新、文档补充
- 不改变运行逻辑的配置调整
- 已验证的依赖版本升级（patch级别）
- **审批**：自动通过，记录存档

### 🟡 审查（Yellow / 審）
- 新增函数/模块但接口兼容
- 逻辑修改但已有测试覆盖
- 依赖版本升级（minor级别）
- **审批**：需同行审查（Peer Review），1人通过即可

### 🔴 阻断（Red / 阻）
- 核心逻辑变更、算法替换
- 破坏性接口修改（Breaking Change）
- 新增外部依赖、网络权限请求
- 涉及用户数据的处理逻辑
- **审批**：核心组全票通过 + 回归测试全部通过

### 审计标记格式
```
[审计-{颜色}] {YYYY-MM-DD} {审计人} {结论}
例如: [审计-🟡] 2025-06-18 龍魂審查員 需補充單元測試
```

## 2. DNA追溯系统

### 2.1 DNA标签格式
```
#龍芯⚡️{YYYY-MM-DD}-{項目}-{模塊}-{版本}
```

- `YYYY-MM-DD`：创建或重大更新日期
- `項目`：项目代号（如 DRAGON, CNSH, TONGXIN）
- `模塊`：模块名（如 SPEC, CORE, AUDIT, TRANSLATE）
- `版本`：版本号（如 v1.0, v2.1.3）

### 2.2 标注位置
- 每个源文件头部注释区
- 每个函数/类的文档字符串中（如该函数为核心逻辑）
- 发布包/Manifest中
- 审计记录中

### 2.3 DNA验证规则
- DNA标签不可修改，只能追加新版本
- 历史DNA必须保留在文件注释中
- DNA变更必须在提交信息中说明理由

## 3. 六层来源链

任何产出必须声明完整的六层来源链，从根本到具体：

```
道統 → 精神 → 設備 → 技術 → 系統 → 生命
```

| 层级 | 名称 | 含义 | 声明示例 |
|------|------|------|----------|
| 第1层 | 道统 | 文化根源、思想传统 | 「源自中华技术道家传统」 |
| 第2层 | 精神 | 设计理念、价值观 | 「秉承中文即标准、底层私有之精神」 |
| 第3层 | 设备 | 硬件环境、基础设施 | 「运行于自托管ARM集群」 |
| 第4层 | 技术 | 核心技术栈、算法 | 「基于PyTorch + 自定义中文Tokenizer」 |
| 第5层 | 系统 | 软件系统、框架版本 | 「CNSH Runtime v2.1 / 龍魂内核 v3.0」 |
| 第6层 | 生命 | 创造者、维护者、社区 | 「由UID9622发起，龍魂社区维护」 |

### 来源链声明格式
```markdown
> 來源鏈：道統(中華技術道家) → 精神(中文即標準) → 設備(自託管ARM) → 
> 技術(PyTorch+中文Tokenizer) → 系統(CNSH_Runtime_v2.1) → 生命(UID9622/龍魂社區)
```

## 4. 君子协议

### 4.1 许可证
- **默认许可证**：CC BY-NC-SA 4.0（署名-非商业性使用-相同方式共享）
- 核心龍魂模块：额外附加「中文理解门槛」条款——代码开源，但核心注释以中文书写，形成天然的理解与使用门槛

### 4.2 使用约束
1. **来源链不可切断**：任何衍生作品必须保留完整的六层来源链声明
2. **DNA标签不可移除**：文件头部的DNA追溯标签必须保留
3. **三色审计继承**：衍生作品的变更仍需执行三色审计
4. **非商业优先**：商业使用需单独授权

### 4.3 贡献规范
- 所有贡献自动视为接受君子协议
- 提交信息使用中文或中英双语
- 新贡献者首次PR需通过 🔴 阻断级审计

```markdown
- [ ] DNA标签完整且格式正确
- [ ] 六层来源链已声明
- [ ] 三色审计标记已附加

- [ ] CNSH命名规范符合度已检查
```

### 5.2 自动化审计触发词
代码审查时扫描以下关键词自动提升审计级别：
- `TODO` / `FIXME` → 至少 🟡
- `hack` / `workaround` → 至少 🟡
- 涉及网络请求、文件系统操作 → 至少 🟡
- 涉及加密、认证、授权 → 强制 🔴
- 新增外部依赖 → 强制 🔴
