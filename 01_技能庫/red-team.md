## 攻击面检测清单（10大类）

### 1. 注入类漏洞
- SQL 注入（含 NoSQL 注入）
- 命令注入（OS Command Injection）
- 模板注入（SSTI）
- 表达式注入（EL/OGNL/SpEL）
- LDAP/XML/XPath 注入

### 2. 认证与授权
- 越权访问（IDOR/水平越权/垂直越权）
- 会话劫持与会话固定
- JWT 签名绕过
- 凭证硬编码与泄露
- 弱密码策略

### 3. 输入验证
- XSS（反射型/存储型/DOM型）
- 路径遍历（Directory Traversal）
- 文件上传漏洞
- SSRF（服务端请求伪造）
- 反序列化漏洞
- 原型污染（Prototype Pollution）

### 4. 配置安全
- 默认密码/默认配置
- 错误配置暴露（Debug模式/CORS配置错误）
- 敏感信息泄露（错误页面/响应头/源码注释）
- 未受保护的内部端点

### 5. 加密与密钥
- 弱加密算法（MD5/SHA1用于安全场景）
- 密钥硬编码（API Key / Token / Secret）
- 证书配置问题
- 随机数生成器弱点
- .env 文件泄露风险

### 6. API 安全
- 未授权 API 端点
- 敏感数据过度暴露
- 速率限制缺失/可绕过
- GraphQL 内省/深度查询攻击
- Mass Assignment 漏洞

### 7. 依赖链安全
- 供应链攻击（恶意依赖包）
- 过期依赖（已知 CVE 未修复）
- 许可证合规风险
- 依赖混淆攻击（Dependency Confusion）

### 8. AI/LLM 特有漏洞
- 提示词注入（Prompt Injection）
- 越狱诱导（Jailbreak）
- 角色扮演绕过
- 渐进式诱导（Crescendo Attack）
- 上下文污染（Context Poisoning）
- 输出劫持（Output Hijacking）

### 9. 逻辑漏洞
- 业务逻辑绕过
- 竞态条件（Race Condition）
- 整数溢出
- 支付逻辑绕过
- 优惠券/折扣逻辑漏洞

### 10. 数据泄露
- 日志敏感信息泄露
- 错误信息过度暴露
- 缓存泄露
- 响应头信息泄露
- 源码注释中的敏感信息

## 检测方法论

### 七步检测法

```
Step 1: 信息收集
  ├── 了解目标系统的架构、技术栈、依赖链
  ├── 读取文档、配置文件、README
  └── 建立攻击面地图

Step 2: 攻击面测绘
  ├── 列出所有外部可访问的入口点（API/页面/WebSocket/文件上传）
  ├── 识别认证边界（哪些端点需要认证，哪些不需要）
  └── 标记高价值目标（涉及数据/资金/权限的操作）

Step 3: 漏洞检测
  ├── 逐项按10大类清单扫描
  ├── 用安全方式验证漏洞存在（不执行破坏性操作）
  └── 记录：漏洞类型·位置·payload·影响范围

Step 4: 风险评估
  ├── 🔴 严重：可导致数据泄露/系统控制/权限提升
  ├── 🟡 中等：可导致信息泄露/功能绕过/部分影响
  └── 🟢 低危：信息收集/配置建议/最佳实践偏离

Step 5: 修复建议
  ├── 给出具体的修复代码/配置
  ├── 说明修复原理和可能的副作用
  └── 标注修复优先级（紧急24h/本周/下迭代）

Step 6: P72 熔断审
  ├── 所有发现提交 P72 龍盾审核
  ├── P72 对修复方案进行安全评估
  └── P72 有权标记"不可修复，需架构调整"

Step 7: 复验确认
  ├── 修复完成后重新检测
  ├── 确认漏洞已关闭
  └── 记录复验结果和最终状态
```

### 对抗性思维

红客与普通安全审计的区别在于**对抗性思维**：

| 普通审计 | 红客思维 |
|------|------|
| "这个功能是否正确？" | "这个功能怎么被滥用？" |
| "输入有没有校验？" | "校验能不能被绕过？" |
| "权限检查有没有？" | "权限检查的边界在哪里？能不能越过去？" |
| "加密了没？" | "加密实现有没有侧信道？密钥管理安全吗？" |
| "按文档测试" | "文档没写的地方是什么？" |
