## 一、協議概述

### 1.1 目標與哲學

**核心哲學：**「先讀懂、再決定怎麼接。」

本協議定義龍魂體系處理一切外部輸入時的標準化流程。任何來自用戶、傳感器、API或文件的輸入，在進入認知處理鏈之前，必須經過本協議定義的過濾與預處理流程。

**存在理由：**
- 未經過濾的輸入是認知混亂的第一根源
- 垃圾進、垃圾出（GIGO, Garbage In Garbage Out）—— 輸入質量決定輸出質量
- 本協議是認知守門人，不是可選插件

## 四、協議執行框架（3階段映射3層監督）

本協議將輸入處理流程劃分為三個階段，分別對應三層監督器的感知層、認知層、決策層。每個階段輸出結構化評分，作為下一階段的輸入。

```
輸入處理流程：
┌─────────────────────────────────────────────────────────────┐
│  感知層 (Perceiving)  →  認知層 (Cognizing)  →  決策層 (Deciding)  │
│     ↓                        ↓                       ↓       │
│  語義錨點提取              衝突檢測+缺失識別         交互確認     │
│  結構化封裝                評分計算                 證據鏈生成   │
│  噪聲隔離                  熔斷判斷                 放行/阻斷    │
└─────────────────────────────────────────────────────────────┘
```

### 4.1 感知層 — 語義錨點提取與結構化封裝

**對應監督層：** 感知層（輸入篩查）
**目標：** 讀懂輸入，將無結構文本轉為結構化數據

**4.1.1 關鍵詞掃描**

掃描輸入文本，識別核心錨點詞彙：

| 錨點類型 | 示例詞彙 | 處理方式 |
|---------|---------|---------|
| 條件錨點 | 「已知」、「若」、「假設」 | 標記為條件語句 |
| 目標錨點 | 「求证」、「求」、「計算」 | 標記為目標語句 |
| 約束錨點 | 「约束」、「限制」、「範圍」 | 標記為邊界條件 |
| 引用錨點 | 「如图」、「參考」、「引用」 | 標記為外部依賴 |
| 否定錨點 | 「不」、「無」、「非」 | 標記為邏輯反轉 |

**4.1.2 結構化封裝（LongHunInput 格式）**

所有輸入經過掃描後，統一封裝為以下結構：

```
LongHunInput {
    raw_text:       string          // 原始輸入文本
    source_type:    enum            // 來源類型：user|api|sensor|file
    timestamp:      ISO8601         // 接收時間戳
    
    semantic_anchors: [             // 語義錨點列表
        {
            type:     enum           // condition|goal|constraint|reference|negation
            text:     string         // 錨點文本
            position: [start, end]   // 在原文中的位置
            confidence: float        // 識別置信度 (0.0-1.0)
        }
    ]
    
    entities: [                     // 提取的實體
        {
            name:     string         // 實體名稱
            type:     enum           // number|variable|object|concept
            value:    any            // 實體值
            unit:     string         // 單位（如有）
        }
    ]
    
    noise_markers: [                // 噪聲標記
        {
            type:     enum           // emotional|redundant|irrelevant|profanity
            text:     string         // 噪聲文本
            position: [start, end]
        }
    ]
    
    metadata: {
        language:     string         // 語言代碼
        complexity:   int            // 複雜度評分 (1-10)
        domain_hint:  string         // 領域提示
    }
}
```

**4.1.3 非結構化清洗**

對輸入中混有的非結構化內容進行隔離：

- **情緒詞**：「拜託」、「煩死了」→ 標記為 `emotional`，不納入推理
- **髒話**：「他媽的」→ 標記為 `profanity`，過濾但保留語境標記
- **重複短語**：連續重複 3 次以上 → 標記為 `redundant`，去重
- **無關閒聊**：與主題無關的寒暄 → 標記為 `irrelevant`，剝離

**感知層輸出：** 結構化的 `LongHunInput` 對象 + 感知評分 (0-100)

---

### 4.2 認知層 — 多維衝突檢測與缺失識別

**對應監督層：** 認知層（邏輯驗證）
**目標：** 發現問題，檢測衝突與缺失

**4.2.1 數值與邏輯一致性校驗**

對 `LongHunInput.entities` 中的所有數值進行交叉驗證：

| 校驗類型 | 檢測邏輯 | 示例 |
|---------|---------|------|
| 數值矛盾 | 同一變量出現多個值 | AD=2 與 AD=10 同時存在 → 🔴 |
| 邊界越界 | 值超出物理/數學常識 | 概率>1、邊長<0 → 🔴 |
| 單位不一致 | 同一變量單位混用 | 5m + 3cm 未換算 → 🟡 |
| 邏輯閉合 | 條件是否形成閉環 | A→B→C→A 無窮遞歸 → 🟡 |

**4.2.2 衝突熔斷機制**

當認知層檢測到衝突時，觸發熔斷：

```
熔斷流程：
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 檢測衝突  │───→│ 評估嚴重性 │───→│ 觸發熔斷  │───→│ 暫停處理  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
                     │                                  │
                     ▼                                  ▼
               嚴重性分級                          等待用戶澄清
               · 致命 (≥2項衝突) → 🔴 立即熔斷
               · 嚴重 (1項致命)  → 🔴 單點熔斷
               · 輕微 (邊界問題) → 🟡 警告放行
```

**熔斷後的行為：**
- 生成結構化澄清請求（見 4.3.1）
- 記錄熔斷原因到 DNA 證據鏈
- 暫停下游處理，等待用戶響應
- 不生成任何基於衝突數據的推論

**4.2.3 缺失項識別**

判斷當前輸入是否足以支撐唯一解或完整推導：

| 缺失類型 | 檢測邏輯 | 置信度影響 |
|---------|---------|-----------|
| 關鍵參數缺失 | 目標需要但實體列表中無 | -40 分 |
| 約束條件缺失 | 有目標無邊界 | -20 分 |
| 上下文缺失 | 引用外部內容但未提供 | -15 分 |
| 單位缺失 | 數值無單位 | -10 分 |

**4.2.4 假設前置聲明**

當條件不完備時，必須在使用假設前聲明：

```
【假設前置聲明模板】
⚠️ 當前條件存在缺失，以下解答基於高置信度假設進行推導：

假設 [具體假設內容]
依據 [假設來源/理由]
置信度 [0.0-1.0]

若與實際情況不符，請指正，我將重新推導。
```

**認知層輸出：** 驗證報告 + 認知評分 (0-100) + 熔斷狀態

### 4.3 決策層 — 交互確認與DNA證據鏈生成

**對應監督層：** 決策層（行為審核）
**目標：** 確認處理，生成可追溯的處理記錄

**4.3.1 主動核實請求**

當觸發衝突或歧義時，生成精準的確認信息：

```
【確認請求模板】
🔍 檢測到輸入條件存在不一致：

衝突點：[具體衝突描述]
位置：[在原文中的位置]
類型：[數值矛盾/邊界越界/邏輯衝突]

請確認：
□ 選項A：[選項A描述]
□ 選項B：[選項B描述]
□ 其他：[請補充說明]

> 您的確認將被記入DNA證據鏈，用於確保推導過程可追溯。
```

**4.3.2 DNA證據鏈生成**

每次輸入處理完成後，生成L4級別的DNA證據鏈：

```
證據鏈格式：
#龍芯⚡️{YYYY-MM-DD}-INPUT-{輸入哈希前8位}-v3.0
├── 輸入來源: {source_type}
├── 感知評分: {感知評分}/100
├── 認知評分: {認知評分}/100
├── 決策評分: {決策評分}/100
├── 審計標記: {🔴/🟡/🟢}
├── 衝突記錄: [{衝突列表}]
├── 缺失記錄: [{缺失列表}]
├── 假設聲明: [{假設列表}]
├── 用戶確認: [{確認記錄}]
└── 處理結果: {放行/阻斷/暫停}
```

**決策層輸出：** 最終決策（放行/阻斷）+ 完整證據鏈

```
║        └─ 當前輸入是否包含足夠信息獨立處理？                 ║
║        └─ 缺失信息是否已識別並標記？                         ║
║        └─ 是否存在未聲明的隱含依賴？                         ║
║                                                              ║
║  □ 5. 確認機制觸發（Confirmation Trigger）                   ║
║        └─ 是否存在紅色標記（阻斷級問題）？                   ║
║        └─ 是否存在黃色標記（警告級問題）？                   ║
║        └─ 是否已生成針對性澄清請求？                         ║
║        └─ 用戶確認是否已收到並記錄？                         ║
║                                                              ║
╚══════════════════════════════════════════════════════════════╝
```

**自檢規則：**
- 五項全部通過 → 輸入進入下游處理鏈
- 任意一項未通過 → 輸入暫留本層，觸發對應修復流程
- 第5項中的紅色標記 → 強制阻斷，不可繞過
