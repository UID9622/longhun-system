# 🐉 训练/测试 回滚守护机制 v1.0

> DNA: #龍芯⚡️丙午·丁酉·壬午·巳时·䷘无妄-TRAIN-ROLLBACK-GUARD-v1.0-AUTO
> 创建者: 诸葛鑫（UID9622）· 归属名: 诸葛鑫 | UID9622 · 龍芯北辰 · License: MulanPSL v2
> 触发源: 老大原话「那些测试数据全部要收集好。有些数据在跑，如果说触发就是走坏了，这个码要回滚，要触发回滚这个机制」
> 实证: v4.2.0 训练曾 METAL GPU 崩溃（iter720·当时零 run 档案·零回滚留痕）

## 引擎
`python3 08_BIN/lh_train_rollback_guard.py`（轻量·纯标准库·不 import 模型库）

## 三条铁律 → 落地映射
| 老大要求 | 机制落地 |
|:---|:---|
| 测试数据全部收集好 | 每次 run 全量档案 → `~/.longhun/train_runs/runs.jsonl`（起止/参数/退出码/崩溃原因/产物哈希/回滚事件·append-only）+ 完整日志 `logs/train_<id>.log` |
| 触发就是走坏了 | 子进程退出码≠0 → 特征词分类：`broken_metal`/`broken_oom`/`broken_nan`/`broken_crash`/`broken_unknown` |
| 触发回滚机制 | 自动固化「崩溃前最优 best」→ `~/.longhun/train_runs/snapshots/<run_id>/` + 回滚事件 `rollback.jsonl` + 打印下次续训回滚点 |

## 回滚规则（崩了回滚到哪）
1. run 内 `best_adapters.safetensors` 存在且 ≠ resume 起点 → 固化**崩前最优**（下轮 rmtree 也丢不了）
2. run 无改善 / 无 best → 回滚点 = **resume 起点**（上一稳定版 best，如 v419 Val 0.8115）
3. 代码层：trainer 脚本改崩了 → git 检出上一稳定 commit 覆盖后重训（引擎 docstring/事件留痕可追溯）

## 用法
```bash
python3 08_BIN/lh_train_rollback_guard.py run v420            # 守护 v4.2.0 train（推荐入口）
python3 08_BIN/lh_train_rollback_guard.py run v420 test       # 守护冒烟
python3 08_BIN/lh_train_rollback_guard.py status [--n 5]      # 最近 run 档案+回滚事件
python3 08_BIN/lh_train_rollback_guard.py recover --log <日志> --adapter <adapter目录> \
        --resume <起点best> --solidify --reason "..."          # 历史 run 补录（数据收集）
python3 08_BIN/lh_train_rollback_guard.py selftest            # 机制自检（不碰真实权重）
```

## 数据主权
档案/快照仅存本地 `~/.longhun/train_runs/`，不入云、不入 git。测试数据=完整收集=本地留底。
