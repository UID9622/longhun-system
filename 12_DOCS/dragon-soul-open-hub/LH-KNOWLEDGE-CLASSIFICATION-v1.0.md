## 一、定位

老大指令：**「不是我拉任何仓库，而是把这些全部归类，到时候按需分布式去填充」**。

- **不拉仓库**：Notion 是主力知识存储（8/28 焊死），内容原址不动
- **归类**：设计统一分类体系 + Notion 数据库结构，让每条知识有固定索引槽位
- **按需分布式填充**：API 网关收到请求 → 查索引 → 按主题从 Notion 对应库拉取 → 返回（RAG 模式）

## 三、Notion 数据库结构（索引库「🐉 龍魂知识索引」）

> 利用 Notion **数据库（database）功能**做统一索引，每个库（data_source）是独立条目。

| 属性 | 类型 | 说明 |
|:---|:---|:---|
| 名称 | title | 库/条目名 |
| 分类 | select | 8 大类（上表） |
| 标签 | multi_select | 二级标签 |
| 数据源ID | rich_text | Notion `data_source_id`（**注意：非 database_id**） |
| 本地路径 | rich_text | 本地对应路径（`[[local:path]]`） |
| 摘要 | rich_text | 一句话摘要 |
| DNA | rich_text | 条目 DNA 追溯码 |
| 更新日期 | date | 最后同步时间 |
| 同步状态 | select | 已同步 / 待同步 / 离线 |

## 四、按需分布式填充（RAG 流程）

```
请求 /v1/knowledge?q=xxx&category=算法
   ↓ 网关计费闸（鉴权→限流→扣费）
   ↓ 查 Notion 索引库 → 命中分类/标签
   ↓ 按 data_source_id 检索对应库内容
   ↓ 组装结果返回（原文不回传，只回命中片段+来源）
```

1. **索引层**：`lh_logs_sync.py` 同款机制，增量把本地/Notion 内容登记进索引库（哈希去重）
2. **检索层**：MCP `API-post-search`（按 data_source_id + query）拉命中页块
3. **缓存层**：命中内容摘要缓存在 `12_DOCS/dragon-soul-open-hub/`（K1/K2 三档，见 `LH-KNOWLEDGE-LINK-DESIGN-v1.0.md`）
