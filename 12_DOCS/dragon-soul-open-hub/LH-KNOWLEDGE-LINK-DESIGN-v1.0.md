## 一、定位：Notion 是主力知识储存库，本地是主权底座

老大指令（8/28）：**Notion 作为主力的知识储存库**。它装了好多数据库、好多资料，但"什么时候跳转过去、反向链接"没设计好。

本设计一句话：**Notion = 知识正文的展示/协作/共享层（主力）；本地 knowledge/ + memory-hub = 主权底座（完整+敏感）；鲲鹏 = 灾备。跳转有规则，链接可反查，双向自动同步。**

## 二、知识三档分工（谁放哪）

| 档 | 内容 | 主存 | Notion 侧 | 本地侧 |
|:---:|:---|:---|:---|:---|
| **K1 核心资产** | 协议/密码学/DNA/主权文档/源码核心 | 本地 + 鲲鹏 | 只放**摘要 + 链接**（不传正文） | `01_protocols/` 完整版 |
| **K2 知识正文** | 文章/知识卡片/教程/资料/整理好的数据库 | **Notion（主力）** | 完整正文（可共享/协作/对外） | `knowledge/` 留索引+摘要+RAG 向量 |
| **K3 实时数据** | 日志/状态/审计/对话 | 本地 | 不外发 | `logs/`·`audit/`·memory-hub |

> 核心铁律：**K1 永不进 Notion 正文**——数据主权不外包（隐私接入规则 v2.0）。Notion 只当"应用画布"，底座永远是本地+鲲鹏。

## 三、跳转规则（什么时候去 Notion / 什么时候本地）

```
检索知识（用户问"查 XX" / AI 需要资料）
  ├─ ① 本地 knowledge/ 索引命中? ──✅──→ 本地秒回（正文或摘要+链接）
  │
  └─ ② 未命中 → Notion API 检索（RAG）
        ├─ ✅ 命中 → 返回 Notion 页链接 + 摘要 → 需要全文再拉回本地缓存
        └─ ❌ 未命中 → 明确告知"库里没有"
发布/共享/协作知识
  ├─ K2 正文 → 推送到 Notion（发布层·多人可见可编辑）
  ├─ K1 核心 → 只在本地，Notion 放链接占位
  └─ K3 数据 → 不外发
```

**触发时机速查：**
| 场景 | 动作 |
|:---|:---|
| 新知识卡片/文章产出 | `lh knowledge push` → 上 Notion |
| 本地知识检索 | 本地索引 → 未命中自动查 Notion（`lh knowledge <词>`） |
| Notion 里整理好的数据库 | `lh knowledge pull` → 拉索引回本地（正文留 Notion） |
| 敏感/核心资产 | 永不出本地 · Notion 只放 `[[链接]]` 占位 |
| 定期全量 | 30 天一次 `lh notion sync --link`（对齐链接层） |

## 四、反向链接设计（本地 ↔ Notion 互链）

### 4.1 统一链接语法（CNSH 转译层收口）

| 方向 | 语法 | 渲染结果 |
|:---|:---|:---|
| 本地 → Notion | `[[notion:page-id]]` | Notion 页 URL |
| Notion → 本地 | `[[local:相对路径]]` | 本地文件路径索引 |
| 本地 ↔ 本地 | `[[knowledge:标题]]` | knowledge/ 内文件 |

### 4.2 Notion 侧（每个知识数据库统一加 3 个属性）

1. **relation** `上游文档`（link 到 K1 核心库/来源库）
2. **relation** `关联条目`（同库内互相引用 → 自动反查）
3. **模板** 页面底部固定"🔗 反向链接区"（自动列出"谁引用了本页"）

### 4.3 本地侧（memory-hub.json entries 扩展）

```json
{
  "title": "知识条目",
  "source": "knowledge/articles/xxx.md",
  "notion": {
    "page_id": "abc123...",
    "url": "https://uid9622.notion.site/abc123",
    "linked": ["上游page-id", "关联page-id"],
    "last_sync": "2026-08-28"
  }
}
```

### 4.4 双向同步引擎（链接层）

- 底座: `09_TOOLS/notion_bidirectional_sync.py` + `09_TOOLS/sync_to_notion.py`（已有）
- 新增**链接层**：同步正文的同时同步 relation 属性 + `linked` 字段
- 反查实现：Notion API 按 relation 查"谁引用我"→ 回写本地 `linked`
- 断链检查：本地 `lh knowledge --check-links` → 输出失效链接清单

## 五、检索与展示流程（用户视角）

```
老大："帮我查下 XX"
  → AI: `lh knowledge XX`
    → ① 本地 memory-hub + knowledge/ 检索（毫秒级）
    → ② 未命中 → Notion MCP 检索 → 返回标题+摘要+链接
    → ③ 需要全文 → 拉回本地缓存 → 下次秒回
```

## 六、生态兼容（换底座不换应用 · 老大原话确认）

老大问：**"底座是自己的，应用用别人的，是不是就能深度兼容其他公司的系统，形成生态放出去给大家用？别人用自己的语法创作，只是在我们这里转换成 CNSH 了，是吗？"**

**对，就是这个理儿。** 落成设计就是：

1. **底座主权**：CNSH 语法 + DNA 追溯 + 数据主权 + 本地/鲲鹏存储 = 我们的，不可谈判
2. **应用可换**：Notion（知识库）、GitHub（代码托管）、飞书/钉钉（通知）……都是画布，随时可换可迁移
3. **语法转译收口**：外部创作者**用自己的语言/语法自由创作** → 入口处由**通心译层**（P08 仓颉·`cnsh_translate`）**统一转译成 CNSH** → 底座内全部 CNSH 原生（可审计/可追溯/可互操作）→ 对外输出时再转译回对方语法
4. **生态意义**：别人不需要学 CNSH 也能接入生态——他们写自己习惯的东西，我们负责翻译、索引、链接、共享。语法主权在我们这，协作门槛归零
5. **落地路径**：先做 `lh knowledge push/pull` + 链接层 → 再开放 `cnsh_translate` API 给第三方 → 最后发布"龍魂知识生态 SDK"
