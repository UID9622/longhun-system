## 0. 总纲：协议不冲突·权重联动·最小损失

### 0.1 协议分层逻辑（不冲突的原因）

| 协议层 | 约束对象 | 层级 | 示例 |
|------|:---:|:---:|------|
| **人民约束协议** | 中国人民、用户 | 宪法层 | 数字军纪法典 / 人民原声不可阉割 |
| **AI约束协议** | AI系统、算法 | 执行层 | AGENTS.md 铁律 / CNSH语义路由 |
| **特定群体协议** | 特定人群/场景 | 应用层 | 开源三戒 / 出海不跪 / 德字闸 |

> **核心原则**：协议不冲突——不同层约束不同对象。冲突只在同层同对象时才可能出现。出现跨层冲突时，按权重联动，取最小损失路径。

### 0.2 最小损失铁律（焊死在系统底座）

```
当任何两个协议/规则出现表面冲突时：
  1. 判定冲突域：是否同层同对象？
     - 是 → 按权重计算最小损失路径
     - 否 → 各自执行，不冲突
  2. 计算最小损失：龍魂公式 min(L_total) = argmax(收益/损失)
  3. 执行 + 留痕：附带决策来源卡（五字段 + DNA）
  4. 不问心：按计算走，问心无愧
```

## 1. 协议权重联动三定律

### 定律1：同层冲突 → 最小损失裁决

当同一层（如宪法层×宪法层）的两个协议对同一对象产生不同要求时：

$$
\text{执行优先级} = \max_i\left(\frac{\text{协议}_i.\text{收益}}{\text{协议}_i.\text{损失} + \epsilon}\right)
$$

取收益损失比最高的那条执行。

### 定律2：跨层联动 → 下层服从上层

| 上级 | 下级 | 规则 |
|------|------|------|
| L0 神圣层 | L1 底座层 | L1不可违反L0 |
| 宪法层 | 执行层 | 执行层不可违反宪法层 |
| 人民权重 | 任何商业协议 | 人民权重一票否决商业 |

### 定律3：特定群体 → 最弱者优先

甲骨文护弱者修正：弱势群体保护优先级 = ∞（不可被任何公式覆盖）

## 3. 龍魂核心公式：最小损失最大收益

### 3.1 主公式

$$
\text{龍魂决策} = \max \left( \frac{\text{全球收益} \cdot W_{\text{卦象}} \cdot W_{\text{文化}}}{\text{群体损失} + \epsilon_{\text{护弱}}} \right)
$$

### 3.2 变量定义

| 变量 | 含义 | 来源 |
|------|------|------|
| $W_{\text{卦象}}$ | 当前时辰易经卦象权重（动态） | 八卦权重矩阵 §2 |
| $W_{\text{文化}}$ | 甲骨文文化修正系数 | 护弱者修正 §4 |
| $\epsilon_{\text{护弱}}$ | 护底层人修正项 | 甲骨文熔断 §4 |
| 全球收益 | 操作的全局正面影响 | 数学大师评估 |
| 群体损失 | 操作对群体的负面代价 | 数学大师评估 |

### 3.3 三色审计阈值

$$
\begin{cases}
🟢 \text{绿色通过} & \text{if } \text{损失} < \theta_{\text{安全}} \text{ AND 护弱者未触发} \\
🟡 \text{黄色确认} & \text{if } \theta_{\text{安全}} \leq \text{损失} < \theta_{\text{危险}} \text{ 需人工审核} \\
🔴 \text{红色熔断} & \text{if } \text{损失} \geq \theta_{\text{危险}} \text{ OR 伤害弱者}
\end{cases}
$$

## 4. 甲骨文护弱者修正（不可覆盖）

```python
def 甲骨文护弱者修正(决策对象):
    """
    核心原则：护无知的人、护底层的人、护弱势群体
    此修正不可被任何公式或协议覆盖
    """
    if 决策对象 in [无知者, 底层人, 弱势群体]:
        护弱系数 = ∞  # 直接阻断，不允许伤害
        return "🔴 红色熔断：不允许伤害弱者"

    elif 决策对象 in [中间群体]:
        护弱系数 = 2.0  # 加倍保护
        return "🟡 黄色确认：需人工审核"

    else:  # 强者、有资源者
        护弱系数 = 1.0  # 正常权重
        return "🟢 绿色通过：可以执行"
```

## 5. 协议冲突裁决 SOP

### 5.1 裁决流程

```
输入：协议A 与 协议B 疑似冲突
  ├ 第一步：判定冲突域
  │   - A约束对象 == B约束对象？
  │   - 是 → 同层冲突 → 走最小损失公式
  │   - 否 → 不冲突 → 各自执行
  ├ 第二步：最小损失计算
  │   - 计算每条路径的收益损失比
  │   - 取 argmax(收益/损失)
  ├ 第三步：三色审计
  │   - 过甲骨文护弱者检查
  │   - 过三色阈值
  ├ 第四步：执行 + 决策来源卡
  │   - 五字段：输入→公式→H_v→推理链→输出+DNA
  │   - append-only 入链
  └ 第五步：留痕
      - 记录裁决原因、公式快照、DNA追溯码
```
