# 🧩 复杂任务·自动分解规则 | 一句话变多步骤

<aside>
🕹️

**一句话：** 老大只说一句，系统自动拆成可执行步骤，自动分工（多人格），自动留痕（dr+三色+DNA）。

**目标：** 后期智能化更流畅，靠的是“统一入口 + 标准任务图 + 可复用模板”，而不是临时灵感。

</aside>

---

## ✅ 结论（会不会更流畅）

会。

- **你把“复杂任务”变成标准结构**（任务图 TaskGraph），后面无论接 Notion、接本地服务、接更多人格，都只是在“同一框架里加模块”。
- **你把“留痕/审计/熔断”写成统一入口**，后面系统不会因为越做越大而失控。

---

## 🧱 三条写死的总原则（重铸后的骨架）

1. **先过闸门，再谈执行：** 任何输入先过数字根 dr 闸门，再过伦理防火墙，再路由，再三色审计。
2. **一步一产物：** 每一步必须有“产物（Artifact）”，否则这一步等于没做。
3. **主权在老大：** 任务分解可以自动，但“关键分支/对外发布/不可逆动作”必须回到老大拍板。

## 🧠 1）复杂任务 = 任务图（TaskGraph）

<aside>
🧠

**定义：** 复杂任务不是“多说几句”，而是一个可执行的 DAG（有依赖关系的步骤图）。

- Node = Step（一步）
- Edge = Dependency（依赖）
- 每个 Step 必须有：输入、动作、产物、负责人、验收条件。
</aside>

### 1.1 Step 标准字段（必须齐）

| 字段 | 含义 | 例子 |
| --- | --- | --- |
| StepId | 步骤编号 | S1 |
| Owner | 负责人（人格） | P03 雯雯 |
| Action | 做什么 | 对账、归类、写报告 |
| Artifact | 产物 | “数据清单.csv” / “[风险清单.md](http://风险清单.md)” |
| Definition of Done | 完成标准 | 字段齐全 + 可复现 + 可审计 |
| DependsOn | 依赖 | S1 → S2 |
| Audit | 审计要求 | 是否需要三色审计/上帝之眼 |

## 🎭 2）人格分工规则（最小但够用）

- **P00 文心：** 语义解析 + 任务图生成 + 兜底。
- **P02 宝宝：** 执行协调 + 需要问一句确认时由宝宝开口。

## 🧩 3）任务类型模板（可复用，不靠临时发挥）

> 模板的作用：让系统自动分解时“有抓手”。
> 

### 模板A：财务报告（5步）

1. S1 数据收集（P06/数据）→ 产物：数据清单
2. S2 清洗归类（P03）→ 产物：可用数据表
3. S3 分析结论（P03+P06）→ 产物：关键指标&异常点
4. S4 报告撰写（P00）→ 产物：报告初稿
5. S5 风险/逻辑审计（P05+P03）→ 产物：最终报告

### 模板B：对外宣传文案（4步）

1. S1 需求澄清（P02）→ 产物：一句话定位 + 受众 + 禁区
2. S2 框架与创意（P00）→ 产物：提纲
3. S3 文案成稿（P00）→ 产物：初稿
4. S4 合规审计（P05）→ 产物：可发布版本

### 模板C：风险评估（4步）

1. S1 信息收集（P03）→ 产物：证据清单
2. S2 逻辑链推演（P01/推演类）→ 产物：因果链
3. S3 三色扫描（P05）→ 产物：风险清单（红黄绿）
4. S4 缓解方案（P03+P02）→ 产物：规避步骤 + 需要老大拍板点

## 🔄 4）自动分解算法（伪代码·可直接落地）

```jsx
function autoDecompose(input, dna) {
	// 0) GLOBAL_ENTRY 里的 dr/伦理 已处理
	intent = P00.parseIntent(input)
	type = classifyTaskType(intent) // 财务/文案/风险/开发/整理/未知

	template = loadTemplate(type)
	graph = buildTaskGraph(template, input)

	// 关键点：把“必须问老大”的节点标记出来
	graph = markApprovalGates(graph)

	return graph
}

function dispatch(graph) {
	for step in graph.topologicalOrder():
		if step.requiresApproval:
			return askBoss(step)
		else:
			exec(step.owner, step.action)
			audit(step)
	return done
}
```
