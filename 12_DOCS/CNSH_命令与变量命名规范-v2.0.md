## 第一章：命令命名规范

### 1.1 命令前缀：`lh6` 与 `lh` 的关系

| 前缀 | 语义 | 适用场景 | 审计要求 | 示例 |
|------|------|---------|---------|------|
| `lh6` | 龍魂 v6 正式入口（完整版） | 开发/运维/管理全场景 | 强制DNA追溯+五行校验 | `lh6 乾 start` / `lh6 震 audit` |
| `lh` | 龍魂轻量版（兼容/快速入口） | 快捷操作/日常查询 | 不强制审计 | `lh 状态` / `lh 编辑器` |

**设计原则：**
- `lh6` 为完整命令集，包含所有子命令、参数校验、审计日志、DNA追溯能力。
- `lh` 为精简版本，仅供高频、低风险操作使用，不强制审计。
- 两者共享同一套底层路由表（六十四卦路由），但权限与审计层级不同。

### 1.2 命令分类：八卦层

基于"太极生两仪，两仪生四象，四象生八卦"的哲学模型，所有 `lh6` 命令划分为八大分类：

| 卦象 | 分类 | 五行 | 说明 | 示例 |
|------|------|------|------|------|
| ☰ 乾 | 启动 | 金 | 系统初始化、服务启动 | `lh6 乾 start` / `lh6 乾 init` |
| ☷ 坤 | 状态 | 土 | 系统状态查询、运行监控 | `lh6 坤 status` / `lh6 坤 health` |
| ☳ 震 | 审计 | 木 | 日志审计、DNA追溯 | `lh6 震 audit` / `lh6 震 dna` |
| ☴ 巽 | 安全 | 木 | 权限检查、密钥管理 | `lh6 巽 secure` / `lh6 巽 cert` |
| ☵ 坎 | 主权 | 水 | 命名空间管理、域隔离 | `lh6 坎 domain` / `lh6 坎 ns` |
| ☲ 离 | 技能 | 火 | 工具扩展、算法调用 | `lh6 离 skill` / `lh6 离 algo` |
| ☶ 艮 | 同步 | 土 | 数据同步、配置分发 | `lh6 艮 sync` / `lh6 艮 push` |
| ☱ 兑 | 部署 | 金 | 服务部署、版本切换 | `lh6 兑 deploy` / `lh6 兑 rollback` |

每个分类对应一个 L0 宪法层不可修改的卦象标识，所有命令必须归属且仅归属一个卦类。

### 1.3 命令格式规范

```
lh6 <卦类> <动作> [参数...] [--flags]
```

- **卦类**：必须为八卦之一（乾、坤、震、巽、坎、离、艮、兑）。
- **动作**：动词形式，小写，如 `start`、`stop`、`list`、`show`。
- **参数**：遵循 GNU 风格，使用双连字符（`--`）。

**示例：**
```bash
lh6 乾 start --service web
lh6 坤 status --all
lh6 震 audit --since 2026-07-01
lh6 离 skill add --name 数据清洗 --path /opt/skills/data_clean.py
lh6 兑 deploy --version v1.2.0
```

### 1.4 参数风格（强制统一·GNU）

```
✅ 正确：
   lh6 震 audit --detail --json
   lh6 兑 deploy --version v1.0 --force

❌ 禁止：
   lh6 震 audit -detail        # 单横线+长选项→混用
   lh6 兑 deploy -v 1.0        # 短选项仅限 --help/-h
```

**唯一允许的短选项：**
- `-h` / `--help`：帮助
- `-v` / `--version`：版本

## 第二章：变量命名规范

### 2.1 命名空间二元划分（太极生两仪）

基于"太极生两仪"的哲学框架，变量命名空间分为两大域：

| 前缀 | 域 | 语义 | 层级 | 可变性 | 示例 |
|------|---|------|------|--------|------|
| `龍_` | 天（主权域） | 系统级、不可变、宪法层 | L0 | 只读·不可修改 | `龍_ROOT`、`龍_VERSION`、`龍_DNA` |
| `数据_` | 地（资源域） | 用户级、可配置、运行态 | L2 | 可配置·DNA审计 | `数据_端口`、`数据_路径`、`数据_配置` |

**铁律：**
- `龍_` 前缀变量：仅允许在 L0 宪法层中定义，运行时只读，任何进程不可修改。违反即熔断。
- `数据_` 前缀变量：允许在应用层自由定义，但每个 `数据_` 变量的创建需留有 DNA 审计记录。

### 2.2 变量命名规则

1. **使用下划线命名法（snake_case）**：`龍_系统版本`、`数据_服务端口`
2. **必须使用半角下划线 `_` (U+005F)**，禁止全角下划线 `＿` (U+FF3F)
3. **变量名长度不超过 64 个字符**
4. **必须包含中文字符**（体现河图洛书文化锚），但首字符禁止为数字
5. **避免保留字**：`DNA`、`L0`、`宪法`、`审计` 等宪法层专用词不可作为普通变量名

**示例：**
```python
# ✅ 合法
数据_服务端口 = 8080
数据_日志级别 = "info"
龍_系统版本 = "v1.0"

# ❌ 非法
端口 = 8080            # 缺少前缀
数据_123 = "test"      # 首字符为数字
数据_DNA = "abc"       # 使用了保留字
龍＿系统版本 = "v1.0"  # 全角下划线(U+FF3F)→编译错误
```

### 2.3 作用域声明

```python
# 全局常量（L0·天域）
龍_编辑器版本 = "v2.0"              # 全局·只读

# 用户级配置（L2·地域）
数据_当前端口 = 9627                 # 全局·可配置·DNA审计

# 实例级变量（L2+）
self.编辑器_当前语言 = "Python"      # 实例级
```

### 2.4 与旧版 CNSH 命名空间的兼容

旧版多前缀体系（引擎_/模块_/系统_/用户_/辅助_/临时_）向 v2.0 二元的迁移：

| 旧版前缀 | v2.0 迁移 | 说明 |
|---------|----------|------|
| `引擎_` | `龍_` 或 `数据_` | 核心引擎归入天域，配置归入地域 |
| `模块_` | `数据_` | 模块类引用归入地域 |
| `系统_` | `龍_` | 系统级配置归入天域 |
| `用户_` | `数据_` | 用户偏好归入地域 |
| `辅助_` | `数据_` | 辅助工具归入地域 |
| `临时_` | `数据_` | 运行时暂存归入地域 |

> **兼容承诺**：v2.0 向后兼容 v1.0 的变量名，旧命名空间仍可解析，但新代码应使用 `龍_` / `数据_` 二元体系。

## 第三章：审计与DNA追溯

### 3.1 DNA审计记录格式

所有命令执行与变量赋值均需生成 DNA 审计记录：

```
<时间戳> | <卦类> | <操作> | <DNA_HASH> | <用户>
```

**示例审计记录：**
```
2026-07-06T01:00:00Z | 乾 | start | DNA_5_a3f8c1d9e2b7f4a6 | UID9622
2026-07-06T01:05:00Z | 震 | audit | DNA_5_b4e9d2f0a3c5e7b8 | UID9622
2026-07-06T01:10:00Z | 离 | skill.add | DNA_5_c5f0e3d4a6b7c8d9 | UID9622
```

### 3.2 河图洛书DNA生成算法

```python
def 河图洛书_DNA生成(操作, 用户, 时间戳):
    # 河图洛书矩阵
    河图 = [1, 2, 3, 4, 5, 6, 7, 8, 9]
    洛书 = [4, 9, 2, 3, 5, 7, 8, 1, 6]

    # 中五不动点计算
    中五 = 河图[4]  # 值为 5
    不动点 = (中五 * len(操作)) % 9

    # 生成DNA HASH（SHA-256取前16位）
    dna_input = f"{操作}{用户}{时间戳}"
    dna_hash = hashlib.sha256(dna_input.encode()).hexdigest()[:16]

    return f"DNA_{不动点}_{dna_hash}"
```

### 3.3 DNA_HASH 特性
- 基于河图洛书不动点算法生成，确保**唯一性**与**不可篡改性**
- 审计日志存储在 `龍_审计_日志` 变量指向的路径，默认路径为 `/var/log/lh6/audit/`

## 第五章：安全层规范

### 5.1 五行权限校验

所有 `lh6` 命令执行前需通过**五行权限校验**（金→水→木→火→土）：

| 步骤 | 五行 | 校验内容 | 说明 |
|------|------|---------|------|
| 1 | 金 | 身份认证 | 基于密钥或令牌验证用户身份 |
| 2 | 水 | 域隔离 | 命名空间权限校验、跨域访问控制 |
| 3 | 木 | 权限检查 | 用户角色与命令权限匹配 |
| 4 | 火 | 审计预检 | 数字根(dr)检查、三色审计预判 |
| 5 | 土 | DNA追溯 | 生成操作DNA、锚定不可变记录 |

**五行相生链路**：金→水→木→火→土（校验执行顺序）

**五行相克约束**：
- 金克木：身份不通过则权限阻塞
- 木克土：权限不足则DNA不生成
- 土克水：DNA不可篡改保证域隔离
- 水克火：域隔离失败则审计无效
- 火克金：审计预检不过则身份需重验

### 5.2 密钥管理

- 密钥存储在 `龍_密钥_存储` 路径下，默认 `/etc/lh6/keys/`
- 密钥命名格式：`密钥_角色_用途.key`
- 密钥轮换周期：每 30 天自动轮换，旧密钥保留 7 天
