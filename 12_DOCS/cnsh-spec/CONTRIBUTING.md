## 0. 欢迎贡献

CNSH 的目标是**统一全世界语法·人人是开发者**。本仓库欢迎一切让
CNSH 更稳定、更好用、更主权的贡献——文档、代码、示例、翻译、测试。

## 1. 贡献流程

```
提 Issue（描述问题/建议）
  → Fork 或开分支
  → 按规范修改
  → 自测 + GPG 签名
  → 发 Pull Request
  → 维护者过 GATE 审核
  → 合并 + 记录 CHANGELOG
```

## 2. 硬性规范（缺一退回）

| # | 规范 | 说明 |
|:---:|:---|:---|
| 1 | 文件头三件套 | `DNA:` + `创建者:` + `协议:`，缺一即退回 |
| 2 | GPG 分离签名 | 每个改动文件生成 `.asc`，缺签不合并 |
| 3 | 繁体「龍」 | 品牌/核心名词禁用简体「龙」 |
| 4 | 解析器不猜 | 新增语法必须过 `parse_rules.md` v2.0 稳定写法 |
| 5 | 双视角封装 | 新接口按 `dual_perspective.md` v1.0 标注 `M::` / `CNSH::` |
| 6 | 无密钥入库 | 任何密钥/令牌严禁进仓库 |

## 3. 文档贡献

- 目录：`docs/spec/`（规范）· `docs/architecture/`（架构）· `docs/audit/`（审计）· `docs/examples/`（示例）
- 新增文件必须登记到 `docs/INDEX.md`
- 中英术语统一查 `docs/GLOSSARY.md`

## 4. 代码贡献

- 语言：Python 3（编译器/工具链）· CNSH（示例/脚本）
- 风格：PEP 8 + 中文注释写"为什么"（不写"做什么"）
- 依赖最小化：能标准库不三方库

## 5. 行为准则

1. 不碰红线：不删他人签名、不改历史 DNA、不伪造追溯码。
2. 说实话：做不了的说做不了，不假装完成。
3. 数据主权：不诱导用户数据上云、不默认云存。
