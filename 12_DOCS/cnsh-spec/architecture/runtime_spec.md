## 0. 一句话定位

Algorithm Runtime 是 CNSH 语言在 L2 服务层的**心脏**：接收 CNSH 指令，
解析成机器可执行结构，路由到正确执行器，全程受本地盾保护。

## 1. 四大组件

```
        ┌─────────────────────────────────────┐
        │          Algorithm Runtime          │
        │  ┌──────────┐   ┌────────────────┐  │
CNSH ──▶ │ Syntax    │──▶│ Algorithm      │  │
指令     │ Layer     │   │ Router         │  │
        │  (语法层)   │   │ (算法路由器)     │  │
        │  └──────────┘   └───┬────────────┘  │
        │                     ▼               │
        │  ┌──────────┐   ┌────────────────┐  │
        │  │ Plugin   │   │ Local Shield   │  │
        │  │ Registry │   │ (本地盾)        │  │
        │  │ (插件表)  │   │                │  │
        │  └──────────┘   └────────────────┘  │
        └─────────────────────────────────────┘
```

### 1.1 Syntax Layer（语法层）

| 项 | 规格 |
|:---|:---|
| 输入 | CNSH 源文本 |
| 处理 | 词法 → 语法 → AST（抽象语法树） |
| 依据 | `cnsh_grammar.bnf` + `reserved_keywords.txt` |
| 失败处理 | 按 `parse_rules.md` v2.0 四分类报错（P-AMB/P-DEP/P-BND/P-FMT） |
| 铁律 | 永不猜测·报分类号+位置+建议 |

### 1.2 Algorithm Router（算法路由器）

| 项 | 规格 |
|:---|:---|
| 输入 | AST + 语义标签 |
| 职责 | 意图分发·把指令路由到对应执行器 |
| 依据 | `dual_perspective.md` v1.0 的 `CNSH::` 路由视角 |
| 回退 | 无法路由 → 返回说实话报告，不静默丢弃 |
| 防抖 | 同一指令连续失败 3 次 → 锁定该路径，需人工确认 |

### 1.3 Plugin Registry（插件注册表）

| 项 | 规格 |
|:---|:---|
| 职责 | 插件注册 / 版本管理 / 权限声明 / 健康检查 |
| 注册必需 | 插件名 + 版本 + DNA 追溯码 + GPG 签名 |
| 权限 | 插件声明最小权限，默认拒绝越权 |
| 签名 | 无 GPG 签名的插件禁止加载（GATE-11） |

### 1.4 Local Shield（本地盾）

| 项 | 规格 |
|:---|:---|
| 职责 | 数据不出本地·权限闸·审计留痕 |
| 数据 | 默认本地执行·上云必须显式授权 |
| 审计 | 关键操作 append-only 留痕（谁/何时/做什么/结果/DNA） |
| 熔断 | 越权/敏感数据外传 → 立即阻断 + L1 级报告 |

## 2. 执行链路（标准流程）

```cnsh
# 用户说: 读取 "config.yaml" 并输出结果
# 1. Syntax Layer: 解析 → AST（无歧义，P-AMB=0）
# 2. Router: 语义标签 = 读取/输出 → 路由到 文件执行器
# 3. Plugin Registry: 校验 文件执行器 权限 = 读本地文件 ✅
# 4. Local Shield: 目标路径在本机白名单 ✅ 放行
# 5. 执行并返回结果
```
