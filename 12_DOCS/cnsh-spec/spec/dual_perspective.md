## 0. 一句话定位

同一个意图，机器用 `M::` 讲，路由用 `CNSH::` 讲。
**`M::` 是给解析器的精确坐标，`CNSH::` 是给路由器的语义标签。** 两者封装在一起，人读得懂、机器猜不错。

## 1. M:: 机器视角（解析器坐标）

`M::` 前缀 = "这句话必须按字面结构解析，不许联想"。

| 要素 | 说明 | 示例 |
|------|------|------|
| 前缀 | `M::` 独占标记 | `M:: 输出 "Hello"` |
| 结构 | 与 BNF 严格对应 | 动宾完整·引号齐全 |
| 用途 | 精确执行·无歧义调用 | 脚本、管道、CI |
| 特性 | 零猜测 | 报错即说实话模式（见 parse_rules §4） |

```cnsh
M:: 读取 "/etc/hosts" | M:: 搜索 "localhost" | M:: 输出
```

## 2. CNSH:: 路由视角（语义标签）

`CNSH::` 前缀 = "这句话是意图描述，交给路由器分发，不直接执行"。

| 要素 | 说明 | 示例 |
|------|------|------|
| 前缀 | `CNSH::` 独占标记 | `CNSH:: 审计 当前仓库` |
| 结构 | 允许自然语序 | 可省略宾语/修饰语 |
| 用途 | 意图路由·人格分发 | 对话入口·总控调度 |
| 特性 | 语义优先 | 由路由器转成 `M::` 后再执行 |

```cnsh
CNSH:: 帮我检查一下今天系统还好吗
# 路由器解析为:
#   M:: 审计 系统 状态
```

## 3. 使用规则与禁忌词

### 3.1 使用规则

| 场景 | 用哪个 |
|------|------|
| 要精确执行、结果要稳定 | `M::` |
| 要表达意图、交给系统决定 | `CNSH::` |
| 混合流水线 | 先 `CNSH::` 路由，落地转 `M::` |

### 3.2 禁忌词（两视角共用·一票否决）

| 禁忌 | 原因 |
|------|------|
| "随便"/"大概" | 无法路由也无法解析 |
| "你懂的" | 依赖上下文猜测 |
| "看着办" | 把歧义抛给机器 |
| 省略主语又省略宾语 | 双缺 = 双视角都断 |

## 4. 输出结构示例

### 4.1 路由响应（CNSH:: → M::）

```cnsh
CNSH:: 部署 到鲲鹏
# 响应:
#   [CNSH::] 意图=部署, 目标=鲲鹏
#   [M::] 执行 "deploy/scripts/DEPLOY.md"
#   [M::] 审计 "部署前安全扫描"
```

### 4.2 机器响应（M:: → 结果）

```cnsh
M:: 运行 "bin/lh_time_engine.py --stamp"
# 响应:
#   [M::] 退出码=0
#   [M::] 输出=[丙午·丙申·戊申·亥时·䷗复·🔴] 2026-08-02T22:41:17+08:00
```

### 4.3 封装格式（一个块里双视角齐备）

```cnsh
CNSH:: 审计 当前会话 用三色判定
M:: 审计 "07_AUDIT" 模式="三色"
# 路由: P05 上帝之眼
# 结果: 🟢 通过
```
