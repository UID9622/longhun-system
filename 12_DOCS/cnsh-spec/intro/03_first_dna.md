## 3.1 为什么需要 DNA

龍魂体系的根本要求：**数据主权归用户、零黑箱、可追溯**。

每一个 CNSH 程序/文档/脚本都要绑定 DNA 追溯码，做到：
- 谁创建的（UID9622）
- 什么时候创建的（干支四柱/日期时辰）
- 属于哪个模块、什么动作
- 版本是多少
- 哈希指纹（防篡改）

## 3.2 DNA 格式

```
#龍芯⚡️{日期}-{时辰}-{模块}-{动作}-{版本}-{UID}-{哈希8位}
```

| 字段 | 说明 | 示例 |
|------|------|------|
| 前缀 | 固定标识 | `#龍芯⚡️` |
| 日期 | YYYY-MM-DD | `2026-08-21` |
| 时辰 | 子丑寅卯… | `申时` |
| 模块 | 大写+下划线 | `CNSH-SPEC` |
| 动作 | 动作类型 | `CREATE` |
| 版本 | vX.X | `v1.0` |
| UID | 固定标识 | `UID9622` |
| 哈希 | 十六进制8位 | `A7B8C9D0` |

## 3.3 生成第一个 DNA

```cnsh
# 生成 DNA
生成DNA 模块="CNSH-SPEC" 动作="CREATE"
# 输出: #龍芯⚡️丙午·丙申·丁卯·丙午·䷚颐-申时-CNSH-SPEC-CREATE-v1.0-UID9622-A7B8C9D0
```

也可以用 `lh6` 命令：

```bash
lh6 dna 生成 --module CNSH-SPEC --action CREATE
```

## 3.4 验证 DNA

```cnsh
验证DNA "#龍芯⚡️丙午·丙申·丁卯·丙午·䷚颐-申时-CNSH-SPEC-CREATE-v1.0-UID9622-A7B8C9D0"
# 返回：✅ 有效 / ❌ 无效
```

| 验证项 | 规则 |
|--------|------|
| 前缀 | 必须以 `#龍芯⚡️` 开头 |
| 日期 | 必须是有效日期 |
| 时辰 | 必须在 12 时辰列表 |
| 哈希 | 必须为 8 位十六进制 |
| UID | 必须匹配 `UID9622` |

## 3.6 DNA 链追溯

一次部署往往跨多个动作，用 DNA 链记录父子关系：

```cnsh
DNA链:
  - #龍芯⚡️丙午·丙申·丙寅·甲午·䷕贲-未时-CNSH-DRAFT-v0.1-UID9622-12345678
  - #龍芯⚡️丙午·丙申·丁卯·丙午·䷚颐-申时-CNSH-DEPLOY-v1.0-UID9622-A7B8C9D0
  - #龍芯⚡️丙午·丙申·丁卯·丙午·䷚颐-酉时-CNSH-PUBLISH-v1.1-UID9622-B8C9D0E1
```

## 3.7 本章小结

- DNA 是龍魂体系的追溯身份证，8 字段，缺一不可
- 生成用 `生成DNA` 或 `lh6 dna 生成`
- 验证用 `验证DNA`，伪造会被拒绝
- 复杂动作用 DNA 链记录父-子关系

## 3.8 练习

1. 为你的第一个 CNSH 程序生成 DNA
2. 验证一个伪造的 DNA（如 `#龍芯⚡️2026-99-99-INVALID`）
3. 构建一条包含 3 个 DNA 节点的追溯链
