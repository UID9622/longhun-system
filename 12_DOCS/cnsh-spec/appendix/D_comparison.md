## D.2 同一任务五种写法

**任务：如果分数大于等于 60 输出"及格"，否则"加油"**

```python
# Python
if score >= 60:
    print("及格")
else:
    print("加油")
```

```cnsh
# CNSH
如果 分数 大于等于 60
  输出 "及格"
否则
  输出 "加油"
```

```json
// JSON（只能表达数据，不能执行）
{"condition": "score>=60", "output": ["及格", "加油"]}
```

```yaml
# YAML（同上，配置为主）
condition: score>=60
output:
  - 及格
  - 加油
```

```text
# Prompt（自然语言，非确定性）
如果分数大于等于60，你就输出及格，否则输出加油。
```

## D.3 各自的定位

| 语言 | 定位 | 什么时候用 |
|------|------|------------|
| **CNSH** | 人机协作指令+审计语言 | 给 AI 下指令、审计追溯、龍魂体系 |
| Python | 通用计算语言 | 复杂算法、后端、生态 |
| JSON | 数据交换格式 | API 传输、存储 |
| YAML | 配置文件格式 | 配置文件、CI/CD |
| Prompt | 自然语言交互 | 讨论意图、对话 |

## D.4 CNSH 的互补定位

CNSH **不是替代品**，而是补齐了其他语言的空白：

```
其他语言缺什么 → CNSH 补什么
├── 中文原生 → 中文开发者零门槛
├── 可追溯 → 每行绑定 DNA
├── 审计内建 → 三色判定即语法
├── 熔断内建 → 安全保护即语法
└── 指令+数据+审计 → 一种语言全覆盖
```

## D.5 建议组合

| 场景 | 推荐组合 |
|------|----------|
| 龍魂内部指令 | CNSH + Shell |
| 数据交换 | CNSH 定义结构 → JSON 传输 |
| 复杂算法 | CNSH 调用 Python |
| 配置 | CNSH 或 YAML（按团队） |
| 对外 API | JSON（标准） |
