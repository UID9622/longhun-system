## 12.1 什么是一致性签名

一致性签名 = 验证**同一份数据在多处呈现是否一致**。龍魂体系在审计、对拍、跨仓库同步中依赖它防"表里不一"。

典型场景：
- 数据集 JSONL 与 MANIFEST 声明的 SHA 是否一致
- 文档头部 DNA 与文件实际内容是否匹配
- 发布仓库与主仓库文件是否同一版本

## 12.2 校验签名

```cnsh
校验一致性 文件="dataset.jsonl" 期望哈希="156d3ebb..."
# 一致 → 🟢 | 不一致 → 🔴

校验SHA 文件="SCHEMA.md"
# 输出当前 SHA-256
```

## 12.3 字符数差值校验

审计数据集时常用"字符数差值"发现截断：

```cnsh
比对 源文件="raw.jsonl" 目标文件="published.jsonl"
  报告 每条记录 字符数差值
  # 差值 > 阈值 → 标记截断嫌疑
```

## 12.4 声明一致性

发布声明与实物必须一致：

```cnsh
声明检查:
  - MANIFEST 声明的 SHA == 数据集实际 SHA
  - 声明的模型数 == 实际模型数
  - 声明的条数 == 实际行数
  - 声明的 GPG 签名 == 签名指纹
全部一致 → 🟢 可发布
```

## 12.5 签名类型对比

| 签名 | 验证什么 | 失败后果 |
|------|----------|----------|
| SHA-256 | 内容完整性 | 数据被改 |
| GPG | 创作者身份 + 完整性 | 非本人/被改 |
| DNA | 追溯身份 | 伪造 |
| 确认码 | 一次性确权 | 越权 |
| 一致性签名 | 多副本一致 | 表里不一 |

## 12.6 跨仓库一致性

```cnsh
同步校验 主仓库="longhun-system" 发布仓库="longhun-financial-deep-seek"
  比对 文件列表 + SHA
  # 不一致 → 重新同步 + GPG 重签
```

## 12.7 本章小结

- 一致性签名验证"多副本一致"，防表里不一
- 常用：SHA 比对、字符数差值、声明一致性检查
- 五种签名各司其职，一致性签名是最后一道闭环

## 12.8 练习

1. 对同一文件跑两次 SHA，验证一致
2. 写一个声明检查块（3 项以上）
3. 模拟：MANIFEST 声明的 SHA 与实际不符，写出报错
