## 一、问题

老大原话：**「我们不是有浏览器的吗，把手动的改成 AI 可以和浏览器协作完成的功能。」**

`bin/lh_browser_historian.py` 原本只支持「手动 SQLite 文件复制 + 定时采集」，AI 拿不到老大的实时浏览上下文，也没法主动在浏览器侧做事。

v1.0 在原引擎上扩展三个能力，让 AI 与老大的浏览器**实时协作**。

---

## 二、三个协作能力

| 能力 | 命令 | 角色 | 数据流 |
|:---|:---|:---|:---|
| **observe** 旁观 | `lh browser observe --port 9222` | AI 顾问（被动） | 老大浏览器 → 龙魂加密日志 |
| **coflow** 评估 | `lh browser coflow --since 120` | AI 评估（按需） | 共生日志 → 域名聚合 + 协作建议 |
| **run** 操作 | `lh browser run --url X` | AI 操作员（主动） | AI 起独立无头 Chrome → 抓页面 |

### 设计原则
1. **数据主权归老大**：CDP 绑 127.0.0.1、白名单域名过滤、沿用 v2.1 LocalEncryptor
2. **AI 不碰老大真实浏览器**：run 命令起独立 user-data-dir + 无头模式 + 一次性进程
3. **白名单机制**：github.com / uid9622.cn / notion.so / csdn.net / localhost 等；其他域名 observe 自动跳过

## 三、CDP 旁观模式（observe）

### 启动方式（一次性）

**老大真实浏览器需要加 `--remote-debugging-port=9222` 启动一次：**

```bash
# Chrome
/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome \
    --remote-debugging-port=9222

# Edge (Chromium 内核)
/Applications/Microsoft\ Edge.app/Contents/MacOS/Microsoft\ Edge \
    --remote-debugging-port=9222

# Firefox (原生不支持 CDP，但 marionette 端口类似)
```

> 想持久化？Mac 用 launchd 加 plist 即可；详见 `launchd/com.longhun.chrome-cdp.plist`（待建）

### 运行 observe

```bash
./bin/lh.py browser observe --port 9222 --max 50
# 监听老大浏览器的 Page.frameNavigated 事件
# 白名单域名才记录·其他自动跳过
# 事件写入 ~/.longhun/browser_coflow/events.jsonl
```

### 30 秒自动退出 / max 事件退出

节能：避免常驻。监听够用即退。

## 六、数据主权铁律（沿用 v2.1）

| 层 | 边界 |
|:---|:---|
| 网络 | CDP 只绑 `127.0.0.1`（防局域网/外网访问老大浏览器） |
| 域名 | 白名单机制（github/notion/uid9622/csdn/localhost） |
| 隔离 | AI run 用独立 user-data-dir + 一次性进程 |
| 加密 | 沿用 `LocalEncryptor`（v2.1 AES-256-GCM）+ `SignatureEngine` |
| 存储 | `~/.longhun/browser_coflow/events.jsonl`（明文本地·不上云） |
| 暂停 | 老大关闭浏览器 = 桥自动失联，无后台留痕 |

---

## 七、与 v2.1 关系

- 复用 `LocalEncryptor` / `SignatureEngine` / `MalwareFilter` / `BrowserCollector`
- 不破坏任何 v2.1 子命令（collect/query/export/verify/validate/install-firewall/uninstall-firewall/update-blocklist/status）
- status 子命令扩展：显示「共生桥事件数 + 白名单」+ 原有「数据目录/总记录/最后采集/黑名单」
