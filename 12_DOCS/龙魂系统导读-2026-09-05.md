## 一、先问一个问题

你有没有遇到过这样的情况：

- 一个"智能系统"替你做了决定，但你**说不清它凭什么这么决定**；
- 一个平台收集了你的数据，但你**不知道它拿去哪、给谁看**；
- 一个工具很强大，但它的规则**只装在别人脑子里**，你想复用却无处下手；
- 代码仓库堆满文件，改了一处，**没人说得清会不会悄悄坏掉另一处**。

我们做龍魂系统，不是为了造一个更聪明的工具，而是为了回答一个问题：

> **一套软件系统，能不能做到：每一条产出都可追溯、每一个决定都可审计、每一次改动都有人负责、每一条数据都归用户自己？**

龍魂的答案是：**能，而且这些能力应该成为系统的默认配置，而不是加分项。**

## 二、龍魂解决了什么

龍魂系统是一套「数字主权底座」——一套给自己用的、能自我审计、自我记账、自我养活的系统。它解决四件事：

### 1. 三色审计：绿黄红，一眼看懂可信度

每一份文档、每一段代码、每一个结论，都带一个三色标记：

| 颜色 | 含义 | 你会看到 |
|:---:|:---|:---|
| 🟢 | 已检查、已实测、全通过 | 可以放心用 |
| 🟡 | 推演中 / 待实测 / 待补充 | 用之前看清楚"待核什么" |
| 🔴 | 红线 / 安全风险 | 立即停，先查为什么 |

> 它的价值在于：**系统从不假装"没测过的东西是好的"**。红色不怕，怕的是把红色说成绿色。

### 2. DNA 追溯：每份文件都有自己的"身份证"

龍魂里每一个正式产出都带一个 DNA 码，形如：

```
#龍芯⚡️丙午·丁酉·戊寅·辰时·䷝离-模块-动作-哈希
```

它记录：**谁、何时、什么干支时辰、做什么动作、什么卦象**。配合 GPG 数字签名（`A2D0092CEE2E5BA87035600924C3704A8CC26D5F`），可以做到：

- 拿到一份文档 → 验证签名 → 确认没被改过；
- 看到一行代码 → 顺 DNA 查回源头 → 知道从哪来、谁负责。

**删 DNA、删署名、冒充原创 = 违约**，系统会把这种行为记上"耻辱墙"。

### 3. 多模态感知 + 账法系统：系统会自己记账

龍魂不是"死代码"。它有 20 个人格化职能（战略/执行/文化/守护）、192 个引擎、一套自感知体系：

- **感知识别（`lh sense`）**：系统自己扫描资产、识别异常、感知"哪里变了"；
- **账法系统（`lh ledger`）**：每一笔关键操作都记账——见证、科目、哈希链，append-only，**记了就不能悄悄抹掉**；
- **每日审计（每日 04:00）**：系统在没人看着的时候，自己审自己一遍，输出综合分，低于阈值自动告警。

这就是"系统自己养自己"：**不靠自觉，靠机制。**

### 4. 主权的三层边界

- **数据主权**：数据归用户，端侧加密，云上只存密文；
- **算法主权**：算法可声明、可复核，不搞黑箱；
- **平台主权**：能自建不依赖外部，关键服务自己掌控。

## 三、怎么接入：5 分钟快速开始

### 第 1 分钟 · 拉代码

```bash
git clone https://github.com/UID9622/longhun-system.git
cd longhun-system
```

### 第 2 分钟 · 看一眼健康

```bash
python3 08_BIN/lh.py health
```

第一次跑，你会看到一张**引擎 / GPG / 命令 / 全局状态**的三色状态表。绿色多 = 系统是健康的。

### 第 3 分钟 · 验证文档可信度

```bash
# 验证一份文档的 GPG 签名
gpg --verify 12_DOCS/QUICKSTART.md.asc 12_DOCS/QUICKSTART.md
```

看到 `Good signature from 诸葛鑫` 说明这份文档是原件、没被动过。

### 第 4 分钟 · 跑一次文档一致性体检

```bash
python3 08_BIN/lh_docs.py check
```

它检查 11 份交付文档与系统是否一致：头部四行、DNA 时间戳、GPG 签名、版本行、命令表。输出 🟢 = 全部一致。

### 第 5 分钟 · 把命令装进全局

```bash
# 之后任意目录都能敲 lh
ln -s "$PWD/bin/lh.py" ~/bin/lh   # 或按 12_DOCS/INSTALL.md 的完整安装
lh health --json | head -20
```

> 完整安装（含依赖、Docker、Windows）见 `INSTALL.md`；更多用法见下面的文档导航。
