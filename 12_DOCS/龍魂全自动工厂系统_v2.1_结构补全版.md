## 📋 二、核心判断（自动化 · 自进化）

> **全自动工厂不是"跑一遍流程"，而是"让系统自己进化"。** 造零件只是开始，质检发现问题，门禁拦截不合格，修复自动介入，发布验证效果，反馈形成闭环——整个系统在无人干预的情况下自我迭代、自我优化、自我防御。**失败不是终点，是下一次迭代的起点。**

| 环节 | 自动化 | 失败时 |
|:---|:---:|:---|
| 零件生产 | ✅ 自动构建+版本+哈希 | 跳过继续 |
| 质检流水线 | ✅ 自动测试+覆盖率+三色 | 生成报告，不阻塞 |
| 质量门禁 | ✅ 自动判定，**不过不发布** | 拦截发布，熔断计数 |
| 自动修复 | ✅ AI 生成修复建议 | 记录耻辱墙 |
| 发布部署 | ✅ 策略化发布+打包 | 自动回滚 |
| 反馈闭环 | ✅ 自动学习高频模式 | 保留历史 |

## 🧬 三、完整实现（落地代码）

> 代码已全部落地为独立文件（见交付物清单），此处只列实现要点，完整代码见对应文件。

### 3.1 工厂主控制器 `08_BIN/lh_auto_factory.py`

- **7 步全链路**：`build → test → gate → repair → release → deploy → feedback+learn`
- 质量门禁 `overall != PASS` → 拦截发布（P0：gate 不过不发布）
- 产物索引持久化（`artifacts_index.json`）→ `artifacts/learn` 跨进程可见
- CLI 支持位置子命令：`run/status/artifacts/learn/monitor/gate/release/rollback/versions/circuit/kunpeng`

### 3.2 数据模型（v2.1 补全汇总）

| 模型 | 字段 | 用途 |
|:---|:---|:---|
| `FactoryTask` | id/type/status/created_at/dna/details | 工厂任务 |
| `BuildArtifact` | id/name/path/version/size/hash/dna | 构建产物（SHA-256 哈希） |
| `TestReport` | total/passed/failed/skipped/errors/coverage/tricolor/dna | 测试报告 |
| `QualityGateResult` | rule/status/actual/threshold/message | 门禁判定（可 JSON 序列化） |

### 3.3 状态机（v2.1 补全）

```
idle → running → completed ✅
   ↓          ↓
 blocked_by_gate / failed ❌ → 熔断计数 → 自动恢复(L3) / 人工恢复(L1/L2)
```

### 3.4 三色审计判定标准（v2.1 补全）

| 色 | 判定条件 | 后续动作 |
|:---:|:---|:---|
| 🟢 通过 | failed=0 | 放行发布 |
| 🟡 待核 | failed ≤ total×10% 或 无测试 | 记录待核，通知 |
| 🔴 红线 | failed > total×10% 或 门禁 FAIL | 拦截+熔断计数 |

### 3.5 失败处理矩阵（v2.1 补全）

| 步骤 | 失败表现 | 自动处理 |
|:---|:---|:---|
| ① 构建 | 源路径不存在 | 报错退出 |
| ② 质检 | 测试失败 | 生成报告，进入门禁 |
| ③ 门禁 | 不达标 | **拦截发布**，熔断计数，通知告警 |
| ④ 修复 | 修复失败 | 记录耻辱墙，人工介入 |
| ⑤ 发布 | 观察期异常 | 自动回滚到上一稳定版 |
| ⑥ 部署 | 部署失败 | 回滚 + 告警 |
| ⑦ 反馈 | 学习无数据 | 保留历史，下次继续 |
