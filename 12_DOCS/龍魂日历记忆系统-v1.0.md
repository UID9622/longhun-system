## 一、老大的构想（2026-09-04 原话翻译）

> **「日历就是我们的记忆系统，是不是云端的记忆系统也行？就每个用户他下载过去都可以用用这个日历，是不是深度集成我们的系统？那这样子的话他们每个人的本地日历存的任何内容，都可以在日历里面被我们的系统检索引用，当个知识库一样嘛，每天做的什么事情说都在嘛，对不对，那不可抹去的是吧」**

骨架翻译 → 工程落地：

| 原话 | 设计落点 |
|:---|:---|
| 日历=记忆系统 | 龍魂万年历 + 统一记忆层引擎（按日聚合 · 全文检索） |
| 云端记忆系统也行 | 选 **本地为主 · Notion 镜像可选 · 数据主权归用户**（P0） |
| 每个用户下载都能用 | 万年历已是可分发本地 app（端口 9527），记忆模块随包 |
| 本地日历存的任何内容 | `note` 当日速记 API（append-only JSONL）—— 用户的亲手记忆 |
| 可被系统检索引用 | `/api/memory/search` + CLI `lh calmem search` 跨全部记忆 |
| 当知识库一样 | 多源（recap/memory/wanli/yearring/notion/note）按日聚合 |
| 不可抹去 | 哈希链 `chain.json`（prev_hash → root_hash）· verify 检测任何篡改 |

**设计原则焊死**：
- ✅ **数据主权**：数据全在用户本机 `~/.longhun/calendar_memory/`（数据家目录可环境变量覆盖，分发给不同用户即各自隔离）
- ✅ **不可抹去**：哈希链 append-only + 文件 append-only + fingerprint 去重（不会因重复摄入堆积）
- ✅ **每个用户可用**：万年历应用 + memory 模块随 app 分发即可，引擎文件 `lh_calendar_memory.py` 同包带上
- ✅ **Notion 可选**：默认读 `notion-mirror/` 本地镜像（已加密落盘的公开内容）；未配则优雅跳过

## 三、命令与 API

### 3.1 CLI · `lh calmem`

```bash
lh calmem ingest         # 摄入当日 · 增量指纹去重
lh calmem ingest-all     # 全量摄入所有日期
lh calmem search <词>    # 跨全部日记忆全文检索（大小写不敏感）
lh calmem day [YYYY-MM-DD]   # 打印某日全部条目（默认今天）
lh calmem seal [date]    # 将某日 root_hash 封进哈希链（幂等）
lh calmem verify         # 重算整链 · ok 或 断点 @i
lh calmem status         # 数据状态概览
lh calmem sources        # 各源文件数/可达性
lh calmem note [date] "<文本>"  # 当日速记（自动 ingest + seal）
```

### 3.2 HTTP · 万年历 API

| 方法 | 路径 | 参数 | 返回 |
|:---|:---|:---|:---|
| GET | `/api/memory/day` | `?date=YYYY-MM-DD` | `{ok, date, count, root_hash, entries[]}` |
| GET | `/api/memory/search` | `?q=&limit=20` | `{ok, kw, results:[{date,count,entries[]}]}` |
| POST | `/api/memory/note` | `{date, text}` | `{ok, date, text}` |
| GET | `/api/memory/status` | — | `{ok, days, entries, chain_links, chain_ok, data_dir}` |

### 3.3 Python API（万年历 server 注入调用）

```python
import lh_calendar_memory as calmem

calmem.get_day          = lambda d: calmem._load_day(d)        # ← 内部使用
calmem.search           (kw, limit=20)
calmem.add_note         (date_str, text)
calmem.seal             (date_str=None)
calmem.status           ()
calmem.verify           ()
```

## 四、数据家

```
~/.longhun/calendar_memory/
├── index.json        # 源文件指纹缓存（mtime+size）
├── chain.json        # 哈希链
├── days/
│   ├── 2025-08-09.json
│   ├── ...
│   └── 2026-09-04.json
└── notes/
    └── 2026-09-04.jsonl   # 用户当日速记（append-only）
```

每日文件 schema：

```json
{
  "schema": "longhun-calendar-memory-v1",
  "date": "2026-09-04",
  "ganzhi": "",
  "updated": "2026-09-04T22:14:13+08:00",
  "count": 25,
  "root_hash": "0515c2980f689c02",
  "entries": [
    {
      "fp": "1a2b3c4d5e6f",
      "source": "recap",
      "kind": "复盘",
      "title": "brain",
      "text": "brain 执行完成 ✅ · 127ms · 3 节点 · 1 决策",
      "dna": "#龍芯⚡️丙午·丁酉·辛巳·午时·䷁咸-recap-brain-60C3BAE8",
      "file": "recap-20260904225049.json"
    }
  ]
}
```

哈希链 schema：

```json
{
  "schema": "longuhn-calendar-memory-chain-v1",
  "chain": [
    { "date":"2026-09-04", "count":23, "prev_hash":"0000000000000000",
      "root_hash":"aed1a2c4398a1acb", "hash":"6cc087781f8f4a10", "ts":"..." }
  ]
}
```

`hash = sha256(date|prev_hash|root_hash|count)[:16]`，改任何字段或当日条目根哈希即 `verify` 断点。

## 五、环境变量（分发适配）

| 变量 | 默认 | 说明 |
|:---|:---|:---|
| `LONGHUN_ROOT` | `~/longhun-system` | 龍魂系统根（影响 memory/yearring/notion 源） |
| `LH_RECAP_DIR` | `~/.longhun/recap/recaps` | 复盘目录（每个用户可独立） |
| `LH_WANLI_DATA` | `~/.龍魂/万年历/private/data` | 万年历私有数据 |

**分发万年历到另一台机器 / 另一用户**：

```bash
# 1. 拷贝万年历目录 + 引擎文件
cp -r ~/.龍魂/万年历 /target/user/万年历
cp 08_BIN/lh_calendar_memory.py /target/user/万年历/modules/memory/

# 2. 启动万年历 → 自动检测 modules/memory/lh_calendar_memory.py
#    → 用户的 ~/万年历/data/ 自动创建 → 数据完全本地隔离
```

无需改一行代码，engine + 模块自动降级到「只 wanli + note」两源，用户的「当天做了什么」照样能搜+封链。
