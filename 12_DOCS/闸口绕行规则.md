## 一、背景

命名闸口（2026-09-01 焊死）要求**新增入库的 `.py` 必须使用 CNSH 中文命名**，否则 pre-commit 硬拦截。
但存在三类**合理的工程惯例冲突**：标准 Python 生态要求 ASCII 标识符。逐案讨论成本高、易漂移，
故将裁决规则固化如下——同类问题**不再讨论，直接按规则执行**。

## 二、三类已知合理冲突（可自动绕行）

| 类型 | 判定 | 典型位置 | 理由 |
|:---|:---|:---|:---|
| `PYTHON_PACKAGE` | 文件位于含 `pyproject.toml`/`setup.py` 的包树内 | `packaging/cnsh-stdlib/cnsh_std/*.py` | PyPI 标准打包依赖 ASCII 模块名，`import cnsh_std.io` 才兼容工具链 |
| `PYTEST_FIXTURE` | 文件名 `test_*.py` | `packaging/**/tests/test_*.py` | pytest 收集器默认发现模式，改名即失效 |
| `CLI_COMMAND` | `08_BIN/` 或 `bin/` 下的命令/引擎脚本 | `08_BIN/cnsh.py`·`cnsh_jsgen.py`·`cnsh_pm.py` | 对外命令名/工具链名 = 品牌命名惯例（同 `lh_*.py` 先例） |

**绕行条件（三者同时满足）**:
1. 违规文件全部可归入以上三类（**不含 `OTHER`**）；
2. 已自动写入审计留档 `07_AUDIT/cnsh_gate_bypass_*.md`（GPG 签名）；
3. 日志已 append `07_AUDIT/cnsh_gate_bypass.log`（带 `type=` 列）。

## 三、`OTHER`（未归类）→ 禁止自动绕行

无法归入三类的英文命名新增 `.py`（如业务代码、Web 模块等）：
- ❌ 工具绝不自动 `--no-verify`；
- 🔴 停下，报告老大，由 **P05 独立审计**判定（是否中文重命名 / 豁免 / 新建规则）。

## 四、自动流程（lh publish pr 内置）

```
lh publish pr <标题> --auto
  ├─ git add 全部目标文件
  ├─ lh_cnsh_gate.py --pre-commit --json    ← 机器判定
  ├─ 有违规且全为三类 → lh_cnsh_gate.py --record <原因> --flow <ID> --tag <ID>
  │     ├─ append cnsh_gate_bypass.log（type=PYTHON_PACKAGE/CLI_COMMAND/PYTEST_FIXTURE）
  │     ├─ 生成/追加 07_AUDIT/cnsh_gate_bypass_<日期>[_<ID>].md（入库 + GPG 签）
  │     └─ git commit --no-verify            ← 留档即绕行凭证
  ├─ 含 OTHER → 停止，报告老大人工 P05
  └─ 无违规 → git commit（正常过闸）
```

手动单步等效命令（供审计复核）:
```bash
python3 08_BIN/lh_cnsh_gate.py --pre-commit --json          # 看违规+类型
python3 08_BIN/lh_cnsh_gate.py --record "原因" --flow PR-20260904-01 --title "标题" --tag PR-20260904-01
git commit --no-verify
```
