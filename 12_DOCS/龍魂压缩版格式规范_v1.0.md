## 一、总则

### 1.1 什么是龍魂压缩版

**龍魂压缩版**（LongHun Compressed Format，代号 `longhun-compress/v1.0`）是龍魂系统的**宪法层数据封装协议**。它把任意长文本（文章、代码、记忆、对话、日志）压缩成一个**可还原、可摘要、可审计、可加密**的标准化包。

不是哈希，不是摘要，是**带 DNA 的可逆压缩容器**。

### 1.2 核心能力

| 能力 | 说明 | 对应三才 |
|------|------|----------|
| **摘要读取** | 人看几百字就知道全文大意 | 人 |
| **一键还原** | 输入压缩包即可恢复原文 | 天 |
| **国密加密** | 可选 SM4-ECB 加密，主权不外泄 | 天 |
| **DNA 锚定** | 每个包都有唯一追溯码 | 中宫 |
| **格式固定** | 任何实现必须遵循本 schema | 地 |

### 1.3 设计原则

1. **可逆优先**：压缩不是销毁，压缩是为了更好的携带与传承。
2. **摘要优先**：普通人先看摘要，必要时再还原全文。
3. **主权优先**：加密算法默认使用中国国密 SM4，密钥由 UID9622 控制。
4. **格式优先**：结构写死，字段固定，版本严格递增。
5. **DNA 优先**：任何压缩包必须有 DNA、确认码、GPG 指纹。

## 三、格式规范（Schema）

### 3.1 顶层结构

龍魂压缩版文件是一个 UTF-8 编码的 JSON 文件，扩展名固定为 `.lhpack`。

```json
{
  "schema": "longhun-compress/v1.0",
  "version": "1.0",
  "dna": "#龍芯⚡️丙午·甲午·己卯·辛未·䷗复-LONGHUN-COMPRESS-4E3EB8C8",
  "confirm_code": "#CONFIRM🌌9622-ONLY-ONCE🧬LK9X-772Z",
  "seal": "#ZHUGEXIN⚡️2025-🇨🇳🐉⚖️♠️🧚🏼‍♀️❤️♾️-DEVICE-BIND-SOUL",
  "created_at": "2026-07-04T14:22:05.629000+00:00",
  "operator": "UID9622",
  "header": { ... },
  "crypto": { ... },
  "payload": { ... },
  "sancai": { ... }
}
```

### 3.2 顶层字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `schema` | string | ✅ | 固定为 `longhun-compress/v1.0` |
| `version` | string | ✅ | 固定为 `1.0` |
| `dna` | string | ✅ | 龍魂 DNA 追溯码，唯一标识此压缩包 |
| `confirm_code` | string | ✅ | UID9622 一次性确认码 |
| `seal` | string | ✅ | GPG/灵魂绑定封印 |
| `created_at` | string | ✅ | ISO 8601 UTC 时间戳 |
| `operator` | string | ✅ | 操作人标识，默认 `UID9622` |
| `header` | object | ✅ | 语义摘要头 |
| `crypto` | object | ✅ | 加密元信息 |
| `payload` | object | ✅ | 压缩数据体 |
| `sancai` | object | ✅ | 三才锚定说明 |

### 3.3 header（语义摘要头）

```json
{
  "title": "龍魂压缩测试",
  "summary": "龍魂压缩测试",
  "keywords": ["龍魂系统", "压缩", "还原", "DNA"],
  "skeleton": {
    "background": "...",
    "problem": "...",
    "solution": "...",
    "key_points": ["...", "..."],
    "next_action": "..."
  },
  "original_hash": "sha256(...)",
  "original_size": 2079,
  "char_count": 1039,
  "language": "zh-CN"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `title` | string | 标题，优先取用户输入，否则取摘要前 40 字 |
| `summary` | string | 一句话摘要，不超过 140 字 |
| `keywords` | list | 关键词列表，最多 15 个 |
| `skeleton` | object | 核心骨架：background / problem / solution / key_points / next_action |
| `original_hash` | string | 原文 SHA-256 哈希，用于完整性校验 |
| `original_size` | int | 原文 UTF-8 字节数 |
| `char_count` | int | 原文字符数 |
| `language` | string | 语言标识，默认 `zh-CN` |

### 3.4 crypto（加密元信息）

```json
{
  "encrypted": false,
  "algorithm": "none",
  "iv": ""
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `encrypted` | bool | 是否加密 |
| `algorithm` | string | 加密算法：`none` / `SM4-ECB` |
| `iv` | string | 初始化向量，base64 编码；SM4-ECB 为空字符串 |

> **主权原则**：默认不加密。一旦加密，必须使用中国国密 SM4。禁止在龍魂压缩版中使用 AES/RSA 等外来算法作为默认加密。

### 3.5 payload（压缩数据体）

```json
{
  "encoding": "base64",
  "method": "zlib",
  "use_dict": true,
  "use_dedup": true,
  "compressed_size": 1032,
  "ratio": 0.496397,
  "saved": 0.503603,
  "data": "eJztWktv4zYQvvtXEE4JJLtYlGRZ..."
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `encoding` | string | 固定为 `base64` |
| `method` | string | 压缩算法：`raw` / `zlib` / `gzip` / `bz2` / `lzma` / `zstd` |
| `use_dict` | bool | 是否使用龍魂字典编码 |
| `use_dedup` | bool | 是否使用重复行去重 |
| `compressed_size` | int | 压缩后字节数 |
| `ratio` | float | 压缩率 = compressed_size / original_size |
| `saved` | float | 节省率 = 1 - ratio |
| `data` | string | base64 编码的压缩（并可能加密）数据 |

### 3.6 sancai（三才锚定）

```json
{
  "tian": "压缩执行·算法选择·加密行动",
  "di": "base64承载·文件存储·数据库归档",
  "ren": "语义摘要·关键词·骨架",
  "zhonggong": "DNA不动点·369归一"
}
```

此字段不可省略，用于在机器解析时也能识别三才结构。

## 四、压缩流程

任何龍魂压缩版实现必须按以下顺序执行：

```
原文 text
  ↓
【天】龍魂字典编码（可选，默认启用）
  ↓
【天】重复行去重（可选，默认启用）
  ↓
【天】算法压缩（auto / zlib / gzip / bz2 / lzma / zstd）
  ↓
【天】SM4-ECB 加密（可选，默认不启用）
  ↓
【地】base64 编码
  ↓
【人】生成摘要、关键词、骨架
  ↓
【中宫】生成 DNA、确认码、seal
  ↓
封装为 longhun-compress/v1.0 JSON
```

### 4.1 龍魂字典编码

- 使用固定的 `LONGHUN_DICT` 高频词表。
- 关键词 → 短标记，用私有使用区字符 `\uE000` 作为边界。
- 编码与解码必须使用正则一次性替换，避免嵌套误替换。
- 字典表必须保证 full → short 是一对一映射。

### 4.2 重复行去重

- 对文本按 `\n` 分割（保留末尾空行）。
- 连续相同行表示为 `<Nx>内容`。
- 解压时按相同规则还原。

### 4.3 算法选择

- `method=auto` 时，依次尝试 `zlib`、`gzip`、`bz2`、`lzma`、`zstd`，选择压缩后最小的一种。
- `zstd` 为可选依赖；不可用时回退到其他算法。

### 4.4 加密

- 仅支持 `SM4-ECB`。
- 密钥由用户提供字符串，经 SHA-256 取前 16 字节作为 SM4 密钥。
- 加密发生在算法压缩之后、base64 编码之前。

## 五、解压流程

```
.lhpack 文件
  ↓
解析 JSON，校验 schema、version、DNA
  ↓
base64 解码
  ↓
SM4-ECB 解密（如 encrypted=true，需提供密钥）
  ↓
算法解压
  ↓
重复行还原
  ↓
龍魂字典解码
  ↓
还原文本
  ↓
可选：校验 original_hash
```

## 六、摘要模式

摘要模式**不还原文本**，只读取 `header` 和 `sancai` 字段，生成给人看的压缩卡。

用途：
- 快速浏览大量文档
- 在不暴露原文的情况下了解内容主题
- 生成索引、目录、知识图谱节点

## 七、CLI 工具

龍魂压缩版标准 CLI 为 `tools/longhun_compress.py`。

### 7.1 命令

```bash
# 压缩文件
python3 longhun_compress.py compress input.txt -t "标题" -o output.lhpack

# 压缩并加密
python3 longhun_compress.py compress input.txt --encrypt --key mysecret -o output.lhpack

# 读取摘要
python3 longhun_compress.py summary output.lhpack

# 还原文件
python3 longhun_compress.py decompress output.lhpack -o restored.txt

# 还原加密文件
python3 longhun_compress.py decompress output.lhpack --key mysecret -o restored.txt

# 验证完整性
python3 longhun_compress.py verify output.lhpack --original input.txt

# 查看元信息
python3 longhun_compress.py info output.lhpack
```

### 7.2 输出文件

- `.lhpack`：机器可解析的压缩包
- `.lhcard`：给人看的 Markdown 摘要卡

## 八、安全与主权声明

### 8.1 数据主权

- 龍魂压缩版的数据主权归 UID9622 / 龍魂系统所有。
- 加密密钥不由任何第三方托管。
- 压缩包中的 DNA、确认码、seal 不可删除、篡改或剥离。

### 8.2 算法主权

- 默认加密算法为中国国密 SM4。
- 哈希算法为中国国密 SM3 或 SHA-256（兼容性）。
- 压缩算法使用国际通用无损算法（zlib/gzip/bz2/lzma/zstd），仅作为容器内动作，不改变数据主权属性。

### 8.3 禁止行为

- 删除、篡改、剥离 DNA 追溯码
- 将龍魂压缩版用于商业 AI 训练数据抓取
- 在未授权情况下解密他人加密压缩包
- 修改 schema 或 version 字段后冒充官方格式
