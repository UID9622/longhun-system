## 2. 🗺️ 两条部署路

### 方案 A：域名指向本机（Mac）· 本地托管官网

适用：想把官网首页放在 Mac 本机 `~/.longhun/www/`，用家庭带宽对外服务。

```text
访客 ──→ uid9622.cn ──→ 路由器公网IP:80/443 ──端口转发──→ Mac 局域网IP:8762 ──→ 官网首页
```

**思路步骤（需 UID9622 决策后执行，涉及网络设备改动）：**

1. **查本机局域网 IP**：`ipconfig getifaddr en0`（或 `en1`）。
2. **路由器端口转发**：登录家用路由器管理页，把公网 `80/443 → 本机局域网 IP:8762`（不同品牌路径不同）。
3. **本地静态服务选一**：
   - 轻量（临时/验证）：`cd ~/.longhun/www && python3 -m http.server 8762`
   - 正式（建议 nginx/caddy 反代 + HTTPS）：nginx 站点根目录指向 `~/.longhun/www/`；caddy 可自动申请证书。
   - launchd 常驻：写 `launchd/com.longhun.www.plist` 保活（参照仓库现有 `launchd/` 惯例，**新增守护须进节能白名单并经 UID9622 确认**）。
4. **备案与网络前提（中国境内访问必读）**：
   - 域名在国内解析/服务需 **ICP 备案**；家庭宽带一般无 80/443 白名单保障，运营商可能封禁家宽入站端口。
   - 家庭宽带多为**动态 IP**：用 DDNS（如 `ddns-go` / 路由器自带 DDNS）把 `uid9622.cn` 的 A 记录动态指向当前公网 IP。
5. **HTTPS 证书**：正式对外须 TLS；证书签发需域名解析已生效。

> ⚠️ 风险提示：家宽入站 = 攻击面扩大；本方案仅建议内网实验或经 UID9622 权衡后使用。

### 方案 B：现网走鲲鹏（现状延续）· 官网并入云端门户

适用：维持 `uid9622.cn → 119.13.90.27` 现状，把官网首页 rsync 到鲲鹏后由 nginx 托管。

**思路步骤（本次不实际执行部署）：**

1. **本地就绪**：官网首页已生成于 `~/.longhun/www/index.html`（相对链接 `../docs/...` 依赖 docs 目录一同发布）。
2. **推送**：`rsync -av ~/.longhun/www/ root@119.13.90.27:/apps/www/`（或鲲鹏 portal 目录，参照既有 `portal` rsync 惯例）。
3. **nginx 根目录**：鲲鹏 nginx 增加 server 块，`root /apps/www; index index.html;` 并把 `uid9622.cn`（或子路径）指到该站点；已有 `/api/`=8777、`/portal/`=8789 不动。
4. **docs 相对链接可达性**：页面内 `../docs/龙魂系统能力清单-2026-09-03.md` 为**相对 www 部署目录** —— 需把仓库 `docs/` 放在 www 的同级（如 `/apps/docs/`）才能点通；或改为发布时只保留必引用的两份 md 于同根。
5. **验收**：`curl -s -o /dev/null -w "%{http_code}" https://uid9622.cn/` 期望 `200`；`curl -s https://uid9622.cn/ | head -20` 检查关键区块。

> 说明：本指南仅提供思路与命令示例，**未在鲲鹏实际执行任何 rsync/nginx 改动**。
