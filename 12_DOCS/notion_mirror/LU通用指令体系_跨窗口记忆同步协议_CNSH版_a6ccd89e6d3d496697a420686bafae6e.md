## 💡 核心理念：把记忆从模型脑袋里搬出来
### 两种记忆
模型记忆（AI的脑袋）
- 特点：不稳定、看心情、跟窗口和账号策略走
- 结论：不能指望它保存你重要的东西
系统记忆（你自己的电话本）
- 特点：你自己保存的（Notion / 本地.md / 日志库 / 编号库）
- 结论：一切严肃的东西都要回落到系统记忆
LU记忆同步 = 把不同窗口里有用的内容，收敛成一份可追溯的系统记忆

## 🗂️ 三层结构：MAIN / BRANCH / LOCK
### MAIN 主干（正式版）
- 定义： 唯一可信版本，能对外引用、能用于决策
- 要求： 通过三色审计为🟢绿，结构完整、可复用
### BRANCH 分支（试验版）
- 定义： 试验、争议、草稿、情绪都可以放这里
- 要求： 允许混乱，但必须有时间戳和来源
### LOCK 闭锁区（待审核）
- 定义： 所有新增内容的临时停车场
- 流程： 先进LOCK → 审计复盘 → 再决定进MAIN还是留BRANCH

## 🚦 CNSH三色审计母模板（与LU绑定）
### 🟢 绿色：可直接入主干（MAIN）
判定条件：
- ✅ 不触碰L0永恒定锚（不违背UID9622的核心价值观与主权条款）
- ✅ 逻辑闭环清晰（有起因、有步骤、有结果）
- ✅ 可执行且可复用（普通人照做可以跑得起来）
- ✅ 不含明显虚构或夸大（没有凭空的性能+X%之类）
输出要求：
- 必须给出：落地步骤 + 参数 + 熔断条件 + 追溯码
- 目标：随时可以直接丢进MAIN当标准流程用
### 🟡 黄色：可用但需提示风险（优先放BRANCH）
判定条件：
- ⚠️ 关键数据缺失 / 需要你补充
- ⚠️ 出现提升X%等无法证实的说法
- ⚠️ 依赖外部平台能力，但没有API或官方文档支撑
输出要求：
- 必须标注：示意/待确认
- 必须给出：最短补齐项清单（3~5条）
### 🔴 红色：禁止写入主干（MAIN）
判定条件：
- 🚫 触碰L0不可变条款（价值观、主权、底线）
- 🚫 涉及违法 / 伤害 / 攻击
- 🚫 伪造身份 / 伪造证据 / 伪造官方结论
输出要求：
- 说明：触发原因（一句话）
- 替代：给安全版本的建议（可选）
- 动作：只能留在LOCK，不能进MAIN

## 🔄 跨窗口同步执行逻辑（6步法）
### 总目标
用MAIN / BRANCH / LOCK三层结构，把到处飞的对话碎片，变成一套可以维护、可以追溯的系统资产。
### 最小可执行流程（无插件版）
步骤1 - 收集：
- 你把各窗口要点复制进LOCK
- 每条写明：来源窗口 + 日期 + 一句话说明
步骤2 - 去重：
- AI按主题合并重复内容
- 给出保留版本与被合并版本列表
步骤3 - 审计：
- 按三色审计模板给出绿/黄/红判定
- 标出每段的颜色和理由
步骤4 - 编号：
- 为通过审计的块生成版本号 + DNA追溯码（示意也行）
步骤5 - 合并：
- 🟢绿 → MAIN候选草稿
- 🟡黄 → BRANCH待补齐清单
- 🔴红 → LOCK冻结，并写明原因
步骤6 - 记账：
- 调用LU-TRACE-LOGBOOK生成日志
- 日志结构：时间、任务ID、变更摘要、风险结论
