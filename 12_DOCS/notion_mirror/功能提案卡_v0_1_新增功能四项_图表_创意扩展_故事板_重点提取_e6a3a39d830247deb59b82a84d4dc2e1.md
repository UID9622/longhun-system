## 总体说明
- 默认策略：先小范围验证（不改库结构）→ 通过 /判断 → 再决定是否入库
- 三色：默认黄（需验证）
- 依赖判定：
---
## 1) 一键数据图表（将数据转化为视觉图表）
- 摘要：从指定数据源生成图表区块或图表视图（表/板/图/时间线/地图/图表视图）
- 适用数据：Notion 数据源（表、select/status/number/date 等字段）
- 依赖：【系统可自动完成】
- 风险与注意：需确认数据字段口径与枚举一致；大数据量可能需分页
- 一键卡（最小验证）
```markdown
/明细 主题：一键数据图表｜字段=数据源,图表类型,维度,指标
```
```markdown
/判断 主题：该数据源是否适合图表化｜关键事实：字段完整性/枚举口径/日期列｜期望：可执行
```
- 验收：能在目标页插入一个图表视图或图表区块并正确显示指定指标
---
## 2) 创意扩展器（从一个点子扩展相关想法）
- 摘要：基于输入主题自动生成若干关联想法，按分类与优先级落成清单
- 依赖：【系统可自动完成】
- 风险与注意：需避免无关扩展；输出需附“用途与下一步”
- 一键卡（最小验证）
```markdown
/提问 目标：扩展主题相关创意｜约束：每条附用途与下一步｜时间：今天
```
```markdown
/明细 主题：创意扩展器输出结构｜字段=主题,创意点,用途,下一步,优先级
```
- 验收：产生≥10条去重的可执行创意点，含用途与下一步
---
## 3) 视觉故事板（把想法转为视觉故事框架）
- 摘要：生成分镜头式结构（场景/角色/冲突/转折/结尾），以列或分栏呈现
- 依赖：【系统可自动完成】
- 风险与注意：故事线需与目标受众一致；避免过长
- 一键卡（最小验证）
```markdown
/明细 主题：视觉故事板｜字段=场景,角色,冲突,转折,行动,结尾
```
```markdown
/补充 目标段末尾追加：示例分镜×6（每格≤60字）
```
- 验收：生成一个6格故事骨架并能被对外复用
---
## 4) 重点提取器（识别并突出关键点）
- 摘要：从长文中抽取关键要点、结论与操作项，标注来源
- 依赖：【系统可自动完成】
- 风险与注意：保持中性措辞，避免绝对化；结论需可追溯
- 一键卡（最小验证）
```markdown
/AI学习 材料：长文或上一轮AI回复｜输出到：规则知识库｜可信度≥中
```
```markdown
/判断 主题：提取结果是否可执行｜关键事实：来源完整/三色口径/操作项明确｜期望：可执行
```
- 验收：输出“要点清单＋可执行项＋来源标注”三件套
---
## 入库与审计
- 对外前：逐条 /判断 并标注三色与依据
- 入库路径：主控操作台一键入库，创建回滚点
