# 第一部分：Go基础语法

## 一、选择题（每题2分，共5题）

### 1. 在Go语言中，以下哪个关键字用于声明一个新的goroutine？
A. thread  
B. go  
C. async  
D. await  

**答案：B**  
**解析：** Go使用`go`关键字启动goroutine，它是Go并发模型的核心。`thread`不是Go关键字；`async`/`await`是其他语言（如C#、JavaScript）的异步模式，Go不采用。

### 2. 以下关于Go变量声明的说法，正确的是？
A. `var x int = 10` 和 `x := 10` 完全等价  
B. `:=` 只能在函数内部使用  
C. 声明后未使用的变量只会导致警告  
D. 全局变量必须使用 `:=` 声明  

**答案：B**  
**解析：** `:=` 是短变量声明，只能在函数体内使用；`var`可在包级别使用。未使用的局部变量在Go中是编译错误，不是警告。全局变量不能用`:=`声明。

### 3. 以下代码的输出是？
```go
package main
import "fmt"
func main() {
    const a = 10
    const b int = 10
    fmt.Printf("%T %T", a, b)
}
```
A. int int  
B. int float64  
C. 10 10  
D. 编译错误  

**答案：A**  
**解析：** 无类型常量`a`在需要时默认为`int`；`b`显式声明为`int`。`%T`打印类型，因此输出`int int`。

### 4. Go中的`rune`类型本质上是？
A. 一个结构体  
B. Unicode码点，等价于`int32`  
C. 字符串的别名  
D. 字节数组  

**答案：B**  
**解析：** `rune`是`int32`的别名，用于表示Unicode码点。Go源文件默认UTF-8编码，字符字面量如`'中'`的类型是`rune`。

### 5. 关于Go的`switch`语句，以下说法错误的是？
A. 默认 break，不需要显式写  
B. 可以使用 `fallthrough` 继续下一个case  
C. case 后面必须是常量或字面量  
D. 可以同时判断多个值，如 `case 1, 2, 3:`  

**答案：C**  
**解析：** Go的`switch`表达式和case值不必是常量，case后面可以是表达式结果。A、B、D都是Go switch的正确特性。

## 二、填空题（每题1分，共4题）

### 6. Go程序的执行入口是 ______ 函数。  
**答案：** `main`  
**解析：** 可执行Go程序必须包含`package main`和`func main()`，后者是程序入口。`main`函数不接受参数也不返回任何值。

### 7. 使用 ______ 关键字可以导入一个包并为其指定别名。  
**答案：** `import`（例如 `import alias "fmt"`）  
**解析：** Go通过`import`导入包，语法为`import alias "path"`。点导入`. "fmt"`可将包符号引入当前命名空间，但不推荐常规使用。

### 8. 在Go中，零值（zero value）是指变量声明后未被显式初始化时自动赋予的值；`bool`类型的零值是 ______。  
**答案：** `false`  
**解析：** Go保证所有变量都有零值。`bool`零值为`false`，数值类型为`0`，字符串为`""`，指针/切片/映射/通道/接口/函数为`nil`。

### 9. 要使一个标识符仅在包内可见，其首字母应使用 ______ 写法。  
**答案：** 小写  
**解析：** Go通过首字母大小写控制可见性：大写标识符为导出（exported），包外可见；小写为未导出（unexported），仅在包内可见。

## 三、判断题（每题1分，共3题）

### 10. Go语言支持函数重载。  
**答案：** ❌错误  
**解析：** Go不支持函数重载，即不能定义同名但参数列表不同的函数。同一作用域内函数名必须唯一。这是为了保持语言简洁和接口实现的清晰。

### 11. `goto`语句在Go中是完全禁止的。  
**答案：** ❌错误  
**解析：** Go支持`goto`，但有严格限制：不能跳过变量声明、不能进入其他代码块、标签名必须区分大小写。虽然可用，但通常不推荐使用。

### 12. 在Go中，`iota`只能在`const`声明中使用，且从0开始递增。  
**答案：** ✅正确  
**解析：** `iota`是常量声明中的预声明标识符，表示当前`const`块中的常量索引，从0开始，每行递增1。在下一组`const`中重置为0。

## 四、简答题（每题2分，共2题）

### 13. 简述Go中`var`、`const`、`type`、`func`四个关键字的作用，并各举一个例子。  
**参考答案：**  
- `var`：声明变量，如 `var x int = 10`。  
- `const`：声明常量，如 `const Pi = 3.14`。  
- `type`：定义类型或类型别名，如 `type MyInt int`。  
- `func`：声明函数，如 `func add(a, b int) int { return a + b }`。  

**解析：** 这四个关键字是Go声明语法的基础。理解它们有助于区分变量、常量、类型抽象和函数定义，是阅读Go源码的前提。

### 14. 解释Go中的“显式类型转换”为什么比C/C++更严格，举例说明。  
**参考答案：**  
Go不允许隐式类型转换，必须显式书写转换表达式。例如 `var a int = 10; var b int64 = int64(a)`，不能直接将`int`赋值给`int64`。不同整型、浮点型之间都需要显式转换。  

**解析：** 严格的类型转换避免了C/C++中因隐式提升导致的精度丢失和意外行为，使代码意图更明确，但也要求开发者显式处理类型边界。

## 五、程序分析题（每题2分，共1题）

### 15. 阅读以下代码，写出输出结果。
```go
package main
import "fmt"
func main() {
    s := "Hello, 世界"
    fmt.Println(len(s))
    fmt.Println(len([]rune(s)))
}
```
**答案：**  
```
13
9
```

**解析：** `len(s)`返回字符串的字节数。"Hello, "占7字节，"世界"每个汉字占3字节（UTF-8），共6字节，所以总字节数为13。`[]rune(s)`将字符串转换为rune切片，每个rune对应一个Unicode字符，共9个字符。

# 第二部分：数据结构与容器

## 一、选择题（每题2分，共4题）

### 16. 关于Go的slice，以下说法正确的是？
A. slice是值类型，传递时会复制底层数组  
B. 使用`append`一定会分配新的底层数组  
C. slice包含指向底层数组的指针、长度和容量  
D. `len(slice)`返回的是容量  

**答案：C**  
**解析：** slice是引用类型（内部包含指针），传递时复制的是slice header（指针、len、cap），底层数组共享。`append`只有在容量不足时才分配新数组。`len`返回长度，`cap`返回容量。

### 17. 以下代码执行后，`m`的内容是？
```go
m := map[string]int{"a": 1, "b": 2}
m["a"]++
delete(m, "b")
fmt.Println(m)
```
A. map[a:1 b:2]  
B. map[a:2]  
C. map[a:1]  
D. 编译错误  

**答案：B**  
**解析：** `m["a"]++`将键`"a"`的值增加到2；`delete(m, "b")`删除键`"b"`。因此最终map为`map[a:2]`。

### 18. 以下哪个操作在Go中是安全的（不会panic）？
A. 读取nil slice的第三个元素 `nilSlice[2]`  
B. 访问map中不存在的键  
C. 对nil map直接赋值 `nilMap["k"] = 1`  
D. 对nil指针解引用  

**答案：B**  
**解析：** 访问map不存在的键返回零值，不会panic。A会越界panic；C会panic，因为nil map不能写入，必须先make；D会nil pointer dereference panic。

### 19. 关于数组和slice的区别，错误的是？
A. 数组长度是类型的一部分，`[3]int`和`[4]int`是不同类型  
B. slice可以通过`make([]int, 5, 10)`指定长度和容量  
C. 数组作为函数参数传递时会复制整个数组  
D. slice不能作为map的value类型  

**答案：D**  
**解析：** slice可以作为map的value，例如`map[string][]int`。数组长度是类型一部分；slice的make语法正确；数组传参会复制整个数组（大数组应用指针）。

## 二、填空题（每题1分，共3题）

### 20. 创建一个长度为5、容量为10的int类型slice，应写为 `make(______, 5, 10)`。  
**答案：** `[]int`  
**解析：** `make([]int, 5, 10)`创建长度为5、容量为10的slice。make的第二个参数是长度，第三个是容量，容量必须不小于长度。

### 21. 在Go中，读取map中不存在的键会返回该value类型的 ______。  
**答案：** 零值  
**解析：** map读取不存在的键不会panic，而是返回对应value类型的零值。常用`v, ok := m[k]`的逗号ok形式来区分键是否存在。

### 22. 切片表达式 `s[low:high]` 返回的新切片长度是 ______。  
**答案：** `high - low`  
**解析：** 切片操作`s[low:high]`包含索引low到high-1的元素，长度为`high-low`，容量为`cap(s)-low`。省略low或high时分别默认为0和len(s)。

## 三、判断题（每题1分，共3题）

### 23. map在Go中是有序的，遍历时会按键的字典序输出。  
**答案：** ❌错误  
**解析：** Go的map遍历顺序是随机的，这是语言规范 deliberate 的设计，防止开发者依赖特定顺序。如需有序输出，应手动对键排序。

### 24. slice的底层数组被多个slice共享时，修改其中一个slice的元素可能会影响其他slice。  
**答案：** ✅正确  
**解析：** 当多个slice共享同一底层数组时，通过其中一个slice修改共享区间的元素，其他slice也会看到变化，这是Go slice行为的重要特性，也是常见bug来源。

### 25. 使用`copy(dst, src)`复制slice时，只会复制min(len(dst), len(src))个元素。  
**答案：** ✅正确  
**解析：** `copy`函数复制元素数量为两个slice长度的较小值，不会自动扩展目标slice。若需要完整复制，需保证dst长度足够或先使用`make`/`append`扩容。

## 四、程序分析题（每题2分，共4题）

### 26. 阅读代码，写出输出。
```go
package main
import "fmt"
func main() {
    a := []int{1, 2, 3}
    b := a[1:2]
    b[0] = 100
    fmt.Println(a)
    fmt.Println(cap(b))
}
```
**答案：**  
```
[1 100 3]
2
```

**解析：** `b := a[1:2]`与`a`共享底层数组，因此修改`b[0]`即修改`a[1]`。`b`的容量为`cap(a)-1 = 3-1 = 2`，长度为1。

### 27. 以下代码输出什么？为什么？
```go
package main
import "fmt"
func main() {
    m := make(map[int][]int)
    m[1] = append(m[1], 10)
    fmt.Println(m)
}
```
**答案：** `map[1:[10]]`  
**解析：** 读取map中不存在的键`m[1]`返回nil slice，对nil slice调用`append`会分配新底层数组并追加元素，结果重新赋值给`m[1]`。因此map中存在键1，值为`[10]`。

### 28. 以下代码是否有问题？若有，如何修复？
```go
package main
import "fmt"
func main() {
    var m map[string]int
    m["key"] = 1
    fmt.Println(m)
}
```
**答案：** 会panic：assignment to entry in nil map。  
**解析：** 声明了map变量但未使用`make`初始化，其值为nil。对nil map写入会panic。修复方法：`m := make(map[string]int)` 或 `var m = map[string]int{}`。

### 29. 写出以下代码的输出。
```go
package main
import "fmt"
func main() {
    s := []int{1, 2, 3, 4, 5}
    s = append(s[:2], s[3:]...)
    fmt.Println(s)
}
```
**答案：** `[1 2 4 5]`  
**解析：** `s[:2]`为`[1 2]`，`s[3:]`为`[4 5]`，append后得到`[1 2 4 5]`。注意此操作可能覆盖原底层数组元素，因为append复用了原数组。

## 五、编程题（每题4分，共1题）

### 30. 编写一个Go函数，接收一个字符串切片，返回去重后的切片（保持原顺序）。
```go
func dedup(s []string) []string {
    seen := make(map[string]bool)
    result := make([]string, 0, len(s))
    for _, v := range s {
        if !seen[v] {
            seen[v] = true
            result = append(result, v)
        }
    }
    return result
}
```
**解析：** 使用map记录已出现的字符串，实现O(n)时间复杂度的去重。`make([]string, 0, len(s))`预分配容量以减少内存分配。保持原顺序只需按遍历顺序追加即可。

# 第三部分：函数/方法/模块

## 一、选择题（每题2分，共3题）

### 31. 关于Go的函数，以下说法错误的是？
A. 函数可以返回多个值  
B. 函数可以作为参数传递  
C. 函数内部可以声明同名函数  
D. 函数支持闭包  

**答案：C**  
**解析：** Go不支持函数内部再声明命名函数（嵌套函数），但可以在函数内部声明匿名函数并赋值给变量，形成闭包。A、B、D都是Go支持的特性。

### 32. 方法 receiver 使用指针类型和值类型的主要区别在于？
A. 指针receiver不能修改接收者字段  
B. 值receiver会复制接收者，大对象影响性能  
C. 接口实现时指针和值receiver可以混用  
D. 值receiver不能调用方法  

**答案：B**  
**解析：** 值receiver会复制整个接收者对象，适合不可变小对象；指针receiver共享对象，可修改字段并避免大对象复制。接口实现时，`*T`的方法集不包含`T`的方法，反之亦然，不能混用。

### 33. 以下关于Go模块（modules）的说法正确的是？
A. `go.mod`文件必须手动编写所有依赖  
B. `GOPATH`模式在Go 1.16后已被移除  
C. `go mod tidy`会自动添加缺失的依赖并移除未使用的依赖  
D. 模块路径通常使用相对路径  

**答案：C**  
**解析：** `go mod tidy`分析源码，添加缺失的import依赖并移除未使用的依赖。`go.mod`通常由`go mod init`和`go get`/`go mod tidy`自动维护。GOPATH模式在Go 1.16后仍可用但不推荐。模块路径通常使用类似`github.com/user/repo`的导入路径。

## 二、填空题（每题1分，共3题）

### 34. 函数 `func swap(a, b int) (int, int)` 返回两个值，调用时应写为 `x, y = swap(1, 2)`，这种返回方式称为 ______。  
**答案：** 多值返回（multiple return values）  
**解析：** Go函数支持返回多个值，常用于错误处理（result, error）。调用时可用相同数量的变量接收，或用空白标识符`_`忽略某些返回值。

### 35. 在方法定义 `func (p *Point) Move(dx, dy float64)` 中，`p` 被称为 ______。  
**答案：** receiver（接收者）  
**解析：** receiver是Go中方法的隐式第一个参数，相当于其他语言中的`this`或`self`。它可以是值类型或指针类型，决定了方法能否修改原对象以及调用时是否发生复制。

### 36. 要发布一个Go模块的v2及以上主版本，模块路径应在末尾加上 ______。  
**答案：** `/v2`（或 `/vN`）  
**解析：** 根据语义化版本规范，Go模块主版本号大于等于2时，模块路径必须包含主版本后缀，如`module example.com/foo/v2`。这样导入路径也需要包含`/v2`。

## 三、判断题（每题1分，共2题）

### 37. Go函数支持默认参数值。  
**答案：** ❌错误

### 39. 解释Go中`defer`语句的执行时机和LIFO特性，举例说明。  
**参考答案：**  
`defer`语句会在包含它的函数返回之前执行，多个defer按后进先出（LIFO）顺序执行。常用于资源释放、锁解锁、关闭文件等。例如：

```go
func example() {
    defer fmt.Println("first")
    defer fmt.Println("second")
    fmt.Println("do something")
}
// 输出：do something, second, first
```

**解析：** defer的执行时机是函数返回前，不是离开作用域时。LIFO顺序意味着最后defer的最先执行，类似栈。defer的参数在defer语句处求值，但函数调用延迟到返回前。

**参考答案：**

**解析：** Go 1.13起默认使用`https://proxy.golang.org`。企业和中国大陆开发者常配置`GOPROXY=https://goproxy.cn,direct`以解决访问慢或无法访问的问题。`GOSUMDB`用于校验模块哈希。

### 58. 解释Go接口值与nil比较的陷阱，并给出避免方法。  
**参考答案：**  
接口值内部包含动态类型和动态值。当将nil具体类型指针赋给接口时，接口的动态类型不为nil，因此接口值不为nil。例如`var p *int = nil; var i interface{} = p; i != nil`。避免方法是在返回error等接口前检查具体值是否为nil，或在接口方法内部处理nil receiver。

### 59. 简述struct embedding与方法提升（method promotion）的作用和限制。  
**参考答案：**  
嵌入字段的方法会被提升到外层结构体，外层类型可直接调用。若外层定义同名方法，则覆盖提升的方法。嵌入指针类型时，外层类型方法集中包含指针receiver的方法。通过提升可实现类似继承的复用，但没有多态。  

**解析：** embedding是Go实现组合复用的关键机制。限制包括：不能提升未导出方法；嵌入类型自身方法集中未导出的方法仍不可从外层访问；方法名冲突时外层优先。

**参考答案：**  
- Type alias（`type T = U`）：创建等价别名，用于渐进式重构，如将旧包类型迁移到新位置时保持兼容。  
- Type definition（`type T U`）：创建新类型，可附加方法和语义，如`type UserID int`防止不同语义整型混用。  

**解析：** 别名在Go 1.9引入，主要用于大型代码库重构。新类型通过编译器强制区分不同语义，提高类型安全，是Go类型系统的核心特性。

### 70. 解释Go内存模型中的Happens Before关系，并说明无缓冲channel如何保证同步。  
**参考答案：**  
Happens Before是事件间的偏序关系：若事件A Happens Before B，则A的结果对B可见。无缓冲channel的发送操作Happens Before对应的接收操作完成。因此，发送方在发送前写入的变量对接收方可见。  

**解析：** Go内存模型通过channel通信和`sync`包原语定义同步。无缓冲channel的同步性使其成为goroutine间传递信号和数据的可靠方式，避免了显式锁。

### 71. 简述`context.Context`的用途和常见使用模式。  
**参考答案：**  
`context.Context`用于在API边界和goroutine之间传递截止时间、取消信号和请求范围值。常见模式：用`context.WithTimeout`/`WithCancel`创建子context；将context作为函数第一个参数传递；监听`<-ctx.Done()`及时退出。  

**解析：** context是Go并发编程的基础设施，解决了请求级取消、超时控制和元数据传递问题。应避免将context存储在struct中，而是显式传递。

### 72. 解释Go中`defer`、`panic`、`recover`的协作流程。  
**参考答案：**  
`defer`注册的函数在函数返回前按LIFO执行。当发生panic时，当前函数停止执行，开始执行defer。若defer中调用`recover`且当前存在panic，则recover返回panic值并停止panic传播；否则panic继续向上传播直到被捕获或程序崩溃。  

**解析：** defer/panic/recover是Go的错误处理补充机制，适用于真正不可恢复的错误。recover只能捕获当前goroutine的panic，不能跨goroutine恢复。

### 75. 编写一个函数，使用`context.WithTimeout`控制一组goroutine在2秒内完成工作，超时则取消。

```go
    "fmt"
    "time"
)

    case <-time.After(time.Duration(id+1) * time.Second):

    }
    time.Sleep(3 * time.Second)
}
```
**解析：** `context.WithTimeout`在2秒后自动取消ctx。worker中通过select监听`ctx.Done()`，超时立即退出。`defer cancel()`确保资源释放，即使超时也会取消。

### 76. 实现一个线程安全的计数器。
```go
type SafeCounter struct {
    mu    sync.Mutex
    count int
}
func (c *SafeCounter) Inc() {
    c.mu.Lock()
    defer c.mu.Unlock()
    c.count++
}
func (c *SafeCounter) Value() int {
    c.mu.Lock()
    defer c.mu.Unlock()
    return c.count
}
```
**解析：** 使用`sync.Mutex`保护共享变量`count`。`Inc`和`Value`都先加锁再操作，保证并发安全。`defer`确保锁在函数返回时释放，即使发生panic也不会死锁。

### 77. 使用`sync.WaitGroup`等待N个goroutine完成并收集结果。
```go
package main
import (
    "fmt"
    "sync"
)
func main() {
    var wg sync.WaitGroup
    results := make([]int, 10)
    for i := 0; i < 10; i++ {
        wg.Add(1)
        go func(i int) {
            defer wg.Done()
            results[i] = i * i
        }(i)
    }
    wg.Wait()
    fmt.Println(results)
}
```
**解析：** 每个goroutine计算平方并写入results的对应索引。WaitGroup等待所有goroutine完成后主函数继续。注意循环变量`i`必须作为参数传入匿名函数，否则所有goroutine会共享同一个变量导致竞态。

### 78. 实现一个函数，使用channel实现扇出（fan-out）模式，将任务分发给多个worker处理。
```go
package main
import (
    "fmt"
    "sync"
)
func worker(id int, jobs <-chan int, results chan<- int, wg *sync.WaitGroup) {
    defer wg.Done()
    for j := range jobs {
        results <- j * j
    }
}
func main() {
    jobs := make(chan int, 100)
    results := make(chan int, 100)
    var wg sync.WaitGroup
    for w := 1; w <= 3; w++ {
        wg.Add(1)
        go worker(w, jobs, results, &wg)
    }
    for j := 1; j <= 9; j++ {
        jobs <- j
    }
    close(jobs)
    wg.Wait()
    close(results)
    for r := range results {
        fmt.Println(r)
    }
}
```
**解析：** 创建固定数量的worker goroutine从jobs channel读取任务，将结果写入results channel。关闭jobs后worker通过range自动退出，WaitGroup等待全部完成后关闭results。注意results channel必须有足够缓冲或由独立goroutine消费，否则可能死锁。

```go
package main

func mayPanic() {
    panic("a problem")
}
func safeCall() (err error) {
    defer func() {
        if r := recover(); r != nil {
            err = fmt.Errorf("recovered: %v", r)
        }
    }()
    mayPanic()
    return nil
}
func main() {

    }
    fmt.Println("continue")
}
```

```
continue
```

### 106. 设计一个 goroutine 池，限制同时运行的任务数量，并收集所有任务的error。  
**参考答案：**
```go
package main
import (
    "context"
    "fmt"
    "sync"
)
type Pool struct {
    max     int
    wg      sync.WaitGroup
    errChan chan error
    sem     chan struct{}
}
func NewPool(max int) *Pool {
    return &Pool{
        max:     max,
        errChan: make(chan error, max),
        sem:     make(chan struct{}, max),
    }
}
func (p *Pool) Submit(ctx context.Context, fn func() error) {
    p.sem <- struct{}{}
    p.wg.Add(1)
    go func() {
        defer p.wg.Done()
        defer func() { <-p.sem }()
        if err := fn(); err != nil {
            select {
            case p.errChan <- err:
            case <-ctx.Done():
            }
        }
    }()
}
func (p *Pool) Wait() {
    p.wg.Wait()
    close(p.errChan)
}
```

**解析：** 使用有缓冲channel作为信号量控制并发数。`Submit`获取信号量后启动goroutine，任务完成后释放。`errChan`收集错误，Wait关闭channel。注意context取消时避免向已关闭channel发送。

### 107. 实现一个基于channel的令牌桶限流器，每秒放入N个令牌，消费时若无令牌则阻塞。  
**参考答案：**
```go
package main
import (
    "fmt"
    "time"
)
type TokenBucket struct {
    tokens chan struct{}
    done   chan struct{}
}
func NewTokenBucket(rate int) *TokenBucket {
    tb := &TokenBucket{
        tokens: make(chan struct{}, rate),
        done:   make(chan struct{}),
    }
    go func() {
        ticker := time.NewTicker(time.Second / time.Duration(rate))
        defer ticker.Stop()
        for {
            select {
            case <-ticker.C:
                select {
                case tb.tokens <- struct{}{}:
                default:
                }
            case <-tb.done:
                return
            }
        }
    }()
    return tb
}
func (tb *TokenBucket) Take() {
    <-tb.tokens
}
func (tb *TokenBucket) Stop() {
    close(tb.done)
}
func main() {
    tb := NewTokenBucket(5)
    defer tb.Stop()
    for i := 0; i < 10; i++ {
        tb.Take()
        fmt.Println("request", i, time.Now())
    }
}
```

**解析：** 使用ticker按固定速率向有缓冲channel放入令牌，请求时从channel读取阻塞等待。channel容量等于桶大小，自然实现漏桶/令牌桶限流。注意优雅关闭ticker和生产者goroutine。

### 108. 设计一个并发安全的本地缓存，支持Set/Get/Delete和过期清理。  
**参考答案：**
```go
type Cache struct {
    mu     sync.RWMutex
    items  map[string]item
    stop   chan struct{}
}
type item struct {
    value      interface{}
    expiration time.Time
}
func NewCache(cleanupInterval time.Duration) *Cache {
    c := &Cache{
        items: make(map[string]item),
        stop:  make(chan struct{}),
    }
    go c.cleanup(cleanupInterval)
    return c
}
func (c *Cache) Set(k string, v interface{}, d time.Duration) {
    c.mu.Lock()
    defer c.mu.Unlock()
    c.items[k] = item{value: v, expiration: time.Now().Add(d)}
}
func (c *Cache) Get(k string) (interface{}, bool) {
    c.mu.RLock()
    defer c.mu.RUnlock()
    it, ok := c.items[k]
    if !ok || time.Now().After(it.expiration) {
        return nil, false
    }
    return it.value, true
}
func (c *Cache) Delete(k string) {
    c.mu.Lock()
    defer c.mu.Unlock()
    delete(c.items, k)
}
func (c *Cache) cleanup(interval time.Duration) {
    ticker := time.NewTicker(interval)
    defer ticker.Stop()
    for {
        select {
        case <-ticker.C:
            c.mu.Lock()
            now := time.Now()
            for k, v := range c.items {
                if now.After(v.expiration) {
                    delete(c.items, k)
                }
            }
            c.mu.Unlock()
        case <-c.stop:
            return
        }
    }
}
```

**解析：** 使用`sync.RWMutex`保证并发安全，读多写少场景下性能较好。后台goroutine定时扫描并删除过期项。生产环境可使用`github.com/patrickmn/go-cache`等成熟库。

## 二、代码调试题（每题3分，共4题）

### 109. 以下代码存在什么问题？如何修复？
```go
package main
import "fmt"
func main() {
    var s []int
    for i := 0; i < 5; i++ {
        go func() {
            s = append(s, i)
        }()
    }
    fmt.Println(s)
}
```
**答案：** 存在竞态条件和闭包变量捕获问题。  
**解析：** `i`被所有goroutine共享，循环结束时i=5，多个goroutine并发读写slice。修复：1）传递i作为参数；2）使用mutex或channel同步append；3）使用WaitGroup等待完成。正确示例如下：

```go
var mu sync.Mutex
var wg sync.WaitGroup
for i := 0; i < 5; i++ {
    wg.Add(1)
    go func(i int) {
        defer wg.Done()
        mu.Lock()
        s = append(s, i)
        mu.Unlock()
    }(i)
}
wg.Wait()
fmt.Println(s)
```

### 110. 以下代码为什么可能输出 `[3 3 3]` 而不是预期的三个不同值？
```go
package main
import "fmt"
func main() {
    s := make([]func(), 3)
    for i := 0; i < 3; i++ {
        s[i] = func() { fmt.Println(i) }
    }
    for _, f := range s {
        f()
    }
}
```
**答案：** 闭包捕获了循环变量`i`的引用，执行时i已是最终值3。  
**解析：** for循环中的`i`是单一变量，所有闭包共享同一引用。执行时i=3，fmt.Println(i)输出3。修复方法：在循环内创建局部变量`j := i`，闭包引用j。

### 111. 以下代码会panic吗？为什么？
```go
package main
import "fmt"
func main() {
    ch := make(chan int)
    close(ch)
    fmt.Println(<-ch)
}
```
**答案：** 不会panic，输出0。  
**解析：** 关闭channel后仍可读取，直到缓冲区为空，之后读取返回零值。这里无缓冲channel关闭后读取返回int零值0。向关闭的channel发送会panic，但接收不会。使用`v, ok := <-ch`可判断channel是否关闭且还有数据。

### 112. 以下代码的输出是什么？是否存在问题？
```go
package main
import "fmt"
func main() {
    m := map[int]int{1: 1, 2: 2, 3: 3}
    for k, v := range m {
        go func() {
            fmt.Println(k, v)
        }()
    }
}
```
**答案：** 输出不确定，存在竞态和闭包捕获问题。  
**解析：** goroutine中的闭包捕获了循环变量k、v的引用，所有goroutine可能打印循环结束后的同一对键值（甚至map遍历结束后的无效状态）。应传递参数`go func(k, v int) { ... }(k, v)`，并注意map并发读写需要同步。

## 三、系统设计题（每题4分，共3题）

### 113. 设计一个基于Go的高并发任务调度系统，要求支持任务提交、优先级、超时取消和错误重试。  
**参考答案：**  
1. 任务定义：包含ID、优先级、payload、deadline、重试次数。  
2. 调度器：维护优先队列（heap.Interface实现），按优先级和提交时间排序。  
3. 执行器：固定数量worker goroutine从队列取任务执行。  
4. 取消：每个任务携带context，worker检查`ctx.Done()`。  
5. 重试：失败任务根据策略放回队列或进入死信队列。  
6. 监控：暴露metrics（任务数、延迟、错误率）。  

**解析：** 核心组件包括任务队列、调度器、worker池、context生命周期管理和重试策略。使用优先队列保证高优先级任务优先执行，context实现超时和取消，channel实现任务分发。

### 114. 设计一个使用Go实现的简单分布式ID生成器，要求趋势递增且支持每秒万级QPS。  
**参考答案：**  
1. 采用号段模式：从数据库或Redis批量获取一段ID区间（如1-1000）。  
2. 本地缓存：服务实例内存中维护当前区间和游标。  
3. 原子递增：使用`sync/atomic`对本地游标原子加1，无锁高性能。  
4. 预加载：当前区间用到一定比例（如80%）时异步加载下一段。  
5. 多实例协调：数据库记录max_id，各实例申请不同区间。  

**解析：** 号段模式将网络IO与ID生成解耦，本地原子操作保证高吞吐。趋势递增适合数据库索引。也可用Snowflake算法，但依赖时钟且ID非连续。Go中`sync/atomic`可实现无锁本地ID分配。

### 115. 设计一个Go实现的WebSocket消息推送系统，支持单播、广播和在线状态管理。  
**参考答案：**  
1. 连接管理：每个连接用一个goroutine + channel表示，Hub维护`map[userID]*Client`。  
2. 消息路由：Hub接收消息后根据类型分发：单播查表发送，广播遍历所有client。  
3. 并发安全：Hub操作加`sync.RWMutex`，client发送channel缓冲避免阻塞。  
4. 心跳：goroutine定时ping，超时未pong则关闭连接。  
5. 在线状态：Hub维护用户上线/下线事件，支持查询和订阅。  

**解析：** Go的goroutine-per-connection模型非常适合WebSocket。Hub中心式管理简化了广播逻辑，但要注意锁粒度、goroutine泄漏和慢客户端问题。可使用`sync.Map`或分段锁优化高并发场景。
