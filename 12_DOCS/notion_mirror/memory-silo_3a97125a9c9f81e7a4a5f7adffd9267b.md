## 容器设计原则
### 一、单容器
所有记忆在一个文件里。不拆分 MEMORY.md / 日期日志 / 观察层 / 投喂归档。 结构分层，但物理上是同一个容器。
### 二、多Agent协同
每个 Agent 写入前必须： 1. 读当前容器 → 检查是否有人在写（锁标记） 2. 获取自己的 Agent 槽位（按时间槽分配） 3. 写入时打上 Agent 签名 + 时间戳 + 操作类型 4. 写完释放锁
### 三、可复盘
每条记录必须含：
- 谁写的（Agent ID）
- 什么时候写的（干支时间戳）
- 做了什么（操作类型：决策/执行/观察/修复/归档）
- 为什么这么做（一句话理由）
- 结果是什么（成功/失败/部分）
### 四、战友谦让
- 写前检查锁 → 有锁就等，不硬抢
- 同一个区域不能同时写 → 按槽位排队
- 读不锁、写锁 → 不阻塞阅读
- 锁超时自动释放（5分钟）→ 防止死锁

## 容器锁机制
```plain text
锁状态: { FREE | LOCKED }
锁持有者: { Agent ID | NULL }
锁获取时间: { 干支时间戳 | NULL }
锁超时: 5分钟
```
规则：
- 任何 Agent 写入前必须检查锁
- 锁为 FREE → 获取锁 → 写入 → 释放锁
- 锁为 LOCKED → 等待（最多30秒）→ 超时则跳过本次写入，记录"因锁冲突跳过"
- 锁超过5分钟未释放 → 任何 Agent 可强制释放（记录"强制解锁"）
