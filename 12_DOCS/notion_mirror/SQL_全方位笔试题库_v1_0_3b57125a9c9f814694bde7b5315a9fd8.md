# 第一部分：SQL基础语法

### 1. 在标准 SQL 中，`WHERE` 子句的正确位置是？
A. `SELECT ... GROUP BY ... WHERE ...`  
B. `SELECT ... WHERE ... GROUP BY ...`  
C. `SELECT ... HAVING ... WHERE ...`  
D. `SELECT ... WHERE ... ORDER BY ... GROUP BY ...`

**答案：B**

**解析：** 标准 SQL 语法顺序为 `SELECT ... FROM ... WHERE ... GROUP BY ... HAVING ... ORDER BY ...`。`WHERE` 在 `GROUP BY` 之前，用于过滤行。

### 2. 要查询姓名以字母 `A` 开头的员工，应使用哪个 `LIKE` 模式？
A. `WHERE name LIKE '%A'`  
B. `WHERE name LIKE 'A%'`  
C. `WHERE name LIKE '_A'`  
D. `WHERE name = 'A%'`

**答案：B**

**解析：** `%` 匹配任意长度字符序列，`A%` 表示以 A 开头。`%A` 表示以 A 结尾，`_` 匹配单个字符，字符串常量不会把 `%` 当通配符。

### 3. 在三值逻辑中，哪个表达式的结果确定为 `TRUE`？
A. `NULL = NULL`  
B. `NULL OR TRUE`  
C. `NULL AND TRUE`  
D. `NOT NULL`

**答案：B**

**解析：** SQL 使用三值逻辑，`NULL OR TRUE` 为 `TRUE`。`NULL = NULL`、`NULL AND TRUE`、`NOT NULL` 的结果均为 `UNKNOWN`。

### 4. `ORDER BY salary DESC, name ASC` 排序时，主要排序依据是？
A. `name`  
B. `salary`  
C. 两列权重相同  
D. 随机排序

**答案：B**

**解析：** `ORDER BY` 按列顺序进行多级排序，先按 `salary` 降序，再按 `name` 升序处理相同 `salary` 的行。

### 5. `SELECT COUNT(*) FROM orders;` 返回什么？
A. `orders` 表中非空列数量  
B. `orders` 表的行数  
C. `orders` 表中不同订单数量  
D. `NULL` 的个数

**答案：B**

**解析：** `COUNT(*)` 统计结果集中的行数，包含所有列值为 `NULL` 的行。`COUNT(column)` 才忽略该列的 `NULL`。

### 6. 在 SQL 中，哪个子句可以直接引用 `SELECT` 列表中定义的列别名？
A. `WHERE`  
B. `GROUP BY`  
C. `HAVING`  
D. `ORDER BY`

**答案：D**

**解析：** 标准 SQL 中，`WHERE` 在 `SELECT` 之前执行，不能引用别名；`ORDER BY` 在 `SELECT` 之后执行，可以使用别名（部分数据库也允许 `GROUP BY` 使用别名，但不标准）。

### 7. 填空：在标准 SQL 中，要返回表 `t` 按 `id` 排序后的前 10 行，应写 `SELECT * FROM t ORDER BY id ______;`

**答案：** `FETCH FIRST 10 ROWS ONLY`（或 `LIMIT 10`，视具体数据库而定）

**解析：** 标准 SQL 使用 `FETCH FIRST n ROWS ONLY` 限制返回行数；MySQL/PostgreSQL 常用 `LIMIT n`。该子句必须位于 `ORDER BY` 之后才能保证结果稳定。

### 8. 填空：补全以下 `CASE` 表达式，使 70–79 分映射为 `C`：
```sql
SELECT CASE WHEN score >= 90 THEN 'A'
            WHEN score >= 80 THEN 'B'
            ______
            ELSE 'D' END AS grade
FROM scores;
```

**答案：** `WHEN score >= 70 THEN 'C'`

**解析：** `CASE` 按顺序匹配第一个为 `TRUE` 的条件，因此范围判断应从高分往低分写。若先写 `>=70`，则 90 分也会被误归为 C。

### 9. 填空：`LIKE 'A_'` 中的下划线通配符匹配 ______ 个字符。

**答案：** 1

**解析：** 在 SQL 的 `LIKE` 中，`_` 精确匹配单个字符，`%` 匹配零个或多个字符。

### 10. 判断：SQL 中字符串常量必须用单引号括起来。

**答案：** ✅正确

**解析：** 标准 SQL 使用单引号 `'...'` 表示字符串字面量。双引号通常用于标识符（如列名），但在 MySQL 中双引号可能被当作字符串，取决于 `SQL_MODE`。

### 11. 判断：`WHERE` 子句中可以使用聚合函数如 `SUM()`。

**答案：** ❌错误

**解析：** 聚合函数在 `WHERE` 阶段尚未计算，因此不能出现在 `WHERE` 中。需要对聚合结果过滤时，应使用 `HAVING` 子句。

### 12. 判断：`SELECT DISTINCT dept, job FROM emp` 会对 `(dept, job)` 组合去重。

**答案：** ✅正确

**解析：** `DISTINCT` 作用于整行输出，当列出多列时，只有当所有列的组合完全相同时才视为重复并去除。

# 第二部分：数据结构与容器

### 13. `PRIMARY KEY` 的主要作用是？
A. 自动创建索引  
B. 唯一标识表中的每一行  
C. 允许列值为 `NULL`  
D. 建立外键约束

**答案：B**

**解析：** 主键用于唯一标识每一行记录，隐含 `NOT NULL` 和唯一性约束。虽然多数数据库会为主键创建索引，但这不是其主要语义。

### 14. 第二范式（2NF）主要消除哪种依赖？
A. 多值依赖  
B. 部分函数依赖  
C. 传递函数依赖  
D. 完全函数依赖

**答案：B**

**解析：** 2NF 要求表首先满足 1NF，并且非主属性完全依赖于整个候选键，消除部分依赖。传递依赖由 3NF 消除。

### 15. `CHAR(10)` 与 `VARCHAR(10)` 的核心区别是？
A. `CHAR` 支持 Unicode，`VARCHAR` 不支持  
B. `CHAR` 固定长度，`VARCHAR` 可变长度  
C. `CHAR` 最大长度更大  
D. 两者完全相同

**答案：B**

**解析：** `CHAR(n)` 存储固定长度字符串，不足时以空格补齐；`VARCHAR(n)` 只存储实际长度。固定长度在定长场景下可能更节省寻址开销，但会浪费存储。

### 16. 外键约束声明 `ON DELETE CASCADE` 时，删除父表记录会？
A. 将子表对应外键设为 `NULL`  
B. 自动删除子表中关联记录  
C. 阻止删除  
D. 仅更新父表

**答案：B**

**解析：** `CASCADE` 级联删除表示删除父表记录时，子表中所有引用该记录的行也会被删除。`SET NULL` 和 `RESTRICT` 是另外两种常见动作。

### 17. 存储精确货币金额时，最合适的数据类型是？
A. `FLOAT`  
B. `DOUBLE PRECISION`  
C. `NUMERIC(19,4)`  
D. `REAL`

**答案：C**

**解析：** `NUMERIC`/`DECIMAL` 是定点数，能精确表示小数，避免浮点误差。浮点类型在货币计算中会产生精度问题。

### 18. 填空：在 `CREATE TABLE` 中，用于确保列值不能为 `NULL` 的约束关键字是 ______。

**答案：** `NOT NULL`

**解析：** `NOT NULL` 约束禁止列出现 `NULL` 值，保证该字段必须有明确数据。它属于列级完整性约束。

### 19. 填空：第三范式（3NF）要求消除非主属性对候选键的 ______ 依赖。

**答案：** 传递

**解析：** 3NF 在 2NF 基础上，要求任何非主属性不依赖于其他非主属性，即消除传递依赖。这样可以进一步减少数据冗余和更新异常。

### 20. 填空：在一个表中引用另一个表主键的列称为 ______ 键。

**答案：** 外（或 foreign）

**解析：** 外键用于维护表与表之间的引用完整性，其取值必须等于被引用表的主键值或为空（若允许）。

### 21. 填空：标准 SQL 中用于存储带时区的日期时间类型是 ______。

**答案：** `TIMESTAMP WITH TIME ZONE`

**解析：** 该类型保存时间戳及其时区信息，检索时会按会话时区转换。无时区类型 `TIMESTAMP` 不保存时区偏移。

### 22. 判断：标准 SQL 中，`UNIQUE` 约束允许存在多个 `NULL` 值。

**答案：** ✅正确

**解析：** 由于 SQL 中 `NULL != NULL`，标准 SQL 认为多个 `NULL` 不构成重复，因此 `UNIQUE` 列可以存在多个 `NULL`。具体实现可能有限制。

### 23. 判断：规范化程度越高，查询性能一定越好。

**答案：** ❌错误

**解析：** 高规范化减少了冗余和更新异常，但查询常需多表连接，可能降低读性能。实际设计常在规范化与反规范化之间权衡。

### 24. 判断：`DROP TABLE customers;` 会同时删除表结构和表中所有数据。

**答案：** ✅正确

**解析：** `DROP TABLE` 是 DDL 操作，会永久移除表定义、数据、索引及依赖对象，且通常不可回滚（在自动提交模式下）。

# 第三部分：函数/方法/模块

### 25. `COUNT(*)` 与 `COUNT(salary)` 的区别是？
A. 两者完全相同  
B. `COUNT(*)` 包含 `salary` 为 `NULL` 的行，`COUNT(salary)` 忽略这些行  
C. `COUNT(salary)` 更快  
D. `COUNT(*)` 只统计非空列

**答案：B**

**解析：** `COUNT(*)` 统计所有行；`COUNT(expr)` 统计 `expr` 不为 `NULL` 的行。若 `salary` 有 `NULL`，两者结果不同。

### 26. 要对聚合后的结果进行过滤，应使用哪个子句？
A. `WHERE`  
B. `HAVING`  
C. `ORDER BY`  
D. `LIMIT`

**答案：B**

**解析：** `HAVING` 在 `GROUP BY` 之后执行，用于过滤分组后的聚合结果。`WHERE` 不能引用聚合函数。

### 27. 严格标准 SQL 中，`SELECT dept, AVG(salary) FROM emp;`（未使用 `GROUP BY`）会？
A. 返回每个部门的平均工资  
B. 返回全表平均工资  
C. 报错  
D. 返回工资最大值

**答案：C**

**解析：** 标准 SQL 要求 `SELECT` 中非聚合列必须出现在 `GROUP BY` 中。`dept` 未聚合且未分组，因此会报错。某些数据库在宽松模式下可能返回任意值。

### 28. `COALESCE(a, b, c)` 的作用是？
A. 返回第一个 `NULL`  
B. 返回第一个非 `NULL` 值  
C. 返回最后一个非 `NULL` 值  
D. 拼接三个值

**答案：B**

**解析：** `COALESCE` 按参数顺序返回第一个非 `NULL` 值，常用于为可能为 `NULL` 的列提供默认值。

### 29. 标准 SQL 中从日期提取年份的表达式是？
A. `YEAR(date_col)`  
B. `EXTRACT(YEAR FROM date_col)`  
C. `DATEPART(YEAR, date_col)`  
D. `GET_YEAR(date_col)`

**答案：B**

**解析：** `EXTRACT(field FROM source)` 是 SQL 标准。`YEAR()` 和 `DATEPART()` 是 MySQL/SQL Server 的方言函数。

### 30. `SELECT SUM(salary) FROM emp WHERE 1=0;` 返回？
A. `0`  
B. `NULL`  
C. 空结果集  
D. 报错

**答案：B**

**解析：** 当 `WHERE` 条件恒为假时，聚合函数没有输入行。`SUM` 在没有行时返回 `NULL`，而 `COUNT` 返回 `0`。

### 31. 填空：统计某列不重复值的数量的聚合写法是 `______(column)`。

**答案：** `COUNT(DISTINCT`

**解析：** `COUNT(DISTINCT col)` 先对列去重，再统计去重后的行数。不能写成 `DISTINCT COUNT(col)`。

### 32. 填空：要筛选出成员数超过 5 的部门，应使用 `GROUP BY dept ______ COUNT(*) > 5;`。

**答案：** `HAVING`

**解析：** `HAVING` 专门对分组结果施加条件。此处若用 `WHERE` 会报错，因为 `COUNT(*)` 是聚合函数。

### 33. 填空：标准 SQL 中返回当前日期的函数是 ______。

**答案：** `CURRENT_DATE`

**解析：** `CURRENT_DATE` 返回会话时区下的当前日期，不含时间部分。不同数据库还有 `CURDATE()`、`GETDATE()` 等方言。

### 34. 填空：标准 SQL 中用于拼接两个字符串的运算符是 ______。

**答案：** `||`

**解析：** 标准 SQL 使用 `||` 进行字符串连接。MySQL 默认使用 `CONCAT()`，但在 `PIPES_AS_CONCAT` 模式下也支持 `||`。

### 35. 判断：如果 `SELECT` 列表中所有列都使用聚合函数，则可以不带 `GROUP BY`。

**答案：** ✅正确

**解析：** 当所有选择列均为聚合函数时，整个结果集被视为一个分组，返回单行汇总结果。这是标准 SQL 的合法写法。

### 36. 判断：`HAVING` 子句可以在没有 `GROUP BY` 的情况下使用。

**答案：** ✅正确

**解析：** 没有 `GROUP BY` 时，所有行被作为一个整体分组，`HAVING` 可以对该整体应用聚合条件，例如 `HAVING COUNT(*) > 0`。

# 第四部分：面向对象/类型系统

### 37. `NUMERIC(10,2)` 的精度含义是？
A. 共 10 位数字，其中整数部分 8 位，小数 2 位  
B. 最大存储 10 字节，保留 2 位小数  
C. 共 10 位有效数字，小数点后 2 位  
D. 整数部分 10 位，小数部分 2 位

**答案：C**

**解析：** `NUMERIC(p,s)` 中 `p` 是总有效数字位数（精度），`s` 是小数位数。因此整数部分最多为 `p-s` 位，即 8 位。

### 38. `CAST('2024-06-01' AS DATE)` 属于？
A. 隐式类型转换  
B. 显式类型转换  
C. 自动截断  
D. 聚合转换

**答案：B**

**解析：** `CAST` 是显式转换函数，允许在不同兼容类型之间安全转换。隐式转换由数据库在执行比较或赋值时自动完成。

### 39. 哪个约束可以限制列值必须属于指定集合？
A. `CHECK`  
B. `FOREIGN KEY`  
C. `UNIQUE`  
D. `DEFAULT`

**答案：A**

**解析：** `CHECK (col IN ('A','B'))` 可以限制取值集合。`FOREIGN KEY` 限制引用另一表的值，`UNIQUE` 限制唯一性，`DEFAULT` 提供默认值。

### 40. `DEFAULT CURRENT_TIMESTAMP` 的作用是？
A. 每次更新都刷新时间戳  
B. 插入时自动填充当前时间戳  
C. 删除时记录时间  
D. 仅用于查询

**答案：B**

**解析：** `DEFAULT` 值在插入行且未显式提供该列值时使用。若需更新时刷新，应额外使用 `ON UPDATE`（MySQL）或触发器。

### 41. 标准 SQL 中创建用户自定义类型可使用？
A. `CREATE DOMAIN`  
B. `CREATE TYPE`  
C. 两者皆可  
D. 两者皆不可

**答案：C**

**解析：** `CREATE DOMAIN` 创建带约束的标量类型，`CREATE TYPE` 可创建复合类型、枚举类型等。具体支持取决于数据库。

### 42. 填空：`CHECK` 约束可以在列级定义，也可以在 ______ 级定义。

**答案：** 表

**解析：** 表级 `CHECK` 约束可以引用多个列，例如 `CHECK (start_date < end_date)`；列级只能引用单个列。

### 43. 填空：当父表记录被删除时，将子表外键设为 `NULL` 的引用动作是 `ON DELETE ______`。

**答案：** `SET NULL`

**解析：** `ON DELETE SET NULL` 会将被引用行删除后，把子表中对应外键列更新为 `NULL`，前提是外键列允许为 `NULL`。

### 44. 填空：四种标准事务隔离级别从低到高依次为 `READ UNCOMMITTED`、`READ COMMITTED`、`______`、`SERIALIZABLE`。

**答案：** `REPEATABLE READ`

**解析：** `REPEATABLE READ` 保证同一事务内多次读取同一行结果一致，但仍可能出现幻读；`SERIALIZABLE` 最高，避免幻读但并发最低。

### 45. 判断：主键会自动创建唯一索引。

**答案：** ✅正确

**解析：** 大多数关系型数据库为了实现主键的唯一性和快速查找，会自动为主键列创建唯一索引（通常是 B-tree 聚集或非聚集索引）。

### 46. 判断：`CHECK` 约束可以直接引用其他表的列。

**答案：** ❌错误

**解析：** 标准 `CHECK` 约束只能引用本表的列，不能跨表。若需跨表完整性，应使用外键约束或触发器。

# 第五部分：高级特性

### 47. 哪种连接会返回左表中所有行，即使右表没有匹配？
A. `INNER JOIN`  
B. `LEFT JOIN`  
C. `RIGHT JOIN`  
D. `CROSS JOIN`

**答案：B**

**解析：** `LEFT OUTER JOIN` 保留左表全部行，右表无匹配时以 `NULL` 填充。`INNER JOIN` 只保留匹配行，`CROSS JOIN` 返回笛卡尔积。

### 48. 表 A 有 3 行，表 B 有 4 行，`A CROSS JOIN B` 的结果行数是？
A. 7  
B. 12  
C. 1  
D. 不确定

**答案：B**

**解析：** `CROSS JOIN` 产生笛卡尔积，结果行数为两表行数乘积，即 `3 × 4 = 12`，每行与另一表每行组合。

### 49. `SELECT a.* FROM A a LEFT JOIN B b ON a.id = b.id WHERE b.id IS NULL;` 返回？
A. A 与 B 的交集  
B. 仅在 A 中而不在 B 中的行  
C. 仅在 B 中而不在 A 中的行  
D. A 与 B 的并集

**答案：B**

**解析：** `LEFT JOIN` 保留 A 的所有行，未匹配时 B 的列为 `NULL`。`WHERE b.id IS NULL` 过滤出 A 中未在 B 找到匹配的行。

### 50. 相关子查询（correlated subquery）的执行特点是？
A. 只执行一次  
B. 对外表每一行执行一次  
C. 与 `JOIN` 语义完全不同  
D. 不能出现在 `SELECT` 列表中

**答案：B**

**解析：** 相关子查询引用外层查询的列，因此需要为外层每一行重新执行一次。这通常比等价的 `JOIN` 效率低。

### 51. 测试子查询是否返回行应使用哪个谓词？
A. `IN`  
B. `EXISTS`  
C. `ANY`  
D. `ALL`

**答案：B**

**解析：** `EXISTS` 只关心子查询是否返回至少一行，通常比 `IN` 更高效，尤其在子查询结果较大或含 `NULL` 时更安全。

### 52. 哪个窗口函数为每一行分配唯一且连续的序号（即使值相同也不同）？
A. `RANK`  
B. `DENSE_RANK`  
C. `ROW_NUMBER`  
D. `NTILE`

**答案：C**

**解析：** `ROW_NUMBER()` 为分区排序后的每一行生成唯一连续序号。`RANK` 会跳跃，`DENSE_RANK` 不跳跃但给相同值相同序号。

### 53. 定义公用表表达式（CTE）使用的关键字是？
A. `WITH`  
B. `USING`  
C. `DECLARE`  
D. `TEMP`

**答案：A**

**解析：** 标准 SQL 使用 `WITH cte AS (SELECT ...) SELECT ...` 定义 CTE，可读性好且可递归（`WITH RECURSIVE`）。

### 54. 填空：合并两个查询结果并去除重复行用 `______`，保留所有重复行用 `______`。

**答案：** `UNION`，`UNION ALL`

**解析：** `UNION` 对两个结果集去重并排序，开销较大；`UNION ALL` 直接追加，不去重，性能更好。两查询需列数相同且类型兼容。

### 55. 填空：自连接需要在 `FROM` 子句中将同一张表引用 ______ 并赋予不同别名。

**答案：** 两次

**解析：** 自连接通过为同一张表取两个别名，使其在逻辑上成为两张表，然后用 `JOIN` 条件建立行之间的关系。

### 56. 填空：在窗口函数中，`SUM(amount) ______ (PARTITION BY dept ORDER BY month)` 可按部门累计金额。

**答案：** `OVER`

**解析：** `OVER` 关键字将聚合函数转变为窗口函数，指定分区与排序。缺少 `OVER` 则为普通聚合，必须配合 `GROUP BY`。

### 57. 填空：只返回单行单列的子查询称为 ______ 子查询。

**答案：** 标量

**解析：** 标量子查询可用于需要单个值的上下文，例如 `WHERE col = (SELECT MAX(col) FROM t)`。若返回多行会导致错误。

### 58. 判断：`FULL OUTER JOIN` 返回两个表的匹配行以及各自未匹配的行。

**答案：** ✅正确

**解析：** `FULL OUTER JOIN` 保留左右两表所有行，匹配不上的列以 `NULL` 填充。MySQL 不直接支持，可用 `UNION` 模拟。

### 59. 判断：窗口函数可以直接出现在 `WHERE` 子句中。

**答案：** ❌错误

**解析：** 窗口函数在 `WHERE` 之后计算，因此不能直接用于 `WHERE`。需要先用 CTE 或子查询计算窗口值，再在外层过滤。

### 60. 程序分析题：分析以下查询是否能正确统计每个部门的员工人数，并指出问题。
```sql
SELECT d.name, COUNT(e.id)
FROM departments d
LEFT JOIN employees e ON d.id = e.dept_id
WHERE e.salary > 5000
GROUP BY d.name;
```

**答案：** 不能正确统计所有部门的员工人数，该查询会把没有高薪员工（或没有员工）的部门过滤掉。

**解析：** `WHERE e.salary > 5000` 在 `LEFT JOIN` 之后过滤，会把右表未匹配行（`e.salary` 为 `NULL`）以及低薪员工全部剔除，导致 `LEFT JOIN` 退化为 `INNER JOIN`。若目标是统计每个部门薪资高于 5000 的人数且保留零人部门，应将条件移到 `ON` 子句：`ON d.id = e.dept_id AND e.salary > 5000`。

# 第六部分：标准库与工程实践

### 61. 关系型数据库中最常用的索引结构是？
A. B-tree  
B. Hash  
C. Bitmap  
D. 堆表

**答案：A**

**解析：** B-tree 索引支持等值查询、范围查询和排序，是最通用的索引类型。Hash 索引仅适合等值查找，Bitmap 索引适合低基数列。

### 62. ACID 四个字母分别代表？
A. Atomicity, Consistency, Isolation, Durability  
B. Availability, Consistency, Isolation, Distribution  
C. Atomicity, Concurrency, Integration, Durability  
D. Authorization, Consistency, Isolation, Dependency

**答案：A**

**解析：** ACID 是事务的四个基本属性：原子性、一致性、隔离性、持久性。它们共同保证数据库事务的可靠性。

### 63. 哪个隔离级别能防止幻读？
A. `READ UNCOMMITTED`  
B. `READ COMMITTED`  
C. `REPEATABLE READ`  
D. `SERIALIZABLE`

**答案：D**

**解析：** `SERIALIZABLE` 通过强制事务串行执行，避免脏读、不可重复读和幻读。`REPEATABLE READ` 在部分数据库可防止幻读，但标准定义中不能。

### 64. 覆盖索引（covering index）是指？
A. 索引覆盖所有表  
B. 索引包含查询所需的所有列  
C. 索引唯一覆盖主键  
D. 索引覆盖所有外键

**答案：B**

**解析：** 如果查询所需的列全部在索引中，数据库无需回表读取数据页，可显著减少 I/O。设计复合索引时常利用覆盖索引优化。

### 65. NoSQL 数据库通常更强调？
A. 强 ACID 事务  
B. BASE 与最终一致性  
C. 复杂表连接  
D. 固定模式

**答案：B**

**解析：** NoSQL 常采用 BASE（基本可用、软状态、最终一致性）模型，以牺牲部分一致性换取高可用和水平扩展能力。

### 66. 填空：显式开启一个事务的标准 SQL 命令是 `______ TRANSACTION`。

**答案：** `START`（或 `BEGIN`）

**解析：** 标准 SQL 使用 `START TRANSACTION` 或 `BEGIN` 开启事务，后续通过 `COMMIT` 提交或 `ROLLBACK` 回滚。

### 67. 填空：事务中的操作要么全部成功提交，要么全部撤销，这体现了 ______ 性。

**答案：** 原子

**解析：** 原子性保证事务是一个不可分割的工作单位。若事务中途失败，已执行的操作会被回滚到事务开始前的状态。

### 68. 填空：查看查询执行计划最常用的命令是 `______`。

**答案：** `EXPLAIN`

**解析：** `EXPLAIN` 显示优化器选择的访问路径、连接顺序、索引使用等信息，是 SQL 性能调优的起点。

### 69. 判断：索引越多，`SELECT` 查询越快，且对写入操作没有负面影响。

**答案：** ❌错误

**解析：** 索引加速查询但增加写入开销（需维护索引结构）和存储空间。过多索引还会导致优化器选择困难。

### 70. 简答题：简述 ACID 四个特性，并举例说明隔离性的重要性。

**参考答案：**
- **原子性**：事务要么全部完成，要么全部不完成，不会停留在中间状态。
- **一致性**：事务执行前后数据库必须满足所有完整性约束。
- **隔离性**：并发事务相互隔离，避免脏读、不可重复读和幻读。
- **持久性**：事务一旦提交，修改永久保存，即使系统故障也不丢失。
- **隔离性示例**：银行转账时，事务 A 扣款未提交前，事务 B 不应读到中间余额，否则可能出现资金不一致。

### 71. 表 `t` 中 `col` 列包含 `1`、`2`、`NULL`，执行 `SELECT * FROM t WHERE col = 1 OR col <> 1;` 会返回？
A. 所有行  
B. `col` 为 `1` 和 `2` 的行  
C. 仅 `col` 为 `1` 的行  
D. 仅 `col` 为 `2` 的行

**答案：B**

**解析：** 对 `NULL` 而言，`col = 1` 和 `col <> 1` 均为 `UNKNOWN`，`UNKNOWN OR UNKNOWN` 仍为 `UNKNOWN`，因此 `NULL` 行被过滤。

### 72. 查找 `users` 表中重复邮箱的正确查询是？
A. `SELECT email FROM users GROUP BY email HAVING COUNT(*) > 1;`  
B. `SELECT email FROM users WHERE COUNT(*) > 1;`  
C. `SELECT DISTINCT email FROM users WHERE COUNT(email) > 1;`  
D. `SELECT email, COUNT(*) FROM users;`

**答案：A**

**解析：** 先按邮箱分组，再用 `HAVING COUNT(*) > 1` 筛选出现多次的组。`WHERE` 中不能直接用聚合函数。

### 73. 表 `t(a, b)` 有两列，执行 `SELECT a, b FROM t INTERSECT SELECT b, a FROM t;` 的结果语义是？
A. 返回所有行  
B. 返回 `a = b` 的行  
C. 返回 `a <> b` 的行  
D. 返回空集

**答案：B**

**解析：** `INTERSECT` 比较的是元组 `(a, b)` 与 `(b, a)`，两者相等当且仅当 `a = b`。

### 74. 要找出在表 `A` 中存在但在表 `B` 中不存在的行，最佳方式是？
A. `A INNER JOIN B`  
B. `A LEFT JOIN B ON A.id = B.id WHERE B.id IS NULL`  
C. `A CROSS JOIN B`  
D. `A UNION B`

**答案：B**

**解析：** 左连接保留 A 所有行，未匹配时 B 列为 `NULL`，通过 `WHERE B.id IS NULL` 即可筛选 A 独有的行。

### 75. 填空：查询第二高薪水可使用 `SELECT MAX(salary) FROM emp WHERE salary < (SELECT ______ FROM emp);`。

**答案：** `MAX(salary)`

**解析：** 子查询得到最高薪水，外层取小于最高值的最大值，即第二高。若有并列最高，可用 `DENSE_RANK` 窗口函数更准确。

### 76. 填空：在三值逻辑中，`TRUE OR NULL` 的结果是 ______。

**答案：** `TRUE`

**解析：** SQL 的逻辑或运算中，`TRUE OR UNKNOWN` 为 `TRUE`，`FALSE OR UNKNOWN` 为 `UNKNOWN`，`UNKNOWN OR UNKNOWN` 为 `UNKNOWN`。

### 77. 判断：`NOT IN` 子查询如果返回 `NULL` 值，外层查询结果为空。

**答案：** ✅正确

**解析：** 若子查询结果包含 `NULL`，`col NOT IN (val1, NULL, ...)` 对每个值比较时会产生 `UNKNOWN`，最终 `WHERE` 条件为 `UNKNOWN`，没有行被选中。

### 78. 智力与逻辑题：某表 `scores(score INT)` 中有一个 `NULL` 值。候选人 A 用 `SELECT MAX(score)` 得到 95；候选人 B 用 `SELECT score FROM scores ORDER BY score DESC LIMIT 1` 得到 `NULL`。请解释差异并给出正确写法。

**答案：** `MAX` 忽略 `NULL`，所以返回最大非空值 95；`ORDER BY ... DESC` 在默认排序中可能把 `NULL` 放在最前面，导致 `LIMIT 1` 取到 `NULL`。

**解析：** 聚合函数 `MAX` 会自动忽略 `NULL`。而排序中 `NULL` 的位置由数据库实现决定（默认常视为最大或最小）。要正确获取最高非空分数，应写 `SELECT score FROM scores WHERE score IS NOT NULL ORDER BY score DESC LIMIT 1`，或使用 `NULLS LAST`。

### 86. 简答题：当你发现某条生产查询变慢时，通常按哪些步骤排查和优化？

**参考答案：**
1. 用 `EXPLAIN` 查看执行计划，确认是否命中索引、扫描行数、连接方式。
2. 检查是否缺少合适索引，或索引列顺序不符合最左前缀原则。
3. 分析查询语句，避免 `SELECT *`，将聚合条件放在 `HAVING` 而非 `WHERE`。
4. 确认表统计信息是否最新，必要时更新统计信息。
5. 对于大数据量，考虑分区、归档历史数据或适当反规范化。
6. 检查锁和事务隔离级别，避免长时间持有锁导致阻塞。

### 87. 编程题：编写 SQL，查询每个部门薪水最高的前 2 名员工（允许并列时取前 2 名），返回部门名、员工名和薪水。

**答案：**
```sql
WITH ranked AS (
    SELECT d.name AS dept_name,
           e.name AS emp_name,
           e.salary,
           DENSE_RANK() OVER (PARTITION BY d.id ORDER BY e.salary DESC) AS rk
    FROM departments d
    JOIN employees e ON d.id = e.dept_id
)
SELECT dept_name, emp_name, salary
FROM ranked
WHERE rk <= 2
ORDER BY dept_name, salary DESC;
```

**解析：** 使用 `DENSE_RANK()` 按部门分区、按薪水降序排名，可正确处理并列。再用 CTE 过滤 `rk <= 2`。若使用 `ROW_NUMBER()`，并列时只会随机取一个，可能漏掉同薪员工。

### 88. 综合应用题：某电商平台需要生成“月度各品类销售额及环比增长率”报表。请给出核心 SQL 思路，需使用窗口函数和聚合。

**参考答案：**
```sql
WITH monthly AS (
    SELECT DATE_TRUNC('month', o.order_date) AS month,
           p.category,
           SUM(o.amount) AS revenue
    FROM orders o
    JOIN products p ON o.product_id = p.id
    GROUP BY DATE_TRUNC('month', o.order_date), p.category
)
SELECT month,
       category,
       revenue,
       LAG(revenue) OVER (PARTITION BY category ORDER BY month) AS prev_revenue,
       ROUND(
         (revenue - LAG(revenue) OVER (PARTITION BY category ORDER BY month))
         / NULLIF(LAG(revenue) OVER (PARTITION BY category ORDER BY month), 0) * 100,
         2
       ) AS growth_pct
FROM monthly
ORDER BY category, month;
```

**解析：** 先按月份和品类聚合得到 `monthly` 收入，再用 `LAG` 窗口函数获取上月同品类收入，从而计算环比增长率。`NULLIF` 避免除零。

### 89. 代码调试题：以下查询报错或结果不符合预期，请指出问题并修正。
```sql
SELECT c.name, o.order_id, SUM(o.amount)
FROM customers c, orders o
WHERE c.id = o.customer_id
GROUP BY c.name;
```

**答案：** 问题在于 `o.order_id` 既不是聚合列，也不在 `GROUP BY` 中，违反标准 SQL；同时使用了隐式连接语法。

**修正：**
```sql
SELECT c.name, SUM(o.amount) AS total_amount
FROM customers c
JOIN orders o ON c.id = o.customer_id
GROUP BY c.id, c.name;
```

**解析：** 若需要展示每笔订单金额，则不应使用 `SUM` 聚合，而应直接 `SELECT c.name, o.order_id, o.amount`。这里 `SUM` 按客户汇总，就必须把 `order_id` 从选择列表中移除。

### 90. 系统设计题：设计一个支持高并发的在线书店数据库，需包含作者、图书、订单、库存。请说明表结构、索引、事务及与 NoSQL 的对比。

**参考答案：**
- **表结构**
  - `authors`（作者）：`id PK, name, bio`。
  - `books`（图书）：`id PK, author_id FK, title, price, published_at`。
  - `inventory`（库存）：`book_id PK/FK, quantity`。
  - `orders`（订单）：`id PK, customer_id, status, created_at, total_amount`。
  - `order_items`（订单明细）：`id PK, order_id FK, book_id FK, quantity, unit_price`。
  - 数据满足 3NF，减少冗余。
- **索引**
  - `books(author_id)` 加速按作者查书。
  - `orders(customer_id, created_at)` 支持订单列表。
  - `inventory(book_id)` 唯一索引。
  - `order_items(order_id, book_id)` 复合索引。
- **事务**
  - 下单时在一个事务中：插订单、插明细、扣减库存，保证原子性；隔离级别使用 `READ COMMITTED` 或 `REPEATABLE READ`，防止超卖。
- **与 NoSQL 对比**
  - 关系型适合强一致性、复杂查询和事务（ACID）。
  - NoSQL（文档型）适合商品详情、用户评价等半结构化读多写少场景，可缓存到文档数据库提升读性能；但跨文档事务能力弱于关系型，需权衡。
