# 第一部分：Swift 基础语法

### 1. `let x: Int? = nil` 的实际类型等价于什么？
A. `Int`  
B. `Optional<Int>`  
C. `Int?`  
D. `Optional<Int>` 与 `Int?` 等价

**答案：D**

**解析：** Swift 中 `Int?` 只是 `Optional<Int>` 的语法糖，二者完全等价。A 忽略了可选包装；B 和 C 各自只给出一种写法，未说明等价关系。

---

### 2. 以下关于 `guard let value = optional else { return }` 的描述，正确的是？
A. 仅用于解包可选值  
B. 当 `optional` 为 `nil` 时进入 `else` 分支  
C. 解包后的 `value` 可在当前作用域剩余部分使用  
D. 以上全部

**答案：D**

**解析：** `guard let` 是“提前返回”模式：成功解包后绑定值在后续代码可用；失败则执行 `else` 分支，通常 `return/throw/break/continue`。A、B、C 均为其特性之一。

---

### 3. 下列哪个类型属于 Swift 中的值类型？
A. `class`  
B. `struct`  
C. `closure`  
D. `function`

**答案：B**

**解析：** `struct`、`enum`、`tuple` 都是值类型；`class`、closure、function 是引用类型。值类型赋值时产生独立副本（Copy-on-Write 优化）。

---

### 4. 要声明一个“可以逃离当前函数、在调用结束后仍然存活”的闭包参数，应使用关键字 `________`。

**答案：** `@escaping`

**解析：** `@escaping` 标记的闭包在函数返回后仍可能被调用（例如存储到属性或异步执行）。未标记的闭包默认是 `@nonescaping`，必须在函数返回前执行完毕。

---

### 5. 希望将一段代码推迟到当前作用域退出时再执行，应使用关键字 `________`。

**答案：** `defer`

**解析：** `defer` 块中的代码会在作用域结束时（return、throw、break 等）按 LIFO 顺序执行，常用于清理资源或配对操作（如 open/close、lock/unlock）。

---

### 6. Swift 中的 `Array` 是值类型，赋值或传参会立即发生深拷贝。

**答案：** ❌错误

**解析：** `Array` 是值类型，但内部采用写时复制（Copy-on-Write）。在真正修改之前，多个变量共享同一份存储，只有在写入时才会复制，兼顾安全与性能。

---

### 7. `guard` 语句的 `else` 分支必须将控制流转移出当前作用域。

**答案：** ✅正确

**解析：** `guard` 的 `else` 分支必须执行 `return`、`throw`、`break`、`continue` 或调用 `fatalError` 等，确保在条件不满足时提前退出，从而保证后续代码能安全使用绑定值。

---

### 8. 简述 `if let` 与 `guard let` 在使用场景上的主要区别。

**参考答案：**
- `if let` 适合需要在解包成功后进入独立分支、且后续代码不一定依赖该值的场景；解包值仅在 `if` 块内有效。
- `guard let` 适合“不满足条件就提前返回”的防御式编程；解包值在 `guard` 之后的整个作用域内有效，减少嵌套层级。

**解析：** 两者都是可选绑定，但 `guard` 强调提前返回与扁平化代码结构，`if let` 更适合可选分支逻辑。

---

### 9. 简述 Swift 中 `struct` 与 `class` 至少三点核心区别。

**参考答案：**
1. `struct` 是值类型，`class` 是引用类型。
2. `struct` 不支持继承，`class` 支持继承。
3. `struct` 自动生成成员逐一初始化器；`class` 必须显式编写初始化器。
4. `class` 需要进行 ARC 引用计数管理，`struct` 不存在引用循环问题。

**解析：** 这些差异决定了 Swift 更偏向协议导向与值类型优先的设计哲学。

---

### 10. 阅读以下代码，写出输出结果。

```swift
let nickname: String? = nil
let display = nickname?.uppercased() ?? "Guest"
print(display)
```

**答案：** `Guest`

**解析：** `nickname` 为 `nil`，可选链 `nickname?.uppercased()` 返回 `nil`；随后 `??`（Nil Coalescing）提供默认值 `"Guest"`。

---

### 11. 阅读以下代码，写出输出结果。

```swift
var a = [1, 2, 3]
var b = a
b.append(4)
print(a.count, b.count)
```

**答案：** `3 4`

**解析：** `Array` 是值类型，`b = a` 产生逻辑副本。对 `b` 追加元素会触发 Copy-on-Write，分配独立存储，因此 `a` 保持 3 个元素，`b` 有 4 个元素。

---

### 12. 编写一个函数，接收可选的 `Int`，若不为 `nil` 返回其两倍，否则返回 0。要求使用 `guard`。

**答案：**

```swift
func doubleOrZero(_ value: Int?) -> Int {
    guard let value = value else { return 0 }
    return value * 2
}
```

**解析：** `guard let` 在 `value` 为 `nil` 时直接返回 0；否则在后续作用域中使用非可选的 `value`。

# 第二部分：数据结构与容器

### 13. Swift 中哪种集合类型天然保证元素唯一性？
A. `Array`  
B. `Set`  
C. `Dictionary`  
D. `Tuple`

**答案：B**

**解析：** `Set` 基于哈希表实现，元素必须遵守 `Hashable`，不允许重复。`Array` 允许重复，`Dictionary` 保证键唯一而非值唯一，`Tuple` 是有限固定组合。

---

### 14. 在 Swift 的 `Dictionary` 中查找某个键对应的值，平均时间复杂度是？
A. O(n)  
B. O(log n)  
C. O(1)  
D. O(n²)

**答案：C**

**解析：** `Dictionary` 底层是哈希表，键查找平均为 O(1)。最坏情况（哈希冲突严重）会退化，但 Swift 标准库会控制负载因子与重哈希。

---

### 15. 以下哪些声明是合法的 Swift 字典类型？
A. `var d: [String: Int]`  
B. `var d: Dictionary<String, Int>`  
C. A 和 B 都合法  
D. 都不合法

**答案：C**

**解析：** `[String: Int]` 是 `Dictionary<String, Int>` 的语法糖，两者等价，均可使用。

---

### 16. 对集合中每个元素进行一对一变换，应使用高阶函数 `________`。

**答案：** `map`

**解析：** `map` 接收一个转换闭包，返回元素个数相同的新集合；`compactMap` 会过滤掉转换结果中的 `nil`；`flatMap` 会扁平化一层嵌套序列。

---

### 17. 根据条件筛选集合元素，应使用高阶函数 `________`。

**答案：** `filter`

**解析：** `filter` 保留使闭包返回 `true` 的元素。与 `map` 不同，它只选择元素而不转换元素。

---

### 18. `Set` 在 Swift 中会保持元素插入顺序。

**答案：** ❌错误

**解析：** `Set` 是无序集合，不保证插入顺序。若需要有序唯一元素，可使用 `Array` 配合手动去重，或依赖外部有序集合实现。

---

### 19. `ArraySlice` 与原数组共享索引体系，其 `startIndex` 不一定为 0。

**答案：** ✅正确

**解析：** `ArraySlice` 是原数组的连续子序列视图，保留原数组索引。例如 `array[2..<5]` 的 `startIndex` 为 2，避免 O(n) 的索引偏移复制。

---

### 20. 简述 Swift 数组的“写时复制”（Copy-on-Write）机制及其意义。

**参考答案：**
- 当多个变量引用同一个数组时，它们共享底层存储。
- 直到某个变量尝试修改数组，才会真正复制出独立存储。
- 意义：在保持值类型安全语义的同时，避免不必要的内存复制，提升性能。

**解析：** 这是 Swift 标准库值类型集合的核心优化，也是 Swift 与很多语言引用类型数组的重要区别。

---

### 21. 简述 `map`、`compactMap`、`flatMap` 在数组上的区别。

**参考答案：**
- `map`：对每个元素做转换，返回与输入元素数量相同的新数组。
- `compactMap`：转换后自动剔除 `nil`，返回非可选元素数组。
- `flatMap`：将每个元素映射为一个序列，然后把结果扁平化一层，常用于二维数组转一维。

**解析：** 三者都是函数式操作，但处理 `nil` 与嵌套结构的能力不同。

---

### 22. 阅读以下代码，写出输出结果。

```swift
let nums = [1, 2, 3, 4, 5]
let result = nums.filter { $0 % 2 == 0 }.map { $0 * $0 }
print(result)
```

**答案：** `[4, 16]`

**解析：** `filter` 保留偶数 `[2, 4]`；`map` 对每个元素平方得到 `[4, 16]`。注意管道顺序：先过滤再映射。

---

### 23. 编写一段代码，使用 `reduce` 对 `[Int?]` 求和，遇到 `nil` 视为 0。

**答案：**

```swift
let values: [Int?] = [1, nil, 3, nil, 5]
let sum = values.reduce(0) { $0 + ($1 ?? 0) }
print(sum) // 9
```

**解析：** `reduce` 从初始值 0 开始累加；通过 `?? 0` 将每个可选值中的 `nil` 替换为 0。

# 第三部分：函数/方法/模块

### 24. `@autoclosure` 的主要作用是？
A. 自动把表达式包装成闭包  
B. 延迟求值  
C. A 和 B 都是  
D. 仅用于异步代码

**答案：C**

**解析：** `@autoclosure` 允许调用者传入一个普通表达式，编译器会自动将其封装为无参闭包，从而在函数内部按需执行，实现惰性求值（如 `&&`、`||` 短路语义）。

---

### 25. Swift 中结构体成员的默认访问级别是？
A. `public`  
B. `internal`  
C. `private`  
D. `fileprivate`

**答案：B**

**解析：** 未显式标注访问级别时，默认是 `internal`，即同模块内可见。`private` 限制在声明作用域，`fileprivate` 限制在同一文件。

---

### 26. 尾随闭包（Trailing Closure）语法可以用于？
A. 函数最后一个参数是闭包  
B. 函数第一个参数是闭包  
C. 任意闭包参数  
D. 仅无参闭包

**答案：A**

**解析：** 当函数调用的最后一个参数是闭包时，可以把它写在圆括号之后。若闭包是唯一参数，圆括号可完全省略。

---

### 27. 在闭包中若要显式捕获 `self` 为强引用，可使用捕获列表 `________` 或不写捕获列表。

**答案：** `[self]`

**解析：** 默认情况下闭包对引用类型捕获是强引用。写 `[self]` 可显式表达意图；为避免循环引用，通常会写 `[weak self]` 或 `[unowned self]`。

---

### 28. 在函数内部主动抛出一个错误，应使用关键字 `________`。

**答案：** `throw`

**解析：** `throw` 配合 `Error` 协议使用。调用带 `throws` 的函数时，需要用 `try` 并在合适的作用域中处理错误。

---

### 29. Swift 中的函数是一等公民，可以作为参数或返回值传递。

**答案：** ✅正确

**解析：** Swift 函数是引用类型（闭包），可以赋值给变量、作为参数传递、作为返回值返回，支持高阶函数与函数式编程风格。

---

### 30. 闭包会自动捕获其定义所在作用域中的变量。

**答案：** ✅正确

**解析：** 闭包会捕获其词法作用域中的变量和常量。对值类型捕获副本，对引用类型默认强引用，可能引发循环引用。

---

### 31. 简述 `@escaping` 与 `@nonescaping` 闭包的区别及使用场景。

**参考答案：**
- `@nonescaping`：闭包在函数返回前必须执行完毕，不能存储到外部变量或异步延迟执行。适合同步回调、临时排序比较等。
- `@escaping`：闭包可能超出函数调用生命周期（如存储到属性、加入 GCD/Combine 管道）。需要遵守引用计数规则，通常显式处理 `self` 捕获。

**解析：** Swift 3 之后闭包参数默认 `@nonescaping`，只有在需要逃离当前函数时才加 `@escaping`。

---

### 32. 什么是尾随闭包？给出一个使用 `sorted(by:)` 的尾随闭包示例。

**参考答案：**
尾随闭包是指当函数最后一个参数为闭包时，将闭包写在函数调用圆括号之后的语法。

```swift
let nums = [3, 1, 2]
let descending = nums.sorted { $0 > $1 }
```

**解析：** 尾随闭包让链式调用或长闭包更易读。`$0`、`$1` 是 Swift 对闭包参数的简写。

---

### 33. 阅读以下代码，写出输出结果。

```swift
func makeMultiplier(_ factor: Int) -> (Int) -> Int {
    return { $0 * factor }
}
let triple = makeMultiplier(3)
print(triple(4))
```

**答案：** `12`

**解析：** `makeMultiplier` 返回一个捕获 `factor` 的闭包。`triple` 是“乘以 3”的函数，调用 `triple(4)` 得到 12。

---

### 34. 编写一个泛型函数 `first(_:where:)`，返回数组中第一个满足谓词的元素，若不存在则返回 `nil`。

**答案：**

```swift
func first<T>(_ array: [T], where predicate: (T) -> Bool) -> T? {
    for element in array {
        if predicate(element) { return element }
    }
    return nil
}
```

**解析：** 函数使用泛型 `T`，适配任意元素类型；谓词闭包判断条件；通过提前返回第一个匹配项实现 O(n) 查找。

# 第四部分：面向对象/类型系统

### 35. Swift 的协议（Protocol）可以声明哪些内容？
A. 属性要求  
B. 方法要求  
C. 关联类型（associatedtype）  
D. 以上全部

**答案：D**

**解析：** 协议可以声明属性、方法、初始化器、关联类型、类型方法等要求。Swift 通过协议实现协议导向编程（POP）。

---

### 36. 下列哪些引用类型可用于打破闭包引起的循环引用？
A. `strong`  
B. `weak`  
C. `unowned`  
D. B 和 C

**答案：D**

**解析：** `weak` 和 `unowned` 都不增加引用计数。`weak` 在对象释放后自动变为 `nil`（必须可选）；`unowned` 假设对象始终存在，释放后访问会崩溃。

---

### 37. 类可以通过哪些方式遵循协议？
A. 在声明时直接遵循  
B. 通过扩展（extension）遵循  
C. A 和 B 均可  
D. 仅能通过继承

**答案：C**

**解析：** 类、结构体、枚举均可在定义时或扩展中遵循协议。Swift 推荐用扩展分离协议实现，提高代码组织性。

---

### 38. 协议中声明一个只读属性要求，应写为 `var name: String { ________ }`。

**答案：** `get`

**解析：** `{ get }` 表示只读；`{ get set }` 表示可读写。遵循类型可用 `let` 存储属性实现只读要求，也可用计算属性。

---

### 39. 使用 `unowned` 引用时，必须保证被引用对象在访问时不会被 `________`。

**答案：** `释放` / `deallocated`

**解析：** `unowned` 是非可选的非强引用，不会自动置为 `nil`。若访问时对象已被释放，会导致运行时崩溃。

---

### 40. 结构体（struct）可以遵循协议。

**答案：** ✅正确

### 42. 简述 ARC 的工作原理，以及循环引用是如何产生的。

**参考答案：**
- ARC（Automatic Reference Counting）在编译期插入引用计数代码，对象的强引用计数为 0 时立即释放。
- 循环引用发生在两个或多个对象互相持有强引用，导致它们的引用计数永远不为 0，从而无法释放。
- 打破方式：将其中一个引用声明为 `weak` 或 `unowned`，或在使用闭包时使用 `[weak self]` / `[unowned self]`。

**解析：** ARC 是 Swift 内存管理的核心机制，理解强/弱引用对避免内存泄漏至关重要。

### 43. 什么是协议导向编程（Protocol-Oriented Programming）？Swift 为什么倾向于它？

**参考答案：**
- 协议导向编程通过协议定义接口，利用扩展提供默认实现，用组合代替继承来构建类型。
- Swift 倾向于 POP 的原因：值类型（struct/enum）无法继承，但可遵循协议；协议扩展避免菱形继承问题；默认实现提高代码复用；编译器可对值类型做更好的优化。

**解析：** POP 是 Swift 的核心设计范式，与面向对象编程互补。

### 60. 编写一个属性包装器 `@Clamped`，将整型属性限制在指定闭区间内。

```swift
@propertyWrapper
struct Clamped {
    private var value: Int
    let range: ClosedRange<Int>
    
    var wrappedValue: Int {
        get { value }
        set { value = min(max(newValue, range.lowerBound), range.upperBound) }
    }
    
    init(wrappedValue: Int, _ range: ClosedRange<Int>) {
        self.range = range
        self.value = min(max(wrappedValue, range.lowerBound), range.upperBound)
    }
}

// 使用

    @Clamped(0...100) var health = 50
}
```

**解析：** `wrappedValue` 控制读写；初始化器接收 `wrappedValue` 和范围参数。写值时通过 `min(max(...))` 钳制在范围内。

### 78. 逻辑题：有三个相互独立的异步网络请求 A、B、C，它们的结果需要全部返回后才能刷新 UI。请用 Swift 并发模型描述一种实现方式。

### 79. 逻辑题：一个 `Task` 闭包捕获了 `self`，为什么可能导致内存泄漏？如何安全处理？

### 85. 阅读以下代码，指出问题并说明输出。

```swift

    func fetch() {
        completion = {

```

**答案：** 不会打印 `DataStore deinit`，存在循环引用。`completion` 闭包强引用 `self`（隐式捕获），`self` 又强引用 `completion`。

**解析：** 修复方式是在闭包中使用 `[weak self]`：`completion = { [weak self] in ... }`。由于当前闭包未实际访问 `self`，也可写为 `[unowned self]`，但最安全的做法是 `[weak self]`。

### 87. 代码调试题：以下 `Worker` 类在释放时可能不会调用 `deinit`，请修复。

```swift
class Worker {
    var task: (() -> Void)?
    func start() {
        task = {
            self.doWork()
        }
    }
    func doWork() {}
    deinit { print("Worker deinit") }
}
```

**答案：**

```swift
class Worker {
    var task: (() -> Void)?
    func start() {
        task = { [weak self] in
            self?.doWork()
        }
    }
    func doWork() {}
    deinit { print("Worker deinit") }
}
```

**解析：** 闭包强引用 `self`，`self` 又强引用 `task`，形成循环引用。使用 `[weak self]` 并在闭包内安全解包即可打破循环。

### 88. 综合应用题：设计一个 SwiftUI 页面，展示从网络获取的用户列表。要求使用 Combine 处理数据流，并区分 Loading/Error/Success 三种状态。

**参考答案：**

```swift
import SwiftUI
import Combine

enum LoadState<T> {
    case loading
    case success(T)
    case failure(Error)
}

class UserViewModel: ObservableObject {
    @Published var state: LoadState<[User]> = .loading
    private var cancellables = Set<AnyCancellable>()
    
    func fetchUsers() {
        state = .loading
        URLSession.shared.dataTaskPublisher(for: URL(string: "https://api.example.com/users")!)
            .map(\.data)
            .decode(type: [User].self, decoder: JSONDecoder())
            .receive(on: DispatchQueue.main)
            .sink(receiveCompletion: { [weak self] completion in
                if case .failure(let error) = completion {
                    self?.state = .failure(error)
                }
            }, receiveValue: { [weak self] users in
                self?.state = .success(users)
            })
            .store(in: &cancellables)
    }
}

struct User: Codable, Identifiable {
    let id: Int
    let name: String
}

struct UserListView: View {
    @StateObject private var viewModel = UserViewModel()
    
    var body: some View {
        Group {
            switch viewModel.state {
            case .loading:
                ProgressView()
            case .success(let users):
                List(users) { user in
                    Text(user.name)
                }
            case .failure(let error):
                Text("Error: \(error.localizedDescription)")
            }
        }
        .onAppear { viewModel.fetchUsers() }
    }
}
```

**解析：** `ObservableObject` + `@Published` 驱动 SwiftUI 刷新；`dataTaskPublisher` + `decode` + `receive(on:)` 构成 Combine 管道；`LoadState` 枚举统一状态管理。

### 90. 系统设计题：如何使用 Swift Actor 设计一个线程安全的图片缓存？说明其优势与注意事项。

**参考答案：**

```swift
actor ImageCache {
    private var storage: [URL: UIImage] = [:]
    
    func image(for url: URL) -> UIImage? {
        storage[url]
    }
    
    func insert(_ image: UIImage, for url: URL) {
        storage[url] = image
    }
}
```

- **优势**：Actor 通过编译器隔离确保同一时刻只有一个任务访问 `storage`，从根本上避免数据竞争。
- **注意事项**：
  1. Actor 外调用其方法需使用 `await`，即使方法不挂起。
  2. 避免在 Actor 内部执行长时间同步任务，以免阻塞 Actor 的消息队列。
  3. 跨 Actor 传递引用类型需谨慎，必要时拷贝数据。

**解析：** Actor 是 Swift 并发中替代传统锁的声明式线程安全机制，比 `NSLock` 更不易出错。
