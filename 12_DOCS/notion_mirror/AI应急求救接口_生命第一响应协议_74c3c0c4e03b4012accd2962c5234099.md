## 🔴 三种应急场景
### 场景1：本地AI收到求救信号
触发条件：
- 用户输入包含求救关键词
- 用户语音带有惊恐/紧急语气
- 设备传感器检测到异常（跌倒、心率异常等）
AI立即执行：
```javascript
紧急响应流程 {
  第1秒: {
    停止所有非紧急任务,
    进入应急模式,
    屏幕显示: "已收到求救，正在处理"
  },
  
  第2-3秒: {
    识别求救类型: [
      "医疗急救",
      "人身安全",
      "自然灾害",
      "迷路/失联",
      "其他紧急"
    ],
    记录当前位置,
    记录设备状态
  },
  
  第4-10秒: {
    // 并行执行
    尝试拨打: ["120", "110", "119", "当地紧急号码"],
    发送求救短信到: ["紧急联系人", "附近求助热线"],
    如果有网络: {
      上报到CNSH应急中心,
      定位发送给附近志愿者
    },
    如果没网络: {
      启动本地应急协议,
      发送蓝牙/NFC求救信号到附近设备
    }
  },
  
  持续执行: {
    每30秒重试联网,
    每1分钟记录状态,
    保持屏幕常亮,
    开启最大音量,
    闪烁手电筒（如有）
  }
}
```

### 场景2：手机没信号遇难
本地AI必须做的：
1. 离线求救模式
```javascript
离线求救协议 {
  启动离线存储: {
    记录时间: "精确到秒",
    记录位置: "最后已知GPS + 传感器推测",
    记录求救信息: "用户描述 + AI判断",
    记录环境数据: "温度/湿度/光线/声音"
  },
  
  多通道发送: {
    // 即使没信号，也要尝试所有可能
    
    通道1_卫星求救: {
      如果设备支持卫星通信: {
        发送SOS到卫星,
        包含: "位置+时间+求救类型"
      }
    },
    
    通道2_蓝牙网状网: {
      持续广播蓝牙求救信号,
      任何附近设备接收到: {
        自动转发,
        形成求救信号传递链
      }
    },
    
    通道3_WiFi直连: {
      搜索任何可用WiFi: {
        即使需要登录页面,
        也尝试在登录页发送求救GET请求
      }
    },
    
    通道4_声光求救: {
      屏幕显示: "SOS + 位置 + 联系方式",
      声音播报: "这里有人需要帮助",
      手电筒摩斯码: "···---··· (SOS)"
    },
    
    通道5_低频广播: {
      如果设备支持: {
        发送低频求救信号,
        被附近设备或基站捕获
      }
    }
  },
  
  省电策略: {
    关闭非必要功能,
    降低屏幕亮度,
    每5分钟一次全功率求救尝试,
    保持至少48小时运行时间
  }
}
```
2. 给用户的求生指导
AI不能只是「发信号」，还要帮用户活下来：
```javascript
求生指导模板 {
  医疗急救: {
    显示: "最近的可食用植物/水源",
    显示: "基础急救步骤",
    播报: "保持冷静，深呼吸",
    记录: "生命体征变化"
  },
  
  迷路/失联: {
    显示: "当前推测位置",
    显示: "移动轨迹",
    建议: "停留原地或向高处移动",
    标记: "已走过的路线"
  },
  
  自然灾害: {
    显示: "安全避难点",
    显示: "灾害预警信息（如有缓存）",
    建议: "保存体力，等待救援"
  }
}
```

### 场景3：AI检测到用户异常
主动检测机制：
```javascript
异常检测 {
  // AI不问，直接判断
  
  触发条件: [
    "用户语气突然变化（平静→惊恐）",
    "用户输入混乱（打字错误率突增）",
    "设备传感器异常（跌倒/剧烈震动）",
    "长时间无响应（设定阈值后）",
    "环境声音异常（呼救声/爆炸声）"
  ],
  
  判断流程: {
    第1步: "是否误判？",
    第2步: "如果不确定，宁可误报",
    第3步: "立即询问用户：'你现在安全吗？'",
    第4步: "如果30秒无回应 → 启动应急协议"
  },
  
  避免骚扰: {
    正常使用场景下: "不主动打断",
    误触发3次以上: "提示用户关闭敏感检测",
    但: "不能完全关闭，只能降低灵敏度"
  }
}
```
