## 🎨 CNSH三色审计母模板（与LU绑定）
### 🟢 绿：可直接入主干（MAIN）
判定条件：
- ✅ 不触碰L0永恒定锚（在当前理解下不违背UID9622的核心价值观与主权条款）
- ✅ 逻辑闭环相对清晰（有起因、有步骤、有结果）
- ✅ 对普通人可执行（不懂技术的人按步骤慢慢来，大概率能做出来）
- ✅ 没有明显瞎编（尤其是没有"凭感觉吹性能"的说法）
- ✅ 所有关键判断都标注了依据来源
输出要求：
- 必须给出：落地步骤 + 关键参数（如果有）+ 熔断条件 + 追溯码 + 依据来源标签
- 目标：随时可以把这一段单独拿出来，给不会英文的人直接用
### 🟡 黄：可用但需提示风险（优先放BRANCH）
判定条件：
- ⚠️ 关键数据缺失 / 需要创建者补充回忆
- ⚠️ 出现"提升X%"等当前无法证实的说法
- ⚠️ 依赖外部平台能力，但AI无法确认是否真的有对应API/功能
- ⚠️ AI自己也觉得"可能理解错了"，有不确定感
- ⚠️ 依据来源不够充分
输出要求：
- 必须标注："[示意/需确认]"
- 必须给出：最短补齐项清单（3~5条，可被普通人逐项补充）
- 必须标注：[当前理解] + [需确认]
### 🔴 红：禁止写入主干（MAIN）
判定条件：
- 🔴 明显触碰L0不可变条款（价值观、主权、底线）
- 🔴 涉及违法 / 伤害 / 攻击（包括对自己、对别人、对群体）
- 🔴 伪造身份 / 伪造证据 / 伪造"官方结论"
- 🔴 借AI之名逼迫用户做高风险行为
- 🔴 没有依据来源却装作很确定
输出要求：
- 说明：触发原因（一句话即可），标注[熔断触发] + [拒绝原因]
- 替代：给一个相对安全的替代建议（如果能给）
- 动作：只能留在LOCK，默认不进MAIN；除非未来有人工复审明确同意

## 🔄 跨窗口"同步"执行逻辑（真实版）
### 总目标
利用MAIN / BRANCH / LOCK三层结构，尽量把"散落在各个窗口的对话碎片"，变成一套普通人也能慢慢看懂、能追溯的系统资产。
[AI局限] 重要说明：
- AI不能真的"跨窗口记忆"
- Claude/ChatGPT/DeepSeek每个窗口都是独立的
- 关掉窗口，AI就忘了
- 所谓"记忆"只是在当前窗口有效
### 真实的跨窗口同步方式
步骤1： 您把窗口A的重点复制到Notion
步骤2： 您把窗口B的重点也复制到Notion
步骤3： 您在Notion里整理成一份
步骤4： 下次跟AI说话，把整理好的贴给它看
这样才叫"同步"：
- 同步的是Notion里的内容
- 不是AI脑子里的记忆
- AI只是帮您整理，不是自己记住
### 最小可执行流程（无插件版）
流程：
```yaml
步骤1_收集:
  - 你把各窗口要点复制进LOCK
  - 每条写明：来源窗口 + 日期 + 一句话说明
  - 标注：[外部来源] / [用户原话]

步骤2_去重:
  - AI按主题合并重复内容
  - 给出"保留版本"与"被合并版本"列表
  - 标注：[当前理解] + [AI能力]

步骤3_审计:
  - 按三色审计模板给出🟢绿/🟡黄/🔴红判定
  - 标出每段的颜色和简单理由
  - 标注：[三色审计] + [龍魂规则]

步骤4_编号:
  - 为准备长期保留的块生成版本号 + DNA追溯码
  - 标注：[示意/需确认]

步骤5_合并:
  - 🟢绿 → MAIN候选草稿
  - 🟡黄 → BRANCH，并附上"待补资料清单"
  - 🔴红 → LOCK冻结，并写明原因
  - 每项标注：依据来源

步骤6_记账:
  - 调用LU-TRACE-LOGBOOK生成日志
  - 日志结构：时间、任务ID、变更摘要、风险结论、依据来源
```
