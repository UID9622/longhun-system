## 一、模板设计原则（写前必读）

### 1.1 铁律三条

| # | 铁律 | 说明 |
|:--:|------|------|
| 一 | **不制造二元对立** | 每给一个"问题面"，必须同体量给出"正向应用面"——不让读者觉得"技术=邪恶" |
| 二 | **数据支撑+亲身案例** | 每个核心论断至少1条研究数据引用+1个普通人可感知的场景 |
| 三 | **破局不只有个人意志力** | 每篇文章必须包含"个人×技术×制度"三方破局矩阵中的至少两方 |

### 1.2 禁止事项

| 禁止 | 原因 | 替代做法 |
|------|------|---------|
| "每一步都……""所有……都……" | 过度绝对化，豆包评议核心问题 | 改为"在特定条件下""大量案例表明""结构性倾向" |
| "系统/算法就是恶的" | 技术悲观主义，缺少辩证 | 改为"技术中立，KPI决定走向" |
| 只有比喻没有数据 | 主观化，削弱严谨度 | 每个比喻跟一个研究数据/统计案例 |
| "你必须……否则……"句式 | 制造焦虑（自己成了焦虑的源头） | 改为"如果你希望……可以尝试……" |
| 龍魂方案只提名字不解释 | 空洞，"信息主权"成空话 | 必须给可操作步骤或技术说明 |

### 1.3 评审对照清单（写完自检）

- [ ] 有没有至少3处研究/数据引用？
- [ ] 有没有为批判对象设置"正向应用"对照？
- [ ] 有没有提到"用户也可以反向影响系统"（双向性）？
- [ ] 有没有至少1处监管/制度维度的补充？
- [ ] 龍魂解法有没有具体可操作的步骤或技术说明？
- [ ] 有没有软化过度的绝对化表述？
- [ ] 结语是否给出了"不做任何事也能开始的第一步"？

### 区块 1：认知地图

**必含三句话，每句不超过2行**：

```markdown
## 认知地图（请在阅读前先看这三条）

> **第一**：[本篇文章不贩卖什么情绪] —— 比如"不是要你痛恨算法"
> **第二**：[读者不是完全被动的] —— 比如"你也在反向影响算法"
> **第三**：[破局有多条路] —— 比如"不只靠个人意志力，还有技术和制度"
```

**设计意图**：在读者被正文情绪带动之前，先建立认知框架。防止文章本身变成"情绪操控"。

### 区块 3：现象——分类拆解+数据+正向对照

**这是全文最核心的重构区块。** 每类现象的固定格式：

```markdown
### 2.X [情绪/现象类型名称]

**数据支撑**：
- [研究机构+年份+样本量+核心发现]
- [统计数据+来源]

**[现象类型]的商业转化链路**：

| 场景 | 机制 | 转化结果 |
|------|------|---------|
| [具体场景] | [触发机制] | [商业转化] |

**关键判断**：[50字以内的辩证分析——不绝对化、区分正常/异常、指明结构性问题]

**正向对照**（必填）：

| 正向场景 | 原理 | 示例 |
|---------|------|------|
| [同样技术做好事的场景] | [原理] | [具体例子] |

**区分标准**：[一句话：普通读者怎么判断自己是在被帮还是在被收割]
```

**重要**：正向对照表必须与批判表**同等体量**。不能是"象征性地提一句"。

## 四、常见写作检查项

### 4.1 语气检查

| 避免 | 替换为 |
|------|--------|
| "你在被操控" | "你的情绪正在被设计影响" |
| "平台故意让你上瘾" | "平台KPI结构天然倾向让你停留更久" |
| "你无能为力" | "你单独的力量不够，但个人+技术+制度可以" |
| "XXX是坏的" | "XXX在以[KPI]为目标的系统中，结构性倾向于[负面结果]" |

### 4.2 数据引用格式

```
**数据支撑**：
- [机构+年份]: [核心发现]（[样本量/范围]）
- [出处格式化引用]
```

### 4.3 表格设计规范

- 所有"批判"表必须有对应的"正向对照"表
- 所有"问题"表必须有对应的"解法"表
- 表格不超过5列（手机阅读友好）

### 4.4 可操作性检查

每一节结尾问自己：**读者读完这一段，知道自己可以做什么吗？**
如果答案是"知道但不能做"——补充怎么做。
如果答案是"做不了"——这就是技术工具或制度维度要解决的部分，标注。
