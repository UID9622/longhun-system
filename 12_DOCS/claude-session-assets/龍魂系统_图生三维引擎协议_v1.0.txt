【第一章 · 引擎定位】

原项目痛点（参考逻辑）:
  · Blender/Three.js 手写建模耗时巨大
  · AI 图片转3D 输出 .glb 文件不可修改
  · 改材质、加动画需从头再来

img2threejs 破局思路（参考逻辑）:
  → 不输出网格文件，输出可读的 TypeScript 代码
  → 浏览器里直接跑 Three.js
  → 改材质、调光照、加动画 = 改代码即可

龍魂系统升级定位:
  → 不输出封闭格式，输出龍魂系统原生语义协议（CNSH 中文语法）
  → 本地终端直接执行，数据不出设备
  → 改材质、调光照、加动画 = 改中文语义指令即可
  → 融合龍魂系统 DNA 追溯、七因子审计、分布式部署

原项目八阶段（参考逻辑，由 forge/ 目录实现）:

  阶段① blockout        — 基础轮廓与大块面
  阶段② structural-pass  — 主要结构与骨架搭建
  阶段③ form-refinement — 形态与造型精细化
  阶段④ material-pass   — PBR 材质基础通道设置
  阶段⑤ surface-pass    — 表面特征、刻痕、倒角与细节
  阶段⑥ lighting-pass   — 光照与环境拟合
  阶段⑦ interaction-pass— 运行时层级、挂载点 Socket 与碰撞体构建
  阶段⑧ optimization-pass— 代码与性能优化

关键约束（参考逻辑）:
  · 八阶段依次进行，上一阶段未通过 → 下一阶段不启动
  · 每阶段在浏览器中渲染结果，与原始图像对比评分
  · 不像就改，改到像了再继续
  · AI 只做一件事：看图判断像不像（pass/fail）
  · 其他活全交给确定性脚本（JSON校验、状态管理、对比图打包）

【第三章 · 核心设计原则（参考逻辑 → 龍魂重构）】
═══════════════════════════════════════════════════════════════════════════════════════

原则一：脚本干粗活，AI 只做视觉判断（参考逻辑）
  原项目实现:
    · JSON校验、状态管理、对比图打包 → Python脚本（标准库实现）
    · AI Token 只用在判断：看对比图，给 pass/fail
    · 脚本运行几乎不花钱，Token 全用在刀刃上

  龍魂系统升级:
    · 脚本层 → 龍魂系统本地执行引擎（bin/lh_3d_pipeline.py）
    · AI判断层 → 龍魂系统视觉审计人格（雯雯·视觉审计师）
    · Token 消耗 → 本地算力消耗，零外部API依赖
    · 审计层 → 七因子行为密码学签名，每次判断留痕

原则二：规格不够详细就不让写代码（参考逻辑）
  原项目实现:
    · 物体五个部分，规格只写了一个 → 直接驳回
    · "不合格的 spec 不配写代码"
    · 从源头杜绝半吊子模型

  龍魂系统升级:
    · 规格书 → 龍魂系统 CNSH 语义规格（中文结构化描述）
    · 驳回规则 → P2 系统规则第41条："规格不完整，引擎拒绝执行"
    · 审计层 → 规格完整性自动检测，缺失项标红

原则三：无依赖，只用标准库（参考逻辑）
  原项目实现:
    · Python脚本只使用标准库
    · PNG读写用 struct + zlib，无需 PIL
    · 无需 pip install，直接运行

  龍魂系统升级:
    · 依赖最小化 → 龍魂系统底座原则："零外部依赖，本地自给"
    · 图像处理 → 龍魂系统内置图像解析模块（国密算法兼容）
    · 部署方式 → 鲲鹏服务器本地运行，数据不出境

原则四：分类赛道，不硬套流程（参考逻辑）
  原项目实现:
    · v1.2 开始分类：object / character / hybrid
    · 角色独立赛道：头身比、脸型特点、姿态对齐
    · 不硬套物体流程

  龍魂系统升级:
    · 分类器 → 龍魂系统场景识别引擎（军事/民用/建筑/角色/自然）
    · 角色赛道 → 龍魂系统人格建模协议（DNA锚定人物形象）
    · 预设节点 → 龍魂系统 Socket 挂载点预定义（武器/装备/交互点）

原则五：细节一个都不能漏（参考逻辑）
  原项目实现:
    · v1.1 增加细节优先分析
    · 光泽、倒角、螺丝、刻线 → 映射到真实零部件
    · 生成旋转点、插槽、碰撞体，方便动画

  龍魂系统升级:
    · 细节分析 → 龍魂系统微观审计层（表面特征→七因子签名）
    · 旋转点/插槽 → 龍魂系统 Socket 协议（标准化挂载接口）
    · 碰撞体 → 龍魂系统物理引擎兼容层（支持多平台物理模拟）

【4.2 执行流程】

  输入图像
    ↓
  [L2 intake] 图像探测 → 可行性报告
    ↓ 通过
  [L2 deconstruct] 部件解构 → CNSH规格书
    ↓ 规格完整
  [L2 forge] 八阶流水线 → 三维模型代码
    ↓ 每阶段审计通过
  [L3 DNA追溯] 嵌入追溯码 → 七因子签名
    ↓
  [L4 输出] 龍魂系统原生3D产物
    · 格式: CNSH语义代码 + Three.js兼容层
    · 特性: 可编辑、可审计、可分布式验证

【4.3 关键接口】

  接口: /api/v1/3d/reconstruct
  方法: POST
  输入: {image: base64, category: "object|character|hybrid", 
        style: "realistic|stylized", audit: true}
  输出: {status: "success|fail", 
        stages: [{stage: 1-9, status: "pass|fail", score: 0-100}],
        output: {code: "CNSH语义代码", dna: "追溯码", 
                signature: "七因子签名", size: "文件大小"}}

【5.1 DNA追溯系统】
  · 每个3D产物嵌入唯一DNA追溯码
  · 格式: #龍芯⚡️{年干支}·{月干支}·{日干支}·{卦名}-{动作标签}-{版本}
  · 示例: #龍芯⚡️丙午·癸未·丁丑·明夷-3D重构-v1.0
  · 功能: 溯源、防伪、分布式验证

【5.2 七因子行为审计】
  · 每个流水线阶段生成行为签名
  · 七因子: {时间戳, 设备指纹, 操作者, 操作类型, 输入哈希, 输出哈希, 随机盐}
  · 功能: 防篡改、可追责、全链路透明

【5.3 CNSH 中文语义层】
  · 原项目输出 TypeScript 代码（英文）
  · 龍魂系统输出 CNSH 中文语义（中文结构化描述）
  · 示例对比:
    原项目: `const geometry = new THREE.BoxGeometry(1, 1, 1);`
    龍魂版: `【几何体】立方体 {长:1, 宽:1, 高:1, 材质:黄铜, 表面:氧化绿锈}`
  · 优势: 普通人可读可改，降低技术门槛

【5.4 分布式部署】
  · 鲲鹏服务器本地运行，数据不出设备
  · 多设备协同：Mac终端 + 鲲鹏服务器 + 华为手机
  · 离线可用：无需联网，本地算力自给

【5.5 军事/民用双轨】
  · 民用层: 开源透明，全球可用，免费贡献
  · 军事层: 国密加密，权限隔离，需审批
  · 物理隔离: 民用与军事数据永不交叉

【第六章 · 使用方式】
═══════════════════════════════════════════════════════════════════════════════════════

【6.1 本地终端执行】

  步骤1: 克隆龍魂系统3D引擎仓库
    ```bash
    git clone https://gitee.com/uid9622/lh-3d-engine.git
    cd lh-3d-engine
    ```

  步骤2: 启动本地引擎（无需pip安装）
    ```bash
    python bin/lh_3d_pipeline.py --input /path/to/image.png --category object
    ```

  步骤3: 查看输出产物
    ```bash
    ls output/
    # 产物: {dna}.cnsd    # CNSH语义代码
    #       {dna}.js      # Three.js兼容层
    #       {dna}.audit   # 七因子审计日志
    ```

【6.2 龍魂系统API调用】

  ```bash
  curl -X POST https://localhost:9622/api/v1/3d/reconstruct     -H "Content-Type: application/json"     -H "X-Longhun-DNA: #ZHUGEXIN⚡️..."     -d '{
      "image": "base64encoded...",
      "category": "object",
      "style": "stylized",
      "audit": true
    }'
  ```

【6.3 与Mac终端Kimi协作】

  在Mac终端输入:
    ```bash
    kimi --task "3d-reconstruct" --input house.png --category object
    ```

  Kimi自动调用龍魂系统3D引擎，执行八阶流水线，
  输出带DNA追溯的3D产物，同步至Notion归档。
