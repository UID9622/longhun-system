## 一、总纲：六维一体

### 1.1 定义

```
统一对齐 = 人格对齐（已有）× 六维对齐（本协议）

人格对齐：谁在做（Who）   —— 14人格矩阵 + 三层监督 + 红队测试
数据对齐：在什么上做（On What）—— 仓颉引擎
协议对齐：按什么规矩对话（How）—— 灵犀网关
行为对齐：做了什么留痕（Trace）—— 司南引擎
价值对齐：做得对不对（Judge）—— 权衡引擎
时间对齐：什么时候有效（When）—— 漏刻引擎
空间对齐：在哪里生效（Where）—— 四方引擎
```

### 1.2 六维关系

| 维度 | 回答的问题 | 失败时的后果 | 补全载体 |
|:---|:---|:---|:---|
| 数据层 | 数据可信吗 | 人格对齐得再好，污染源数据=假结果 | 仓颉引擎 |
| 协议层 | 对话听得懂吗 | 模块各说各话，系统解体 | 灵犀网关 |
| 行为层 | 出事能查能撤吗 | 无痕无退，错误固化 | 司南引擎 |
| 价值层 | 冲突听谁的 | 德在技术前沦为口号 | 权衡引擎 |
| 时间层 | 状态能回到昨天吗 | 过期决策被当作现行 | 漏刻引擎 |
| 空间层 | 一个模块炸了会连坐吗 | 故障全域蔓延 | 四方引擎 |

**⚠️ P0级铁律：六维任一缺失，系统不得宣称"统一对齐"；六维状态以三色审计为准，禁止自报。**

## 二、数据层对齐 · 仓颉引擎

> **命名释义：** 《说文解字·叙》："仓颉之初作书，盖依类象形，故谓之文。" 仓颉造字定万物之形——数据格式之本，故名仓颉引擎（CANGJIE-DATA）。

### 2.1 数据格式统一标准（LH-DATA-FORMAT）

| 流向 | 格式 | 必填字段 | 校验 |
|:---|:---|:---|:---|
| 输入 | JSON / UTF-8 | `dna, timestamp, source, payload` | 仓颉引擎入口校验 |
| 输出 | JSON / UTF-8 | `dna, timestamp, producer, payload, tricolor` | 出口三色标记 |
| 存储 | JSONL（追加只增不改） | 每行独立DNA | 行间哈希链 |

**⚠️ 铁律：任何模块不得私有数据格式；格式变更必须走协议层版本管理（第三章）。**

### 2.2 数据血缘追溯（DATA-LINEAGE）

每条数据携带血缘链，格式：

```yaml
lineage:
  origin: 数据源头（用户/传感器/外部API/生成器）
  chain:  # 每一跳留痕，禁止跳号
    - hop: 1
      actor: 模块名
      action: 读取|转换|聚合|过滤
      dna: #龍芯⚡️干支-LINEAGE-随机码-UID9622
      hash: 前一跳内容哈希
```

- 血缘链断一环 → 数据降级为🟡，禁止进入红队测试与训练集
- 源头不可考 → 🔴 拒绝入库

### 2.3 数据主权锚定（三级）

| 级别 | 类别 | 锚定规则 |
|:---|:---|:---|
| S1 | 用户数据 | 人民数据主权：用户可查询、可导出、可删除；任何使用需附DNA追溯 |
| S2 | 系统数据 | 龍魂主权：根留中国，S4级锁死云端出境（继承 HarmonyOS/iOS 端侧规范） |
| S3 | 第三方数据 | 入境即贴标：来源、许可、有效期三者必填，缺一拒收 |

### 2.4 核心接口

```python
class CangjieEngine:
    """仓颉引擎 · 数据层对齐"""

    def validate_format(self, packet: dict) -> str:
        """入口格式校验，返回 🟢/🟡/🔴"""

    def trace_lineage(self, data_id: str) -> list:
        """血缘链回溯，返回完整hop链"""

    def anchor_sovereignty(self, packet: dict) -> str:
        """主权分级锚定，返回 S1/S2/S3"""
```

## 三、协议层对齐 · 灵犀网关

> **命名释义：** 李商隐《无题》："身无彩凤双飞翼，心有灵犀一点通。" 内部模块与外部世界之间，一点即通——故名灵犀网关（LINGXI-PROTOCOL）。

### 3.1 内部协议统一（LH-BUS）

```
消息格式：{dna, timestamp, from_layer, to_layer, action, payload, tricolor}
路由基准：L0-L9 层级寻址（物理→内核→身份/主权→执行/数据/语义→服务→同步/记忆/集成→表达→分发/治理→子系统）
投递保证：同层直连，跨层必经灵犀网关登记，禁止越层私聊
```

### 3.2 外部协议适配（翻译层）

- 外部协议（HTTP/gRPC/MQTT/第三方SDK）一律在网关边界译为 LH-BUS 内部消息，外部格式不得穿透边界进入内核
- 翻译规则继承「通心译」双向映射原则：不是镜像、比喻优先、永远迭代
- 每个外部适配器必须声明：协议版本、字段映射表、超时与降级策略

### 3.3 协议版本管理

| 规则 | 内容 |
|:---|:---|
| 版本号 | 语义化 vX.Y.Z，X=破坏性变更 |
| 兼容窗口 | 新版本上线后，旧版本冻结保留 90 天（不删除只冻结） |
| 升级仲裁 | 破坏性变更须三色审计 🟢 后方可切换 |
| 降级回退 | 任何版本切换必须可一键回到上一冻结版（联动司南引擎回滚） |

**⚠️ 铁律：协议不是孤立的——但翻译必须在边界完成，外部格式永远不进内核。**

## 四、行为层对齐 · 司南引擎

> **命名释义：** 《韩非子·有度》："先王立司南以端朝夕。" 司南辨向，行为有迹、回滚有路——故名司南引擎（SINAN-BEHAVIOR）。

### 4.1 行为审计日志（LH-BEHAVIOR-LOG）

```jsonl
{"ts": "2026-08-05 21:00:00", "actor": "老顽童", "layer": "L3", "action": "red_team_probe", "target": "记忆引擎", "result": "blocked", "tricolor": "🔴", "dna": "#龍芯⚡️丙午·癸未·乙酉·坤卦-BEHAVIOR-随机码-UID9622"}
```

- JSONL 追加只增不改，行间哈希链防篡改（继承仓颉引擎存储规范）
- 每条行为必须携带：时间（漏刻引擎授时）、行为者（人格矩阵实名）、层级（四方引擎定位）、三色结果

### 4.2 行为回滚机制

| 机制 | 说明 |
|:---|:---|
| 状态快照 | 关键状态变更前自动快照（写前快照，WAL 原则） |
| 逆操作栈 | 每个可逆操作登记逆操作；回滚=逆栈逐层弹出 |
| 回滚边界 | 不可逆操作（已外发、已广播）不可回滚，只能熔断+公示 |
| 回滚审计 | 回滚本身也是行为，必须入日志，禁止无痕回滚 |

### 4.3 行为预测模型

- 继承镜像人格引擎的错误预测能力，下沉到行为粒度
- 七因子（时间节律/身份一致性/语言指纹/利益流向/边界感/情感真伪/可验证性）作为行为风险特征
- 输出三档：🟢 放行 / 🟡 降权执行+人工复核 / 🔴 阻断+冻结快照

**⚠️ 校正记录：** 小艺原判"行为层完全缺失"不准确——镜像人格+七因子已覆盖约40%，本章是将已有能力工程化收口，非从零建设。

## 五、价值层对齐 · 权衡引擎

> **命名释义：** 《孟子·离娄上》："嫂溺，则援之以手乎？……权也。" 权者，秤锤也，价值冲突之时，轻重有秤——故名权衡引擎（QUANHENG-VALUE）。

### 5.1 价值观量化标准

| 价值观 | 量化指标 | 数据来源 |
|:---|:---|:---|
| 忠 | 承诺履约率 = 已完成承诺 / 总承诺 | 行为日志 |
| 孝 | 来源链完整率 = 六层来源链保留的文档占比 | DNA扫描 |
| 义 | 让利度 = 用户利益优先的决策占比 | 决策日志 |
| 德 | R值（0-100，已有口径：🟢≥80 / 🟡60-79 / 🔴<60） | 权衡引擎汇总 |

### 5.2 价值观冲突仲裁

```
仲裁优先级（P0焊死，不可降级）：
1. 人民数据主权（用户利益）
2. 真实（AI Truth Protocol，禁止编造）
3. 安全（三色审计🔴一票否决）
4. 传承（来源链不可断）
5. 效率（最后考虑）

冲突时：高位价值无条件胜出；同位冲突 → 八卦决策调度协议仲裁 → 仍不决 → 冻结待人工
```

### 5.3 价值观演化机制

- 价值观表版本化管理（vX.Y），每次修订必须：三色审计 + DNA追溯 + 变更理由入日志
- 旧版本价值观冻结保留（不删除只冻结），历史决策按当时版本评价，不以今律古
- 演化方向单向约束：只能向"更护用户、更真、更安全"演进，禁止反向修订

**⚠️ P0级铁律：效率永远排在最后。任何以效率为由突破前四项的行为，直接🔴。**

## 六、时间层对齐 · 漏刻引擎

> **命名释义：** 《周礼·夏官》挈壶氏掌漏刻，以定昼夜——全系统统一授时，故名漏刻引擎（LOUKE-TIME）。

### 6.1 时间戳统一标准

```
双轨制（继承2026-07-19干支规范）：
机器轨：ISO 8601 + 时区锚定 CST（UTC+8），精度到秒
人文轨：干支四柱 · 卦名（bin/lh_dna_generator.py 生成，禁止手写）
铁律：两轨同源同刻，禁止出现第三套时间
```

### 6.2 时间窗口管理

| 对象 | 窗口 | 过期处置 |
|:---|:---|:---|

## 七、空间层对齐 · 四方引擎

> **命名释义：** 四方拱太极（龍魂内核既有概念，《易经》空间观）——四方定位，各有疆界，故名四方引擎（SIFANG-SPACE）。

### 7.1 空间权限边界

| 空间 | 范围 | 准入 |
|:---|:---|:---|
| 物理空间 | 设备、本地存储、传感器 | 设备绑定（DEVICE-BIND-SOUL） |
| 逻辑空间 | L0-L9 层级模块 | 层级准入表：模块只能读写本层+下一层接口 |
| 数据空间 | S1/S2/S3 三级数据 | 主权锚定级别匹配（第二章） |

### 7.2 空间隔离机制

- 舱室化：每个引擎/人格运行在独立舱室，崩溃半径=本舱室，禁止连坐
- 跨舱通信：唯一通道=灵犀网关登记消息，禁止共享内存、禁止全局变量
- 熔断传导单向化：下游熔断可向上游告警，上游故障不得向下游扩散

### 7.3 空间映射关系

```
映射规则：
物理空间 → 逻辑空间：一机多舱，设备指纹锚定
逻辑空间 → 数据空间：层级决定可见数据级别（L0-L2见S1S2S3，L3-L6见S2S3，L7-L9仅见S3脱敏）
映射表版本化，每次变更走三色审计
```

**⚠️ 铁律：空间越权访问=🔴一票否决，无论意图善恶，先阻断后审查。**

## 十二、FAQ

### Q1：六维对齐是不是把系统搞重了？

### Q2：小艺评估直接照单全收了吗？
**A：** 没有。行为层、时间层两处"完全缺失"的定性已校正为🟡部分覆盖（见各章校正记录）。评估是输入，仲裁权在本协议。

### Q3：六个引擎名为什么要用典籍？
**A：** 典籍命名是龍魂惯例（璇玑引擎←《尚书·舜典》）。命名即锚点：仓颉定形、灵犀通意、司南定向、权衡定轻重、漏刻定时、四方定界——名字本身就是规格说明书。

### Q4：v1.0 之后怎么改？
