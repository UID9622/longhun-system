## 1. 目的

解决AI视觉识别中的**幻觉输出**与**过度自信**问题。核心原则：

> **不确定时，不准说"是"，必须输出候选概率。**

---

## 2. 适用范围

- 车牌识别（OCR）
- 车型/仪表盘识别
- 人脸/身份识别
- 任何涉及"从图像推断结论"的龍魂系统模块

---

## 3. 核心规则

### 3.1 图像质量预检（前置闸门）

识别前必须量化评估：

| 指标 | 阈值 | 判定 |
|------|------|------|
| 亮度 | 30–230 | 低于30或高于230标记为"异常" |
| 清晰度（拉普拉斯方差） | >25.0 | 低于25标记为"模糊" |
| 分辨率 | ≥300×200 | 低于阈值标记为"不足" |
| 角度/透视 | 人工标注 | 明显倾斜时降级处理 |

**质量差时，置信度阈值自动上调：**
- 正常图像：确认线90%，疑似线60%
- 质量差图像：确认线95%，疑似线70%

### 3.2 多引擎并行投票

至少注册三个独立OCR引擎：

| 引擎 | 默认权重 | 说明 |
|------|----------|------|
| PaddleOCR | 0.40 | 中文场景首选 |
| EasyOCR | 0.25 | 多语言备选 |
| Tesseract | 0.20 | 开源基线 |
| 自定义特征库 | 0.15 | 龍魂专用车型/标识库 |

**权重动态可调：** 根据历史准确率日志，每月自动校正一次。

### 3.3 置信度聚合算法

```
候选文本置信度 = Σ(引擎权重 × 引擎对该文本的原始置信度) / 总权重
```

结果按聚合置信度降序排列，取TOP5输出。

### 3.4 输出闸门（三档）

| 档位 | 条件 | 行为 |
|------|------|------|
| **CONFIRMED** | 最高候选 ≥ 确认线 | 直接输出结论，附加"✅ 可采纳" |
| **SUSPECTED** | 最高候选 < 确认线 但 ≥ 疑似线 | 输出结论，强制附加"疑似"标注 + "建议人工复核" |
| **UNCONFIRMED** | 最高候选 < 疑似线 | 拒绝直接结论，仅输出候选列表 + 图像质量报告 + "⚠️ 不可作为法律证据" |

### 3.5 输出格式标准

所有视觉识别输出必须遵循以下结构：

```
[VISUAL-IDENTITY-{任务类型}]
├─ DNA追溯: #龍芯⚡️...
├─ 图像来源: {路径/URL}
├─ 识别状态: {CONFIRMED|SUSPECTED|UNCONFIRMED}
├─ 结论: {文本}
├─ 候选列表:
│  ├─ 候选1: {文本}  置信度 {X}%
│  ├─ 候选2: {文本}  置信度 {X}%
│  └─ ...
├─ 图像质量评估:
│  ├─ 亮度: {值} ({正常|异常})
│  ├─ 清晰度: {值} ({清晰|模糊})
│  ├─ 分辨率: {宽}x{高}
│  └─ 总体评价: {good|poor}
└─ {✅ 可采纳 | ⚠️ 警告：低置信度输出，请勿作为法律证据使用}
```

**禁止行为：** 低置信度时输出单一确定答案。

## 4. 执行层参考实现

### 4.1 依赖

```bash
pip install opencv-python numpy pillow pytesseract easyocr paddlepaddle paddleocr
```

Tesseract需单独安装并配置环境变量。

### 4.2 核心脚本

脚本名：`VISION-UID9622-CONFIDENCE-OCR-PIPELINE-v1.0.py`

功能模块：
1. `assess_image_quality()` — 图像质量评估
2. `enhance_image()` — 预处理（去噪、锐化、反光抑制、直方图均衡）
3. `OCRWrapper` — 统一引擎接口
4. `aggregate_candidates()` — 加权投票聚合
5. `confidence_gate()` — 三档闸门判定
6. `format_output()` — 龍魂协议格式输出
7. `run_vision_audit()` — 主流程（读图→质检→增强→识别→聚合→闸门→输出→归档）

### 4.3 使用示例

单张识别：
```bash
python VISION-UID9622-CONFIDENCE-OCR-PIPELINE-v1.0.py \
    --image ./car_plate.jpg \
    --task plate
```

批量处理：
```bash
python VISION-UID9622-CONFIDENCE-OCR-PIPELINE-v1.0.py \
    --batch ./images/ \
    --task plate
```

### 4.4 日志与迭代

每次识别写入JSONL日志：

```json
{
  "timestamp": "2026-08-02T20:17:00+08:00",
  "image": "./car_plate.jpg",
  "task": "plate",
  "status": "SUSPECTED",
  "candidates": [["浙C·587Q6", 0.52], ["浙C·5A70F", 0.31]],
  "quality": {"brightness": 45.2, "blur_score": 23.5, "quality_overall": "poor"},
  "dna": "#龍芯⚡️20260802-VISION-UID9622-A1B2C3D4"
}
```

**迭代机制：** 每月统计各引擎准确率，动态调整 `CONFIG["weights"]`。

---

## 6. 边界与限制

- 本协议**不保证100%识别正确**，只保证"不确定时不瞎说"。
- 低置信度输出**不可作为法律证据**。
- 夜间、反光、遮挡、极端角度场景，必须人工复核。
- 车型识别依赖仪表盘/UI特征库，新车型未入库时置信度必然偏低。
