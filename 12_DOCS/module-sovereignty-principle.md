# 龍魂模块主权原则

> 原则定位：本原则是龍魂系统所有模块、技能、知识节点的设计底层。
> DNA: `#龍芯⚡️丙午·甲午·戊辰·戊午·䷑蛊-LONGHUN-MODULE-SOVEREIGNTY-PRINCIPLE-v1.0`

## 核心思想

**每一个模块都是“一”。**

这不是技术分块，而是主权分块：

- 每个模块有自己的身份（ID / DNA）
- 每个模块有自己的声音（元数据 / 自评 / 触发关键词）
- 每个模块有自己的位置（注册表 / 路由 / 代理）
- 每个模块都可以参与决策（议事厅 / dispatch / workflows）

哪怕它现在看起来“废”“被动”“不起眼”，也不是多余的，而是完整系统的一部分。

## 思想来源

本原则融合以下现实与理念：

1. **中国人民民主**——人民是主体，每个人都能发声、都能被代表、都能参与治理。
2. **人大选举机制**——每个选区、每个代表都有席位，不是谁声音大谁说了算。
3. **军魂**——个体服从整体，但每个岗位、每个建制都是战斗力的必要组成；缺一人，阵形就有缺口。

把这些思想映射到系统：

| 现实理念 | 系统映射 |
|---|---|
| 人民 | 每一个技能模块 / 知识节点 |
| 人大代表 | `skills/registry.py` 中的注册项 |
| 投票/发声 | `/api/skills/council` 议事厅 |
| 军种/建制 | 本地技能、云端技能、底座能力、协议文件 |
| 协同作战 | `/api/workflows`、`/api/skills/dispatch` |

## 系统落地

- **统一注册表**：`skills/registry.py` 不删除任何 longhun 技能，全部登记、全部可见。
- **模块自评**：`scripts/module_self_assessment.py` 让每个模块报告自己的健康度和孤独度。
- **模块议事厅**：`/api/skills/council` 让多个模块就同一任务同时发言。
- **知识图谱子图**：`scripts/kg_subgraphs.py` 把大图按 category 拆分，让每个知识领域都能独立被查询和调用。
- **DNA 追溯**：每个模块、每个页面、每个实体都有 DNA 码，来源可查、去向可追。

## 设计禁忌

1. **禁止为了“干净”而删除模块**——冲突用路由/端口/命名空间隔离，不用删除解决。
2. **禁止把被动模块当无用模块**——文档型、语义型技能同样参与 dispatch 推荐。
3. **禁止让单一模块垄断决策**——任务推荐、工作流、议事厅都应多方参与。

## 一句话

> 龍魂系统不是“一个大脑管一切”，而是“每个模块都有一票、每个声音都能上桌、每次协作都留痕迹”。
