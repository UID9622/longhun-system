## 一、为什么模型会"一本正经地胡说八道"？

> 📌 送审件原文（逐字保留）

### 先理解"生成闭环"

大模型生成回答时，内部有一个**自回归循环**：

```
输入 Prompt
    ↓
模型计算下一个 token 的概率分布
    ↓
采样一个 token（贪心/温度采样/核采样）
    ↓
把新 token 拼回输入，再预测下一个
    ↓  ←———————————————循环———————————————←
直到输出终止符或达到最大长度
```

每一步的微小误差，会在循环中被**逐步放大**——这就是幻觉产生的**结构性温床**。

> 📌 送审件原文（逐字保留）

### 触发路径：三类主流成因

**成因①：训练数据噪声（最底层）**

互联网文本本身就充满错误信息、过时知识、虚构内容。模型在预训练时"照单全收"，把这些噪声学进了参数里。当模型被问到一个它"学过但学错了"的知识点时，它会以极高的置信度输出错误答案——**因为它真心认为那是真的**。

> 🔑 关键词：**Garbage In, Garbage Out**——训练数据的质量上限，就是模型知识的上限。

**成因②：解码策略的"创造性"副作用**

| 解码策略 | 温度 | 幻觉倾向 | 适用场景 |
|---|---|---|---|
| 贪心解码 | 0 | 低 | 事实问答、代码生成 |
| 核采样 | 0.7~0.9 | 中 | 创意写作、头脑风暴 |
| 高温度采样 | >1.0 | 高 | 艺术创作、发散思维 |

温度越高，模型越"敢说"——但"敢说"和"说对"是两回事。**创造力与准确性是一对永恒的矛盾。**

> 🔑 关键词：**Sampling Bias**——推理时的高温度，是"主动型幻觉"的最大来源。

**成因③：上下文越长越容易"记串"（AI 协作重建补充·🟢 技术共识）**

对话轮次一多、上下文一长，模型对"哪句话是用户说的、哪句话是我自己刚编的、哪句是检索回来的资料"会逐渐分不清边界。它会把**自己刚生成的推测**再当成**输入事实**喂回给自己——自我强化，越说越离谱。

> 🔑 关键词：**上下文串扰（context contamination）**——幻觉会"滚雪球"。

## 二、幻觉能"数"出来吗？——H 指数大白话

> 本节依据系统引擎 `08_BIN/lh_hallucination_metrics.py` 实况（🟢 已验证）

直觉上我们说"这回答像编的、那回答是靠谱的"——这是**凭感觉**。龍魂把它变成一把**能量化的尺子**，叫 **H 综合指数（无幻觉度·质量分）**：

```
H = 混淆矩阵F1 / Token精确率 / 语义完全匹配(EM) / 五个领域平均分
   + 0.2 × (五维度均值 − 0.5)    ← 跨领域表现越好，越加分

最后压到 0~1 之间 → 三个色闸：
   🟢 ≥ 0.80   质量好，放行
   🟡 0.50~0.80  需要复查
   🔴 < 0.50    不达标，拒绝交付
```

- **H 越高 = 幻觉越少**（分数与直觉同向）。
- 另报 **ECE 置信度校准**：衡量模型"嘴上说多自信 vs 实际有多准"，0 分=完全校准（不吹牛），越高=越爱"一本正经胡说"。注意 ECE 与 H **方向相反**，单独看。
- 每条结论带 `_formula` 字段，可直接粘到 Python 里复算——**审计不靠信誓旦旦，靠公式重跑**。
- 内置独立数学验证器 `MathValidator`：从原始分项**重新算**一遍 H，防"自算自夸"。

三色口诀：**没跑过的不标已验证，算得出的才算数**（判据④·21.5 铁律）。

## 五、普通人被 AI 忽悠了怎么办？（四个自保姿势）

1. **让它给出处**：问"你这句话的依据是什么？"——拿不出源的，当它放屁。
2. **关键事实自己验**：数字、人名、法条、剂量，动手搜一遍只要十秒。
3. **问第二次、换个问法**：真知识经得起换个角度复述；编的会越描越圆、越问越假。
4. **涉及钱和命，找真人复核**：AI 是参考，不是责任主体。责任永远在人。
