## 一、为什么要做这件事

在 DeepSeek-V3 社区 issue #1466 的讨论中，大家反复提到一个病根：

> **「数字口径不自声明 + 不可复现 + 无一致性对拍」**

很多评估算法看起来合理，但——
- 权重怎么来的？不声明
- 同输入再跑一遍，结果一样吗？不保证
- 维度分和总分对得上吗？不对拍

龍魂的原则是**零黑箱**：每一个数字都能复现，每一个判断都能验证。所以我们把这个原则落地成了一个可运行的工程底座，开源给所有人。

## 二、算法长什么样

**核心逻辑**: 五维打分 → 加权合成 → 数字根 → 风险等级 → 审计轨迹

```
五维: 流动性 / 负债 / 效率 / 盈利 / 稳定
权重: 0.25 / 0.20 / 0.20 / 0.20 / 0.15
合成: Σ(维度分 × 权重) = 综合分
数字根: dr(n) = 1 + ((n-1) mod 9)  ← 369底座
等级: 🟢优秀 🟢良好 🟡一般 🔴较差 🔴危急
```

## 三、v2.0 六大落地（和其他算法的本质区别）

| # | 特性 | 解决什么 |
|:---:|:---|:---|
| 1 | **内容寻址DNA** | 同输入+同公式→同DNA，可复现可对拍（不用 time.time() 当种子） |
| 2 | **口径锁** | 每个数字自报"公式+版本+输入哈希"，杜绝口径漂移 |
| 3 | **明细-聚合对拍** | 维度分与总分自动交叉验证，偏差超容差标 🟡 MISMATCH |
| 4 | **黄金回归** | --self-test 内置12锚点，算法改动防悄悄退化 |
| 5 | **真·数字根** | 用 369 底座 dr(n)=1+((n-1) mod 9)，不是拍脑袋映射 |
| 6 | **权重A-BOM备案** | 每个权重声明来源，可覆盖、可审计 |

## 四、30秒跑通


## 五、为什么说"用数据说话"

- 每个维度分的公式在源码里逐行可查（`_score_liquidity` 等五个函数）
- 每个输出的 DNA 可按同输入复算，两跑对比即可对拍
- 所有发布文件带 GPG 分离签名（密钥 `A2D0092CEE2E5BA87035600924C3704A8CC26D5F`），`gpg --verify` 可验真伪
