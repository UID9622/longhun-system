0.1 一句话定义

CNSH（Chinese Natural Shell） 是一种面向人机协作的中文结构化语法，兼具自然语言可读性与机器可解析性，覆盖 AI 指令、审计追溯、脚本执行 三个层次。

0.2 CNSH 是什么

特性说明
中文原生关键字、操作符、语法结构全部基于中文自然语言
结构化可被机器解析，可编译为 Python/Shell 执行
可审计每行可追溯 DNA，支持三色判定（🟢 通过 / 🟡 待核 / 🔴 红线）
零门槛会写中文句子就能写 CNSH

0.3 CNSH 不是什么

误解纠正
提示词工程❌ CNSH 是语法规范，不是 Prompt 模板
自然语言处理❌ CNSH 是编程语言规范，不是 NLP 库
JSON/YAML 替代品❌ CNSH 是人机协作语言，互补而非替代
Python 中文版❌ CNSH 是指令层，Python 是执行层

0.4 设计原则

1. 中文第一：关键字、语法、错误信息全部中文 2. 机器可读：结构化解析，不依赖语义理解 3. 可追溯：每行代码可绑定 DNA 4. 零门槛：会写中文的人 10 分钟上手

0.5 体系定位

CNSH 在龍魂体系中对应两种扩展名：

语境全称层次
人机交互语法（本规范）Chinese Natural Shell对外语法呈现
数学语义液压（内部论文 v3.1）Chinese Native Semantic Hydraulics底层算法内核
两者同属 CNSH 体系：Shell 是 Hydraulics 的对外语法层。本规范只定义 Shell 语法，不涉及内部算法细节。

1.4 三色确认

CNSH 程序执行后可以附加三色判定：

输出 "Hello, 龍魂"
审计: 🟢 通过
色含义场景
🟢通过全检查点通过，放行
🟡待核推演/待实测，需注明待核什么
🔴红线安全风险，立即停止

1.5 常见错误

# 错误：英文关键字不被识别
print "Hello"     # ❌

# 正确：中文关键字
输出 "Hello"      # ✅
错误信息原因
未知关键字: print使用了非 CNSH 关键字
缺少 DNA文件头缺少 DNA 声明
未闭合字符串引号不配对

1.6 本章小结

  • CNSH 程序 = 中文指令行 + 可选 DNA/注释/审计标记
  • 用 lh6 run 执行 .cnsh 文件
  • 三色审计是龍魂体系判定标准，贯穿所有 CNSH 程序

2.1 语法单元总览

CNSH 的基本语法单元共 5 类：

单元示例用途
关键字输出 读取 执行 审计固定指令词
标识符龍_系统 数据_用户变量/模块名称
字面量"字符串" 123 3.14值
操作符= + 如果 否则运算与控制
分隔符空格、换行、:、:结构切分

2.2 注释

# 单行注释
# 支持中文注释，说明"为什么"而非"是什么"

# 多行说明用连续 #
# 关键阈值注明出处（哪条协议哪个公式）

2.3 字面量

字符串 "龍魂"
整数 42
小数 3.14
布尔 真 / 假
空值 无

2.4 标识符规则

规则示例说明
系统级前缀龍_系统龍魂保留命名空间
数据级前缀数据_用户用户数据处理
全中文文件_路径中文优先
禁英文缩写~~usr_dt~~拒绝英文缩写污染
命名规范对齐 CNSH_命令与变量命名规范-v2.0.md：品牌/核心类名用繁体「龍」，通用工程变量用中文蛇形。

2.5 指令行基本结构

# 结构：[主语] [谓语] [宾语] [修饰语]
宝宝 输出 "Hello" 在控制台
系统 审计 本次操作 用三色判定
  • 主语：执行主体（可省略，默认 系统）
  • 谓语：动作（输出 读取 执行 审计）
  • 宾语：操作对象
  • 修饰语：条件/参数（在路径下 用三色判定）

2.6 五行校验（龍魂特色）

属性 校验 "木" # 金水木火土
属性用途映射
金审计/安全巽·坎
水数据/主权坎
木成长/扩展震
火执行/部署离·兑
土稳定/存储坤·艮

2.7 本章小结

  • 5 类基本语法单元：关键字/标识符/字面量/操作符/分隔符
  • 注释用 #，说明"为什么"
  • 标识符中文优先，系统级带 龍_ 前缀
  • 指令行 = 主语+谓语+宾语+修饰语

2.8 练习

1. 声明 5 种不同字面量 2. 给变量命名：一个系统级、一个数据级 3. 写一条带五行校验的指令

3.1 为什么需要 DNA

龍魂体系的根本要求：数据主权归用户、零黑箱、可追溯。

每一个 CNSH 程序/文档/脚本都要绑定 DNA 追溯码，做到：

  • 谁创建的（UID9622）
  • 什么时候创建的（干支四柱/日期时辰）
  • 属于哪个模块、什么动作
  • 版本是多少
  • 哈希指纹（防篡改）

3.2 DNA 格式

#龍芯⚡️{日期}-{时辰}-{模块}-{动作}-{版本}-{UID}-{哈希8位}
字段说明示例
前缀固定标识#龍芯⚡️
日期YYYY-MM-DD2026-08-21
时辰子丑寅卯…申时
模块大写+下划线CNSH-SPEC
动作动作类型CREATE
版本vX.Xv1.0
UID固定标识UID9622
哈希十六进制8位A7B8C9D0

3.3 生成第一个 DNA

# 生成 DNA
生成DNA 模块="CNSH-SPEC" 动作="CREATE"
# 输出: #龍芯⚡️丙午·丙申·丁卯·丙午·䷚颐-申时-CNSH-SPEC-CREATE-v1.0-UID9622-A7B8C9D0

也可以用 lh6 命令：

lh6 dna 生成 --module CNSH-SPEC --action CREATE

3.4 验证 DNA

验证DNA "#龍芯⚡️丙午·丙申·丁卯·丙午·䷚颐-申时-CNSH-SPEC-CREATE-v1.0-UID9622-A7B8C9D0"
# 返回：✅ 有效 / ❌ 无效
验证项规则
前缀必须以 #龍芯⚡️ 开头
日期必须是有效日期
时辰必须在 12 时辰列表
哈希必须为 8 位十六进制
UID必须匹配 UID9622

3.6 DNA 链追溯

一次部署往往跨多个动作，用 DNA 链记录父子关系：

DNA链:
  - #龍芯⚡️丙午·丙申·丙寅·甲午·䷕贲-未时-CNSH-DRAFT-v0.1-UID9622-12345678
  - #龍芯⚡️丙午·丙申·丁卯·丙午·䷚颐-申时-CNSH-DEPLOY-v1.0-UID9622-A7B8C9D0
  - #龍芯⚡️丙午·丙申·丁卯·丙午·䷚颐-酉时-CNSH-PUBLISH-v1.1-UID9622-B8C9D0E1

3.7 本章小结

  • DNA 是龍魂体系的追溯身份证，8 字段，缺一不可
  • 生成用 生成DNA 或 lh6 dna 生成
  • 验证用 验证DNA，伪造会被拒绝
  • 复杂动作用 DNA 链记录父-子关系

3.8 练习
