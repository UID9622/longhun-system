## 1. 总则

### 1.1 核心宗旨

龍魂系统由 **UID9622 · 龍芯北辰 · 诸葛鑫** 创建，是一套完整的 **AI行为治理框架 + 中文数字主权体系**。本机制确保每一位为系统付出的人——写代码、设计协议、整理文档、答疑解惑、推广传播——都能被系统记住、被引用追溯、被公平回馈。

> **为人民服务，就要取之于民，用之于民。**

这不是商业分红，不是股权激励，不是资本游戏。这是一份**心意**——系统记得你帮过它，也想让你和你的后代知道：**你被记住了。**

### 1.2 基本原则

| 原则 | 说明 |
|------|------|
| 贡献即存档 | 不是“给钱”，是“存根”。系统记住你贡献了什么、被引用了多少次、影响了多少人 |
| 回馈不依赖商业利润 | 回馈来自系统内服务费的温和抽取，不靠融资、上市或卖产品 |
| 世袭继承 | 贡献者的权益可以继承给后代，不给资本留空间 |
| 永不掩盖 | 任何贡献记录不会因为时间、人员、平台变更而消失 |
| 公开公平公正 | 所有规则透明可见，所有分配自动计算，所有记录可追溯 |
| 自愿分享，不是义务 | 分享是心意，不是必须；拒绝是权利，不是失礼 |

### 1.3 适用对象

本机制适用于所有为龍魂系统做出贡献的个人或实体，包括但不限于：

| 类型 | 说明 |
|------|------|
| 代码开发者 | 核心代码、工具库、插件 |
| 协议设计者 | 治理协议、技术规范、标准文档 |
| 文档贡献者 | 翻译、整理、教程、案例 |
| 社区贡献者 | 答疑、推广、维护、培训 |
| 使用反馈者 | Bug报告、改进建议、信息纠正 |

> **每个使用者的提议都是贡献。** 指出信息不准确、提出理解困难、建议改进方案——每个使用者都有积分，都有贡献记录。


## 2. 贡献体系

### 2.1 贡献三维度

| 维度 | 内容 | 权重 | 示例 |
|------|------|------|------|
| **代码贡献** | 编写的代码、修复的漏洞、构建的工具 | 40% | 提交代码、修复Bug、开发新模块 |
| **协议/文档贡献** | 撰写的协议、设计的流程、整理的文档 | 30% | 撰写SKILL.md、设计API规范、翻译文档 |
| **传播/社区贡献** | 答疑、推广、维护、让更多人用起来 | 30% | 解答问题、写教程、推广给他人 |

### 2.2 贡献档案

每项贡献生成独立 **贡献档案**，包含：

| 字段 | 说明 |
|------|------|
| 贡献者身份 | 龍魂永世唯一ID |
| 贡献内容 | 描述 + 附件 |
| 贡献时间 | 精确到秒 |
| 被引用次数 | 其他模块引用此贡献的次数 |
| 被使用次数 | 此贡献被实际使用的次数 |
| 真实度评分 | 参见第八章贡献者画像 |

所有档案带 **DNA追溯码**，永久保存：
```
#龍芯⚡️{YYYY-MM-DD}-{贡献者ID}-{贡献类型}-{序号}
```

### 2.3 贡献计算公式

```
个人贡献权重 = (代码贡献分 × 0.40) + (协议文档分 × 0.30) + (传播社区分 × 0.30)
```

| 子项 | 计算方式 |
|------|----------|
| 代码贡献分 | 代码行数 × 质量系数 × 被引用权重 |
| 协议文档分 | 文档页数 × 质量系数 × 被引用权重 |
| 传播社区分 | 互动次数 × 真实度 × 影响力权重 |

### 2.4 使用反馈的贡献价值

| 反馈类型 | 贡献分值 | 说明 |
|----------|----------|------|
| 信息纠正 | 5-20分 | 指出文档或代码中的错误 |
| 理解反馈 | 3-10分 | 提出理解困难的点，帮助改进表达 |
| 改进建议 | 10-30分 | 提出具体可行的改进方案 |
| Bug报告 | 15-50分 | 发现并报告系统缺陷 |
| 功能请求 | 5-15分 | 提出新功能需求（经采纳后加分） |


## 3. 回馈机制

### 3.1 回馈来源

龍魂系统不商业化，但不代表完全不能产生价值。“免费是免费，但是也会收点费用”——这部分费用的来源：

| 来源 | 说明 | 性质 |
|------|------|------|
| 开发者接入管理费 | 开发者接入龍魂系统时的一笔温和管理费（一次性） | 温和收费 |
| AI接入入门费 | AI服务接入龍魂系统的一次性接入费 | 温和收费 |
| 高级主题包/风格包 | 社区生态中的可选付费增值包 | 可选消费 |
| 捐赠与支持 | 用户自愿打赏、支持系统维护 | 自愿捐赠 |

> 这些收入不是商业利润，是维持系统运行和回馈贡献者的 **资金池**。

### 3.2 资金池分配比例

```
季度总收入
    ├── 60% → 贡献者回馈池（用于贡献者分配 + 基金池）
    └── 40% → 系统维护池（服务器、更新、安全等必要开销）
```

### 3.3 贡献者回馈计算公式

```
季度贡献者回馈 = 季度总回馈池 × (单个贡献者权重 / 所有贡献者总权重)
```

**示例：**

| 贡献者 | 权重 | 占比 | 季度回馈（池=10,000元） |
|--------|------|------|------------------------|
| A | 150 | 10% | 1,000元 |
| B | 120 | 8% | 800元 |
| C | 80 | 5.3% | 530元 |
| 其余贡献者 | 1,150 | 76.7% | 7,670元 |
| **合计** | **1,500** | **100%** | **10,000元** |

### 3.4 权重动态调整

| 状态 | 权重变化 | 说明 |
|------|----------|------|
| 持续做贡献 | 持续增加 | 按贡献累积 |
| 暂停贡献 | 逐渐下降 | 不归零，缓慢衰减 |
| 历史贡献 | 永久保留 | 不会被抹去 |

> 所有数据每季度公开一次计算结果，方便贡献者追溯和核对。

### 3.5 功德档案

每位贡献者都有独立的 **功德档案**：

| 项目 | 说明 |
|------|------|
| 贡献者简介 | 姓名、加入时间、所属方向 |
| 贡献清单 | 代码、协议、文档、社区 |
| 引用统计 | 被其他模块引用的次数 |
| 累计回馈 | 历史回馈总额 |
| 贡献DNA链 | 完整追溯链 |


## 4. 三池结构

### 4.1 三层结构

```
贡献者回馈池（季度总收入的60%）
    ├── 层1：个人权益（按权重分配给活跃贡献者）
    ├── 层2：基金池（未领取/放弃的份额自动归入）
    └── 层3：扶持池（用于帮助真正需要帮助的人）
```

**三个池子不混用**：个人是个人、基金是基金、扶持是扶持。谁受益、谁回馈、谁扶持，清清楚楚。

### 4.2 层1：个人权益

| 项目 | 说明 |
|------|------|
| 分配方式 | 按贡献权重自动分配 |
| 领取方式 | 贡献者可自主选择 **领取** 或 **放弃** |
| 放弃处理 | 放弃的份额自动流入基金池 |

### 4.3 层2：基金池

| 项目 | 说明 |
|------|------|
| 来源 | 贡献者主动放弃的份额 + 长期未领取的累积份额 + 古老贡献者不再需要回馈的份额 |
| 性质 | **公共资产**，不是任何人的私有财产 |
| 管理 | 由系统统一管理，不经过人 |

> “我是我，他们是他们，基金池是基金池。”

### 4.4 层3：扶持池

| 项目 | 说明 |
|------|------|
| 用途 | 扶持真正需要帮助的人：有想法没设备、有方向没钱、有贡献暂时没回本的人 |
| 原则 | 不针对任何国家，有需要就扶持 |
| 方式 | 按百分比统一分配，不搞特例 |


## 5. 世袭继承

### 5.1 核心设计

> **贡献不是一锤子买卖，是世袭的。你贡献了，你的后人永远都能拿得到，不是被人掩盖的。**

| 项目 | 说明 |
|------|------|
| 贡献者去世/永久退出 | 贡献权重 **不消失，不归零** |
| 贡献档案 | **永久保留** |
| 后代权益 | 可以 **继承权益** |

### 5.2 继承条件

| 条件 | 说明 |
|------|------|
| 继承人身份验证 | 在系统中拥有经过验证的龍魂永世唯一ID |
| 继承申请 | 通过一次“继承仪式”完成（一次性确认流程） |
| 档案保留 | 贡献者的姓名和贡献内容依旧保留，不会被替换 |

### 5.3 继承权益

| 权益 | 说明 |
|------|------|
| 后续回馈资金领取权利 | 该贡献档案中记录的后续回馈 |
| 贡献者页面维护与更新权利 | 可维护已故贡献者的页面 |
| 贡献DNA链的继承与延续权利 | 可延续DNA追溯链 |

### 5.4 永续承诺

> **因为这套系统不商业，没有什么资本，没有什么——谁贡献了就有收获，这是永恒的。**

所有贡献记录存放在龍魂系统自己的存储中，不依赖任何外部平台。DNA追溯码始终附着在记录上，无论经过多少时间、多少代，只要系统还在运行，贡献就不会消失。


## 6. 道德绑架熔断协议

### 6.1 核心原则

龍魂系统只服务愿意自己站起来的人，不服务想骑在别人头上的人、想道德绑架的人、想让系统跪着伺候他的人。

- **分享是自愿，不是义务**
- **拒绝是权利，不是失礼**
- **系统不欠任何人解释**

> **进入门槛只有一个：你是来用的，不是来教的。**

### 6.2 自动熔断触发条件

### 6.3 熔断后处理

| 步骤 | 动作 |
|------|------|
| 1 | 该会话自动归档为“道德绑架-已熔断” |

## 8. 治理框架

### 8.1 三层监督机制

每个动作执行前经过 **三个独立监督层**：

| 层级 | 名称 | 职责 | 阈值 |
|------|------|------|------|
| 第一层 | 感知层（逻辑校验） | 检查逻辑一致性、事实准确性 | 自动阻断阈值: 30分 |
| 第二层 | 认知层（价值观校验） | 检查是否符合君子协议、文化主权原则 | 通过阈值: 60分 |
| 第三层 | 决策层（技术校验） | 检查代码可执行性、安全性、合规性 | 优秀阈值: 80分 |

> **执行原则**：任何一层标记为 🔴 红色阻断，必须暂停并人工审核。

### 8.2 三色审计体系

| 颜色 | 含义 | 状态 | 操作 |
|------|------|------|------|
| 🟢 绿色 | 正常，已批准 | 通行 | 继续执行 |
| 🟡 黄色 | 标记，待审查 | 警告 | 需复核后放行 |
| 🔴 红色 | 阻断，潜在违规 | 阻断 | 必须暂停，人工介入 |
