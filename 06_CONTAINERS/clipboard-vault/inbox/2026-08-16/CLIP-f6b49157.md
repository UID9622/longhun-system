## 三步走部署流程

### 第一步：鲲鹏服务器部署

```bash
# 在 Mac 上执行，把整套配置传上去
scp -r /mnt/agents/output/longhun-dsh-kunpeng-deploy root@<鲲鹏IP>:/opt/

# SSH 上去一键跑
ssh root@<鲲鹏IP>
cd /opt/longhun-dsh-kunpeng-deploy
chmod +x scripts/*.sh
./scripts/deploy-kunpeng.sh
```

部署脚本会自动：
1. 检查 Docker / 架构
2. 生成龍魂 Profile 补丁 + 系统提示词
3. 拉取 `linux/arm64` 镜像
4. 启动 Ollama + dsh + 看板
5. 拉取 `deepseek-r1:14b` 模型（根据鲲鹏规格可选 7b/14b/32b）

### 第二步：Mac 本地环境

```bash
# 运行本地设置脚本
./scripts/local-mac-setup.sh <鲲鹏IP>

# 这会创建：
#   ~/.longhun/bin/lh          ← 龍魂终端命令
#   ~/.longhun/scripts/        ← SSH 隧道脚本
#   ~/.longhun/configs/        ← CodeBuddy 配置指引
```

### 第三步：日常使用

```bash
# 建立 SSH 隧道（把鲲鹏端口映射到本地）
lh tunnel

# 浏览器打开 DSH Web UI
lh dsh

# CodeBuddy 直接调用本地 Ollama 端点 (零费用)
# 已配置在 configs/codebuddy-settings.json，贴进 VSCode 即可

# 执行 headless 任务
lh headless "审查这个代码库的内存泄漏问题"

# 切换模型（如 7b 轻量版）
lh model deepseek-r1:7b
```

## 关键设计决策

**为什么用 Ollama 而不是 vLLM？**
- 鲲鹏是 ARM64，vLLM 的 ARM 支持仍在完善中，编译灾难多
- Ollama 官方原生支持 `linux/arm64`，拉下来就能跑
- 14b 模型在 4C8G 鲲鹏上推理延迟可接受（日常编码辅助场景）

**为什么 dsh 只监听 127.0.0.1？**
- P0 安全基线：不暴露公网，降低被扫描攻击面
- 外部访问必须通过 SSH 隧道或 WireGuard
- 符合龍魂"民用层分布式本地部署"定位

**"训练自己的龍魂模型"当前阶段指什么？**
- 🟢 **阶段一（现在就能做）**：系统提示词人格注入，零算力，修改 `configs/longhun-system-prompt.md` 即可
- 🟡 **阶段二（数据积累后）**：LoRA 微调，鲲鹏 4C8G 可跑 7B 模型的 LoRA，见 `training/llama-factory-lora.sh`
- 🔴 **阶段三（未来）**：昇腾 NPU 全量训练，需华为云昇腾实例，当前为理论假设
