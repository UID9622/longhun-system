## 一、问题：营销话术在进化，硬编码规则不够用了

我们常见的反诈/反营销系统，大多基于关键词黑名单。你说"微信"就触发，你说"赚钱"就标记。

但现实是：**营销话术在进化。**

骗子不会直接说"加我微信"，而是说"加我薇❤️"。

骗子不会直接说"月入十万"，而是把"十万"写在直播间的白板上，口播只念"家人们懂的都懂"。

骗子不会在公屏打出"传销"，而是用emoji、数字暗号、拆字法层层加密。

这就是四种**"隐身术"**：
1. **谐音字隐身** — 谐音替换规避关键词检测
2. **拆字笔画隐身** — 拆字法绕过敏感词
3. **直播小纸条隐身** — 非文字通道传递关键信息
4. **平台规避话术** — 利用"平台不让我说"制造神秘感

## 三、四种隐身术：实例拆解

### 隐身术一：谐音字规避

**原理**：用同音/近音字、拼音首字母、emoji替换敏感词，绕过关键词过滤器。

| 原始表达 | 规避写法 | 我们的还原 |
|:---|:---|:---|
| 微信 | 威信、薇信、VX、薇❤️、🆅🆇 | → 微信 |
| 支付宝 | 致富宝、zfb、支fb | → 支付宝 |
| 钱 | 米、圆、💰、💵 | → 钱 |
| 传销 | C X、C-X、传肖 | → 传销 |
| 投资 | 投Z、T Z、💰资 | → 投资 |

**引擎做的事**：先谐音归一化 → 再用标准模式库检测。比如"加我薇❤️月入五万躺赚" → 归一化为"加我微信月入五万躺赚" → 触发过度承诺检测。

```python
# 谐音归一化是检测前的前置步骤
def _normalize_homophones(text):
    # "加我薇❤️" → "加我微信"
    for standard, variants in homophone_map.items():
        for variant in variants:
            text = text.replace(variant, standard)
    return text
```

### 隐身术二：拆字/笔画拆分

**原理**：把敏感字拆成部件，如"骗"写成"马+扁"，"传销"写成"专 肖"。

常见拆字手法：
- **合字拆**：马扁（骗）、言乍（诈）、其欠（欺）
- **偏旁替换**：亻言、讠乍、扌包
- **全角/半角混排**：ａｂｃ、ＡＢＣ 打乱视觉识别
- **字符圈号**：ⓜⓐⓘ、🅐🅑🅒
- **Unicode圈号**：①②③④⑤⑥ 替代数字

**引擎检测**：笔画拆分正则 + Unicode圈号检测 + 全角字符检测。

```regex
# 拆字检测正则（简化示例）
"(马扁|言乍|其欠)"           # 合字拆
"[ⓐ-ⓩⓐ-ⓩ①②③④⑤⑥⑦⑧⑨⑩]"   # 圈号字符
"[ａ-ｚＡ-Ｚ]{3,}"            # 全角字母串
```

### 隐身术三：直播小纸条/互动暗号

**原理**：直播间里，口播说的是合规的，但白板、小纸条、屏幕上写的是真实的。观众需要"看得懂颜色"。

典型手法：
- 画面白板写着"私我""加微"——但口播不念
- "家人们懂的都懂，看右下角"
- "这个我没法说太明，你品你细品"
- 弹幕互动："想要的家人们扣1" → 然后私信发真实信息

**引擎检测**：
```regex
# 检测引导观看非文字渠道的话术
"(看|注意|仔细).{0,4}(纸|板|屏幕|画面|右下|左下|上方)"
"(懂的都懂|懂的人自然懂|你品|你细品)"
"(扣|打|输|按|点).{0,4}[1-9]"
```

### 隐身术四：平台规避话术

**原理**：以"平台不让我说"为由，把用户引导到私域流量（微信/QQ），在私聊中实施诈骗。

典型话术：
- "这个在公屏不能说，会被限流，加我私聊"
- "平台监控太严了，看主页简介加我"
- "之前说过一次被警告了，懂的加"
- "话说到这了，其它的你品"

**危险性**：一旦进入私聊，平台审核完全失效。所有"不方便说"的背后，大概率是见不得光的事。

**引擎检测**：
```regex
"(平台|系统|官方|这里).{0,4}(不让说|不能说|限制|敏感|限流|屏蔽)"
"(换个地方|私下|私聊|微信|加好友).{0,4}(说|聊|谈|讲)"
```
