## 已修复记录

### JS-SYNTAX-001 | 2026-07-06 | `escHtml()` 缺收口 `)`

**症状**：20 个 JS 语法错误集中在 `web/symbiote-dashboard.html`

**根因**：
1. `escHtml(\`...\`` 模板字面量开头写 `escHtml(\`)` ，末尾只写 `` ` `` 忘了 `)`——**缺了关闭 `escHtml(` 的 `)`**
2. 箭头函数 `n => {)` —— `{` 和 `)` 挤在同一行，解析器把 `{` 当空块体处理，后面的 `return` 掉到全局产生语法错误
3. `.join(''));` 缺少 `escHtml(` 的关闭 `)`

**根本模式**：多层嵌套函数调用时，忘记收外层函数的口。

**修复方案**：
- 所有 `escHtml(arr.map(fn).join('')) ` 拆为两行：先算结果，再传 `escHtml(result)`
- 模板字面量 `escHtml(\`...\`)` 确保末尾有 `)`

**影响文件**：`web/symbiote-dashboard.html`（6 处函数）

**DNA 修复链**：`#龍芯⚡️2026-07-06-SYMBIOTE-JS-SYNTAX-FIX-ZERO-E1F9C3D2`

**改前自查清单**（下次写相同代码必过）：
- [ ] `escHtml(` 的 `)` 收了吗？
- [ ] 箭头函数 `{` 和 `)` 是不是分在不同行？
- [ ] 嵌套调用是不是拆成两步更清晰？

### JS-SYNTAX-002 | 2026-07-06 | `escHtml()` 同类错误蔓延至 `longhun_hub.html`

**症状**：`longhun_hub.html`（dashboard + portal 两副本）出现 11 个同类 JS 语法错误。

**根因**：与 JS-SYNTAX-001 **完全相同**的书写模式——`escHtml(\`)` 没收 `)`、`escHtml(arr.map(fn => {) ...).join('')` 嵌套混乱。

**追问：为什么记了错还是再犯？**

| 深层根因 | 说明 |
|------|------|
| **记错本没有变成自动检查** | 记了错、写了自查清单，但人不会每次写代码都翻记错本 |
| **lint 规则只在 IDE 里生效** | 没有 `pre-commit` 钩子、没有 CI 检查、`lh health` 的检查只覆盖了 symbiote-dashboard 一个文件 |
| **两个副本没有自动同步** | `dashboard/web/p0-controls/longhun_hub.html` 和 `portal/portal/p0-controls/longhun_hub.html` 是手动 cp 同步的，改一个另一个漏了 |
| **`escHtml` API 设计本身容易出错** | 函数签名 `escHtml(str)` 接收一个参数，但写法习惯 `escHtml(\`...\`)` 让人以为模板字面量末尾就是结束——实际上还需要关 `escHtml(` 的 `)` |

**根本解决方案**（不止于"下次注意"）：

1. **`lh health` 升级**：从只扫 symbiote-dashboard 扩展到全项目所有 HTML
2. **`pre-commit` 钩子**：提交前自动跑 JS 语法检查（已有 `.pre-commit-config.yaml`，加一条 eslint/html-validate）
3. **副本自动同步**：建立符号链接或用脚本自动同步
4. **API 层防御**：在 `lh-utils.js` 里加一个 `safeHTML(el, templateFn)` 包装函数，自动处理 `escHtml` 的收口

**影响文件**：
- `L5_服务层/services/dashboard/web/p0-controls/longhun_hub.html`（8 处）
- `L5_服务层/services/portal/portal/p0-controls/longhun_hub.html`（同步修复）

**DNA 修复链**：`#龍芯⚡️2026-07-06-LONGHUN-HUB-JS-SYNTAX-FIX-11-E2A7D4F1`

## 🔬 追本溯源 · 为什么一再犯错

> 写于 2026-07-06，在第二次修复同一类错误后。

### 错误链追溯

```
AI 生成代码
  └→ 使用了 escHtml(`...`) 模式（看起来像写对了）
      └→ 模板字面量末尾写 ` 后，忘了 escHtml( 还需要 )
          └→ 浏览器解析器不报错（HTML 容错），但 JS 引擎报语法错
              └→ lint 报了 20 个错，修好了 symbiote-dashboard
                  └→ 但同样的模式在 longhun_hub.html 里也存在（没扫到）
                      └→ 又报了 11 个错 ← 就是现在
```

### 五问法追根

1. **为什么 escHtml 没收口？** → 因为多层嵌套时视觉上难以追踪括号配对
2. **为什么记了错还是再犯？** → 因为记错本是被动文档，不会主动阻止错误
3. **为什么第一次修复时没扫全项目？** → 因为 `lh health` 只写了 symbiote-dashboard 的专项检查
4. **为什么没写全项目扫描？** → 因为没有意识到同样的错误模式会在多个文件里复制粘贴
5. **为什么会有复制粘贴？** → 因为 dashboard 的 HTML 文件有多个副本（portal/dashboard 两套），而系统没有副本同步机制

### 根因（根本的根本）

**「记错」不等于「防错」**。记错本是给人类看的，但人类（包括 AI）不会在每次写代码前翻记错本。必须把记错本的内容**编译成自动检查规则**。

### 解决原则（铁律更新）

| 旧规则 | 新规则 |
|------|------|
| 记错本只归档 | 记错本每一条必须对应一条自动化检查 |
| 修复一个文件 | 修复后全项目扫描同类模式 |
| 手动同步副本 | 建立自动同步机制或去副本化 |
