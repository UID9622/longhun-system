## 摘要

XPay 是龍魂体系旗下的主权支付与激励协议，旨在构建一个**去中介化、透明可验证、文化主权优先**的数字经济基础设施。本白皮书系统阐述 XPay 的激励模型：从用户真实意愿确认、贡献度量、身份声誉、收益分配到防刷风控与治理升级，形成一套完整、专业、可落地的经济系统。

核心主张：

- **货币是主权，文化是世界的**——数字人民币是标杆，不是围墙。
- **收益归贡献者，数据归人民**——平台不占有用户资产，只记录不可篡改的 DNA 存根。
- **激励即治理**——经济设计本身就是对龍魂社区行为的引导与约束。

## 第一章 背景与问题

### 1.1 当前数字经济的问题

1. **平台垄断收益**：用户贡献数据、内容、注意力，但收益被平台截留。
2. **虚假流量盛行**：刷单、刷量、机器人账号扭曲了真实的价值创造。
3. **数据主权丧失**：用户行为数据被境外平台收集、分析、变现。
4. **激励不透明**：收益分配规则黑箱化，贡献者无法验证自己是否被公平对待。
5. **文化与主权脱节**：现有加密经济模型普遍以西方金融逻辑为中心，缺乏中华文明语境下的主权表达。

### 1.2 XPay 的立场

XPay 不是一家支付公司，也不是一个投机性代币项目。它是一个：

- **主权支付管道**：连接各国官方数字货币（CBDC）适配器，系统本身不触碰资金。
- **贡献激励协议**：将社区成员的真实贡献转化为可验证、可分配的经济权益。
- **文化主权基础设施**：以中文母语语义、龍魂符号体系、DNA 追溯码为底层表达。

## 第四章 身份等级与声誉系统

### 4.1 芯级体系

XPay 采用“芯级”作为用户身份与声誉的可视化表达，呼应龍魂“龍芯”文化符号：

| 等级 | 积分范围 | 称号含义 | 权益 |
|------|---------|---------|------|
| **铜芯** | 0–100 | 你在这里有根了。 | 基础支付、参与任务、提交反馈。 |
| **银芯** | 101–500 | 核心贡献者。 | 解锁审计权限、参与小型投票、获得贡献分成。 |
| **金芯** | 501–2000 | 塑造龍魂。 | 发起提案、参与治理、优先获得节点资格。 |
| **龍芯** | 2001+ | 与龍魂同呼吸。 | 最高治理权重、规则修订表决、文化大使身份。 |

### 4.2 声誉计算

声誉不是积分总和，而是积分经时间衰减与质量加权后的长期表现：

```
Reputation_t = α × Reputation_{t-1} + (1 - α) × QualityScore_t × Contribution_t
```

其中：

- `α`：衰减系数（默认 0.95），鼓励持续贡献，抑制一次性刷分。
- `QualityScore_t`：当期贡献质量分，范围 [0, 1]。
- `Contribution_t`：当期标准化贡献量。

声誉不可交易、不可转让，只与真实身份绑定。

## 第五章 贡献度量模型

### 5.1 贡献分类与权重

| 贡献类型 | 权重 | 示例 |
|---------|------|------|
| 代码提交 | 1.2 | 修复 bug、新增功能、性能优化 |
| 文档与翻译 | 0.9 | 白皮书、API 文档、多语言翻译 |
| 测试与审计 | 1.0 | 测试用例、安全审计、漏洞报告 |
| 社区运营 | 0.7 | 答疑、活动策划、内容传播 |
| 治理参与 | 0.8 | 提案、投票、规则讨论 |
| 真实支付使用 | 0.5 | 使用 XPay 完成合规交易 |

权重由治理层按季度审议调整，调整前需公示 14 天。

### 5.2 核心公式

**单期贡献值**：

```
Contribution_i = ActivityCount_i × QualityScore_i × FieldWeight_i × TimeDecayCoefficient
```

**个人当期 merit**：

```
Merit_i = Σ Contribution_i
```

**月度收益分配**：

```
MonthlyRevenue_i = (Merit_i / TotalMerit) × DistributablePool
```

其中：

- `DistributablePool`：当月可分配收益池，由系统维护费、捐赠、合规服务收入组成。
- `TotalMerit`：当期所有合格贡献者的 merit 总和。
- 未分配余额滚入下期池，不进入平台私账。

### 5.3 时间衰减

为防止“躺在功劳簿上”，贡献值随时间衰减：

```
TimeDecayCoefficient = exp(-λ × Δt)
```

- `λ`：衰减率（按月计，默认 0.1）。
- `Δt`：距离贡献发生经过的月数。

衰减后的贡献仍保留在 DNA 记录中，只是对经济分配的影响逐渐降低。

## 第六章 收益池与代币经济

### 6.1 收益池来源

| 来源 | 说明 | 占比（初始） |
|------|------|------------|
| DNA 维护费 | 每笔交易象征性费用（预设 0.001 CNY） | 40% |
| 社区捐赠 | 个人或组织自愿捐赠 | 30% |
| 合规服务收入 | 经授权的机构接入服务费 | 20% |
| 储备释放 | 龍魂储备池按治理规则释放 | 10% |

### 6.2 收益分配比例

```
总收益池 100%
├── 贡献者激励池          60%   → 按 merit 分配
├── 节点运营与基础设施     20%   → 按服务可用性分配
├── 安全与审计储备         10%   → 用于漏洞赏金、安全审计
└── 治理与公共品基金       10%   → 用于开源公共品、文档、教育
```

### 6.3 关于 XPay 积分

XPay 积分是系统内部计量单位，用于：

- 记录贡献值。
- 决定身份等级与治理权重。
- 作为收益分配的核算依据。

**XPay 积分不是加密货币**，不具备以下属性：

- 不得在公开二级市场交易。
- 不得用于投机炒作。
- 不得兑换为法定货币以外的支付工具（除非经治理层特别授权）。

积分与法定货币的兑换仅通过主权支付网关、按合规渠道完成。

## 第七章 防刷与风控机制

### 7.1 多层防御

| 层级 | 机制 | 说明 |
|------|------|------|
| L1 身份层 | 设备指纹 + 行为生物特征 | 识别机器人和批量注册。 |
| L2 行为层 | 异常模式检测 | 短时间内高频重复操作触发审查。 |
| L3 质量层 | 社区评分 + AI 辅助审计 | 低质量贡献被降权或标记。 |
| L4 举报层 | 同行举报与反作弊委员会 | 社区共治打击刷量。 |
| L5 冻结层 | 只冻结不删除 | 保留 DNA 证据，等待申诉或治理裁决。 |

### 7.2 作弊处罚

| 违规类型 | 处罚措施 |
|---------|---------|
| 轻微刷量 | 该贡献清零，警告一次。 |
| 重复刷量 | 冻结账号 30 天，扣除当期 50% merit。 |
| 大规模作弊 | 永久冻结，列入 DNA 黑名单，公示审计报告。 |
| 串通审计 | 审计者与被审计者一并冻结，撤销审计资格。 |

所有处罚只冻结、不删除，确保来源链完整。

## 第八章 治理与升级

### 8.1 治理结构

XPay 采用分层治理：

- **L0 宪法层**：UID9622 宪法原则，永不更改。
- **L3 经济层**：本白皮书及激励参数，需经金芯以上用户 2/3 多数通过方可修订。
- **执行层**：龍魂操作台与治理合约自动执行已通过提案。

### 8.2 参数升级流程

1. 任意金芯以上用户提交参数调整提案。
2. 公示 14 天，社区讨论。
3. 金芯 + 龍芯用户投票，需 2/3 赞成。
4. 通过后由系统自动更新参数，并生成升级 DNA。
5. 升级记录写入 `var/governance/governance_heal.jsonl`。

### 8.3 紧急冻结

当出现以下情况时，系统可自动触发紧急冻结：

- L0 宪法层异常。
- 发现重大安全漏洞或资金风险。
- 国家法律法规要求暂停某项功能。

紧急冻结由守护进程执行，事后 24 小时内提交治理复盘。

## 第九章 合规与主权

### 9.1 数据主权

- 用户收益数据、贡献记录、身份等级默认本地存储。
- 出境传输需经用户明确授权，并符合中华人民共和国数据安全法律。
- 系统优先使用龍芯、华为、CNSH 等自主可控技术栈。

### 9.2 支付合规

- XPay 网关仅作为透明传输管道，不沉淀资金、不做资金池、不做投资。
- 真实接入各国 CBDC 需获得该国央行或授权机构正式 API 与合规牌照。
- 在未完成授权前，所有支付功能均为演示状态，禁止用于真实生产支付。

### 9.3 反洗钱与 KYC

- 涉及法币兑换的功能必须接入合规 KYC/AML 流程。
- 大额或异常交易触发二级审查。
- 审查记录 DNA 化，确保可追溯、不可篡改。
