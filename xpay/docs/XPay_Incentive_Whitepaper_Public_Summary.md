# XPay Sovereign Incentive Model — Public Summary

**Version**: 1.0

## What is XPay?

XPay is a sovereign payment and incentive protocol. It is designed to be:

- **Transparent**: all formulas, pools, and distributions are publicly verifiable.
- **Sovereign-first**: user data stays local; the platform never takes custody of user funds.
- **Contribution-based**: economic rewards flow to real contributors, not middlemen.
- **Culturally rooted**: built with Chinese-native semantics and symbolic identity layers.

XPay is not a payment company, a bank, or a speculative token project. It is a transparent transmission pipe that connects sovereign currency adapters (starting with e-CNY) and records tamper-proof DNA stubs for every transaction.

---

## Core Design Principles

1. **Sovereignty first** — data and earnings belong to users.
2. **Real contribution only** — incentives require quality auditing and anti-fraud checks.
3. **Transparency** — formulas and distributions are open for verification.
4. **Gradual evolution** — upgrades are governance-driven, never radical experiments.
5. **No deletion, only freezing** — evidence chains are preserved.

---

## Identity & Reputation

XPay uses a four-tier identity system called the **Core Levels**:

| Level | Points | Meaning |
|-------|--------|---------|
| Bronze Core | 0–100 | You have a root here. |
| Silver Core | 101–500 | Core contributor. |
| Gold Core | 501–2000 | Shaping the ecosystem. |
| Dragon Core | 2001+ | In full alignment with the ecosystem. |

Reputation decays over time to encourage continuous contribution and resist one-time score pumping.

---

## Contribution Measurement

```
Contribution = Activity × QualityScore × FieldWeight × TimeDecay
Merit        = Σ Contribution
Revenue_i    = (Merit_i / TotalMerit) × DistributablePool
```

Fields include code, documentation, testing, community operations, governance, and compliant payment usage.

---

## Revenue Pool

The distributable pool is composed of:

- DNA maintenance fees (preset at a symbolic level).
- Community donations.
- Compliant service revenue.
- Reserve releases approved by governance.

Initial allocation:

- 60% contributor incentives
- 20% node operations and infrastructure
- 10% security and audit reserve
- 10% public-goods fund

---

## Anti-Fraud

Multi-layer defense:

- Identity layer: device fingerprinting and behavioral biometrics.
- Behavior layer: anomaly detection.
- Quality layer: community scoring and AI-assisted auditing.
- Reporting layer: peer reporting and anti-fraud committees.
- Freezing layer: accounts are frozen, not deleted, preserving evidence.

---

## Compliance

- XPay does not hold user funds; it only routes to official CBDC adapters.
- Real production use requires formal API access and licenses from relevant authorities.
- KYC/AML flows are mandatory for fiat on/off-ramp functions.
- Cross-border data transfers require explicit user consent and comply with applicable data-security laws.
